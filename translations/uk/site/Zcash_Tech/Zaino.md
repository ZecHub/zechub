# Zaino Індексатор

## Коротко

* **Zebra** перевіряє ланцюг Zcash.
* **Zaino** індексує дані ланцюга Zebra і надає API для клієнтів.
* **Zallet** — компонент гаманця в стеку Z3. У типовій конфігурації Z3 Zallet напряму взаємодіє з Zebra і не потребує окремого сервісу Zaino.
* Окремий сервіс Zaino корисний, коли операторам потрібна сумісна з lightwalletd кінцева точка gRPC, проксі JSON-RPC або інфраструктура для легких гаманців, оглядачів блоків, кранів та подібних сервісів.
* Zaino — активна інфраструктура, але перед запуском у виробничому середовищі операторам слід перевірити офіційні Zaino і документацію Z3, щоб дізнатися про актуальні деталі розгортання.

## Основне пояснення

Zaino — індексатор Rust для блокчейну Zcash. Він зчитує дані ланцюга з повного вузла Zebra. Він надає дані, потрібні гаманцям, оглядачам блоків, кранам та іншим сервісам, не покладаючи на Zebra відповідальність за всі клієнтські індекси.

### Що робить Zaino

Zaino розташований між Zebra і клієнтським програмним забезпеченням. Zebra — вузол консенсусу: він завантажує, перевіряє та відстежує блокчейн Zcash. Zaino використовує Zebra як джерело даних ланцюга, а потім готує індексовані представлення, до яких клієнтські програми можуть швидко надсилати запити.

Такий поділ чітко розмежовує ролі:

| Компонент | Роль |
|:--|:--|
| Zebra | Повний вузол і валідатор |
| Zaino | Індексатор і API-сервіс для клієнтів |
| Zallet | Сервіс гаманця |
| lightwalletd | Старіший сервер легких гаманців, який Zaino призначений замінити або доповнити |

Zaino надає функціональність для легких клієнтів, повних клієнтів або гаманців, а також оглядачів блоків. Він забезпечує доступ до фіналізованого ланцюга, найкращого нефіналізованого ланцюга та даних мемпулу, які зберігає Zebra.

### Як це вписується в поточний Zcash Stack

Поточний стек Z3 побудований на Zebra, Zallet та необов’язковому Zaino.

У типовому розгортанні Z3 Zebra і Zallet працюють разом. Zallet напряму звертається до Zebra, тому оператору, який запускає лише локальний стек гаманця, не потрібно запускати окремий сервіс Zaino.

Zaino додають, коли оператор хоче обслуговувати зовнішніх клієнтів. У Z3 він працює за профілем Compose `indexer` і надає:

* кінцеву точку gRPC, сумісну з lightwalletd, для клієнтів легких гаманців
* проксі JSON-RPC для оглядачів блоків, кранів і серверних компонентів сервісів
* базу даних індексатора окремо від стану ланцюга Zebra

Тому Zaino особливо актуальний для серверних компонентів гаманців, операторів публічної інфраструктури, оглядачів блоків, кранів і розробників, які тестують сервіси, що потребують індексованих даних ланцюга Zcash.

### Zaino і lightwalletd

lightwalletd — початковий сервер легких гаманців. Zaino — наступний варіант для цієї ролі на основі Rust. Його мета — за можливості надавати сумісні API, щоб гаманці та сервіси могли переходити на нього без необхідності одразу повністю переписувати їх.

Це не означає, що кожне розгортання lightwalletd уже перейшло на Zaino. Операторам слід розглядати Zaino як частину поточного стека на основі Zebra та перевіряти найновішу документацію проєкту, випуски й панелі керування сервісами перед вибором того, що запускати.

## Візуальне пояснення / аналогія

Уявіть блокчейн Zcash як величезний архів сторінок реєстру.

Zebra — архіваріус. Він отримує кожну нову сторінку, перевіряє, чи відповідає вона правилам, і кладе її на належне місце.

Zaino — довідкова стійка перед архівом. Вона читає те, що впорядкував Zebra, створює каталоги для швидкого пошуку й оперативно відповідає відвідувачам. Легкі гаманці, оглядачі блоків і крани звертаються до цієї стійки із запитаннями на кшталт «що міститься в цьому блоці?» або «які транзакції очікують у мемпулі?». Довідкова стійка не визначає, які сторінки справжні. Це робота архіваріуса.

Zallet у типовій конфігурації Z3 працює в тій самій будівлі й прямує просто до архіваріуса. Довідкова стійка йому не потрібна.

## Поглиблений огляд

### Примітки для операторів

Найпростіший офіційний шлях розгортання — репозиторій Z3. Z3 містить Zaino як необов’язковий сервіс:

```bash
docker compose --env-file .env.<network> --profile indexer up -d
```

Спочатку виконайте звичайне налаштування Z3 і дочекайтеся синхронізації Zebra, перш ніж запускати залежні сервіси в Mainnet або Testnet.

Zaino надає два види мережевих сервісів. Сервіс gRPC — це API для легких гаманців. Сервіс JSON-RPC призначений для доступу через loopback або з довірених приватних мереж, якщо інший рівень не забезпечує захист. Не відкривайте в публічному інтернеті незахищену автентифікацією чи шифруванням кінцеву точку JSON-RPC.

## Поширені помилки

**Вважати Zaino повним вузлом.** Zaino не є валідатором. Zebra перевіряє ланцюг; Zaino індексує дані з Zebra.

**Припускати, що кожному розгортанню Z3 потрібен окремий Zaino.** У типовому стеку Z3 Zallet може напряму звертатися до Zebra. Запускайте Zaino, коли для зовнішніх клієнтів потрібен окремий сервіс індексатора.

**Подавати заплановані функції як уже розгорнуті.** Zaino активно розробляється, тому перевіряйте актуальні примітки до випусків і документацію, перш ніж стверджувати, що певна функція доступна.

**Необережно відкривати JSON-RPC.** Інтерфейс JSON-RPC Zaino призначений для loopback або довірених приватних мереж, якщо його не захищено іншим рівнем.
