# Опублікуйте вебсайт в IPFS 

![](/content-images/IPFS-40c2e22732.webp)

## Вступ до IPFS 

IPFS (InterPlanetary File System) — це одноранговий протокол і мережа, розроблені для створення децентралізованого способу зберігання та обміну файлами. 

На відміну від традиційної клієнт-серверної моделі інтернету, IPFS дозволяє користувачам ділитися файлами безпосередньо один з одним, замість того щоб покладатися на централізований сервер для зберігання та розповсюдження контенту. 

Файли в IPFS адресуються за допомогою *content-addressing*, тобто кожному файлу надається унікальний хеш або CONTENT IDENTIFIER (CID) на основі його вмісту, і саме цей хеш використовується для отримання файлу з мережі.

IPFS зберігає вміст у вигляді блоків, що ідентифікуються за CID. Додавання файлу зберігає його на вашому вузлі, але не копіює автоматично на інші вузли. Щоб інші читачі могли його отримати, тримайте доступну копію онлайн або налаштуйте віддалене закріплення (remote pinning). Див. [IPFS збереження даних](https://docs.ipfs.tech/concepts/persistence/).

Прочитайте [Вступ до IPFS](https://blog.infura.io/post/an-introduction-to-ipfs)



## Створення вашого сайту 

У цьому прикладі ми створюємо простий вебсайт. 

[Приклад сайту](https://squirrel.surf)


**Крок 1:** Якщо ви не знайомі з вебдизайном, напишіть основний вміст для свого вебсайту, включно із заголовком, основним текстом, посиланнями на інші сторінки/сайти та нижніми колонтитулами.

**Крок 2:** Скористайтеся [HTML шаблоном!](https://nicepage.com/html-templates) Вставте написаний вами текст у відповідні місця. За бажанням також можна створити .CSS stylesheet для вашого вебсайту. 

**Крок 3:** Розмістіть свою головну сторінку у `index.html` у кореневій теці сайту. Додайте її зображення та CSS, використовуючи відносні шляхи, як-от `style.css`, щоб вони також працювали за URL-адресою шлюзу IPFS.

## Налаштування вузла

[IPFS Desktop](https://docs.ipfs.tech/install/ipfs-desktop/) керує вузлом за вас. Не закривайте його, поки ділитеся своїм сайтом.

Для [варіанту з командним рядком](https://docs.ipfs.tech/how-to/command-line-quick-start/) один раз ініціалізуйте новий репозиторій:

```sh
ipfs init
```

Потім запустіть вузол і залиште цей термінал відкритим:

```sh
ipfs daemon
```

Виконайте решту команд у другому терміналі. Не запускайте другий демон, якщо IPFS Desktop уже керує цим репозиторієм.

**Додайте папку сайту до IPFS**: 

У IPFS Desktop виберіть теку з файлами вашого вебсайту за допомогою опції «Add Folder».

![](/content-images/ipfs-site-folder-2c96524d98.webp)

--

Для варіанта через CLI запустіть цю команду з батьківської теки папки вашого сайту:

```sh
ipfs add -r folder_name
```

Замініть `folder_name` на назву своєї папки (назви з пробілами беріть у лапки). Збережіть CID з останнього рядка `added ... folder_name`: він ідентифікує весь каталог, а не лише `index.html`.

### Закріпіть сайт в IPFS: 

Команда CLI `ipfs add` за замовчуванням закріплює (pin) імпортований вміст локально. Перевірте закріплення папки за допомогою:

```sh
ipfs pin ls YOUR_FOLDER_CID
```

Замініть `YOUR_FOLDER_CID` на CID з попереднього кроку; у виводі має бути `recursive`. Закріплення (pinning) захищає копію на цьому вузлі від збирання сміття, але не тримає вимкнений комп'ютер онлайн. Щоб вміст залишався доступним, поки ваш вузол офлайн, налаштуйте [віддалене закріплення](https://docs.ipfs.tech/how-to/work-with-pinning-services/) і переконайтеся, що віддалений сервіс завершив закріплення.

### Доступ до вашого вебсайту в IPFS: 

Спочатку перевірте свій сайт через локальний шлюз за адресою `http://127.0.0.1:8080/ipfs/YOUR_FOLDER_CID/` (якщо ваш демон показує інший порт шлюзу, використайте його). Завдяки скісній риці в кінці відносні посилання працюватимуть усередині каталогу.

Публічний шлюз, наприклад `https://ipfs.io/ipfs/YOUR_FOLDER_CID/`, зможе його відобразити, щойно отримає вміст із доступного вузла. Успішний локальний попередній перегляд не доводить, що сайт публічно доступний.

## IPNS 

Interplanetary Naming System (IPNS) дозволяє вам оновлювати CID IPFS, пов’язані з вашим вебсайтом, і при цьому зберігати статичне посилання. Він надається як ключ.

## DNS Link 
 
Сайт створено, тепер нам потрібен спосіб прив’язати URL до контенту. 

Для `example.com` додайте цей DNS-запис, замінивши `YOUR_FOLDER_CID` на CID вашого каталогу:

| Тип | Назва | Значення |
|---|---|---|
| TXT | `_dnslink.example.com` | `dnslink=/ipfs/YOUR_FOLDER_CID` |

Деякі DNS-провайдери додають зону автоматично; там введіть лише `_dnslink`. Якщо використовуєте ім'я IPNS, наведене вище, значенням натомість може бути `dnslink=/ipns/YOUR_IPNS_NAME`. Див. [DNSLink](https://docs.ipfs.tech/concepts/dnslink/).

![](/content-images/example-c2a9edb28b.webp)

Після поширення DNS спробуйте `https://ipfs.io/ipns/example.com/`. Щоб сайт відкривався безпосередньо за адресою `https://example.com/`, також потрібні шлюз із підтримкою DNSLink і налаштування HTTPS; сам лише запис TXT цього не налаштовує. Дотримуйтеся [посібника з власного домену](https://docs.ipfs.tech/how-to/websites-on-ipfs/custom-domains/).

Вітаємо! Ви налаштували вебсайт, стійкий до цензури.
