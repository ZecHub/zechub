## Вступ до IPFS

IPFS (InterPlanetary File System) — це peer-to-peer протокол і мережа, створені для децентралізованого зберігання та обміну файлами.

На відміну від традиційної клієнт-серверної моделі інтернету, IPFS дозволяє користувачам обмінюватися файлами безпосередньо один з одним, а не покладатися на централізований сервер для зберігання та розповсюдження вмісту.

Файли в IPFS адресуються за допомогою *content-addressing*, тобто кожному файлу присвоюється унікальний хеш або CONTENT IDENTIFIER (CID) на основі його вмісту, і саме цей хеш використовується для отримання файлу з мережі.

IPFS зберігає вміст у вигляді блоків, ідентифікованих за CID. Коли ви додаєте файл, він зберігається на вашому вузлі й не копіюється автоматично на інші вузли. Тримайте доступну копію онлайн або налаштуйте віддалене закріплення (pinning), щоб інші читачі могли його отримати. Див. [IPFS про збереження даних](https://docs.ipfs.tech/concepts/persistence/).

**Читайте: [Вступ до IPFS](https://blog.infura.io/post/an-introduction-to-ipfs)**

## Створення вашого сайту

У цьому прикладі ми створюємо простий вебсайт.

[Приклад сайту](https://squirrel.surf/)

**Крок 1:** Якщо ви не знайомі з вебдизайном, напишіть основний вміст для вашого вебсайту, включно з назвою, основним текстом, посиланнями на інші сторінки/сайти та нижнім колонтитулом.

**Крок 2:** Використайте [HTML шаблон!](https://nicepage.com/html-templates) Вставте написаний вами текст відповідним чином. За бажанням також можна створити .CSS stylesheet для вашого вебсайту.

**Крок 3:** Розмістіть свою головну сторінку в `index.html` у корені папки сайту. Додайте її зображення та CSS, використовуючи відносні шляхи, як-от `style.css`, щоб вони працювали також за URL-адресою шлюзу IPFS.

## Налаштування вузла

[IPFS Desktop](https://docs.ipfs.tech/install/ipfs-desktop/) керує вузлом за вас. Не закривайте його, поки ділитеся своїм сайтом.

Для [варіанту з командним рядком](https://docs.ipfs.tech/how-to/command-line-quick-start/) один раз ініціалізуйте новий репозиторій:

```sh
ipfs init
```

Потім запустіть вузол і залиште цей термінал відкритим:

```sh
ipfs daemon
```

Виконайте решту команд у другому терміналі. Не запускайте другий демон, якщо IPFS Desktop уже керує цим репозиторієм.

### **Додайте папку сайту до IPFS**:

У IPFS Desktop виберіть папку з файлами вашого вебсайту за допомогою опції Add Folder.

<a href="">
    <img src="/content-images/ipfs-site-folder-2c96524d98.webp" alt="" width="400" height="200"/>
</a>

–

Для варіанта через CLI виконайте цю команду з батьківського каталогу папки вашого сайту:

```sh
ipfs add -r folder_name
```

Замініть `folder_name` на назву вашої папки (назви з пробілами беріть у лапки). Збережіть CID з останнього рядка `added ... folder_name`: він ідентифікує весь каталог, а не лише `index.html`.

### Закріпіть сайт у IPFS:

Команда CLI `ipfs add` за замовчуванням закріплює (pin) імпортований вміст локально. Перевірте закріплення папки за допомогою:

```sh
ipfs pin ls YOUR_FOLDER_CID
```

Замініть `YOUR_FOLDER_CID` на CID із попереднього кроку; у виводі має бути `recursive`. Закріплення (pinning) захищає копію на цьому вузлі від збирання сміття, але не тримає вимкнений комп'ютер онлайн. Щоб вміст залишався доступним, поки ваш вузол офлайн, налаштуйте [віддалене закріплення](https://docs.ipfs.tech/how-to/work-with-pinning-services/) і переконайтеся, що віддалений сервіс завершив закріплення.

### Доступ до вашого вебсайту в IPFS:

Спочатку перевірте свій сайт через локальний шлюз за адресою `http://127.0.0.1:8080/ipfs/YOUR_FOLDER_CID/` (якщо ваш демон показує інший порт шлюзу, використовуйте його). Скісна риска в кінці потрібна для того, щоб відносні посилання працювали всередині каталогу.

Публічний шлюз, наприклад `https://ipfs.io/ipfs/YOUR_FOLDER_CID/`, зможе віддавати його, щойно отримає вміст із доступного вузла. Успішний локальний перегляд не доводить, що вміст публічно доступний.

## DNS Link

Сайт створено, тепер нам потрібен спосіб спрямувати URL на цей вміст.

Для `example.com` додайте цей DNS-запис, замінивши `YOUR_FOLDER_CID` на CID вашого каталогу:

| Тип | Назва | Значення |
|---|---|---|
| TXT | `_dnslink.example.com` | `dnslink=/ipfs/YOUR_FOLDER_CID` |

Деякі DNS-провайдери додають зону автоматично; там введіть лише `_dnslink`. Якщо використовуєте наведене вище ім'я IPNS, значенням натомість може бути `dnslink=/ipns/YOUR_IPNS_NAME`. Див. [DNSLink](https://docs.ipfs.tech/concepts/dnslink/).

<a href="">
    <img src="/content-images/example-c2a9edb28b.webp" alt="" width="400" height="100"/>
</a>


Після поширення DNS спробуйте `https://ipfs.io/ipns/example.com/`. Щоб сайт відкривався безпосередньо за адресою `https://example.com/`, також потрібні шлюз із підтримкою DNSLink і налаштування HTTPS; сам лише TXT-запис їх не налаштовує. Дотримуйтеся [посібника з налаштування власного домену](https://docs.ipfs.tech/how-to/websites-on-ipfs/custom-domains/).
