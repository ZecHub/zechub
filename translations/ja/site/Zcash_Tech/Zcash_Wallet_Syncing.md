# Zcash ウォレット（Wallet）の同期

## TL;DR

* シールドされた（shielded）Zcashトランザクション（transaction）は詳細を隠すため、サーバーはBitcoinやEthereumのような公開型（transparent）コインの場合のように、ウォレット（wallet）の残高を単純に照会できません。
* ライトウォレットは、専用サーバー（lightwalletd）から小さな「コンパクトブロック（compact blocks）」をダウンロードし、秘密鍵を使用して関連データを自ら復号します。
* これらのブロックを復号して処理するには時間がかかるため、ウォレットは資金をより早く利用できるよう、高速な同期方法を使用します。
* 注目すべきアプローチには、Warp Sync（YWallet）、Spend-before-sync（Zcash Mobile Wallet SDK V2）、Blaze Sync（Zecwallet）、および提案されているDAGSyncがあります。
* これらの方法は一般に、より高速な同期のために追加のメモリまたは処理能力を必要とします。

## 基本的な説明

### Zcashの同期の仕組み

Zcashは、ゼロ知識proof（zero-knowledge proofs）を用いて、権限のない第三者からトランザクションの詳細をシールドします。このプライバシー（privacy）により、ライトウォレットの同期は難しくなります。ライトウォレットは完全なブロックチェーンをローカルに保存せず、必要な情報をサーバーに依存しているためです。BitcoinやEthereumでは、サーバーがブロックチェーンにインデックスを作成し、アカウントデータを迅速に返すことができます。しかし、Zcashでは、サーバーはトランザクションの詳細を見ることができません。では、ライトウォレットはブロックチェーン全体を自らダウンロードして復号することなく、どのように残高と履歴を同期できるのでしょうか。

Zcashは、複数の手法を組み合わせることでこの問題を解決します。フルノードからデータをフィルタリングし、トランザクション識別に必要なものだけを保持する専用サーバー、lightwalletdを備えています。このデータはコンパクトブロックと呼ばれ、元のブロックよりもはるかに小さくなっています。ライトウォレットはまずlightwalletdサーバーからこれらのコンパクトブロックをダウンロードし、その後、秘密鍵で復号します。

これらのコンパクトブロックであっても、復号と処理にはかなりの時間がかかる場合があります。特に、ブロックごとのトランザクション数が多い場合は顕著です。そのため、ウォレットは同期を高速化し、できるだけ早く資金を利用できるようにするさまざまな方法を用いています。

## 視覚化 / たとえ

ブロックチェーンを、鍵のかかった箱でいっぱいの巨大な郵便室だと考えてみてください。公開型コインでは、郵便室の係員がラベルを読めるため、どの箱があなたのものかをすぐに教えてくれます。Zcashではラベルが隠されているため、あなたのウォレットは鍵を使い、自分で静かに箱を確認して、開けられる箱を見つけなければなりません。以下の同期方法は、これらの箱をより速く確認するための異なる戦略です。

## 詳細解説

### Warp Sync

Warp Syncは、各コンパクトブロックを復号・処理する中間ステップを省略し、最終結果へ直接進むYWalletの機能です。

これを実現するために、各ステップを経ることなく最終結果を計算する数学と暗号技術を使用します。

Warp Syncは、通常の同期方法よりはるかに高速で、1秒あたり数千ブロックを処理できます。つまり、YWalletのユーザーは、アカウントに数十万件のトランザクションや受信したノートがあっても、高速で滑らかなパフォーマンスを享受できます。

このステップ省略技術に加え、YWalletは複数のブロックを同時に処理し、利用可能なハードウェア全体に負荷を分散することで、処理をさらに高速化できます。

[Warp Sync](https://ywallet.app/warp/)で詳しく読む

> Warp Syncはここでは同期技術として説明されています。Ywallet自体はすでに保守されておらず、Ironwood向けに更新される予定もないため、現在インストールするウォレットではありません。

### 同期前支払い

同期前支払いは、Zcash Mobile Wallet SDK V2の新機能であり、ユーザーはウォレットを開いた際、完全なウォレット同期を待たずに即座に資金を支払うことができます。この機能は、ウォレットの利用可能な残高の検出を高速化し、ユーザー体験を改善します。

同期前支払いは、lightwalletdサーバーからのブロックを非線形の順序で処理するコンパクトブロック同期アルゴリズムを使用して機能します。つまり、1つのブロックが完全に処理されるのを待ってから次に進むのではなく、ウォレットは少し多くのメモリと処理能力を使用して、ブロックチェーンの異なる部分をスキャンできます。通常は、古いブロックをダウンロード・処理している間に、より新しいトランザクションを探すため、異なる範囲をスキャンします。最近の未使用ノートが見つかった場合、それは直ちに利用可能になります。

### Blaze Sync

Zecwalletチームによって開発されたBlaze Syncは、最も高い最新ブロックから開始して後方へ進み、ブロックチェーンを逆方向にスキャンするライトウォレット向けの同期アルゴリズムです。

これにより、ウォレットは受信したノートより先に使用済みノートを見つけられ、以前は未使用だったノートを、完全な同期プロセスの終了を待たずに利用可能にできます。

さらに、ブロックのダウンロード、試行復号の実行、ウィットネスの更新という同期コンポーネントを互いに分離し、並列処理することで、順不同同期を使用します。これはより多くのメモリとCPUリソースを必要としますが、同期速度を5倍に向上させます。

### DAGSync

DAGSyncは、同期を高速化することでZcashのシールドされたウォレットのユーザー体験を改善することを目指した、提案中の同期アルゴリズムです。

これは、[有向非巡回グラフ（Directed Acyclic Graph、DAG）](https://words.str4d.xyz/dagsync-graph-aware-zcash-wallets/)を使用して、Zcashウォレット内のノート、ウィットネス、およびヌリファイア間の依存関係を表現します。

DAGは、ノードとエッジから構成されるデータ構造であり、各エッジには2つのノード間の関係を示す方向があります。DAGにはサイクルがないため、あるノードから開始してエッジをたどり、同じノードへ戻ることはできません。

## 実用上の影響

興味深いことに、これらすべての仕組みは、Zcash Securityが[Scalable Private Messaging](https://zecsec.com/posts/scalable-private-money-needs-scalable-private-messaging/)に関する投稿で提起した疑問と、プライベートな支払いシステムとの関係に対処することを目指しています。一部はさらに進み、アドレス専用のデータを除くすべてのメモデータをサーバーからダウンロードすることで、わずかな追加リソースを必要とする代わりにプライバシーを高めています。

また、Zcash Foundationはライトウォレットのパフォーマンスを改善するため、他の選択肢も検討しています。その例が[Oblivious Message Retrieval（OMR）](https://zfnd.org/oblivious-message-retrieval/)です。これは、財団が「Zcashウォレットのユーザーに影響を与えた最近のパフォーマンス問題に対する潜在的な解決策となるかどうかを判断するため」に研究している構成です。

## よくある誤解

**lightwalletdサーバーがあなたの残高を把握していると考えること。** サーバーが配信するのはコンパクトブロックだけです。ウォレットは自身の鍵を使い、ローカルでそれらを復号して解釈します。

**同期を早く停止しすぎること。** 一部の方法では、完全な同期が完了する前に最近の利用可能な資金を使用できますが、古い履歴やノートはまだ処理中の場合があります。

**Zcashの同期を公開型チェーンの同期と直接比較すること。** 遅い経路は欠点ではなく、プライバシーを維持するためのコストである場合があります。ウォレットは、公開型コインのサーバーであればアカウントを公開して読み取ることで行う作業を担っています。
