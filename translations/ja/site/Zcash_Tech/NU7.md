# NU7

> NU7は、2026年11月6日02:34 UTC（米国のタイムゾーンでは11月5日の夜）に、ブロック（block）3,543,405でZcash Mainnetにおいて有効化され、それ以降稼働しています。

この記事でわかること：NU7が変更した内容（より高速なブロック、シールドされた（shielded）アクションの上限、手数料（fee）の再発行、バージョン4トランザクション（transaction）の終了）、変更しなかった内容、そしてノード（node）運用者、ウォレット（wallet）、取引所（exchange）、マイナー（miner）が必要とした対応です。

NU7は、Zcashの[ネットワークアップグレード（network upgrade）](../start-here/network-upgrades)であり、[ZIP 259](https://zips.z.cash/zip-0259)によって展開されました。ブロック間の時間を75秒から25秒へ短縮し、1つのブロックに含められるシールドされたアクション数を制限し、トランザクション手数料の60%を流通から除去して将来のマイナーへ再発行できるようにし、バージョン4トランザクションを無効化しました。これにより古いSproutプール（pool）は廃止されました。新しいトランザクション形式は導入していません。コンセンサス（consensus）ブランチIDは`0x77190ad9`です。

これが重要な理由です。NU7以前は、最初の承認まで平均75秒待つ必要があり、店舗のレジ、取引所への入金、クロスチェーン（cross-chain）スワップ（swap）には遅すぎました。NU7は、より多くのZECを発行することなく、その時間を約25秒に短縮しました。ブロックあたりの報酬を3分の1にしたため、1日あたりの発行量は同じままです。また、ブロック報酬が縮小した後のネットワークセキュリティの費用を賄うことを目的とした仕組みを追加する、最初のアップグレードでもあります。

Zcashを初めて知る方は、まず[ZECとは何かZcashと](../start-here/what-is-zec-and-zcash)[シールドされたプール](../using-zcash/shielded-pools)をお読みください。その後にこの記事へ戻ってください。

## TL;DR

平たく言うと、ブロックは25秒ごとに生成されるようになり、1日あたりの新規ZEC発行量は同じままです。各手数料の一部は将来のマイナーのために保管され、古いSproutプールは閉鎖されました。

- **25秒ブロック**（[ZIP 218](https://zips.z.cash/zip-0218)）：最初の承認は75秒ではなく約25秒です。ブロック補助金は1.5625から0.52083333 ZECに減少したため、1日あたり約1,800 ZECは引き続き発行されます。
- **シールドされたアクションの上限**（ZIP 218）：すべてのプールを通じて、1ブロックあたり最大330のシールドされたアクションと、プールごとの上限を設け、最悪時のブロック検証およびウォレット同期コストを以前より低く抑えます。
- **ネットワーク持続可能性メカニズム**（[ZIP 235](https://zips.z.cash/zip-0235) + [ZIP 237](https://zips.z.cash/zip-0237)）：各ブロックのトランザクション手数料の60%は流通から除去され、後でマイナーに再発行されます。開始はブロック8,939,664（2031年2月頃の予測）です。2,100万の供給上限は変更されません。
- **バージョン4トランザクションは無効です**（[ZIP 2003](https://zips.z.cash/zip-2003)）：ウォレットはv5またはv6トランザクションを構築する必要があります。Sproutはv4でしか支出できないため、Sproutに残る資金は凍結されています。
- **ソフトウェア**：[Zebra 7.0.0](https://github.com/ZcashFoundation/zebra/releases/tag/v7.0.0)以降はNU7に従います。`zcashd`にはNU7対応のリリースはありません。

## 視覚的な例え

チェーン（chain）を鉄道路線だと考えてください。NU7以前は、75秒ごとに列車が出発し、2 MBに収まるだけの乗客を乗せられました。NU7では、25秒ごとに列車を走らせ、各運転手には以前の運賃の3分の1を支払うことで1日の合計を同じに保ちます。また、最も重い乗客（シールドされたアクション）が1列車に乗車できる人数に上限を設けるため、1本の列車の確認に過度な時間がかかることはありません。

## NU7が変更した内容

### 25秒のブロック目標間隔（ZIP 218）

- 難易度調整は、75秒ではなく**25秒**ごとに1ブロックを目標とするようになりました。そのため、ブロックは3倍の頻度で生成されます。
- ブロック補助金は3分の1になりました。現在の半減期（halving）期間では、ブロックあたり**0.52083333 ZEC**です（以前は1.5625 ZECでした）。1日あたりの発行量は約1,800 ZECのままです（1日あたり1,152ブロックではなく3,456ブロック）。
- 半減期は引き続き4年ごとに発生します。ブロックが高速化されたため、次の半減期はブロック**6,132,390**へ移動し、25秒間隔では2028年11月下旬頃と予測されています（ZIP 259）。
- 難易度の平均化ウィンドウは17ブロックから**102ブロック**へ拡大され、調整は引き続き同程度の時間幅を参照します。
- デフォルトのトランザクション有効期限は40ブロックから**120ブロック**へ拡大され、約50分に維持されます。

### シールドされたアクションの上限（ZIP 218）

各ブロックには共有予算とプールごとの上限があります。

| 上限 | 1ブロックあたり |
|---|---|
| プール全体にわたるすべてのシールドされたアクション | 330 |
| Orchardアクション | 330 |
| Ironwoodアクション | 330 |
| Sapling入力 + 出力 | 300 |
| Sprout JoinSplits | 許可されません |

NU7以前は、完全な2 MBブロックには、約617のOrchardまたはIronwoodアクション、あるいは約2,107のSapling出力を含めることができ、プールごとの制限はありませんでした。ZIP 218は、新しい上限を設定しています。ブロック数が3倍になっても、ノードとウォレット同期の最悪ケースは以前より低くなります（例えば、ライトクライアント（light client）のシールドされた同期帯域幅の最大値は、1日あたり約271 MBから169 MBへ低下します）。一方で、Orchardプロトコルのスループットは2倍以上になります（2アクションのトランザクションでは毎秒約2.9から6.6トランザクション）。

### ネットワーク持続可能性メカニズム（ZIP 235 + ZIP 237）

- **手数料の除去（ZIP 235）：** 各ブロックのトランザクション手数料の60%は流通から除去され、残りの40%は従来どおりマイナーに渡ります。バーンとは異なり、除去されたZECは追跡されるため、後で再発行できます。
- **再発行（ZIP 237）：** 除去されたZECは、NSM Value Balanceと呼ばれる公開コンセンサス状態に保管されます。これは、過去にマイナーが請求しなかった価値を使ってNU7に初期化されました。ブロック**8,939,664**（2031年2月頃の予測）から、各ブロックで通常の半減期スケジュールに加えて、その残高の一定割合が発行されます。
- 供給上限は増加しません。残高がゼロになると、発行量は従来の半減期スケジュールと完全に同じになります。
- NU7は、[ZIP 233](https://zips.z.cash/zip-0233)（ユーザーによる任意の除去）も、[ZIP 234](https://zips.z.cash/zip-0234)（半減期を滑らかな曲線に置き換えること）も導入していません。コイン保有者の投票では、ZIP 237において半減期を維持する設計が選ばれました。
- 数値（初期値の368.58 ZEC、ブロックごとの再発行割合、開始がブロック8,939,664である理由）については、[Network Sustainability Mechanism](./Network_Sustainability_Mechanism.md)のページをご覧ください。

### バージョン4トランザクションの禁止（ZIP 2003）

- NU7以降、すべてのバージョン4トランザクションは無効です。Sprout送金だけでなく、公開型（transparent）のみのトランザクションや、v4形式で構築されたSaplingトランザクションも対象です。バージョン5（NU5）およびバージョン6（[Ironwood](../zcash-tech/ironwood)）のトランザクションは変更されません。
- Sprout送金はv4形式にしか存在しないため、[Sprout](../zcash-tech/sprout)プールからは支出できなくなりました。[資金の回復](../using-zcash/recovering-funds)を参照してください。

### 小さな変更項目

- 開発基金のルール改訂により、資金ストリームは25秒ブロックで機能します（[ZIP 207](https://zips.z.cash/zip-0207)改訂2、[ZIP 214](https://zips.z.cash/zip-0214)改訂3）。また、資金ストリームのアドレス一覧も更新されました（[ZIP 2008](https://zips.z.cash/zip-2008)）。
- NU7ノードは、Mainnetでネットワークプロトコルバージョン**170190**を広告し、有効化後は古いピアを切断します。

## NU7が変更しなかった内容

- **新しいトランザクション形式はありません。** NU7は、Ironwoodがv6トランザクションを導入した直後に、ウォレットとパーサーを再び移行することを意図的に避けました。
- **供給上限および4年ごとの半減期の周期に変更はありません。**
- **コインベース成熟度に変更はありません。** マイニングされたコインは、引き続き支出可能になるまで100ブロックを必要とします（現在は約2時間ではなく約42分です）。
- **新しいシールドされたプールはありません。** Ironwood（NU6.3）は引き続き最新のプールであり、OrchardはIronwood以降と同様に支出専用のままです。

## 各グループが必要とした対応

- **ノード運用者：** [Zebra 7.0.0](https://github.com/ZcashFoundation/zebra/releases/tag/v7.0.0)以降を実行してください。Zebra 7は、最初の起動時にデータベースをv28形式からv29形式へ移行します。Zebra 6.xはv29を読み取れないため、アップグレード前に`state/v28`をバックアップしてください。`zcashd`にはNU7リリースはありません（最新リリースは2026年6月の6.20.0です）。Zebraブックの[zcashdAPI移行ガイド](https://zebra.zfnd.org/user/zcashd-api-migration-guide.html)では、各`zcashd` RPCがZebra、[Zallet](../zcash-tech/zallet)、またはその代替に対応づけられています。[フルノード](../zcash-tech/full-nodes)および[強化されたZebraガイド](../guides/hardened-zebrad)を参照してください。
- **ウォレット：** v4トランザクションの構築を停止し、120ブロックのデフォルト有効期限を使用し、3ブロックのアンカー深度（現在は約1.25分）を維持し、ブロックごとのアクション上限を遵守してください。単独で上限を超えるトランザクションは、決してマイニングされません。
- **取引所および支払いサービス：** 承認には現在25秒かかるため、同じ承認回数が対象とする時間は3分の1になります。以前の数を慣習的に維持するのではなく、実際に必要な時間とセキュリティに照らして入金承認回数を再確認してください。
- **マイナーおよびプール：** マイニングソフトウェアおよびテンプレートは、新しい補助金、手数料分配、アクション上限を使用する必要があります。古いルールに基づいて構築されたブロックは拒否されます。

## よくある誤解

- **「古いノードがまだ動いているので問題ありません。」** NU7に限り、ZIP 259は、アップグレード前のソフトウェアが有効化前に自動停止する通常のルールを免除しました。6.xのZebraまたは`zcashd`ノードは、古いルールのままオンラインを維持し、気付かないうちに実際のチェーンから外れる可能性があります。ノードが3,543,405を超える高さを報告し、ブロックエクスプローラーと一致することを確認してください。
- **「ブロックが速くなると、より多くのZECが発行されます。」** いいえ。ブロックあたりの補助金は3分の1に減少したため、1日あたりの発行量は変わりません。
- **「手数料の60%は永久にバーンされます。」** いいえ。これらは除去され、後でNSMによってマイナーに再発行されます。供給上限は変わりません。
- **「v4の変更の影響を受けるのはSproutユーザーだけです。」** 公開型のみのものやSaplingのものを含め、v4トランザクションをまだ生成しているウォレットまたはスクリプトはすべて動作しなくなりました。保留中のv4トランザクションは有効化時に無効となり、再署名だけでは有効にできません。
- **「ブロック数で設定された値はそのまま引き継がれます。」** ブロックで測定されるもの（承認、有効期限、ロック時間、タイムアウト）はすべて、実時間では3倍速く経過します。

## 用語集

| 用語 | わかりやすい意味 |
|---|---|
| Block target spacing | 難易度調整が目標とするブロック間の平均時間：NU7以降は25秒 |
| Block subsidy | 各ブロックで新たに作成され、マイナーと開発基金ストリームの間で分配されるZEC |
| Shielded action | トランザクション内のシールドされた処理の1単位（OrchardまたはIronwoodアクション、あるいはSapling入力または出力） |
| Network Sustainability Mechanism (NSM) | 手数料の一部を流通から除去し、将来のマイナーに再発行するルール |
| NSM Value Balance | 流通から除去され、再発行を待つZECの公開累計値 |
| Version 4 transaction | Saplingからのトランザクション形式で、NU7により無効化されました。v5とv6は有効なままです |
| Consensus branch ID | コンセンサスルールのセットを識別する番号です。署名はこれにコミットするため、古いルール向けに署名されたトランザクションは新しいルールでは無効です |

## FAQ

**NU7はいつ有効化されましたか？** 2026年11月6日02:34 UTCに、Mainnetのブロック3,543,405で有効化されました。Testnetではそれより早く、2026年10月4日にブロック4,465,026で有効化されました。

**ブロック報酬は変更されましたか？** ブロックあたりでは、はい。1.5625 ZECではなく0.52083333 ZECです。1日あたりでは、いいえ。どちらの場合も約1,800 ZECです。

**私のSprout ZECは失われましたか？** Sproutの支出にはv4トランザクションが必要であり、それらは現在無効なため、移動できなくなっています。実際に何を意味するかについては、[資金の回復](../using-zcash/recovering-funds)を参照してください。

**新しいウォレットが必要ですか？** NU7をサポートするウォレットのバージョンが必要です。ZecHubの[ウォレット](../using-zcash/wallets)ページでは、どのウォレットがNU7互換かを確認できます。

**手数料の再発行はいつ始まりますか？** Mainnetではブロック8,939,664から始まります。ブロックの平均が25秒のままであれば、2031年2月頃と予測されます。

**NU7が新しいトランザクション形式を省略したのはなぜですか？** Ironwoodのv6形式の直後に、ウォレットとパーサーに2回目の移行を強いないためです。また、手数料分配はブロックごとに計算されるため、新しいトランザクションフィールドは必要ありませんでした。

## 理解度チェック

1. NU7後も1日あたりのZEC発行量が同じなのはなぜですか？
2. 流通から除去された手数料の60%はどうなりますか？
3. NU7後、なぜSprout資金は支出できないのですか？
4. 一度もアップグレードされていないノードが、このアップグレードで特に危険なのはなぜですか？

回答：（1）ブロックが3倍の頻度になった一方で、ブロックあたりの補助金が3分の1に削減されたためです。（2）NSM Value Balanceに入り、ブロック8,939,664からマイナーに再発行されます。（3）Sproutの支出は、NU7が無効化したv4形式にしか存在しないためです。（4）ZIP 259が自動停止を免除したため、古いノードは誤ったチェーン上で動作し続ける可能性があります。
