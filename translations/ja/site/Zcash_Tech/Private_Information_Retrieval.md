# プライベート情報検索（Private information retrieval）

## 要約

- プライベート情報検索、すなわちPIRは、サーバーがどの項目を要求されたかを知ることなく、デバイスがサーバーのデータベースから1件の項目を取得できるようにします
- Zcashでこれが必要なのは、プライベートなウォレットが自身のトランザクションをサーバーに問い合わせると、自身を特定されてしまうためです
- 現在、ウォレットは必要以上に多くのデータをダウンロードしてスキャンしており、これが同期が遅い主な理由です
- PIRにより、ウォレットはプライバシーを損なうことなく、自身のデータだけをプライベートに取得でき、このボトルネックを解消できます
- これはZcashにおける活発な研究分野であり、理論上は強力で、実際のウォレットで実用化されつつあります

<br/>

## 対象読者

- プライベートなウォレットが、どのコインかを漏らさずに自身のコインをどのように見つけるのか疑問に思った方
- Zcashのスケーリング作業とともにPIRが言及されるのを何度も見かける初心者の方
- まず概念を理解し、その後に基礎となる暗号技術を知りたい読者の方

<br/>

## PIRがZcashで解決する問題

Zcashは、トランザクションの送付先を隠します。このプライバシーは厄介な疑問を生みます。ネットワークがどのトランザクションが自分のものかを見られない場合、自分のウォレットはどのようにしてそれらを見つけるのでしょうか。

現在の答えは単純です。ウォレットはサーバーに「どのトランザクションが自分のものか」と尋ねることはできません。なぜなら、その質問によってZcashが隠そうとしているものが正確に明らかになるからです。そのため、代わりにウォレットは大量のデータをダウンロードし、各項目をローカルで検査して、自身に属するものを確認します。これは機能し、プライバシーを維持しますが、遅く負荷も大きいものです。このスキャンは、ウォレットの同期がもたつく主な理由の1つです。

理想的なのは、ウォレットがサーバーに自身のデータだけを正確に要求し、サーバーが何を要求されたかを一切知ることなく、そのデータを受け取れる方法です。まさにそれを提供するのがプライベート情報検索です。

<br/>

## PIRとは

プライベート情報検索は、クライアントがサーバーのデータベースから1つのエントリーを読み出す際に、サーバーへどのエントリーを読んだかを明かさない暗号技術です。

欲しい本を正確に受け取れる一方で、司書にはどの本を渡したのか分からない図書館を想像してください。目的の品を手に入れつつ、関心はプライベートに保たれます。PIRはこの考えを数学的に表現し、あらゆるデータベースに適用したものです。

この概念は数十年にわたり暗号技術で研究されてきました。最初に導入されたのは1995年で、Chor、Goldreich、Kushilevitz、Sudanが複数サーバー方式を説明しました。その後、1997年にKushilevitzとOstrovskyによる初の単一サーバー版が登場しました。これはZcashが発明したものではなく、Zcashが現在、現実に存在する根強い問題へ適用している確立された分野です。

<br/>

## PIRの仕組み：最初の概観

PIRを構築する大まかな方法は2つあり、その違いは重要です。

1つ目は複数のサーバーを使います。クライアントは複数のサーバーそれぞれにクエリの一部を送り、回答をローカルで組み合わせます。単一のサーバーだけでは、何が要求されたのかを知るのに十分な情報を得られません。これは効率的ですが、サーバー同士が共謀しないことに依存しており、現実世界では保証が困難です。

2つ目は、複数の当事者ではなく、単一のサーバーと巧妙な暗号技術を使用します。ここでクライアントは準同型暗号化（homomorphic encryption）と呼ばれる特別なツールに依存します。複数の非共謀サーバーを必要としないため、これは実際の導入に最も有用な方向です。

<br/>

## 仕組み：準同型暗号化

準同型暗号化は、データを暗号化したままサーバーがそのデータを計算できるようにする暗号化の一種です。サーバーは、基になる値を見ることなく、正しい暗号化済みの回答を生成します。

この方式で構築された単一サーバーPIRの考え方は次のとおりです。クライアントはリスト内の3番目の項目を求めています。実質的には、位置3に対する暗号化された「はい」と、それ以外のすべての位置に対する暗号化された「いいえ」からなるクエリを構築します。サーバーにとって、このクエリは意味のないノイズにすぎず、「はい」がどの位置にあるかは分かりません。

次にサーバーは、準同型暗号化の特別な性質を使って、自身のデータベースとこの暗号化済みクエリを組み合わせます。保存された各項目に対応する暗号化済みの「はい」または「いいえ」を乗算し、結果を加算します。結果として得られるのは、クライアントが求めた項目だけを含む1つの暗号化済みパッケージであり、どの項目だったかを明らかにするものはありません。クライアントはそのパッケージを復号し、項目を読み取ります。サーバーは質問を知ることなく、その質問に回答したのです。

対称PIR（symmetric PIR）と呼ばれるより強力なバージョンでは、2つ目の保証が加わります。クライアントは要求した項目だけを知り、データベース内の他のエントリーについては何も知りません。これにより、クライアントだけでなくデータベースも保護されます。

<br/>

## 技術的な読者向けの詳細

現代の単一サーバー方式は格子暗号を基盤とし、最も一般的にはLearning With Errors仮定を用います。クライアントのクエリは暗号文のベクトルであり、対象インデックスでは1、それ以外では0を暗号化したものです。この暗号化は加法準同型であるため、サーバーは復号することなく、暗号文を加算し、平文のデータベースエントリーを掛け合わせられます。

サーバーはデータベースを行列として扱い、暗号化済みの選択ベクトルを適用し、目的の行へ復号される単一の暗号文を返します。クエリはランダムノイズと区別できないため、サーバーはインデックスに関する情報を得られません。

歴史的な障害は常にコストでした。単純には、サーバーはクエリごとにデータベース内のすべてのエントリーに触れる必要があり、計算コストが高くなります。また、暗号文は大きいため、帯域幅のコストも高くなります。近年の研究は前処理によってこれに取り組んでいます。SimplePIRやFrodoPIRのような方式では、サーバーが事前にデータベースを準備し、各クライアントへ小さなヒントを渡せます。これにより作業の多くをオフライン段階へ移し、リアルタイムのクエリを高速化します。有用な副次的利点として、格子ベースの構成は量子攻撃にも耐性があると考えられており、これはZcashによる耐量子プライバシーへの幅広い移行とも一致します。

<br/>

## ZcashにおけるPIR

PIRは、Zcashを大規模でもプライベートかつ高速にする取り組みの一部です。

先に説明したウォレットスキャンのボトルネックが対象です。Valar Groupでの作業では、サーバーがどのエントリーを要求されたかを知ることなく、ウォレットがサーバーから自身のデータを取得できるようにするプライベート情報検索技術を開発しています。具体的な用途の1つは、ヌリファイア（nullifier）をプライベートに確認することです。ヌリファイアは、ノートが使用された際に公開される一意のマーカーであり、同じ資金が二重に使用されることを防ぎます。ウォレットは、特定のヌリファイアがすでに現れているか、言い換えればノートがまだ未使用かどうかを確認する必要がよくあります。しかし現在、サーバー経由でそれを行うと、どのノートについて尋ねているかが漏れる可能性があります。プライベート情報検索により、ウォレットは関心のあるヌリファイアを明かすことなく、その質問を行えます。これは、Project Tachyonや新しいノードソフトウェアを含む、現在プライベートなウォレットを制約している性能上の限界を取り除くことを目的とした他のスケーリング作業と並行しています。

この段階については正直であることが重要です。これは活発な研究とエンジニアリングであり、完成して提供済みの機能ではありません。概念は十分に確立され、方向性も定まっていますが、一般的なデバイス上の日常的なウォレットに十分な効率でPIRを実現することこそ、現在取り組まれている難しい部分です。

<br/>

## よくある誤解

- PIRは要求した項目を隠しますが、必ずしもサーバーへ接続した事実自体を隠すわけではありません。ネットワークレベルのメタデータは別の問題です
- PIRはZcashに固有のものではなく、Zcashがウォレットのプライバシーに適用している一般的な暗号技術ツールです
- PIRによる高速な同期は進行中の目標であり、すでにウォレットに存在する機能ではありません
- 現在の方式である、すべてをダウンロードしてローカルでスキャンする方法はプライベートですが遅いものです。PIRは、プライバシーを維持しながら遅さを取り除くことを目指します
