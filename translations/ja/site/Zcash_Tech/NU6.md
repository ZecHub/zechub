# NU6

> NU6は、Zcashメインネットでブロック2,726,400（2024年11月23日 UTC）に有効化されました。

ここで学べること：Zcashが半減期（halving）後も自身の開発資金をどのように維持するか、使途がまだ決まっていない準備金をなぜ確保したのか、そしてZECの総供給量をどのように正確に予測可能にしたのかを学べます。

NU6は、Zcashの[ネットワークアップグレード](../start-here/network-upgrades)であり、[ZIP 253](https://zips.z.cash/zip-0253)によってデプロイされ、2024年11月にブロック2,726,400でメインネットに有効化されました。これは金融および[開発資金](../start-here/development-fund)に関するアップグレードです。2024年11月の半減期後もブロック報酬の一部を開発に充て続け、将来コミュニティが決定する用途のためのプロトコル内準備金を設け、新規ZECの計上方法を厳密化しました。NU6は、Electric Coin CompanyとZcash Foundationの両方から承認されました。

これが重要な理由。Zcashの[開発基金](../zcash-tech/canopy)は、その歴史で2回目となる2024年11月頃の半減期で終了する予定でした。NU6はこの資金提供を継続しましたが、すべてのコインを固定の受取人へ渡す代わりに、一部をプロトコル内に確保し、コミュニティが後から使途を決定できるようにしました。また、これまで見過ごされていた会計上の空白も解消したため、将来存在するZECの総量を正確に予測できるようになりました。

## 要点まとめ（TL;DR）

- NU6は、ZIP 253によってデプロイされ、ブロック2,726,400（2024年11月23日 UTC）でメインネット上で有効化されました。
- 2024年11月の半減期後も、ブロック報酬の20%を開発資金へ送り続けました。8%はZcash Community Grants（ZCG）へ、12%は新設のDeferred Dev Fund Lockbox（ZIP 2001）へ送られます。
- このロックボックスはプロトコル内の準備金で、支出者は定義されていません。NU6はガバナンスの問題を意図的に未解決のまま残し、後にNU6.1（2025年）がその答えを示しました。
- ZIP 236により、すべてのコインベーストランザクションの収支が正確に一致することが必須となりました。そのため、マイナーが報酬を少なく請求して誤ってZECをバーンしてしまうことはもうありません。これにより、将来の総供給量を正確に予測できるようになります。
- 残高、プライバシー、トランザクションのルールは変更されていません。NU6は資金調達と会計に関するアップグレードです。

## 視覚的なたとえ

NU6を、建設を担う人たちに決まった手当を支払い続けてきて、その支給日がまもなく終わる予定だと分かっている家庭だと考えてみてください。NU6は支払いを止めるのではなく、手当を分けます。一部は引き続きコミュニティの助成金（Grant）委員会に渡り、残りは家族の金庫に入ります。この金庫の暗証番号はまだ発表されていません。家庭が後で金庫を開けるルールに合意するまで、お金は金庫に取り分けられたままになります。その合意がNU6.1です。

## NU6が変更したこと

NU6は、[ZIP 1015](https://zips.z.cash/zip-1015)で定義されたルールに基づき、2024年11月の半減期後もブロック報酬の20%を開発資金へ送る仕組みを継続しました。この20%は2つに分けられました。

1. ブロック報酬の8%は、コミュニティによる、コミュニティのための活動に資金を提供するZcash Community Grants（ZCG）へ送られます。
2. 12%は、将来コミュニティが決定する用途のために保有される、新たなプロトコル内ロックボックスに入ります。

ブロック報酬の残りとトランザクション手数料は、ネットワークを保護するマイナーに送られます。NU6は、この新しい構造に適合するよう、既存の資金ストリームおよび開発基金のルール（ZIP 207およびZIP 214）も更新しました。

![NU6 development-fund split: 20 percent of the block subsidy goes to development, with 8 percent to Zcash Community Grants and 12 percent into the Deferred Dev Fund Lockbox](/content-images/nu6-dev-fund-split-08bc73e317.webp)

## 繰り延べロックボックス

12%の配分は、NU6における新しい考え方です。受取アドレスへ支払う代わりに、この価値は[ZIP 2001](https://zips.z.cash/zip-2001)で定義される、Deferred Dev Fund Lockboxというプロトコル内プールへ直接預け入れられます。

1. ロックボックスは新しい資金ストリーム種別（DEFERRED_POOL）であり、ブロック報酬の価値は個人や組織ではなく、プロトコル自体に入ります。
2. ネットワークはこれを、シールドされたプールの残高を追跡するのと同じように、独自のチェーン価値プール残高として追跡します。
3. NU6は意図的にロックボックスを作成しましたが、誰がこれらの資金を管理し、どのように解放するのかという難しい問題は未解決のまま残しました。

この問題は後に[NU6.1](../zcash-tech/nu6-1)によって解決され、ガバナンスが定められました。これはZcash Community Grantsへのブロック報酬8%のストリームを継続し、ロックボックスを原資とするコイン保有者管理の基金へ12%のストリームを送るものです。

## 帳尻を合わせる

NU6は、新しいZECの生成方法における会計上の空白も解消しました。これは[ZIP 236](https://zips.z.cash/zip-0236)で定義されています。Coinbaseトランザクションは、各ブロックの新規ZECと手数料を支払う特別なトランザクションです。

1. NU6以前は、コインベーストランザクションは受け取るべき額を超えて請求しないことだけが求められていました。マイナーは報酬全額より少なく請求でき、それによってそのZECが気付かれないうちにバーンされる可能性がありました。
2. NU6以降、コインベーストランザクションは正確に均衡しなければなりません。出力価値の合計は、マイナー報酬と手数料の合計に等しくなければならず、多くても少なくてもいけません。
3. マイナーは過少請求によってZECを誤ってバーンできなくなったため、将来存在するZECの総量を正確に予測できるようになりました。

![Coinbase balancing before and after NU6: before, coinbase could under-claim and burn ZEC so supply was not exactly predictable. After, coinbase must balance exactly so issuance is exactly predictable](/content-images/nu6-coinbase-balance-0fa2394799.webp)

## 資金提供の変遷

NU6は、Zcashがどのように自身の費用を賄うかという長い物語の1章です。

1. Canopy（2020年）は、当初の創設者報酬を終了し、[開発基金](../start-here/development-fund)を創設しました。
2. NU6（2024年11月）は、2回目の半減期後に資金提供を再編し、将来コミュニティが決定する助成金のために発行量の一部を確保するDeferred Dev Fund Lockboxを設けました。
3. NU6.1（2025年）は、NU6が残した「誰が確保された資金を管理するのか」という問題に答え、ブロック報酬の8%をZcash Community Grantsへ継続して送り、12%をロックボックスを原資とするコイン保有者管理の基金へ送ることにしました。

![How Zcash funding evolved: Canopy created the development fund, NU6 set up the lockbox, and NU6.1 set the rules for who controls it](/content-images/nu6-funding-timeline-2427db58c0.webp)

## よくある間違い

- **NU6が金融政策を変更したと考えること。** 発行スケジュールと半減期（Halving）のタイミングは変更されていません。NU6が変更したのは補助金（Subsidy）の一部を誰が受け取るかであり、新たに発行されるZECの量ではありません。
- **ロックボックスを財団のウォレットと混同すること。** Deferred Dev Fund Lockbox は、コンセンサス（Consensus）によって追跡されるチェーン（Chain）の価値プール（Pool）であり、誰かが資金を使えるアドレス（Address）ではありません。
- **NU6.1とNU6を同じアップグレードだと思い込むこと。** NU6が準備金を創設し、NU6.1がそれを誰が管理するかを決定しました。8%はZCGに、12%はコイン保有者が管理する基金に割り当てられます。
- **正確な残高ルール（ZIP 236）がユーザーのコインを変更すると信じること。** このルールが制約するのはコインベーストランザクション（Coinbase Transaction）、つまりブロック（Block）ごとの発行による支払い（Payment）であり、既存の残高や通常のトランザクションではありません。
- **20%の開発資金分を新しいものと解釈すること。** 20%の開発資金はCanopy以来存在していました。NU6はそれを半減期以降も継続し、ZCGに8%、ロックボックスに12%と分割しました。

## 用語集

| 用語 | 平易な意味 |
|---|---|
| Block subsidy | マイニングされた各ブロックとともに生成される新しいZEC |
| Coinbase transaction | ブロックの報酬と手数料を支払う特別なトランザクション |
| Deferred Dev Fund Lockbox | 将来コミュニティが決定する用途のために発行量の一部を保有するプロトコル内準備金 |
| Zcash Community Grants (ZCG) | Zcashコミュニティによる、コミュニティのための活動に資金を提供する委員会 |
| Consensus branch id | ブロックがどのアップグレードのルールに従うかをノードが識別するために用いる識別子 |
| Network upgrade (NU) | 定められたブロック高で有効化される、Zcashのコンセンサスルールに対する協調的な変更 |

## よくある質問

NU6は私のZECやプライバシーを変更しますか？ いいえ。NU6は開発資金の提供方法と発行量の計上方法に関するものであり、あなたのトランザクションやプライバシーに関するものではありません。あなたの資金およびシールドされたトランザクションには影響しません。

資金はどこから来ますか？ ブロックがマイニングされる際に発行される、新しいZECであるブロック報酬から来ます。その20%が、すべてをマイナーへ送る代わりに開発へ振り分けられます。

ロックボックスは何のためのものですか？ コミュニティが後から使途を決定できるよう、発行量の一部をプロトコル内に確保します。NU6が準備金を確保し、NU6.1が誰がそれを管理するかのルールを定めました。

正確な均衡ルールは私のコインを変更しますか？ いいえ。各ブロックのコインベーストランザクションが、受け取るべき額を正確に支払うことだけを求めます。既存の残高ではなく、新規発行の会計に影響します。

NU6は技術的に何で定義されていますか？ NU6はZIP 253によってデプロイされ、メインネットでのブロック2,726,400における有効化とコンセンサスブランチIDを定めています。コンセンサス変更そのものはZIP 236、ZIP 1015、ZIP 2001に由来し、ZIP 207およびZIP 214は適合するよう更新されました。

NU6はNU6.1とどう異なりますか？ NU6は資金提供を再編し、ロックボックスを作成しました。NU6.1は、誰がロックボックス資金を管理するか、および確保された配分をどのように分割するかを決定しました。

## 理解度を確認しましょう

NU6はDeferred Dev Fund Lockboxを設けましたが、誰がそれを管理するかは定めませんでした。なぜアップグレードは準備金を作成し、そのガバナンスを意図的に後回しにするのでしょうか？

<details>
<summary>回答</summary>

準備金を作成することで、発行量の一部を固定の受取人へ支払うのではなく、プロトコル内に確保することが確定しました。誰がその資金を管理し、どのように解放するかを決定することは、より難しいガバナンス上の問題です。NU6はこれを意図的に未解決のまま残し、NU6.1が答えを示しました。ブロック報酬の8%はZcash Community Grantsへ継続して送られ、12%はロックボックスを原資とするコイン保有者管理の基金へ送られます。
</details>
