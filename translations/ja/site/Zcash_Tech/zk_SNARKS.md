# ZKP & ZK-SNARKS

## 要約

- **zk-SNARKs** = ゼロ知識（Zero-Knowledge）簡潔非対話型知識論証
- これは、ある当事者が情報そのものを明かさずに、**何かを知っていることを証明**できるようにします
- Zcashはzk-SNARKsを使用して、**送信者、受信者、または金額を明かすことなく**、トランザクション（transaction）が有効であること（正しい金額、未使用の入力）を証明します
- 「簡潔」とは、複雑な命題であってもプルーフ（proof）が小さく、検証が高速であることを意味します
- Orchardプール（pool）は、**トラステッドセットアップ（trusted setup）を必要としない**zk-SNARKシステムであるHalo 2を使用します

## プルーフとは何ですか？

プルーフは、すべての数学の基礎です。プルーフとは、証明しようとしている主張または定理と、その定理が証明されたことを宣言するための導出の連続です。たとえば、三角形の内角の和が180°であることは、誰でも独立して確認できます（検証者）。

**プルーフ** 

証明者 ---> 主張を行う ---> 検証者が選択 ---> 受理/却下 

（証明者と検証者の両方がアルゴリズムです）

コンピュータサイエンスでは、効率的に検証可能なプルーフをNPプルーフと呼びます。これらの短いプルーフは多項式時間で検証できます。大まかな考え方は、「定理の解が存在し、それが検証者に渡されて確認される」というものです。

NP言語では、次の2つの条件を満たす必要があります。 

完全性：真の主張は検証者に受理されます（正直な証明者が検証に到達できるようにします）

健全性：偽の主張にはプルーフがありません（不正な証明者のあらゆる戦略において、不正確な主張の正しさを証明することはできません）。


### 対話型・確率的プルーフ

**対話**：検証者はプルーフを読むだけでなく、複数回のメッセージラウンドを通じて証明者とやり取りします。

**ランダム性**：検証者の証明者への要求はランダム化され、証明者はそれぞれに正しく回答できなければなりません。

 <img width="855" height="399" alt="IPmodel1" src="/content-images/1542be12-d3fd-4934-8413-0d16f95b8d10-58bfcb4059.webp" alt="" width="600" height="400"/>

対話とランダム性を組み合わせることで、確率的多項式時間（PPT）において、見えていない検証者に対して主張を証明できます。 

対話型プルーフは、NPプルーフよりも多くのことを効率的に検証できますか？

NPプルーフとIPプルーフ：

|  命題   |    NP     | IP    |
|--------------|-----------|--------|
|    NP        |  はい      |  はい   |
|    CO-NP     |  いいえ       |  はい   |
|    #P        |  いいえ       |  はい   |
|    PSPACE    |  いいえ       |  はい   |


NP - 命題に対する解が存在すること

CO-NP - 命題に対する解が存在しないことを証明すること

#P - 命題に対していくつの解が存在するかを数えること

PSPACE  - 異なる命題の交替を証明すること

### ゼロ知識とは何ですか？

検証者が対話後に計算できることは、対話前に証明できたことと同一です。証明者と検証者の複数ラウンドにわたる対話によって、検証者の計算能力が高まることはありません。

**シミュレーション Paradigm**

この実験は暗号技術全体で用いられています。「実際のビュー」と「シミュレートされたビュー」を提示します。 

実際のビュー：証明者と検証者（P,V）の間で起こり得るすべての対話履歴

シミュレートされたビュー：検証者が証明者と検証者の間で起こり得るすべての対話をシミュレートしたもの

<a href="">
    <img width="850" height="397" alt="simulation1" src="/content-images/0e68649d-a231-44d8-a76a-25a307f68b9e-ba1f0027cf.webp"  alt="" width="600" height="400"/>
</a>

多項式時間識別器は、実際のビューとシミュレートされたビューのどちらを見ているかを判定しようとし、両方から繰り返しサンプルを要求します。

実際またはシミュレートされたビューから多項式個のサンプルを受け取った後であっても、すべての識別アルゴリズム/戦略に対して確率が>1/2である場合、2つのビューは「計算量的に識別不能」であるとされます。 

**ゼロ知識知識論証**

対話型プロトコル（P,V）は、すべての確率的多項式時間検証者について（定理が正しい場合）、実際のビューとシミュレートされたビューを決定する確率分布が計算量的に識別不能となるようなシミュレータ（アルゴリズム）が存在する場合、ゼロ知識です。 

対話型プロトコルは、検証者が1人の場合に有用です。例として、ゼロ知識「納税プルーフ」アプリケーションにおける税務監査官が挙げられます。

## SNARKとは何ですか？

**簡潔非対話型知識論証**

広義の定義では、命題が真であることを示す簡潔なプルーフです。プルーフは短く、検証が高速でなければなりません。SNARKでは、証明者から検証者へ1つのメッセージが送信されます。検証者はその後、受理または却下を選択できます。 

命題の例：「SHA256(m)=0となるメッセージ（m）を私は知っている」

zk-SNARKでは、プルーフはメッセージ（m）について何も明かしません。

**多項式**：定数（1、2、3など）、変数（x、y、zなど）、および変数の指数（x²、y³など）を含む項の和です。 

例：「3x² + 8x + 17」

**算術回路**：多項式を計算するためのモデルです。より一般的には、グラフの各ノードで算術演算が実行される有向非巡回グラフとして定義できます。回路は加算ゲート、乗算ゲート、およびいくつかの定数ゲートで構成されます。ブール回路がワイヤ上でビットを運ぶのと同様に、算術回路は整数を運びます。

<img width="785" height="368" alt="circuit1" src="/content-images/be1de1d6-60d3-4fd1-b9a2-5094c65d696f-dbd3177247.webp" alt="" width="300" height="200"/>
</a>

この例では、証明者は算術回路に対する解を知っていることを検証者に納得させたいと考えています。  

**コミットメント**：これを行うため、証明者は回路に関連するすべての値（プライベートおよびパブリック）をコミットメントに入れます。コミットメントは、出力が不可逆である関数を使用して入力を隠します。

Sha256は、コミットメントスキームで使用できるハッシュ関数の一例です。

証明者が値をコミットした後、コミットメントは検証者に送信されます（検証者は元の値を一切明らかにできないと確信しています）。その後、証明者はグラフのノードにある各値についての知識を検証者に示すことができます。 

**Fiat-Shamir変換**

プロトコルを*非対話型*にするため、証明者は暗号学的ハッシュ関数を使用して、検証者に代わってランダム性（隠されたチャレンジに使用されます）を生成します。これはランダムオラクルとして知られています。証明者はその後、検証者に1つのメッセージを送信でき、検証者はそれが正しいことを確認できます。 

一般的な回路に使用できるSNARKを形成するには、2つの要素が必要です。

機能的コミットメントスキーム：コミッターが短い文字列を用いて多項式にコミットでき、検証者がコミットされた多項式の主張された評価を確認するために使用できます。

多項式対話型オラクル：検証者は、多項式コミットメントスキームを使用して、任意に選択したさまざまな点で全コミットメントを開示するよう証明者（アルゴリズム）に求め、それらの間で恒等式が成り立つことを確認します。

**セットアップ**

セットアップ手順は、回路を要約してパブリックパラメータを出力することで、検証者を支援します。 

<a href="">
<img width="845" height="398" alt="setup1" src="/content-images/c41212ca-b5e9-4ac8-8695-be612c45a679-80a6a87752.webp" alt="" width="600" height="300"/>
</a>

**前処理セットアップの種類**：

回路ごとのトラステッドセットアップ（Trusted Setup） - 回路ごとに個別に実行されます。この結果得られる共通参照文字列（Common Reference String、CRS）には、証明者と検証者が使用する公開パラメータが含まれます。秘密に保持して破棄しなければならないのは CRS ではなく、セットアップの過程で生じる秘密の中間データ（「有毒廃棄物（toxic waste）」）です。ECCの[公開パラメータに関する解説](https://zodl.com/snark-parameters/)では、この2つを区別しています。

必要な秘密のセットアップ情報が保持されたり復元されたりした場合、不正な証明者が偽の命題の証明を作成できてしまう可能性があります。MPCセレモニー（MPC ceremony）では、少なくとも1人の参加者がプロトコルに従い、自身の秘密の寄与分を破棄することにセキュリティが依存する場合があります。

トラステッドかつユニバーサルなセットアップ - 1回のトラステッドセットアップ（Trusted Setup）で生成されたパラメータから、サポートされるサイズの範囲内で複数の回路の証明鍵と検証鍵を導出できます。ただし、この方式でも秘密情報が確実に破棄されているという前提は残ります。ユニバーサルであることは、公開型（Transparent）であることを意味しません。

公開型セットアップ（トラステッドセットアップなし）- 公開パラメータは、誰かが破棄することを信頼しなければならない秘密のセットアップのトラップドア（trapdoor）なしで生成できます。これは、証明の生成にランダム性を一切使用しないことや、システムに公開パラメータが存在しないことを意味するものではありません。[Halo 2 の書籍](https://zcash.github.io/halo2/background/pc-ipa.html#setup)では、公開されたグループパラメータの例が示されています。


**SNARKプルーフ構成の種類**：

[Groth16](https://eprint.iacr.org/2016/260)：トラステッドセットアップを必要としますが、非常に短いプルーフを高速に検証できます。

[Sonic](https://www.youtube.com/watch?v=oTRAg6Km1os)/[Marlin](https://www.youtube.com/watch?v=bJDLf8KLdL0)/[PLONK](https://eprint.iacr.org/2019/953)：ユニバーサルなトラステッドセットアップ。

[DARK](https://eprint.iacr.org/2019/1229)/[Halo](https://eprint.iacr.org/archive/2019/1021/20200218:011907)/[STARK](https://www.youtube.com/watch?v=wFZ_YIetK1o)：トラステッドセットアップは不要ですが、やや長いプルーフを生成するか、証明者の実行により長い時間がかかる場合があります。 

SNARKは、Zcashのようなブロックチェーンや[Aztec](https://docs.aztec.network)のようなzk-ロールアップなど、複数の検証者が必要な場合に有用です。これにより、複数の検証ノードが各プルーフについて複数ラウンドにわたって対話する必要がなくなります。 

## zk-SNARKはZcashでどのように実装されていますか？

一般に、ゼロ知識プルーフは、情報を一切明かすことなく、プロトコルにおける誠実な行動を強制するツールです。 

Zcashは、プライベートなトランザクションを可能にする公開型ブロックチェーンです。zk-SNARKは、トランザクションに関する他の詳細を一切明かさずに、プライベートトランザクションがネットワークのコンセンサスルール内で有効であることを証明するために使用されます。 

[動画による解説](https://www.youtube.com/watch?v=Kx4cIkCY2EA) - この講義では、Ariel Gabizonが、Zcashノートコミットメントツリー、ブラインド多項式評価、準同型的に隠されたチャレンジ、およびそれらがネットワーク上でどのように実装されているかを説明しています。 

詳細については、[Halo2ブック](https://zcash.github.io/halo2/index.html)をお読みください。

## その他のゼロ知識アプリケーション 

zk-SNARKsは、多種多様なアプリケーションにおいて複数の利点を提供します。いくつかの例を見てみましょう。

**スケーラビリティ**：これは「計算のアウトソーシング」によって実現されます。L1チェーンがオフチェーンサービスの作業を検証するために、ゼロ知識が厳密に必要なわけではありません。トランザクションは、zk-EVM上で必ずしもプライベートではありません。

プルーフベースのロールアップ（zk-ロールアップ）サービスの利点は、数百または数千のトランザクションのバッチを処理し、L1がすべてのトランザクションが正しく処理されたことを示す簡潔なプルーフを検証できる点です。これにより、ネットワークのトランザクションスループットは100倍または1000倍にスケーリングされます。

**相互運用性**：これは、ソースチェーンで資産を「ロック」し、資産がロックされたことをターゲットチェーンに証明する（コンセンサスのプルーフ）zk-ブリッジで実現されます。

**コンプライアンス**：[Espresso](https://www.espressosys.com/blog/decentralizing-rollups-announcing-the-espresso-sequencer)などのプロジェクトは、トランザクションの詳細を明かすことなく、プライベートトランザクションが現地の銀行法に準拠していることを証明できます。 

**偽情報との戦い**：ブロックチェーンおよび暗号資産以外の複数の例として、ニュースおよびメディア機関によって処理された画像に対してプルーフ生成を使用することで、視聴者は画像の出所と、その画像に対して実行されたすべての操作を独立して検証できます。https://medium.com/@boneh/using-zk-proofs-to-fight-disinformation-17e7d57fe52f
