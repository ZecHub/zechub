# ビューイングキー（Viewing Keys）

シールドされたアドレスでは、Zcashブロックチェーン上で可能な限り情報を明かさずにトランザクションを行えます。では、保有しているものや送信したものを特定の相手に見せる必要が*ある*場合はどうなるでしょうか。すべてのシールドされたアドレスには、支出する能力を付与せずに読み取りアクセスを与えるビューイングキーがあります。ビューイングキーは[ZIP 310](https://zips.z.cash/zip-0310)で導入され、Saplingネットワークアップグレードでプロトコルに追加されました。

ビューイングキーは、選択的開示（selective disclosure）のためのツールです。誰に何を見せるかを選択でき、そのために支出権限を渡すことはありません。

## 要約

ビューイングキーは、シールドされたZcashアドレスまたはアカウントの活動に対する**読み取り専用**アクセスを付与します。保持者は受信トランザクション（およびフルビューイングキーの場合は送信トランザクション）を確認できますが、支出することは決してできません。

- **これは何か：** シールドされたプールの選択的開示ツールです。[ZIP 310](https://zips.z.cash/zip-0310)で導入され、Saplingネットワークアップグレードでプロトコルに追加されました。
- **付与されるもの：** 入金の検出（`uivk…`受信キー）またはアカウントの完全な入出金可視性（`uview…`統合フルビューイングキー）、および旧式のSapling`zxviews…`キーです。
- **付与されないもの：** 支出権限です。ビューイングキー保持者が行ういかなる操作でも、資金を移動することはできません。
- **現在利用できる場所：** [Zallet](https://github.com/zcash/zallet)（v0.1.0-beta.2以降、`z_exportviewingkey` / `z_importviewingkey`）でのエクスポート／インポート、およびZkoolなどのウォレットにおける監視専用アカウントです。現在の対応表については[ウォレット](/using-zcash/wallets)ページを参照してください。
- **経験則：** 尋ねられた質問に答えるために最も限定的なキーを選び、渡したキーは取り消せないことを覚えておいてください。資金を移動することでしか、そのキーより長く存続することはできません。

## なぜビューイングキーを使うのですか？

このテーマに関するElectric Coin Companyの記述では、最も頻繁に発生する状況が示されており、現在も一般的な用途です。

- **入金を監視する取引所。** 取引所は、インターネットに接続された検出ノードに受信ビューイングキーを読み込ませ、シールドされたアドレスへの顧客入金を検知できます。一方で支出鍵は、ネットワークに一切接続しないハードウェアに保管されます。
- **保有資産を示すカストディアン。** カストディアンは、各シールドされたアドレスのフルビューイングキーを監査人に渡します。監査人はそれらの残高を確認し、それらのアドレスへの、およびそれらのアドレスからの過去の活動を確認できますが、それ以外は何もできません。
- **取引相手に対するデューデリジェンス。** 取引所が強化デューデリジェンスの一環として顧客のシールドされた履歴を確認する必要がある場合、資金ではなくビューイングキーを求めることができます。

## ビューイングキーが明らかにするものと明らかにしないもの

キーには複数の種類があり、その違いによってどれだけの情報を渡すかが決まります。

| キー | プレフィックス | 付与されるもの |
|---|---|---|
| 統合フルビューイングキー（UFVK） | `uview…` | アカウント内のすべてのプールについて、受信**および**送信トランザクションを確認できます |
| 統合受信ビューイングキー（UIVK） | `uivk…` | アカウント内のすべてのプールについて、受信トランザクションのみを確認できます |
| Sapling拡張フルビューイングキー | `zxviews…` | キーのアドレスにおける受信および送信Sapling活動を確認できます |

これらのいずれも支出することはできません。重要な意味では、すべて恒久的です。渡したキーは取り消せず、相手がキーを保有していないアカウントへ資金を移動することでしか、そのキーより長く存続することはできません。

何かを共有する前に知っておくべき、2つの開示上の落とし穴があります。

**受信は限定的を意味しません。** 統合受信ビューイングキーは、尋ねられた1つのアドレスではなく、アカウント全体を対象としています。単一のSaplingアドレス用にUIVKをエクスポートしても、そのアカウント内のすべてのプールにわたる受信可視性が付与されるため、名前に含まれるアドレスよりも多くが開示されます。[Zallet Book](https://zcash.github.io/zallet/zcashd/json_rpc.html)では、この点が明記されています。

**公開されたアドレスは、将来の攻撃者に対してその受信ビューイングキーをすでに露出させます。** [ZIP 326](https://zips.z.cash/zip-0326)では、量子コンピューターを持つ攻撃者は公開された多様化アドレスから受信ビューイングキーを復元できる可能性があり、これはヌリファイアキーの復元とは異なり実行可能であると述べられています。現在アドレスを公開することはビューイングキーを公開することと同じではありませんが、十分に長い期間では両者の距離は近くなります。

## Ironwood以降のビューイングキー

NU6.3ではIronwoodシールドされたプールが導入され、Orchardプールは支出専用となったため、資金は時間をかけて一方から他方へ移行します。アップグレード自体については、[Ironwood](/zcash-tech/ironwood)および[ターンスタイル](/zcash-tech/the-turnstile)を参照してください。

**Ironwood以前に発行されたビューイングキーは、移行後も機能し続けます。** ZIP 326では、レシーバーとそれに対応する受信ビューイングキーはプールではなくOrchard*プロトコル*を対象とすると定められています。同じ受信ビューイングキーで、OrchardプールとIronwoodプールの両方のノート暗号文を試行復号できます。Zalletはこのように実装しており、IronwoodノートをOrchard形状として記述し、Ironwoodノート暗号化ドメインの下でアカウントのOrchardビューイングキーにより試行復号します。

キーを保有または発行するすべての人にとって、3つの結果があります。

1. **残高はプール間を移動し、閲覧者はその移動を確認します。** [ZIP 318](https://zips.z.cash/zip-0318)では、移行はランダム化されたスケジュールでブロードキャストされる、小さく意図的に均一なOrchardからIronwoodへのトランザクション群として定められています。各トランザクションは1つのOrchardノートを支出し、標準額面の1つのIronwood出力を生成します。ビューイングキーで監査する人は、保有資産が一度に移動するのではなく、数週間にわたって段階的に一方のプールから他方へ移ることを確認します。ウォレットは、ビューイングキーを用いてチェーンデータから自身の移行進捗を再構築できます。
2. **各移行ステップは、移動する価値を明らかにします。** これはターンスタイルを通過することに内在する性質であり、移行を監査可能にするものです。残高を標準額面に分割するため、単一のトランザクションがOrchardプールの残高全体を明らかにすることはありません。
3. **Ironwood後に作成されたアカウントでは、キーの導出方法が異なる場合があります。** [ZIP 2005](https://zips.z.cash/zip-2005)では、量子復元可能なキーのための`use_qsk`フラグが追加され、受信、送信、多様化キーの導出方法が変更されるため、`use_qsk = true`キーは真に異なるキーです。ZIP 326では、そのフラグをアカウント全体で統一することが求められ、MainnetでNU6.3が有効化される前に`use_qsk = true`キーを生成することを禁じています。したがって、Ironwood以前に存在していたアカウントからエクスポートされたキーは`use_qsk = false`キーであり、そのアカウントでは引き続き正しいものです。あるアカウントからエクスポートしたキーが別のアカウントを表すと考えないでください。

## ビューイングキーのエクスポート

### Zallet

[Zallet](https://github.com/zcash/zallet)は、zcashd内のウォレットを置き換えたフルノードウォレットです。ビューイングキーのエクスポートとインポートは**v0.1.0-beta.2（2026年7月28日）**で導入されたため、まずバージョンを確認してください。以前のビルドにはこれらのメソッドはありません。メソッド名の後に続く各引数は有効なJSONである必要があり、文字列値にはそれぞれ二重引用符を付けます。一般的なコマンド形式については、[Zalletクイックリファレンスガイド](/using-zcash/zallet-quick-reference-guide)を参照してください。

ウォレットが保有するものを一覧表示します。

```bash
zallet rpc listaddresses
```

統合アドレスを渡して、アカウントの統合フルビューイングキーをエクスポートします。

```bash
zallet rpc z_exportviewingkey '"<unified address>"'
```

代わりに、オプションの`ivk`引数を使用して、アカウントの統合受信ビューイングキーをエクスポートします。

```bash
zallet rpc z_exportviewingkey '"<unified address>"' true
```

Saplingアドレスを渡すと、そのアカウントのSapling拡張フルビューイングキー（`zxviews…`）が返され、以前のzcashdの動作と一致します。文書化された制限は2つあります。Sproutアドレスは拒否され、アカウント自体が監視専用としてインポートされたものである場合は、Sapling拡張フルビューイングキーをエクスポートできません。これはウォレットがそのキーを再構築できないためです。`ivk`形式は、インポートされた監視専用アカウントでも機能します。

### 自身のインターフェースからビューイングキーをエクスポートするウォレット

[ウォレット](/using-zcash/wallets)ページでは、各ウォレットのビューイングキー対応状況とIronwood対応状況を追跡しています。執筆時点で、ビューイングキー対応と**Ironwood: Ready**の両方を記載しているウォレットには、ZODL、Zingo!、Zkool、Cake、Zallet、zecd、Nozyがあります。対応状況は変化するため、特定のウォレットに依存する前に、このページを確認してください。

## ビューイングキーを監視専用アカウントとしてインポートする

### Zkool

[Zkool](https://github.com/hhanh00/zkool2)は、統合キーと旧式キーの両方を受け入れるため、ここでは最も柔軟な選択肢です。そのREADMEには、**統合ビューイングキー**または**Sapling拡張ビューイングキー**から作成する監視専用アカウントと、zcashdからエクスポートされた旧式のシールドされた拡張キーが記載されています。新しいアカウントを追加し、監視専用の手順を選択して、`uview…`または`zxviews…`キーを貼り付けてください。するとアカウントが同期し、支出権限なしで残高と履歴を報告します。

Ironwoodプロトコル対応とOrchardからIronwoodへの移行は、Zkool 6.24.0（2026年7月20日）で導入され、6.26.1（2026年8月2日）ではメモリプール内のIronwoodトランザクション検出が修正されました。6.26.1以降を実行してください。

### Zallet

```bash
zallet rpc z_importviewingkey '"<zxviews… key>"' '"whenkeyisnew"' 0
```

2番目の引数は再スキャンポリシーです。`"whenkeyisnew"`（デフォルト）、`"yes"`、または`"no"`を指定できます。3番目は再スキャンを開始するブロック高です。Zalletはキーを監視専用アカウントとしてインポートし、支出権限なしでそのアドレスの受信および送信トランザクションを追跡します。

**ZalletがインポートできるのはSapling拡張フルビューイングキーのみです。** 統合フルビューイングキーをエクスポートできても、`uview…`統合フルビューイングキーはインポートできません。統合アカウント全体への読み取りアクセスを渡すには、ZalletからUFVKをエクスポートし、Zkoolのように統合キーを受け入れるウォレットへインポートしてください。

インポートしたキーをtxid、手数料、メモを含む完全なトランザクション履歴ファイルに変換するには、[Viewing Keyからのトランザクション履歴のエクスポート](/guides/viewing-key-transaction-export)を参照してください。

## 変更されたことと、探すのをやめるべきもの

このページの古いバージョン、またはその翻訳を参照していた場合、3つの方法はもう機能しません。

- **`zcash-cli z_exportviewingkey`と`z_importviewingkey`。** zcashdは2026年7月18日にサポート終了停止に達し、もはや動作しません。Zalletの同名メソッドが代替です。[移行ガイド](/guides/migration-guide-zcashd-to-zebrad-zallet)を参照してください。
- **Ywalletの手順解説。** ウォレットページではYwalletを**Ironwood: Not Ready**と記載しているため、Ironwood時代のビューイングキーで人に勧めるべきウォレットではありません。同じデベロッパーによるZkoolは、同じ範囲のキーを受け入れ、Readyと記載されています。
- **zcashblockexplorer.com/vk。** このサービスは無効な証明書とともにHTTP 503を返しており、代替されることなく廃止されました。ウェブサイトにビューイングキーを貼り付けると、トランザクション履歴全体をそのウェブサイトの運営者に渡すことになります。これは以前のページの3つの選択肢の中でも常に最も弱いものでした。代わりに、自分で運用するウォレットへキーをインポートしてください。

## 視覚化／たとえ

### 監査人の窓

シールドされたアカウントを、銀行の貸金庫室だと考えてください。

- **支出鍵**は、その部屋の鍵です。これを持つ人は箱を開け、中身を取り出せます。
- **ビューイングキー**は、その部屋を覗く監査人の窓です。監査人はすべての箱の出入りを見て、ラベルを読み、台帳を記録できます。しかし窓には取っ手がありません。部屋の中にあるものを、窓から見ている人が動かすことはできません。

### 窓で見えないもの

窓は部屋に面しており、その外の世界には面していません。これは監視対象アカウントのシールドされた活動を示しますが、閲覧者をブロックチェーン全体の観測者にするものではなく、アカウントの活動を他者の非シールド履歴と関連付けることもできません。また、窓はアカウント単位で設置されるため、1つの貸金庫箱（単一アドレス）の覗き穴を誰かに渡しても、その人には部屋全体の受信ビューが与えられます。これこそが、最も限定的なキーを選ぶというルールが存在する理由です。

### 窓を取り戻せない理由

ビューイングキーは許可エントリではなく、情報の一部です。一度コピーされると、そのキーが監視するアカウントから資金が離れるまで存在し続けます。実用的な対処法はローテーションです。残高を、相手がキーを一度も受け取っていない新しいアカウントへ移せば、古い窓は空の部屋に面することになります。

## 詳細解説

### 試行復号：閲覧が実際に機能する仕組み

すべてのシールドされたトランザクションは、ノートの平文を意図された受取人向けに暗号化します。ビューイングキーを持つウォレットは、**試行復号**を実行します。チェーン上で見つけた各トランザクションについて、キーを使ってノート暗号文の復号を試みます。成功するとノートの価値、受取人の多様化子、メモが明らかになり、失敗してもコストはかかりません。これが、同じ受信ビューイングキーがOrchardとIronwoodのプールをまたいで機能し続ける理由です。[ZIP 326](https://zips.z.cash/zip-0326)では、レシーバーをOrchard*プロトコル*の対象と定めているため、Ironwoodノート暗号文はOrchard形状であり、Ironwoodノート暗号化ドメインの下でアカウントのOrchardビューイングキーにより試行復号されます。

### フルと受信：導出によって決まること

**フル**ビューイングキー（full viewing key）は送信ビューイング機能（outgoing-viewing capability）を導出でき、トランザクション（transaction）が復号されると、監査担当者は送金の*送信者*側を再構築できます。**受信**ビューイングキー（incoming viewing key）は意図的にそこまで到達しません。受信ノート（incoming notes）を検出して復号できますが、送信リンクを再構築することはできません。これらの機能間の導出は一方向です。受信キーはフルキー*から*導出され、その逆は決してありません。これにより、「受信のみ」は約束ではなく、実際のダウングレードになります。`use_qsk`のフラグ（flag）は[ZIP 2005](https://zips.z.cash/zip-2005)から導出そのものを変更するため、量子で復元可能なキー（quantum-recoverable keys）は、古いもののバリアントではなく、まったく異なるキーファミリーです。

### 閲覧者に見える移行の姿

[ZIP 318](https://zips.z.cash/zip-0318)の移行は、小さく均一なOrchardからIronwoodへのトランザクションをランダム化して連続実行するものであるため、キーを持つ閲覧者には階段状に見えます。1回の大きな移動ではなく、標準額面の価値が多数の段階に分かれて見えるのです。1つのステップで移行中の総残高が明らかになることはありませんが、*パターン*は認識可能です。これは監査可能なターンスタイルが意図するトレードオフです。

## 実務上の意味

- **取引所および決済処理業者向け：** アカウントの受信ビューイングキー（完全なカバレッジにはUFVK）を検出ノードへ読み込み、公開型アドレスと同様に顧客入金を自動照合できます。ただし、顧客の支出鍵がコールドストレージから出ることはありません。
- **監査人および準備金プルーフ向け：** フルビューイングキーは「私たちを信頼してください」を「これを検証してください」に変えます。監視対象アカウントの残高と完全なトランザクション履歴を確認できますが、それらに触れる能力は一切ありません。単一の支払いに関する個別のプルーフには、[支払い開示](/zcash-tech/payment-disclosures)を組み合わせてください。
- **デューデリジェンス向け：** 取引相手には、関係するアカウントのキーを渡し、ウォレット全体のキーは渡さないでください。関係が終了した場合は、アカウントをローテーションしてください。
- **ツールの選択向け：** ZalletはUFVKをエクスポートし、Sapling拡張フルビューイングキーをインポートします。Zkoolは統合キーと旧式キーを監視専用アカウントとして受け入れます。ウォレットを標準化する前に、現在のIronwood対応表について[ウォレット](/using-zcash/wallets)ページを確認してください。
- **開示のコストは恒久的です：** キーを保有する人が1人増えるごとに、閉じることのできない恒久的なプライバシーの信用枠が増えます。関係ごとにキーを発行し、1つのアカウントに範囲を限定し、誰が何を保有するかを文書化してください。

## よくある間違い

| よくある考え | 実際の状況 |
| --- | --- |
| 「ビューイングキーが漏洩すると資金を支出できる。」 | できません。ビューイングキーには支出権限がなく、漏洩による最悪の結果は履歴の開示です。 |
| 「後からビューイングキーを取り消せる。」 | できません。渡したキーは、相手がキーを保有していないアカウントへ資金が移動するまで機能します。 |
| 「1つのアドレス用にUIVKをエクスポートすれば、そのアドレスだけが表示される。」 | ビューイングキーはアカウント単位です。UIVKはアカウント内のすべてのプールにおける受信活動を表示します。 |
| 「`zcash-cli z_exportviewingkey`はまだ機能する。」 | いいえ。zcashdは2026年7月18日にサポート終了停止に達しました。代わりにZalletの`z_exportviewingkey` / `z_importviewingkey`を使用してください。 |
| 「閲覧専用なので、ビューイングキーをウェブツールに貼り付けても安全だ。」 | 閲覧専用であっても、そのアカウントのトランザクション履歴全体をサイト運営者に渡すことを意味します。自分で運用するウォレットへキーをインポートしてください。 |
| 「ZalletはZalletがエクスポートできるすべてのビューイングキーをインポートできる。」 | いいえ。ZalletがインポートできるのはSapling拡張フルビューイングキーのみです。統合`uview…`キーは、Zkoolのように統合キーを受け入れるウォレットに入れる必要があります。 |
