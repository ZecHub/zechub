# シールドされたコイン保有者投票

> 2026年8月、Zcashは、Valar Groupが構築したシールド投票プロトコルを用いて、投票用紙を暗号化したまま最終集計のみを公開するコイン保有者投票を実施しました。

このページで学べること：保有するZECの量に応じて重み付けされた投票を、投票内容や保有量を誰にも知られることなく、正確に集計する仕組み。

シールドされたコイン保有者投票では、Zcash保有者がシールドされたZECを使ってエコシステム上の問題に投票できます。個々の投票内容やZEC保有量を知る者はいませんが、誰でも集計結果が正しいことを監査できます。これはValar Groupが構築した専用の投票チェーン上で実行され、Zcashメインネットとは分離されているため、実際の資金が移動することはありません。Zcashのより広範な意思決定については、[Zcash資金調達とガバナンスの概要](../zcash-community/zcash-governance)を参照してください。このページでは暗号学的な投票プロトコルのみを扱います。

Zcashを初めて知る方は、まず[ZECとは何か、およびZcash](../start-here/what-is-zec-and-zcash)、[シールドプール](../using-zcash/shielded-pools)、[zk-SNARKs](../zcash-tech/zk-snarks)を確認してから、ここに戻ってきてください。

## プライベート投票が難しい理由

優れたコイン保有者投票には、同時に満たしたい4つの要件があります。しかし、それらを実現するための明白な方法は互いに衝突します。

1. ステークに応じた重み付け。より多くのZECを保有するほど、投票の重みが大きくなります。
2. 選択のプライバシー。誰にも投票内容を知られません。
3. 残高のプライバシー。誰にもZEC保有量を知られません。
4. 誰でも検証できる、正確で監査可能な集計。

ステークに応じて重み付けするには、全員の残高が必要に思えます。投票用紙を集計するには、それを開封する必要があるように思えます。どちらも単純な方法で行えば、[シールドプール](../using-zcash/shielded-pools)が保護するために存在するプライベート情報そのものが漏洩し、過去のコイン投票でもこの理由で残高情報が漏洩しました。シールド投票は、シールド送金を支えるのと同じ技術、すなわち[ゼロ知識証明](../zcash-tech/zk-snarks)、ヌリファイア、暗号化によって、この緊張関係を解決します。

## 直感的な理解：自ら集計する投票箱

> 回転式ゲートを使えば、銀行の金庫の中を見ずに、そこを通過するものを数えられます。シールド投票箱はさらに一歩進み、封をした投票を一度も開封せずに合計します。

3つの珍しい能力を持つ投票箱を思い描いてください。封をした封筒を開けずに、実行中の合計へ加算できます。鍵を単独で持つ者がいない職員グループが、後で最終合計だけを公開します。そして封筒を投じる前に、どのコインが自分のものかを示すことなく、固定された過去の時点にZECを保有しており、まだ投票していないことを非公開で証明します。以下では、この投票箱が実際にどのように構築されているかを説明します。

## 適格性とスナップショット

投票ラウンドでは、単一のZcashメインネットブロックであるスナップショット高が固定され、あなたの重みは、そのブロック時点の[Ironwood](../zcash-tech/ironwood)プールにおける使用可能なシールド残高です。ルールは単純で、スナップショット時点のIronwood1ZECが1票に相当します。NU7スコープ投票では、スナップショットはメインネットのブロック3,459,350で、2026年8月24日19:00 UTC頃でした。投票は2026年9月14日19:00 UTCまで受け付けられました。トランスペアレントなZECは、このプロトコルではなく従来の方法で別途扱われます。

1. 資金が移動したりロックされたりすることはありません。適格性はスナップショット時点で固定されるため、その直後にZECを使用または移動しても投票には影響しません。
2. 登録手続きはありません。必要なのはスナップショット高だけであり、これにより手続きが軽くなり、投票意思のある人を明らかにせずに済みます。

## 残高を明かさずに証明する

投票時、ウォレットはスナップショット時点で未使用のシールドされたZECを自分が管理していたことを示すゼロ知識証明を生成します。これは有効な残高とその額を非公開の集計機構に対して立証しますが、ノートを公開せず、Zcashメインネット上のトランザクションも生成しません。

この証明により、投票チェーン上で、スナップショット残高と等しい投票クレジットが発行されます。これは、このラウンド専用にウォレットが生成する新しい投票鍵によって所有されます。この鍵はZcashアドレスと新規かつ無関係であるため、投票チェーン上の情報から実際のノートへ追跡することはできません。オンチェーン上のアイデンティティと投票用紙は、設計上リンク不可能です。

## 二重投票を非公開で防ぐ

同じコインで誰かが2回投票するのを防ぐため、システムは残高の裏付けとなるノートがスナップショット時点で未使用だったことを確認する必要があります。メインネットでは、これはノート固有の使用済みマーカーであるヌリファイアを公開することで行われ、フルノードが再利用を確認します。しかし、ここでヌリファイアを公開すると、投票用紙がノートへ直接リンクされてしまいます。

![Private double-vote prevention: instead of revealing a nullifier, the wallet uses Private Information Retrieval to fetch proof material while hiding which nullifier it asked about, then proves the note was unspent](/content-images/shielded-voting-pir.webp)

そこでプロトコルは、反対のことを非公開で証明します。スナップショット時点ですでに使用されたすべてのヌリファイアのリストを構築し、ウォレットがゼロ知識で、自分のノートのヌリファイアがそのリストに存在しないことを証明します。これにより、どのノートかを明かさずに、そのノートが未使用だったことを示します。

なお問題が残ります。サーバーからこのリストの必要な一部を取得すると、サーバーにヌリファイアを明かすことになり、リスト全体は大きく、Orchard時代のデータでおよそ2 GB、Zcashの成長に伴ってさらに大きくなります。[プライベート情報検索](../zcash-tech/private-information-retrieval)（PIR）はこの両方を解決します。ウォレットは、要求したデータを暗号学的に隠しながら、必要なデータだけを取得します。結果は公開されたヌリファイアリストの要約と照合されるため、不正なサーバーが偽の結果を作成することはできません。

## 暗号化された投票用紙を投じる

各質問について、ウォレットは3つのことを行います。

1. 準同型暗号を使用して、投票の重みを集計委員会へ暗号化します。これは、復号せずに暗号文同士を加算できる暗号方式です。これにより、投票箱は読めない票を集計できます。
2. 投票を16個の個別シェアに分割します。これにより、委員会が完全に共謀したとしても、1人が投じた量を再構成することは困難になります。
3. 複数のサーバーを経由して、ランダム化された時刻にそれらのシェアを送信します。これにより、観察者は到着時刻からシェアが同じ投票者のものだと判断できません。

各シェアには、それが有効な投票用紙の正当な一部であることを示す独自のゼロ知識証明が付随するため、裏付けのない票を追加することはできません。検証済みのシェアは、選択した回答の暗号化された実行中の合計に準同型的に加算されます。

## 投票用紙を開封せずに集計する

集計は分散型選挙機関によって実行されます。少なくとも10の投票チェーンバリデータで構成され、単独で何かを復号できる者はいません。ラウンド開始時、これらは共同で鍵生成セレモニーを実行し、対応する復号鍵が全員に分割され、1か所に組み立てられることのない暗号鍵を生成します。

> 単独の職員が鍵を持つことはありません。投票箱が開くのは、そのうち3分の2が鍵を一緒に使うときだけであり、その場合でも公開されるのは合計のみです。

ラウンド終了時には、上記の準同型加算による暗号化済み合計がすでに存在します。各バリデータは部分復号と、正しく復号したことを示す証明を公開します。少なくとも3分の2が貢献すると、その部分を組み合わせて各質問の最終的な平文集計が得られ、それ以外のものが復号されることはありません。その後、任意のフルノードが結合された正当性証明を確認できるため、一般の人々はバリデータを信頼せずに集計を検証できます。

## 誰が運用し、何ができないのか

設計では、どのグループも過剰な権限を持たないよう、2つの役割を分離しています。

![Separation of powers: a coordinator multisig sets which questions appear but cannot see votes, while a validator set counts but cannot read individual ballots or forge a tally](/content-images/shielded-voting-roles.webp)

コーディネーターのマルチシグは、Project Tachyon、[Zcash Foundation](../zcash-organizations/zcash-foundation)、ZODL、[Shielded Labs](../zcash-organizations/shielded-labs)、Valar Groupの代表者からなる5人中2人のグループです。どの質問をチェーンに載せるかを決定し、各ラウンドの暗号鍵を認証しますが、個々の投票を閲覧、変更、阻止することはできません。ソフトウェアはオープンでパーミッションレスであるため、質問に不満がある人は誰でも独自の投票チェーンを運用できます。

バリデータは、分割された復号鍵を保持し、しきい値復号を実行する少なくとも10のノードです。各復号には公開の正当性証明が添えられるため、個別の投票用紙を復号することも、偽の集計を作成することもできません。

## クオーラムの目的

主催者は参加しきい値を設定します。棄権を含め、少なくとも1つの質問に1,000,000 ZEC以上が参加した場合にのみ、投票結果はコイン保有者を代表するものとして扱われます。クオーラムは質問を決定するものではなく、質問ごとに適用されるものでもありません。投票全体に対する単一の確認であり、相当量のZECが参加した場合にのみ、結果が真剣に受け止められます。それを下回る場合、結果は意味のあるシグナルとはみなされません。

## このプロトコルが保護しないもの

設計を理解するには、その限界を明確にすることも重要です。

1. これは拘束力のある決定ではなく、シグナルです。コイン保有者投票は、ステークに応じて重み付けされた意見を測定し、Zcashの通常の[ガバナンスプロセス](../zcash-community/zcash-governance)に情報を提供しますが、それを置き換えるものではありません。
2. これはコイン加重であるため、影響力は保有量に従います。摩擦が低くなることで投票率は上がるかもしれませんが、ZECの集中度は変わりません。
3. 議題は、どの質問を掲載するかを選ぶコーディネーターのマルチシグによって設定されます。投票には手を加えられず、誰でも競合するチェーンを運用できますが、議題設定は依然として影響力のある地点です。
4. 集計にはオンラインのバリデータが必要です。集計結果を出すには、そのうち少なくとも3分の2の協力が必要なため、大規模な障害や協調的な拒否により結果が遅延する可能性があります。
5. 完全な共謀下での残高プライバシーは、定理ではなく多層防御です。委員会全体が秘密裏に鍵を再構成した場合、残高を保護するのはシェア分割と時間を分散した送信であり、設計者はこれらが共謀下では弱くなることを認めています。高度なトラフィック分析は残余リスクです。
6. 従来の設計よりも可動部が多くあります。PIRサーバー、送信サーバー、新しい投票鍵、多段階の証明は、それぞれバグや設定ミスが生じうる箇所です。システムはオープンソースで、一部は独立監査を受けており、これによりリスクを管理しますが、取り除くわけではありません。

このプロトコルが強力かつ検証可能に保護するのは、最も重要な2点です。投票用紙をアイデンティティにリンクできないこと、そして最終合計だけが公開されることです。

## 用語集

| 用語 | 平易な意味 |
|---|---|
| Voting chain | Valar Groupが構築した、投票を実行する独立したブロックチェーン。あなたのZcashノートがそこへ移動することはありません |
| Snapshot height | 残高が投票の重みを決めるメインネットブロック（NU7投票ではブロック3,459,350） |
| Nullifier | ノート固有の使用済みマーカー。公開すると投票用紙がノートへリンクされるため、投票では代わりに非所属を証明します |
| Private Information Retrieval (PIR) | 要求したデータを隠しながら、サーバーからデータを取得すること |
| Homomorphic encryption | 復号せずに暗号文同士を加算できる暗号化 |
| Coordinator multisig | 質問とラウンド鍵を承認する5人中2人のグループ。ただし投票の閲覧や変更はできません |
| Election authority | 分割された復号鍵を共同で保持し、最終集計のみを公開する10人以上のバリデータ |
| Threshold decryption | ここでは3分の2のように、十分な数の鍵シェア保有者が協力した場合にのみ結果を復元すること |
| Quorum | 投票を代表的なものとみなすための、1,000,000 ZECという最低参加量 |

## FAQ

投票するとコインは移動またはロックされますか？ いいえ。適格性はスナップショットブロック時点で測定されるため、ZECはそのまま使用可能です。投票ではZcashトランザクションではなく、独立したチェーン上で証明が生成されます。

誰かが投票内容や保有量を知ることはできますか？ いいえ。投票用紙は暗号化され、復号されるのは集計合計だけです。投票はアイデンティティとリンク不可能であり、残高は共謀する委員会からも保護するため、時間を分散した16のシェアに分割されます。

誰かが二重投票したり、保有していないコインで投票したりするのを何が防ぎますか？ 各投票用紙には、実在する未使用のスナップショット残高によって裏付けられていることを示すゼロ知識証明が付属します。また、PIRベースの非所属証明により、どのノートかを明かさずに、基礎となるノートがすでに使用されていないことを示します。

誰が票を数えますか？ 少なくとも10人のバリデータからなる分散セットであり、単独で何かを復号できる者はいません。合計を公開するには3分の2の協力が必要で、各復号には公開の正当性証明が付随します。

結果に拘束力はありますか？ これはステークに応じて重み付けされたコイン保有者の意見シグナルです。変更を自動的に実施するのではなく、Zcashの通常のガバナンスに情報を提供します。

自分でこれを運用または監査できますか？ はい。投票チェーンのソフトウェア、回路、PIRシステム、集計監査ツールは、すべてValar Groupによって公開されており、誰でも検査・運用できます。

## 理解度チェック

すべての投票用紙が暗号化され、すべての投票者が匿名であるなら、公開された合計が正しく、誰も二重投票していないことを、どうすれば確信できるのでしょうか？

<details>
<summary>回答</summary>

3つの証明が機能します。各投票用紙には、実在するスナップショット残高によって裏付けられていることを示すゼロ知識証明が付随するため、裏付けのない票は集計されません。PIRベースの非所属証明は、その背後のノートが未使用であったことを示し、ノートを明かさずに二重投票を防ぎます。そして、バリデータが合計を復号するとき、それぞれが正当性証明を公開するため、任意のフルノードが最終数値が暗号化された投票用紙から正直に復号されたことを確認できます。
</details>
