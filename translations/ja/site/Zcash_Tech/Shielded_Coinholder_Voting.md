# シールドされた（Shielded）コイン保有者投票

> 2026年8月、Zcashは、投票用紙が暗号化されたままで最終集計のみが公開されるコイン保有者投票を実施しました。この投票では、Valar Groupが構築したシールドされた投票プロトコルが使用されました。

このページで学べること：保有するZECの量に応じて重み付けされた投票を、投票内容や保有額を誰にも知られずに、正確に集計する方法です。

シールドされたコイン保有者投票では、Zcashの保有者がシールドされたZECを使ってエコシステムに関する質問に投票できます。個々の投票内容やZECの保有量は誰にも分かりませんが、集計結果が正しいことは誰でも監査できます。これはValar Groupが構築した専用の投票チェーン（chain）上で実行され、Zcashメインネットとは分離されているため、実際の資金が移動することはありません。Zcashがより広範に意思決定を行う方法については、[Zcash資金調達とガバナンスの概要](../zcash-community/zcash-governance)を参照してください。このページでは、暗号学的な投票プロトコルのみを扱います。

Zcashを初めて利用しますか？まずは[ZECとは何か、およびZcash](../start-here/what-is-zec-and-zcash)、[シールドされたプール（Pool）](../using-zcash/shielded-pools)、そして[zk-SNARKs](../zcash-tech/zk-snarks)を確認してから、このページに戻ってください。

## 非公開投票が難しい理由

優れたコイン保有者投票には、同時に満たすべき4つの要件がありますが、それらを実現する明白な方法は互いに衝突します。

1. ステークに応じた重み付け。より多くのZECを保有するほど、より大きな重みを持ちます。
2. 選択のプライバシー（privacy）。投票内容を誰にも知られないようにします。
3. 残高のプライバシー。ZECの保有量を誰にも知られないようにします。
4. 誰でも確認できる、正確で監査可能な集計。

ステークに応じて重み付けするには、全員の残高が必要に思えます。投票用紙を集計するには、開封する必要があるように思えます。どちらも素朴な方法で行えば、[シールドされたプール](../using-zcash/shielded-pools)が保護するために存在する非公開情報そのものを漏えいさせます。この理由から、以前のコイン投票では残高情報が漏えいしていました。シールドされた投票は、シールドされた支払い（payment）を支えるのと同じツール、すなわち[ゼロ知識プルーフ（zero-knowledge proofs）](../zcash-tech/zk-snarks)、ヌリファイア（nullifier）、および暗号化（encryption）を用いて、この緊張関係を解決します。

## 直感的な理解：自ら集計する投票箱

> ターンスタイル（turnstile）を使えば、銀行の金庫の中を見ずに、そこを通過するものを数えられます。シールドされた投票箱はさらに一歩進み、封印された票を一度も開封せずに合計します。

3つの珍しい能力を持つ投票箱を想像してください。封印された封筒を開けずに、累積合計へ追加できます。鍵を単独で保有しない複数の担当者が、後で最終合計だけを公開します。また、封筒を投函する前には、どのコインが自分のものかを示さずに、固定された過去の時点でZECを保有しており、まだ投票していないことを非公開で証明します。以下では、この投票箱が実際にどのように構築されるかを説明します。

## 適格性とスナップショット

投票ラウンドでは、スナップショット高、すなわち単一のZcashメインネットブロックを固定します。あなたの重みは、そのブロック時点で[Ironwood](../zcash-tech/ironwood)プールにある支出可能なシールドされた残高です。ルールは単純で、スナップショット時点のIronwood ZEC 1つが1票に相当します。NU7スコープ投票では、スナップショットはメインネットのブロック3,459,350であり、2026年8月24日19:00 UTC頃でした。投票は2026年9月14日19:00 UTCまで受け付けられました。公開型（transparent）のZECは、このプロトコルではなく、従来の方式で別途扱われます。

1. あなたの資金が移動したりロックされたりすることはありません。適格性はスナップショット時点で固定されるため、その直後にZECを支出または移動しても、投票には影響しません。
2. 登録手続きはありません。必要なのはスナップショット高のみであり、プロセスを簡潔に保ち、投票意向を明かさずに済みます。

## 残高を明かさずに証明する

投票時に、あなたのウォレット（Wallet）は、スナップショット時点で未使用のシールドされたZECを管理していたことを示すゼロ知識プルーフを生成します。これは有効な残高とその額を非公開の集計機構に示しますが、ノート（note）は公開せず、Zcashメインネット上にトランザクション（transaction）を生成することもありません。

このプルーフは、スナップショット残高に等しい投票クレジットを投票チェーン上で発行します。そのクレジットは、このラウンド専用にウォレットが生成する新しい投票鍵によって所有されます。この鍵は新規であり、あなたのZcashアドレス（address）と接続されていないため、投票チェーン上の情報を実際のノートまで追跡することはできません。あなたのオンチェーン（on-chain）アイデンティティと投票用紙は、設計上関連付け不能（unlinkable）です。

## 非公開での二重投票防止

同じコインを使った二重投票を防ぐには、システムは残高の裏付けとなるノートがスナップショット時点で未使用だったことを確認する必要があります。メインネットでは、ノート固有の使用済みマーカーであるヌリファイアを公開し、フルノード（full node）が再利用を検査します。しかし、ここでヌリファイアを公開すると、投票用紙がノートに直接結び付いてしまいます。

![Private double-vote prevention: instead of revealing a nullifier, the wallet uses Private Information Retrieval to fetch proof material while hiding which nullifier it asked about, then proves the note was unspent](/content-images/shielded-voting-pir.webp)

そのため、このプロトコルは逆のことを非公開で証明します。スナップショット時点ですでに使用されたすべてのヌリファイアのリストを構築し、ウォレットは自身のノートのヌリファイアがそのリストに含まれないことをゼロ知識で証明します。これにより、どのノートであるかを明かさずに、そのノートが未使用であったことを示します。

なお、必要なリストの一部をサーバーから取得すると、あなたのヌリファイアがサーバーに明らかになってしまいます。また、リスト全体は大きく、Orchard時代のデータでは約2 GBであり、Zcashの成長に伴ってさらに大きくなります。[プライベート情報検索（Private Information Retrieval、PIR）](../zcash-tech/private-information-retrieval)は両方の問題を解決します。ウォレットは、要求したデータを暗号学的に隠しながら、必要なデータだけを取得します。結果は、公開されたヌリファイアリストの要約と照合されるため、不正なサーバーが偽の結果を作成することはできません。

## 暗号化された投票用紙の投票

各質問について、ウォレットは3つの処理を行います。

1. 準同型暗号化を用いて、あなたの投票の重みを集計委員会向けに暗号化します。これは、復号せずに暗号文同士を加算できる暗号化の一種です。これにより、投票箱は読み取れない票を合計できます。
2. 投票を16個の別々のシェアに分割します。これにより、委員会が完全に結託した場合であっても、個人が投じた量を再構成することは困難になります。
3. 複数のサーバーを経由し、ランダム化された時刻にそれらのシェアを送信します。これにより、到着時刻からシェアが同じ有権者に属することを観測者が判断できません。

各シェアには、それが有効な投票用紙の正当な一部であることを示す独自のゼロ知識プルーフが含まれるため、裏付けのない票を追加することはできません。検証済みのシェアは、選択した回答の暗号化された累積合計へ準同型的に加算されます。

## 投票用紙を一切開封しない集計

集計は、分散型の選挙機関によって実行されます。これは少なくとも10個の投票チェーンバリデーターで構成され、単独で何かを復号できるバリデーターはありません。ラウンドの開始時に、彼らは共同で鍵生成セレモニーを実施し、対応する復号鍵が全員に分割され、1か所に組み立てられることのない暗号化鍵を生成します。

> 単独の担当者が鍵を保有することはありません。投票箱が開くのは、そのうち3分の2が一緒に鍵を用いたときだけであり、その場合でも公開されるのは合計のみです。

ラウンド終了時には、上記の準同型加算による暗号化済みの合計がすでに存在します。各バリデーターは部分復号と、正しく復号したことを示すプルーフを公開します。少なくとも3分の2が貢献すると、それらの部分が結合され、各質問の最終的な平文集計値になります。それ以外のものが復号されることはありません。その後、任意のフルノードが結合された正しさのプルーフを確認できるため、一般の人々はバリデーターを信頼せずに集計を検証できます。

## 誰が運営し、何ができないのか

この設計では、どのグループも過大な権限を持たないよう、2つの役割を分離しています。

![Separation of powers: a coordinator multisig sets which questions appear but cannot see votes, while a validator set counts but cannot read individual ballots or forge a tally](/content-images/shielded-voting-roles.webp)

コーディネーターのマルチシグは、Project Tachyon、[Zcash Foundation](../zcash-organizations/zcash-foundation)、ZODL、[Shielded Labs](../zcash-organizations/shielded-labs)、およびValar Groupの代表者から成る5者中2者のグループです。このグループは、どの質問をチェーンに載せるかを決定し、各ラウンドの暗号化鍵を認証しますが、個々の投票を確認、変更、または妨害することはできません。ソフトウェアはオープンでパーミッションレス（permissionless）であるため、質問に不満がある人は誰でも独自の投票チェーンを運用できます。

バリデーターは、分割された復号鍵を保持し、しきい値復号を実行する少なくとも10個のノード（node）です。すべての復号には公開された正しさのプルーフが付くため、個別の投票用紙を復号したり、虚偽の集計結果を作成したりすることはできません。

## 定足数の目的

主催者は参加しきい値を設定します。棄権を含め、少なくとも1,000,000 ZECが少なくとも1つの質問に参加した場合にのみ、その投票結果はコイン保有者を代表するものとして扱われます。定足数はどの質問も決定せず、質問ごとにも適用されません。これは投票全体に対する単一の確認であり、相当量のZECが参加した場合にのみ、結果は真剣に受け止められます。この水準を下回る場合、結果は意味のあるシグナルとは見なされません。

## このプロトコルが保護しないもの

設計を理解するには、その境界を明確にすることも重要です。

1. これは拘束力のある決定ではなく、シグナルです。コイン保有者投票は、ステークに応じて重み付けされた意見を測定し、Zcashの通常の[ガバナンスプロセス](../zcash-community/zcash-governance)に情報を提供しますが、それを置き換えるものではありません。
2. これはコイン量に応じた重み付けであり、影響力は保有量に従います。摩擦の低減によって参加率は上がる可能性がありますが、ZECの集中度は変わりません。
3. 議題はコーディネーターのマルチシグによって設定され、どの質問を掲載するかを選択します。投票に手を加えることはできず、誰でも対抗するチェーンを運用できますが、議題設定は依然として影響力を持つ点です。
4. 集計にはオンラインのバリデーターが必要です。集計値を生成するには少なくとも3分の2の協力が必要なため、大規模な障害や協調した拒否により結果が遅れる可能性があります。
5. 完全な結託下での残高プライバシーは、定理ではなく多層防御です。委員会全体が秘密裏に鍵を再構成した場合、残高を保護するのはシェア分割と時刻をずらした送信です。設計者は、これらの保護が結託下では弱くなることを認めています。高度なトラフィック分析は残存リスクです。
6. 従来の設計よりも構成要素が多くなります。PIRサーバー、送信サーバー、新しい投票鍵、多段階のプルーフは、それぞれバグや設定ミスが発生し得る場所です。システムはオープンソースであり、一部は独立監査を受けています。これによりリスクは管理されますが、除去されるわけではありません。

このプロトコルが強力かつ検証可能な形で保護するのは、最も重要な2つの事項です。あなたの投票用紙はアイデンティティに結び付けられず、公開されるのは最終合計だけです。

## 用語集

| 用語 | 平易な説明 |
|---|---|
| Voting chain | Valar Groupが構築した、投票を実行する独立したブロックチェーン（blockchain）です。あなたのZcashノートがこのチェーンへ移動することはありません |
| Snapshot height | 残高によって投票の重みを定めるメインネットブロックです（NU7投票ではブロック3,459,350） |
| Nullifier | ノート固有の使用済みマーカーです。公開すると投票用紙がノートに結び付くため、投票では代わりに非所属を証明します |
| Private Information Retrieval (PIR) | 要求したデータを隠しながら、サーバーからデータを取得することです |
| Homomorphic encryption | 復号せずに暗号文同士を加算できる暗号化です |
| Coordinator multisig | 質問とラウンド鍵を承認する5者中2者のグループですが、投票を確認または変更することはできません |
| Election authority | 分割された復号鍵を共同で保持し、最終集計のみを公開する10個以上のバリデーターです |
| Threshold decryption | ここでは3分の2のように、十分な数の鍵シェア保有者が協力した場合にのみ結果を復元することです |
| Quorum | 投票が代表的と見なされるために必要な、ZECの最低参加量1,000,000です |

## よくある質問

投票時にコインは移動したりロックされたりしますか？いいえ。適格性はスナップショットブロック時点で測定されるため、ZECはその場に留まり、支出可能です。投票は、Zcashトランザクションではなく、別のチェーン上でプルーフを生成します。

誰かが私の投票内容や保有量を知ることはできますか？いいえ。投票用紙は暗号化され、集計合計のみが復号されます。あなたの投票はアイデンティティに関連付け不能であり、結託した委員会からも残高を保護するために、残高は時刻をずらした16個のシェアに分割されます。

誰かが二重投票したり、保有していないコインで投票したりするのを何が防ぎますか？各投票用紙には、実在する未使用のスナップショット残高によって裏付けられていることを示すゼロ知識プルーフが含まれます。また、PIRに基づく非所属プルーフにより、どのノートかを明かさずに、元となるノートがすでに使用されていないことを示します。

誰が票を集計しますか？少なくとも10個のバリデーターから成る分散型の集合であり、単独で何かを復号できる者はいません。合計を公開するには3分の2が協力する必要があり、すべての復号には公開された正しさのプルーフが付随します。

結果には拘束力がありますか？これはステークに応じて重み付けされたコイン保有者の意見シグナルです。変更を自動的に実施するのではなく、Zcashの通常のガバナンスに情報を提供します。

自分でこれを運用または監査できますか？はい。投票チェーンのソフトウェア、回路、PIRシステム、集計監査ツールはすべてValar Groupによって公開されており、誰でも調査・実行できます。

## 理解度を確認する

すべての投票用紙が暗号化され、すべての有権者が匿名である場合、公開された合計が正しく、誰も二重投票していないことを、どのように確認できるのでしょうか？

<details>
<summary>回答</summary>

3つのプルーフが機能します。各投票用紙には、実在するスナップショット残高によって裏付けられていることを示すゼロ知識プルーフが含まれるため、裏付けのない票は集計されません。PIRに基づく非所属プルーフは、その背後のノートが未使用であったことを示し、ノートを明かさずに二重投票を防ぎます。そして、バリデーターが合計を復号する際には、それぞれが正しさのプルーフを公開するため、任意のフルノードが暗号化された投票用紙から最終数値が正直に復号されたことを確認できます。
</details>
