# Sapling

> Saplingは、Zcashメインネットのブロック419,200（2018年10月29日 02:15 UTC）で稼働しました。

ここで得られること：Saplingにより、プライベートなZcash支払いは、スマートフォンやハードウェアウォレット（hardware wallet）でも実行できるほど高速かつ軽量になりました。

Saplingは、Zcashにおける2回目の大規模なネットワークアップグレード（network upgrade）であり、Zcashの2周年に有効化されました。これは、シールドされた（shielded）プライベートトランザクション（transaction）の構築方法を再設計したコンセンサス（consensus）ハードフォークです。デプロイはZIP 205で定義され、新しいトランザクション署名（signature）ルールはZIP 243で定義されています。いずれもネットワークアップグレードの仕組みであるZIP 200を基盤としています。詳細はZcashプロトコル仕様に記載されています。Electric Coin Companyはこのアップグレードを開発し、これをサポートする最初のバージョンであるzcashd 2.0.0を2018年8月にリリースしました。オンチェーン（on-chain）では、ネットワークはコンセンサスブランチIDによってSaplingのルールを識別します。

これが重要な理由です。Sapling以前は、真にプライベートな支払いを行うには、コンピューターが数ギガバイトのメモリを使ってプルーフ（proof）を構築する間、数分待つ必要がありました。これは多くの人にとって遅すぎ、負荷も重すぎたため、多くのユーザー、取引所（exchange）、店舗はシールドされたトランザクションを避け、代わりにZECを公開状態で送信していました。Saplingは、この処理を数秒、約40メガバイトのメモリまで削減しました。この1つの変更により、シールドされたZECは、一般的なスマートフォンやハードウェアウォレットで日常的に使えるものになりました。

## 要約

- Saplingは、Zcashにおける2回目の主要なネットワークアップグレード（network upgrade）であり、ブロック419,200（2018年10月29日02:15 UTC）で有効化されました。これはZcashの2周年に当たります。
- シールドされたトランザクション（shielded transaction）を、用途別に設計された2つの回路（SpendとOutput）を中心に再構築し、Sproutの低速な単一のJoinSplit回路を置き換えました（ZIP 205、ZIP 243）。
- その結果、プルーフの構築（proof construction）は数分と数ギガバイトのメモリから、数秒と約40 MBへと削減され、携帯電話やハードウェアウォレット（hardware wallet）でも利用できる軽さになりました。
- 新機能には、多様化アドレス（1つの鍵から多数の関連付け不能な支払いアドレスを生成）、監査専用アクセスのためのビューイングキー（viewing keys）、およびプルーフ生成と署名の分離が含まれます。
- パラメータは、2段階の複数当事者セレモニー（Powers of Tau + Sapling MPC）から得られました。参加者のうち1人でも誠実であれば、安全性は維持されます。

## 視覚的な類推（Visual analogy）

Sproutは、すべての手紙を手で抱えて国中を運ぶ民間の配達員でした。完璧にプライベートでしたが、遅くて大変でした。Saplingは、その同じ配達員を軽いバックパックを背負った自転車乗りに変えました。依然としてプライベートでありながら、日常的な配達には十分な速さです。そして新しいビューイングキー（viewing keys）は、荷物の鍵を決して渡すことなく、監査人に配達員の記録簿を見渡せる明確な窓を与えるようなものです。

## 変更点

Saplingの中心は、シールドされたトランザクションのプライバシーを維持するゼロ知識（zero-knowledge）プルーフを、より高速に構築する方法です。元のSprout設計では、低速でメモリ消費の大きい単一のプルーフ回路（JoinSplit回路）を使用していました。Saplingはこれを、Zcashプロトコル仕様で説明されている、用途別に設計された2つの回路、Spend回路とOutput回路に置き換えました。その結果、コストは大幅に下がりました。Electric Coin Companyによれば、シールドされたトランザクションは、約40メガバイトのメモリを使用して最短数秒で構築できます。Sapling以前のSproutの基準ははるかに重く、数分と数ギガバイトのメモリを必要としていました（これらのSprout側の数値は、広く引用されるおおよその基準値です）。

## 新しい鍵

Saplingは、新しいシールドされたアドレス（address）と鍵のセットも導入しました。1つの鍵から多数の多様化アドレスを導出でき、それらは外部の観測者が互いに関連付けできない個別の支払いアドレスです。Saplingはビューイングキー（viewing key）も追加しました。フルまたは受信ビューイングキーにより、資金を支出する能力を渡すことなく、ウォレット（wallet）のトランザクション詳細を閲覧する能力を共有できます。これは監査、会計、または単に支払いが行われたことの証明に役立ちます。

関連する変更として、Saplingはプルーフを構築する作業とトランザクションに署名する作業を分離しました。ゼロ知識プルーフを構築するデバイスは、もはや支出権限を保持するデバイスである必要はありません。この分離により、別のデバイスがより負荷の高いプルーフ構築作業を行う間、ハードウェアウォレットが支出鍵（spending key）を隔離して保持できます。

![Proving device hands the proof to a separate signing device](/content-images/sapling-decoupled-spend-6fceca13a2.webp)

## トラステッドセットアップ

Saplingの回路は、慎重に生成する必要がある一連の公開パラメーターに依存しています。単一の当事者がこれらを単独で生成し、残存する秘密データ（「トキシックウェイスト」）を保持していた場合、その当事者はプルーフを偽造できた可能性があります。これを避けるため、パラメーターは2段階の複数参加者セレモニーによって生成されました。Powers of Tauと呼ばれる第1段階は回路非依存であり、Sapling固有の回路には結び付いていませんでした。第2段階であるSapling MPCは、回路固有のものでした。各段階は、少なくとも1人の参加者が正直でトキシックウェイストを破棄していれば安全であり、したがってセレモニーが失敗するのは、すべての参加者が共謀した場合に限られます。

## 有効化の仕組み

Saplingは、ネットワークのアップグレード機構を準備した2018年6月のアップグレードであるOverwinterに続くものでした。Electric Coin Companyは、2018年8月にリリースされたzcashd 2.0.0でメインネットの有効化高度を設定し、ブロック419,200がマイニング（mining）された時点で、ネットワークはSaplingルールに切り替わりました。オンチェーンでは、その瞬間はSaplingコンセンサスブランチIDによって示されます。

## よくある間違い

- **シールドされた支払い（shielded payments）が常に利用可能だったと考えること。** Sapling以前は、proofの構築に数分と数ギガバイトのメモリが必要だったため、ほとんどのユーザー、取引所、店舗はシールドされたトランザクションを完全に利用していませんでした。
- **SaplingのアドレスをSproutのものと同じだと呼ぶこと。** Saplingは独自のアドレスと鍵の種類（多様化アドレスおよびビューイングキーを含む）を導入しました。Sproutの鍵はSaplingのアドレスと相互運用できません。
- **トラステッドセットアップが「ある1社の秘密」だと信じること。** これは複数者によるセレモニーでした。すべての参加者が共謀した場合にのみ、proofを偽造できました。
- **Saplingが発行量または残高を変更したと考えること。** これはシールドされたトランザクションの構築方法を変更したものであり、ZECの金額には影響しませんでした。
- **proofの生成と署名は同じデバイスで行う必要があると考えること。** Saplingの分離により、ハードウェアウォレットは支出鍵を隔離したまま、別のデバイスでproofを構築できます。

## 用語集

| 用語 | 平易な説明 |
|---|---|
| Shielded transaction | 送信者、受信者、金額を隠すプライベートなZcashトランザクションです。 |
| Sprout | Zcashで開始された元のシールドされたプロトコルであり、Saplingよりも低速で負荷が大きいものです。 |
| Spend and Output circuits | Sproutの単一のJoinSplit回路を置き換えた、2つの新しいSaplingプルーフ回路です。 |
| Diversified address | 1つの鍵から導出できる、多数の関連付け不能（unlinkable）な支払いアドレスの1つです。 |
| Viewing Key | ウォレットから支出することなく、そのトランザクションを閲覧できる鍵です。 |
| Consensus branch id | トランザクションがどのアップグレードのルールに従うかをネットワークに伝える短いコードです。 |

## FAQ

Saplingによって、私が保有するZECの量は変わりましたか？ いいえ。Saplingが変更したのはシールドされたトランザクションの構築方法であり、誰かが保有するZECの量や総供給量ではありません。残高には影響しませんでした。

Sapling後も私のZECはプライベートですか？ はい、しかもより使いやすくなりました。Saplingはシールドされたトランザクションの強力なプライバシー（privacy）を維持しつつ、実際に使えるほど高速かつ低コストにしました。シールドされた資金は従来と同じ方法で隠され続けます。

何かする必要がありますか？ 保有者として必要な操作はありません。Saplingは、ウォレットおよびノード（node）ソフトウェアが採用したネットワークアップグレードでした。最新のウォレットはすでにSaplingアドレスをサポートしています。

SproutとSaplingの違いは何ですか？ Sproutは最初のシールドされたプロトコルであり、低速でメモリ消費の大きい1つのプルーフ回路を使用していました。Saplingはこれをより高速なSpend回路とOutput回路に置き換え、ビューイングキーと多様化アドレスを追加し、シールドされたトランザクションをスマートフォンやハードウェアウォレットでも使えるほど軽量にしました。

一部の情報源が10月28日とし、他が10月29日としているのはなぜですか？ 有効化高度は、2018年10月28日を目標として事前に設定されていました。実際に変更を引き起こしたブロック419,200は、UTCで10月29日早朝にマイニングされました。多くの現地時間帯では、まだ10月28日でした。いずれの場合も、同じブロックと同じ瞬間です。

ビューイングキーとは何ですか？ ビューイングキーにより、シールドされたウォレットへの読み取りアクセスを共有できます。フルまたは受信ビューイングキーを持つ人は、ウォレットのトランザクション詳細を確認できますが、その資金を支出することはできません。詳しくは[ビューイングキー](../zcash-tech/viewing-keys)をご覧ください。
