# Zcash ライトウォレットノード

## TL;DR

* ほとんどの人は、ブロックチェーン全体をダウンロードしないライトウォレットを通じて Zcash を利用しています。代わりに、すでにその作業を済ませたサーバーと通信します。
* 現在ライトウォレットを提供するソフトウェアは2つあります。Goで書かれた元祖サービスの **lightwalletd** と、Rustで書かれた新しいインデクサーの **Zaino** です。
* あなたの鍵がデバイスから外に出ることはなく、サーバーはあなたの資金を使用したり、完全にシールドされたトランザクション内の金額やメモを読んだりできません。
* サーバーが把握しやすいのは、あなたのIPアドレスとアクティビティのタイミングです。シールドされたトランザクションが保護するのはブロックチェーン上で起きることであり、サーバーへの接続そのものではありません。
* Tor はIP識別子を取り除きます。`zcash_client_backend` を基盤とするウォレットで利用でき、ZODL では高度な設定の項目です。
* ウォレットが使用するサーバーを変更することも、自分で運用することもできます。lightwalletd と Zaino はどちらもオープンソースです。

## 基本的な説明

ほとんどの人は、ブロックチェーン全体をダウンロードしないライトウォレットを通じて Zcash を利用しています。代わりに、すでにその作業を済ませたサーバーと通信します。このページでは、それらのサーバーとは何か、あなたについて何を見られ、何を見られないのか、接続を Tor 経由にする方法、そしてウォレットが使用するサーバーを変更する方法を説明します。

現在ライトウォレットを提供するソフトウェアは2つあります。**lightwalletd** はGoで書かれた元祖サービスです。**Zaino** は、zcashd 廃止作業の一環として構築された、Rustで書かれた新しいインデクサーです。

### ライトウォレットサーバーの役割

ライトウォレットサーバーは、あなたのウォレットと Zcash ブロックチェーンの間に位置し、帯域幅効率の高いチェーンの表示を提供します。主に3つのことを行います。

コンパクトブロックを提供します。ブロック全体ではなく、ウォレットがシールドアドレスへの支払いを検出し、ノートの支出を検出し、ウィットネスを更新するために必要なものだけを含むコンパクトな形式を送信します。

あなたのトランザクションを中継します。送信時、ウォレットは完成したトランザクションをサーバーに渡し、サーバーがネットワークにブロードキャストします。

現在のブロック高や、ウォレットが必要とする手数料情報などのチェーン照会に応答します。

ウォレットは引き続き、プライベートな処理をローカルで行います。鍵を保持し、ブロックを試行復号してノートを見つけ、デバイス上でトランザクションを構築して署名します。

### サーバーが見られるものと見られないもの

ここは誤解されやすい部分です。鍵がデバイスから外に出ないことは、サーバーがあなたについて何も知れないことと同義ではありません。

ここでの基準は、[Zcash ウォレットアプリの脅威モデル](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)です。この点を気にするなら、全文を読む価値があります。そこでは複数の種類の敵対者が示されています。このページに関連するのは、あなたのウォレットとインターネット間、およびサーバーとインターネット間のトラフィックを監視できる敵対者です。ウォレットはサーバー運営者に直接接続するため、サーバーを運営する人は本質的にその立場の一部にいます。

まず、保護されるものから始めましょう。サーバーを侵害した者を含むモデル内のすべての敵対者に対しても、敵対者は「ユーザーの暗号鍵マテリアル（支出鍵、閲覧鍵、シードフレーズなど）を一切知ることができず」、あなたの資金を盗むことも、意図していない資金送信をさせることもできません。完全にシールドされたトランザクション内の金額とメモは暗号化されたままです。

次に、保護されないものがあります。脅威モデルは、トラフィックを観測する敵対者に対する既知の弱点として、以下を挙げています。

| 弱点 | 方法 |
|:--|:--|
| あなたが誰かを特定する | 「敵対者はユーザーのIPアドレスを知っており、それによってユーザーの実際の身元につながる可能性がある」 |
| おおよその居場所を特定する | IPアドレスを「ジオロケーションデータベースで検索して、おおよその位置を推定する」 |
| シールドされたトランザクションを送受信したことと、そのタイミングを知る | 送信では「より多くの帯域幅を使用するため、接続が暗号化されていても可視である」。モデルは、送受信という行為自体がサーバーには見えると指摘しています |
| 時間の経過に伴うトランザクション数を数える | より長い期間にわたって観測される、同じ帯域幅パターン |
| 繰り返される支払いパターンを見つける | アクティビティが発生するタイミングを観測する |
| アドレスがあなたのものかを推測する | すでにアドレスを知っている敵対者は、「そのアドレスに資金を送り、ウォレットが取得する際に帯域幅の急増があるか」を観察できる |

モデルはまた、通常のケースでは「ユーザーと lightwalletd サーバー運営者との信頼関係」を前提としていると指摘しています。

したがって、正直な要約はこうです。ライトウォレットサーバーはあなたの資金を使えず、シールドされたトランザクション内の金額やメモも読めません。一方で、IPアドレスとアクティビティのタイミングは把握しやすく、この2つを組み合わせると個人について多くのことが分かり得ます。シールドされたトランザクションが保護するのはブロックチェーン上で起きることです。それだけでサーバーへの接続を隠せるわけではありません。

## 図解 / たとえ

これまでに発行されたすべての新聞を所蔵する公共図書館を考えてみてください。フルノードは、アーカイブ全体を自宅に持ち帰る読者です。ライトウォレットは、代わりに司書へ日刊ダイジェストを頼む読者です。自分に関係する内容があるかを見つけるのに十分な情報だけを含む、薄い一枚の紙です。

ダイジェストは封印されています。司書はどの項目があなたに重要かを読めないまま作成し、あなたは自分の鍵で自宅で開封します。これがコンパクトブロックであり、開封がデバイス上での試行復号です。

しかし司書には、どの読者が入ってきたか、何時だったか、どれほど厚い束を持ち出したかが見えます。これがIPアドレスとタイミングです。封筒がどれほど厳重に封印されていても、受付から見えます。Tor は匿名の配達人を送ることに相当します。司書は同じ束を渡しますが、それがどの家に届くかは分からなくなります。

## 詳細

### Tor 経由でのルーティング

Tor は、IPアドレスとウォレットのトラフィックとの結び付きを断ち、上の表にある最も強い識別子を取り除きます。

多くの Zcash ウォレットが基盤とする Rust ライブラリにはサポートがあります。zcash_client_backend には、Tor の Rust 実装である [Arti](https://tpo.pages.torproject.net/core/arti/) を基盤とする Tor モジュールが含まれているため、ウォレットは別個の Tor クライアントを同梱せずに、同期、トランザクションのブロードキャスト、価格照会を Tor 経由で行えます。

Zaino 開発者も脅威モデルを直接引用し、同じ主張をしています。Zcash のインデックスサーバーからクライアントの身元を曖昧にするには、「匿名トランスポートプロトコル（Nym や Tor など）を使用する必要がある」としています。

**ZODL** では、Tor は高度な設定の項目です。ウォレットのリリースノートでは、メタデータ露出を減らしたい場合、ユーザーに「高度な設定で Tor を有効にする」ことに加え、手動接続モードを案内しています。またアプリは、ウォレット復元前に Tor を有効化するよう提案します。これは、そうでなければ新しいIPアドレスがウォレット履歴全体に結び付けられる瞬間です。

注意点が2つあります。Tor はサーバーからIPアドレスを隠しますが、サーバーがあなたのリクエストから知る内容を変えるものではありません。また、オニオンルーティングには遅延が加わるため、同期には時間がかかります。自分のサーバーを運用すれば、運営者が自分自身になるため、信頼の問題を別の形で回避できます。

### Rust インデクサー、Zaino

[Zaino](/zcash-tech/zaino) は、zcashd 廃止作業の一環として lightwalletd を置き換えるために Zingo チームが Rust で開発したインデクサーです。ライトクライアント、フルクライアント、ブロックエクスプローラーにサービスを提供し、「Zebra または Zcashd のフルバリデーター」のいずれかが保持するチェーンデータを読み取ります。

現在活発に開発されており、バージョン0.8.0は2026年8月にリリースされました。可能な限り lightwalletd との後方互換性を維持することを目指しているため、ウォレットは書き換えなしでこれを指定できます。

Zaino にはアーキテクチャ図を含む専用ページがあるため、このページではライトウォレットサーバーとしての役割だけを扱います。

### 自分で運用する

最も強力な選択肢は、自分自身が運営者になることです。これにより信頼の問題を完全に取り除けます。両方のサーバーはオープンソースです。Go製の [lightwalletd](https://github.com/zcash/lightwalletd) と、Rust製の [Zaino](https://github.com/zingolabs/zaino) です。どちらもフルバリデーターからデータを読み取るため、[Zebra](/zcash-tech/zebra-full-node) も必要になります。

## よくある間違い

**サーバーがトランザクションを読めると思うこと**。読めません。鍵はデバイス上に残り、完全にシールドされたトランザクション内の金額とメモは、サーバーを侵害した敵対者に対しても暗号化されたままです。

**「シールド」を「匿名接続」と解釈すること**。シールドされたトランザクションが保護するのはブロックチェーン上で起きることです。IPアドレスとアクティビティのタイミングは別の層であり、その層こそサーバーに見えるものです。

**Tor がすべての痕跡を消すと考えること**。Tor はサーバーからIPアドレスを隠しますが、サーバーがあなたのリクエストから知る内容を変えるものではなく、同期には遅延も加わります。

**Wikiページ上のサーバー一覧を信用すること**。運営者は参入と撤退を繰り返します。ウォレットを何かに接続する前に、実際に稼働しているものを [hosh.zec.rocks](https://hosh.zec.rocks/zec) で確認してください。

## まとめ

ライトウォレットなら、ディスク容量を使わずにシールドプールを利用できます。これは良いトレードオフです。ただし、何と引き換えにしているのかを明確に理解してください。サーバーはあなたの資金を奪えず、シールドされた金額を読むこともできませんが、IPアドレスと取引のタイミングを把握しやすい立場にあります。Tor 経由で接続し、運営者を意図的に選ぶか、自分で運用してください。
