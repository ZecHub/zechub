# Zcash ライトウォレットノード

## 要約

* ほとんどの人はライトウォレットを通じてZcashを利用します。ライトウォレットはブロックチェーン全体をダウンロードせず、すでにその作業を済ませたサーバーと通信します。
* 現在、ライトウォレットによく使われるソフトウェアは3つあります。**lightwalletd**（元祖のGo製サービス）、**Zaino**（Rust製インデクサー）、そして公開高速ネットワークfastz.cashを支える、Zcash Labs製の高性能なRustインデクサーztreamerです。
* 鍵がデバイスの外に出ることはありません。サーバーは資金を使ったり、完全にシールドされたトランザクション内の金額やメモを読み取ったりできません。
* サーバーが把握しやすいのは、IPアドレスとアクティビティのタイミングです。シールドされたトランザクションが保護するのはブロックチェーン上の情報であり、サーバーへの接続ではありません。
* Torを使うとIPアドレスによる識別を防げます。`zcash_client_backend`を基盤とするウォレットで利用でき、ZODLでは「詳細設定」の項目から設定できます。
* ウォレットが使うサーバーは変更できます。また、自分でサーバーを運用することもできます。lightwalletd、Zaino、ztreamerはすべてオープンソースです。

## 基本的な説明

ほとんどの人はライトウォレットを通じてZcashを利用します。ライトウォレットはブロックチェーン全体をダウンロードせず、すでにその作業を済ませたサーバーと通信します。このページでは、サーバーの仕組み、あなたについて把握できることとできないこと、Tor経由で接続する方法、ウォレットが使うサーバーを変更する方法を説明します。

現在、ライトウォレットに対応するソフトウェアは一般的に3つあります。**lightwalletd**はGoで書かれた元祖のサービスです。**Zaino**はRustで書かれた新しいインデクサーで、zcashdの廃止作業の一環として開発されました。**ztreamer**は、Zcash Labsによる高性能なRustインデクサーで、公開ネットワークfastz.cashを稼働させています。

### ライトウォレットサーバーの役割

ライトウォレットサーバーは、ウォレットとZcashのブロックチェーンの間に入り、チェーンの情報を帯域幅効率よく提供します。主な役割は3つあります。

コンパクトブロックを提供します。ブロック全体ではなく、ウォレットがシールドされたアドレスへの支払いを検出し、ノートの使用を検出し、ウィットネスを更新するのに必要な情報だけを含む簡潔な形式で送信します。

トランザクションを中継します。送金するとき、ウォレットは完成したトランザクションをサーバーに渡し、サーバーがネットワークにブロードキャストします。

チェーンに関する問い合わせにも応答します。たとえば、現在のブロック高やウォレットに必要な手数料情報です。

プライベートな処理は、引き続きウォレットがローカルで行います。鍵を保持し、ブロックを試行復号してノートを見つけ、デバイス上でトランザクションを作成して署名します。

### サーバーが把握できることとできないこと

ここは誤解しやすい点です。鍵がデバイスの外に出ないからといって、サーバーがあなたについて何も把握できないわけではありません。

ここでは[Zcashウォレットアプリの脅威モデル](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)を参照しています。このテーマに関心がある場合は、全文を読む価値があります。脅威モデルでは複数の攻撃者が想定されています。このページに関係するのは、ウォレットとインターネットの間、およびサーバーとインターネットの間の通信を監視できる攻撃者です。ウォレットはサーバーに直接接続するため、サーバーの運営者は必然的にその立場の一部にいます。

まず、保護される情報を見てみましょう。サーバーを侵害した攻撃者を含め、モデルで想定されるすべての攻撃者に対して、「ユーザーの暗号鍵の素材（支出鍵、ビューイングキー、シードフレーズなど）を知ることはできず」、資金を盗んだり、意図していない送金をさせたりすることもできません。完全にシールドされたトランザクション内の金額とメモは暗号化されたままです。

一方、保護されない情報もあります。脅威モデルでは、通信を監視する攻撃者に対する既知の弱点として次の点が挙げられています。

| 弱点 | 仕組み |
|:--|:--|
| あなたが誰かを特定する | 「攻撃者はユーザーのIPアドレスを知っており、そこからユーザーの実際の身元が判明する可能性がある」 |
| おおよその所在地を特定する | IPアドレスを「位置を推定するためにジオロケーションデータベースで調べる」 |
| シールドされたトランザクションを送受信したことと、その時刻を把握する | 送信では「帯域幅が多く使われるため、接続が暗号化されていてもそれが見える」。送受信の行為そのものはサーバーから見えるとモデルに記されています |
| 時間の経過とともに行ったトランザクションの数を数える | 同じ帯域幅のパターンを、より長い期間にわたって観察する |
| 繰り返される支払いパターンを見つける | アクティビティが発生する時刻を観察する |
| あるアドレスがあなたのものかを推測する | すでにアドレスを知っている攻撃者が「そのアドレスに資金を送り、ウォレットが取得する際に帯域幅の急増があるかを監視する」 |

また、このモデルでは一般的な状況として、「ユーザーとlightwalletdサーバー運営者の間に信頼関係がある」ことを前提としています。

率直にまとめると、ライトウォレットサーバーはあなたの資金を使えず、シールドされたトランザクションの金額やメモを読み取れません。一方、IPアドレスとアクティビティのタイミングは把握しやすく、この2つを組み合わせれば個人について多くのことが分かる場合があります。シールドされたトランザクションが保護するのはブロックチェーン上の情報です。それだけでは、サーバーへの接続は隠せません。

## 図解／たとえ

あらゆる新聞を保管している公共図書館を想像してください。フルノードは、新聞の全アーカイブを持ち帰る読者です。ライトウォレットは、毎日司書に要約を頼む読者のようなものです。要約は、関係する記事があるかどうかを確認できるだけの情報を含む薄い紙です。

要約は封印されています。司書は、どの記事があなたに関係するかを読めないまま作成し、あなたは自分の鍵を使って自宅で開封します。これがコンパクトブロックで、デバイス上で開封する処理が試行復号です。

ただし司書には、誰がいつ訪れ、どれほどの厚さの束を持ち帰ったかが見えます。これはIPアドレスとタイミングに当たり、封筒をどれほど厳重に封印しても、カウンターからは分かります。Torは匿名の配達人を使うようなものです。司書は同じ束を渡しますが、それが誰の家に届くのかは分からなくなります。

## 詳細

### Tor経由でのルーティング

Torを使うと、IPアドレスとウォレットの通信の結び付きが切れ、上の表にある最も強力な識別情報を取り除けます。

多くのZcashウォレットが基盤としているRustライブラリには、この機能のサポートがあります。zcash_client_backendには、TorのRust実装である[Arti](https://tpo.pages.torproject.net/core/arti/)を基盤とするTorモジュールが含まれています。そのためウォレットは、別途Torクライアントを同梱することなく、同期、トランザクションのブロードキャスト、価格の照会をTor経由で行えます。

Zainoのdeveloperも同じ見解を示しており、脅威モデルを直接引用しています。「クライアントの身元をZcashのインデックスサーバーから隠すには、（NymやTorなどの）匿名トランスポートプロトコルを使う必要がある」。

**ZODL**では、Torは「詳細設定」の項目です。ウォレットのリリースノートでは、「メタデータの露出を減らしたい」ユーザーに対し、手動接続モードにして「詳細設定でTorを有効にする」よう案内しています。また、ウォレットを復元する前にTorを有効にする選択肢もあります。復元時は、新しいIPアドレスとウォレットの履歴全体が結び付けられる可能性があるためです。

注意点が2つあります。TorはサーバーからIPアドレスを隠しますが、送信するリクエストからサーバーが把握する情報は変わりません。また、オニオンルーティングには遅延が加わるため、同期に時間がかかります。自分でサーバーを運用すれば、運営者が自分になるため、別の形で信頼の問題を解消できます。

### Zaino、Rustインデクサー

[Zaino](/zcash-tech/zaino)はZingoチームがRustで開発したインデクサーで、zcashdの廃止作業の一環としてlightwalletdに代わるよう設計されました。ライトクライアント、フルクライアント、ブロックエクスプローラーに対応し、「Zebraまたはzcashdのフルバリデーター」が保持するチェーンデータを読み取ります。

現在も積極的に開発が続いており、バージョン0.10.1は2026年9月にリリースされました。可能な限りlightwalletdとの後方互換性を保つ方針のため、ウォレットを書き換えずに接続先として指定できます。

Zainoにはアーキテクチャ図を掲載した専用ページがあるため、このページではライトウォレットサーバーとしての役割だけを扱います。

### ztreamerとfastz.cash

[ztreamer](https://github.com/zcashlabs/ztreamer)は、RustでZcash Labsが開発した、高性能なZcashインデクサー兼ライトウォレットサーバーです。低レイテンシーと高スループットを実現するよう設計されており、公開[fastz.cash](https://forum.zcashcommunity.com/t/announcing-fastz-cash-rpc-by-zcash-labs/59478)インデクサーネットワークを支えています（2026年11月19日発表）。

fastz.cashは地域ごとのエッジサーバーを運用しています（現在はフランクフルト、ロンドン、バージニア、オレゴン、サンパウロ、シンガポール、大阪です）。各地域には独自のフルノードとローカルのztreamerインデックスがあります。TLSはノードで終端します。GetLatestBlock呼び出しの初回応答までの世界全体の実測中央値は約35 msでした。ブロック範囲の同期は、最近のlightwalletdより最大約3倍高速と報告されており、インデックスの容量も小さい（約18 GB）ため、エッジロケーションを追加しやすくなっています。

ステータスと最寄りのエンドポイント: [status.fastz.cash](https://status.fastz.cash).

**プライバシーに関する注意：** fastz.cashはValar Groupのwallet-pirサービスも運用しています。Vizorのユーザーは現在、プライベートな同期クエリに利用できます。これにより、要求されているノートや範囲についてサーバーが学習するメタデータを減らせます。これは、上記で説明した通常のライトウォレットの脅威モデルに加わるプライバシー保護の層です。Torや運用者の選択に代わるものではありません。

ztreamerはオープンソースで、単独で実行できます（組み込みのZakuraノード、またはリモートモード）。lightwalletdやZainoと同様に、gRPC経由でライトウォレットプロトコルを提供します。現在も活発に開発されており、本番環境向けのインフラであると同時に、将来のライトウォレットプロトコルの改善に向けた実験の場として位置づけられています。

### 自分で運用する

最も確実な選択肢は、自分で運営者になることです。これにより、信頼するかどうかという問題そのものがなくなります。3つのサーバーはすべてオープンソースです。Goで書かれた[lightwalletd](https://github.com/zcash/lightwalletd)、Rustで書かれた[Zaino](https://github.com/zingolabs/zaino)、そしてRustで書かれた[ztreamer](https://github.com/zcashlabs/ztreamer)です。これらはフルバリデーターから読み取るため、[Zebra](/zcash-tech/zebra-full-node)またはZakuraも必要になります。zec.rocksサーバーは、オープンソースのHelmチャートとDocker Composeキットである[Zcash Stack](/guides/zcash-stack)を使ってデプロイされ、Zebraとlightwalletdを一緒に実行します。

### ウォレットのサーバーを変更する

信頼できる運営者を選びたい場合、複数の運営者にアクティビティを分散したい場合、または自分のサーバーを指定したい場合に役立ちます。

以下のメニュー経路は、このページの更新時点では正しいものでした。ただしウォレットの画面は変更されるため、正確な手順というより手がかりとして利用してください。「詳細設定」やサーバーの項目を探してください。

#### ZODL

以前はZashiでした。右上の歯車アイコンを選び、「詳細設定」を開きます。Torは同じ画面にあります。また、サーバーが古いために同期に失敗した場合は、ZODLから「サーバーを切り替える」ショートカットを利用できます。

#### Zkool

同じdeveloperによるYwalletの後継アプリです（Ywallet自体はメンテナンスされておらず、Ironwood以降はネットワークに追従できません）。アカウント画面上部の歯車アイコン（「設定を開く」）を選び、「ライトノードサーバー」欄を開きます。横のリストボタンでは既知のサーバーから選べます。その下の「直接／Tor／Nym／プロキシ」の切り替えでは、ウォレットの接続方法を設定できます。

#### Zingo

左上のハンバーガーメニューを開き、「設定」を選んで下にスクロールします。

![Zingo server settings](/content-images/ea8f7672-e644-41a5-a422-db131740404a-2626f5fa79.webp)

#### eZcash

左上のハンバーガーメニューを開き、「設定」を選んでから「詳細設定」を開きます。

![eZcash server settings](/content-images/655c0172-61a0-4322-b8cf-4eee4bb53b51-0b93df2e71.webp)

これらのスクリーンショットは2025年3月に撮影されており、その後アプリはリリースを重ねています。ボタンの位置が変わっている可能性があります。

## よくある間違い

**サーバーはトランザクションを読めると思い込むこと**。読めません。鍵はデバイス上にとどまり、完全にシールドされたトランザクション内の金額やメモは暗号化されたままです。サーバーを侵害した攻撃者であっても同じです。

**「シールドされた」を「匿名で接続できる」と解釈すること**。シールドされたトランザクションが保護するのはブロックチェーン上の情報です。IPアドレスとアクティビティのタイミングは別の層にあり、サーバーから見えるのはまさにこの情報です。

**Torですべての痕跡が消えると思い込むこと**。TorはサーバーからIPアドレスを隠しますが、送信するリクエストからサーバーが把握する情報は変わらず、同期にも遅延が加わります。

**Wikiページ上のサーバーリストを信頼すること**。運営者は入れ替わります。ウォレットを何かに接続する前に、実際に稼働しているものを[hosh.zec.rocks](https://hosh.zec.rocks/zec)と[status.fastz.cash](https://status.fastz.cash)で確認してください。

## まとめ

ライトウォレットを使うと、ディスク容量を抑えながらシールドされたプールを利用できます。これは便利なトレードオフです。ただし、何と引き換えにしているのかを理解しておきましょう。サーバーは資金を奪ったり、シールドされた金額を読んだりできませんが、IPアドレスやトランザクションの時刻は把握しやすいです。Tor経由で接続する、運営者を慎重に選ぶ、または自分で運用する方法があります。
