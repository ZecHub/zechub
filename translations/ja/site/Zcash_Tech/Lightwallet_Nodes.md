# Zcash ライトウォレットノード（Lightwallet Nodes）

## 要約

* ほとんどの人は、ブロックチェーン（blockchain）全体をダウンロードしないライトウォレット（light wallet）を通じてZcashを使用します。代わりに、すでにその作業を済ませたサーバーと通信します。
* 現在、2つのソフトウェアがライトウォレットを提供しています。Goで書かれた元祖のサービスである**lightwalletd**と、Rustで書かれた新しいインデクサーである**Zaino**です。
* あなたの鍵がデバイスから出ることはなく、サーバーはあなたの資金を使用したり、完全にシールドされたトランザクション（fully shielded transactions）内の金額やメモ（memos）を読んだりできません。
* サーバーが把握しやすいのは、あなたのIPアドレスと活動のタイミングです。シールドされたトランザクションはブロックチェーン上で行われることを保護しますが、サーバーへの接続は保護しません。
* TorはIP識別子を取り除きます。これは`zcash_client_backend`上に構築されたウォレットで利用でき、ZODLではAdvanced Settings内の設定です。
* ウォレットが使用するサーバーは変更できますし、自分で運用することもできます。lightwalletdとZainoはいずれもオープンソースです。

## 基本説明

ほとんどの人は、ブロックチェーン全体をダウンロードしないライトウォレットを通じてZcashを使用します。代わりに、すでにその作業を済ませたサーバーと通信します。このページでは、それらのサーバーとは何か、サーバーがあなたについて確認できることと確認できないこと、Tor経由で接続をルーティングする方法、そしてウォレットが使用するサーバーを変更する方法を説明します。

現在、2つのソフトウェアがライトウォレットを提供しています。**lightwalletd**はGoで書かれた元祖のサービスです。**Zaino**はRustで書かれ、zcashdの廃止作業の一環として構築された新しいインデクサーです。

### ライトウォレットサーバーの役割

ライトウォレットサーバーは、あなたのウォレットとZcashブロックチェーンの間に位置し、チェーンの帯域幅効率の高い表示を提供します。主に3つのことを行います。

コンパクトブロックを提供します。ブロック全体ではなく、ウォレットがシールドされたアドレス（shielded address）への支払いを検出し、ノート（notes）の使用を検出し、証人を更新するために必要な情報だけを含むコンパクトな形式を送信します。

トランザクションを中継します。送信時、ウォレットは完成したトランザクションをサーバーに渡し、サーバーはそれをネットワークにブロードキャストします。

現在の高さや、ウォレットに必要な手数料（fee）情報など、チェーンへの問い合わせに回答します。

ウォレットは引き続き、プライベートな処理をローカルで行います。鍵を保持し、ブロックを試行復号してノートを見つけ、デバイス上でトランザクションを構築して署名します。

### サーバーが確認できることと確認できないこと

ここは誤解しやすい部分です。鍵がデバイスから出ないことは、サーバーがあなたについて何も知り得ないこととは異なります。

ここで参照するのは、[Zcashウォレットアプリの脅威モデル](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)です。この点を気にするなら、全文を読む価値があります。このモデルでは、複数の種類の敵対者を定義しています。このページで重要なのは、あなたのウォレットとインターネットの間、およびサーバーとインターネットの間のトラフィックを監視できる敵対者です。ウォレットはサーバーに直接接続するため、サーバーの運用者は本質的にその立場の一部にいます。

まず、保護されているものから見ていきます。サーバーを侵害した者を含め、モデル内のあらゆる敵対者に対して、敵対者は「ユーザーの暗号鍵素材（支出鍵、ビューイングキー、シードフレーズなど）を一切知ることができず」、あなたの資金を盗むことも、意図しない資金送信を強制することもできません。完全にシールドされたトランザクション内の金額とメモは暗号化されたままです。

次に、保護されていないものがあります。脅威モデルでは、トラフィックを監視する敵対者に対する既知の弱点として以下を挙げています。

| 弱点 | 方法 |
|:--|:--|
| あなたが誰かを特定すること | 「敵対者はユーザーのIPアドレスを知っており、それがユーザーの実際の身元につながる可能性がある」 |
| おおよその居場所を特定すること | IPアドレスを「位置情報データベースで検索し、その所在地を推定する」 |
| シールドされたトランザクションを送受信したか、またその時期を特定すること | 送信では「接続が暗号化されていても可視である、より多くの帯域幅を使用する」。モデルでは、送受信という行為自体はサーバーに見えると指摘しています |
| 時間の経過に伴うトランザクション数を数えること | より長い期間にわたって観測される、同じ帯域幅パターン |
| 繰り返される支払いパターンを見つけること | 活動が発生する時期を観測すること |
| アドレスがあなたのものかを判断すること | すでにアドレスを知っている敵対者は、「そのアドレスに資金を送り、ウォレットが取得する際に帯域幅の急増があるかを監視できる」 |

またモデルでは、通常のケースでは「ユーザーとlightwalletdサーバー運用者の間に信頼関係がある」と想定しています。

したがって、率直な要約はこうです。ライトウォレットサーバーはあなたのお金を使うことができず、シールドされたトランザクション内の金額やメモも読めません。一方で、IPアドレスと活動のタイミングは把握しやすく、この2つを組み合わせると個人について多くのことが分かります。シールドされたトランザクションはブロックチェーン上で行われることを保護します。それだけではサーバーへの接続を隠せません。

## 視覚化 / たとえ話

これまでに印刷されたすべての新聞を所蔵する公共図書館を考えてみてください。フルノード（full node）は、アーカイブ全体を自宅に持ち帰る読者です。ライトウォレットは、代わりに司書へ毎日のダイジェストを依頼する読者です。自分に関係するものがあるかどうかを見つけるのに十分な情報だけを含む薄い紙です。

そのダイジェストは封印されています。司書はどの項目があなたにとって重要かを読めないまま作成し、あなたは自分の鍵で自宅で開封します。これがコンパクトブロックであり、開封はデバイス上での試行復号です。

しかし司書には、どの読者が入ってきたか、いつ来たか、どれほど厚い束を持ち出したかが見えます。これはIPアドレスとタイミングに当たります。封筒がどれほど厳重に封印されていても、受付から見えます。Torは匿名の配達人を送ることに相当します。司書は同じ束を渡しますが、どの家に届くのかは分からなくなります。

## 詳細解説

### Tor経由のルーティング

Torは、IPアドレスとウォレットトラフィックの結び付きを断ち、上の表にある最も強力な識別子を取り除きます。

多くのZcashウォレットが基盤とするRustライブラリには、この機能のサポートがあります。zcash_client_backendには、[Arti](https://tpo.pages.torproject.net/core/arti/)上に構築されたTorモジュールが含まれています。ArtiはTorのRust実装であるため、ウォレットは別個のTorクライアントを同梱せずに、同期、トランザクションのブロードキャスト、価格照会をTor経由でルーティングできます。

Zainoのdeveloperも、脅威モデルを直接引用して同じ主張をしています。すなわち、「クライアントの身元をZcashのインデックスサーバーから曖昧にするために、匿名のトランスポートプロトコル（NymやTorなど）を使用する必要がある」としています。

**ZODL**では、TorはAdvanced Settings内の設定です。ウォレットのリリースノートでは、メタデータの露出を減らしたい場合、「手動接続モードに加えてAdvanced SettingsでTorを有効にする」ようユーザーに案内しています。また、ウォレットを復元する前にTorを有効にする選択肢を提供しています。これは、新しいIPアドレスがウォレット履歴全体に結び付けられる可能性があるタイミングです。

注意点が2つあります。TorはサーバーからIPを隠しますが、サーバーがあなたのリクエストから知ることは変えません。また、オニオンルーティングは遅延を加えるため、同期にはより時間がかかります。自分のサーバーを運用すれば、運用者が自分自身になるため、信頼の問題を別の形で回避できます。

### Zaino、Rustインデクサー

[Zaino](/zcash-tech/zaino)は、ZingoチームがRustで書いたインデクサーです。zcashdの廃止作業の一環として、lightwalletdを置き換えるために構築されました。「Zebraまたはzcashdフルバリデーター」のいずれかが保持するチェーンデータを読み取り、ライトクライアント、フルクライアント、ブロックエクスプローラーに提供します。

現在も積極的に開発されており、バージョン0.8.0は2026年8月にリリースされました。可能な限りlightwalletdとの後方互換性を維持することを目指しているため、ウォレットを作り直さずに接続先として指定できます。

Zainoにはアーキテクチャ図を含む専用ページがあるため、このページではライトウォレットサーバーとしての役割のみを扱います。

### 自分で運用する

最も強力な選択肢は、自分自身が運用者になることです。これにより信頼の問題を完全に取り除けます。両方のサーバーはオープンソースです。[lightwalletd](https://github.com/zcash/lightwalletd)はGoで、[Zaino](https://github.com/zingolabs/zaino)はRustで書かれています。どちらもフルバリデーターから読み取るため、[Zebra](/zcash-tech/zebra-full-node)も必要になります。

## 実用上の意味

### サーバー一覧

[hosh.zec.rocks](https://hosh.zec.rocks/zec)ダッシュボードは公開サーバーとその健全性を追跡しており、実際に稼働しているものを確認する場所です。[status.zec.rocks](https://status.zec.rocks/)ではサービス状況を確認できます。

執筆時点でそのダッシュボードに掲載されているサーバーは次のとおりです。

| サーバー | 注記 |
|:--|:--|
| zec.rocks:443 | na.zec.rocks、eu.zec.rocks、ap.zec.rocks、sa.zec.rocksにも地域別エンドポイントが掲載されています |
| zec-node.cakewallet.com:443 | Cake Walletのドメイン上 |
| zec.0xrpc.io:443 | 多数のチェーン向けに無料の公開エンドポイントを提供し、容量費用を賄うための寄付を求めている0xRPCが運用しています |
| zaino.unsafe.zec.rocks:443 | Zainoのインスタンスです。ホスト名に注意し、実験的なものとして扱ってください |
| testnet.zec.rocks:443 | テストネットです。zaino.testnet.unsafe.zec.rocksにはZainoのテストネットインスタンスが掲載されています |

この一覧を信用するのではなく、ダッシュボードを確認してください。運用者は現れたり去ったりするため、このようなページは古くなります。

### ウォレットでサーバーを変更する

信頼する運用者を選びたい場合、活動を複数の運用者に分散したい場合、または自分のサーバーを指定したい場合に有用です。

以下のメニュー経路はこのページの更新時点では正しかったものですが、ウォレットのインターフェースは変わるため、正確な経路ではなく手掛かりとして扱ってください。Advanced Settingsまたはサーバーのオプションを探してください。

#### ZODL

以前はZashiでした。右上の歯車アイコンを選び、次にAdvanced Settingsを選びます。Torは同じ画面にあります。ZODLでは、サーバーが古いことによって同期失敗が発生した場合、「Switch server」ショートカットも提供されます。

## よくある間違い

**サーバーがあなたのトランザクションを読めると考えること**。読めません。鍵はデバイス上にあり、完全にシールドされたトランザクション内の金額とメモは、サーバーを侵害した敵対者に対しても暗号化されたままです。

**「シールドされた」を「匿名接続」と解釈すること**。シールドされたトランザクションはブロックチェーン上で行われることを保護します。IPアドレスと活動のタイミングは別の層であり、その層こそがサーバーに見えるものです。

**Torがあらゆる痕跡を消すと考えること**。TorはサーバーからIPを隠しますが、サーバーがあなたのリクエストから知ることは変えず、同期に遅延を加えます。

**wikiページ上のサーバー一覧を信頼すること**。運用者は現れたり去ったりします。ウォレットの接続先を指定する前に、実際に稼働しているものについては[hosh.zec.rocks](https://hosh.zec.rocks/zec)を確認してください。

## まとめ

ライトウォレットは、ディスク容量を使わずにシールドされたプール（shielded pool）を提供します。これは良いトレードオフです。ただし、何を交換しているのかを明確に理解してください。サーバーはあなたの資金を取ることも、シールドされた金額を読むこともできませんが、IPアドレスとトランザクションを行う時期を確認しやすい立場にあります。Tor経由でルーティングするか、意図して運用者を選ぶか、自分で運用してください。
