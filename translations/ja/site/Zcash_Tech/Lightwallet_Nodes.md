# Zcash ライトウォレットノード

## はじめに

ほとんどの人は、ブロックチェーン全体をダウンロードしないライトウォレットを通じて Zcash を利用しています。その代わり、すでにその作業を済ませているサーバーと通信します。このページでは、それらのサーバーが何であるか、あなたについて何を見られて何を見られないのか、Tor 経由で接続をルーティングする方法、そしてウォレットが使うサーバーを変更する方法を説明します。

現在、ライトウォレットにサービスを提供しているソフトウェアは 2 つあります。**lightwalletd** は Go で書かれた元祖のサービスです。**Zaino** は Rust で書かれた新しいインデクサで、zcashd 廃止作業の一環として構築されました。

## ライトウォレットサーバーの役割

ライトウォレットサーバーは、あなたのウォレットと Zcash ブロックチェーンの間に位置し、帯域幅効率のよいチェーンの見え方を提供します。役割は 3 つあります。

コンパクトブロックを配信します。ブロック全体ではなく、ウォレットがシールドアドレスへの支払いを検出し、ノートの使用を検出し、witness を更新するために必要なものだけを含むコンパクトな形式を送ります。

トランザクションを中継します。送金時には、ウォレットが完成したトランザクションをサーバーに渡し、サーバーがそれをネットワークにブロードキャストします。

現在のブロック高や、ウォレットが必要とする手数料情報などのチェーンクエリに応答します。

一方で、ウォレットはプライベートな処理を引き続きローカルで行います。鍵を保持し、ブロックを試行復号して自分のノートを見つけ、デバイス上でトランザクションを作成し署名します。

## サーバーに見えること／見えないこと

ここは誤解されやすい部分です。あなたの鍵がデバイスから出ることはありませんが、それはサーバーがあなたについて何も学べないという意味ではありません。

ここでの基準となるのは [Zcash wallet app threat model](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html) で、この点を気にするなら全文を読む価値があります。この文書では複数種類の adversary が定義されています。このページで重要なのは、あなたのウォレットとインターネットの間、およびサーバーとインターネットの間のトラフィックを監視できる adversary です。サーバー運営者は、あなたのウォレットが直接その相手に接続する以上、本質的にその立場の一部にあります。

まず、何が保護されているかです。このモデルでは、サーバーが侵害された場合を含むあらゆる adversary に対しても、相手は「ユーザーの暗号学的な鍵素材（spending keys、viewing keys、seed phrase など）を一切学習できない」とされており、あなたの資金を盗むことも、あなたが意図しない送金をさせることもできません。完全にシールドされたトランザクション内の金額やメモは暗号化されたままです。

次に、保護されないものです。threat model では、トラフィック監視 adversary に対する既知の弱点として次を挙げています。

| 弱点 | どのように |
|:--|:--|
| あなたが誰かを特定すること | 「adversary はユーザーの IP アドレスを知っており、それがユーザーの実際の身元につながる可能性がある」 |
| あなたが大まかにどこにいるかを特定すること | あなたの IP を「位置情報データベースで引いて、おおよその場所を推定する」 |
| あなたがシールドトランザクションを送受信した事実とその時刻を特定すること | 送信は「より多くの帯域幅を使うため、接続が暗号化されていてもそれが見える」。モデルでは、送受信という行為自体がサーバー自身には見えることも指摘しています |
| 時間の経過とともに、あなたが何件のトランザクションを行ったかを数えること | より長い期間にわたって観測される同じ帯域幅パターン |
| 繰り返しの支払いパターンを見つけること | いつアクティビティが起きるかを観測すること |
| あるアドレスがあなたのものかどうかを推測すること | すでにあるアドレスを知っている adversary は、「そのアドレスに資金を送り、あなたのウォレットがそれを取得するときに帯域幅のスパイクがあるかを監視できる」 |

モデルはまた、通常のケースでは「ユーザーと lightwalletd サーバー運営者との間に信頼関係がある」ことを前提としていると述べています。

ですので、正直な要約はこうです。ライトウォレットサーバーはあなたのお金を使うことはできず、あなたのシールドトランザクション内の金額やメモを読むこともできません。一方で、学習しやすいのはあなたの IP アドレスとアクティビティのタイミングであり、その 2 つを組み合わせると個人について多くのことが分かり得ます。シールドトランザクションが保護するのは、ブロックチェーン上に載る内容です。それだけでサーバーとの接続自体を隠してくれるわけではありません。

## Tor 経由のルーティング

Tor は、あなたの IP アドレスとウォレットトラフィックの結びつきを断ち切るので、上の表で最も強い識別子を取り除きます。

多くの Zcash ウォレットが基盤としている Rust ライブラリには、このサポートが存在します。zcash_client_backend には、Tor の Rust 実装である [Arti](https://tpo.pages.torproject.net/core/arti/) を基盤とした Tor モジュールが含まれているため、ウォレットは別個の Tor クライアントを同梱せずに、同期、トランザクションのブロードキャスト、価格照会を Tor 経由でルーティングできます。

Zaino の開発者たちも、threat model を直接引用しつつ同じ主張をしています。すなわち、「クライアントの身元を Zcash のインデクシングサーバーから見えにくくするために、匿名のトランスポートプロトコル（Nym や Tor など）を使う必要がある」ということです。

**ZODL** では、Tor は Advanced Settings 内の設定です。ウォレットのリリースノートでは、「メタデータ露出を減らしたい」ユーザーに対して、「手動接続モードに加えて Advanced Settings で Tor を有効にする」よう案内しています。また、ウォレットを復元する前、つまり新しい IP がウォレット全体の履歴と結びついてしまいかねないタイミングで、アプリは Tor を有効にするかどうかを提案します。

注意点が 2 つあります。Tor はサーバーからあなたの IP を隠しますが、あなたが行うリクエストからサーバーが学べる内容自体は変えません。また、オニオンルーティングは遅延を追加するため、同期にはより時間がかかります。自分でサーバーを運用すれば、運営者が自分自身になるため、この信頼の問題を別の形で回避できます。

## Zaino、Rust 製インデクサ

[Zaino](/site/Zcash_Tech/Zaino) は Zingo チームによる Rust 製のインデクサで、zcashd 廃止作業の一環として lightwalletd を置き換えるために作られました。ライトクライアント、フルクライアント、ブロックエクスプローラにサービスを提供し、「Zebra または Zcashd のフルバリデータのいずれか」が保持するチェーンデータを読み取ります。

活発に開発が続いており、2026 年 8 月にはバージョン 0.7.0 がリリースされました。可能な限り lightwalletd との後方互換性を維持することを目指しており、そのためウォレット側を全面的に書き換えなくても接続先に指定できます。

Zaino にはアーキテクチャ図を含む専用ページがあるため、このページではライトウォレットサーバーとしての役割に限って扱います。

## サーバー一覧

[hosh.zec.rocks](https://hosh.zec.rocks/zec) ダッシュボードでは公開サーバーとその稼働状況を追跡しており、実際に何が動いているかを確認する場所として適しています。[status.zec.rocks](https://status.zec.rocks/) ではサービスステータスを確認できます。

執筆時点でそのダッシュボードに掲載されていたサーバー:

| サーバー | 備考 |
|:--|:--|
| zec.rocks:443 | これに加えて、na.zec.rocks、eu.zec.rocks、ap.zec.rocks、sa.zec.rocks の地域別エンドポイントも掲載されています |
| zec-node.cakewallet.com:443 | Cake Wallet のドメイン上 |
| zec.0xrpc.io:443 | 0xRPC が運用。複数のチェーン向けに無料の公開エンドポイントを提供しており、容量維持のための寄付を募っています |
| zaino.unsafe.zec.rocks:443 | Zaino インスタンス。ホスト名に注意し、実験的なものとして扱ってください |
| testnet.zec.rocks:443 | テストネット。zaino.testnet.unsafe.zec.rocks に Zaino の testnet インスタンスも掲載されています |

この一覧をそのまま信じるのではなく、ダッシュボードを確認してください。運営者は入れ替わりますし、このようなページは時間とともに古くなります。

## ウォレット内でサーバーを変更する

信頼できる運営者を選びたい場合、複数の運営者にアクティビティを分散したい場合、または自分のサーバーを指定したい場合にやる価値があります。

以下のメニューパスはこのページ更新時点では正しかったものですが、ウォレットのインターフェースは変わるので、正確な経路というより手がかりとして扱ってください。Advanced Settings またはサーバー設定を探してください。

#### ZODL

旧称 Zashi。右上の歯車を開いて Advanced Settings へ。Tor も同じ画面にあります。ZODL は、同期失敗の原因がサーバーの古さにある場合、Switch server のショートカットも提供します。

右上の歯車を開いて、次に Zcash タブへ。

## 自分で運用する

最も強力な選択肢は、自分自身が運営者になることです。そうすれば信頼の問題を完全に取り除けます。どちらのサーバーもオープンソースです。[lightwalletd](https://github.com/zcash/lightwalletd) は Go、[Zaino](https://github.com/zingolabs/zaino) は Rust で書かれています。どちらもフルバリデータから読み取るため、[Zebra](/site/Zcash_Tech/Zebra_Full_Node) も用意するとよいでしょう。

## まとめ

ライトウォレットは、ディスク容量を使わずにシールドプールを利用可能にしてくれます。これは良いトレードオフです。ただし、何と引き換えにしているのかは明確に理解しておくべきです。サーバーはあなたの資金を奪うことも、シールドされた金額を読むこともできませんが、あなたの IP アドレスや取引したタイミングを見るには非常に都合のよい位置にあります。Tor 経由で接続するか、運営者を意識的に選ぶか、あるいは自分で運用してください。
