# Project Tachyon

## TL;DR

- Tachyonは、Zcashウォレットがシールドされた資金を見つけて使用する方法を再設計する提案であり、ネットワークを非常に大規模なユーザー数へ成長させることを目的としています
- 現在、ウォレットは自分宛ての支払いを見つけるためにブロックチェーンの大部分を復号しようと試みる必要があり、これがシールド同期が遅く感じられる主な理由です
- Tachyonはこれを**秘匿同期**に置き換えます。これにより、ウォレットはすべてをスキャンせず、どの部分を必要としたかをサーバーに知らせることなく、必要な情報を取得できます
- また、支払いの詳細をブロックチェーンから支払いリクエスト自体へ移します。これによりプロトコルは単純になりますが、責任はウォレット側へ移ります
- これは提案であり、2025年4月に初めて公開され、NU7の候補として挙げられました。**まだ実装・提供されておらず**、Saplingアップグレードと同規模のエンジニアリング作業が必要です

<br/>

## 対象読者

- シールドウォレットの同期を見て、なぜこれほど時間がかかるのか疑問に思った人
- NU7やZcashのスケーリングと並んでTachyonの名前を目にする初心者
- まずアイデアを理解し、その後に暗号技術を知りたい読者

## Tachyonが解決する問題

Zcashは、支払いの受取人を隠します。それこそが本来の目的ですが、厄介な問題も生みます。誰にも支払いの帰属先がわからないなら、自分のウォレットはどうやって自分宛ての支払いを見つけるのでしょうか？

Bitcoinではこれは簡単です。アドレスは公開されているため、ウォレットはサーバーに「このアドレスには何が送られましたか？」と尋ね、回答を得られます。Zcashウォレットはその質問をできません。質問すること自体が、シールドプールが隠すよう設計されている情報を正確に明かしてしまうからです。

そこでZcashは別の方法を取ります。送信者は支払いの詳細を暗号化し、トランザクション自体の中に埋め込みます。受取側のウォレットは、チェーン上のトランザクションを順に処理し、それぞれを復号しようと試みます。ほとんどすべての試行は失敗します。成功するわずかなものが、自分宛ての支払いです。これは**試行復号**と呼ばれ、プライベートで正確ですが、遅い方法です。

![現在のZcashウォレットは、自分宛てのわずかな支払いを見つけるために、すべてのシールドトランザクションをダウンロードして一つずつ復号しようと試みますが、ほとんどの試行は失敗します](/content-images/tachyon-scanning-today.svg)

問題は、この作業が何に依存するかです。ウォレットが費やす労力は、実際に受け取った支払いの数ではなく、チェーンの大きさで決まります。一度も支払いを受け取ったことがない人でも、毎日受け取る人とほぼ同じだけの作業が必要です。Zcashが成長するほど、これは誰にとっても悪化します。提案書の言葉を借りれば、これは「単純にスケールしない」のです。

<br/>

## Tachyonが変えること

Tachyonは、支払いの秘密情報を届ける手段としてブロックチェーンを使うことをやめることで、この問題を根本から解決しようとします。

代わりに、必要な詳細情報は支払いリクエスト自体とともに、帯域外で送られます。支払いリクエスト、URI、またはQRコードが、これまでトランザクションに暗号化されていた情報を運びます。Sean Boweはこれを、Zcashのシールドプロトコルとして初めて**帯域外支払い**を受け入れることだと説明しています。

チェーンがこの情報を保持しなくなれば、ウォレットがそれを探索する理由もなくなり、試行復号の問題は解消されます。

ただし、ウォレットが支払いを行うには、現在のチェーン状態を知る必要があります。ここが設計の後半、**秘匿同期**です。これは、ウォレットが必要な特定の情報を取得しながら、どの情報を要求したかをサーバーに明かさない方法です。

![Tachyonでは、送信者が支払いの詳細を帯域外で受取人に渡し、ウォレットはチェーン全体をスキャンする代わりに秘匿同期を用いて必要なデータだけを取得します](/content-images/tachyon-oblivious-sync.svg)

## ウォレットを使う人にとっての意味

- **同期はチェーンの規模に応じて増えなくなります。** ウォレットが追いつくために費やす時間は、Zcashの規模ではなく自分自身の利用状況に連動します。
- **支払いは、誰かに請求書を手渡すことにより近くなります。** 支払いリクエストには受取人が必要とする情報が含まれるため、送信者と受取人の間のやり取りは現在より重要になります。
- **ウォレットがより大きな責任を負います。** チェーンには支払い詳細の暗号化コピーが残らなくなるため、ウォレットデータを失うことの影響はより大きくなります。バックアップと復旧は、プロトコル機能から、ウォレットソフトウェアが正しく実現すべきものへ移ります。
- **馴染みのある要素の一部は移動するか、なくなります。** Tachyonは、鍵の多様化、Viewing Key、支払いアドレスをコアプロトコルから外し、ウォレット層に委ねます。これは提案の中でも特に重要な部分の一つであり、現在も検討が進められています。

<br/>

## 技術読者向けの詳しい説明

Tachyonは、Orchardプロトコルに対するリバース互換の変更として説明されています。既存のOrchardプールのアップグレードとして導入することも、ZcashがIronwoodで用いたものと同じ仕組みである[ターンスタイル](https://zechub.wiki/zcash-tech/the-turnstile)を通じて到達する別個のシールドプールとして導入することもできます。選択は導入方法に影響しますが、設計自体には影響しません。

Orchardからいくつかの要素を引き継ぎます。RedPallas鍵の再ランダム化、準同型の価値コミットメントとバインディング署名、そしてデバイスが支出権限を渡すことなく証明生成を委任できる、分割された鍵構造です。

スケーリングの仕組みは**証明付きデータ**に依拠しています。これは、データが自身の正しさの証明とともに移動する技術であり、他の証明付きデータと組み合わせると、その証明を継承・拡張したものが生成されます。これにより、大量の検証済み作業を、検証が小さく高速なものに圧縮できます。Zcashの開発チームが発見したHaloによって、証明付きデータは構築に使えるほど実用的になりました。

第3の要素は**シールドトランザクション集約**であり、シールド状態の変更を伝達する方法を変え、署名の仕組みにも連鎖的な影響を与えます。

<br/>

## 開発状況

Tachyonは**提案であり、実装・提供済みの機能ではありません**。2025年4月に公開され、2025年5月の続編記事でコンセンサスへの影響が検討されました。Ironwoodに続く次の大型アップグレードであるNU7の候補に挙げられていますが、NU7の内容はコイン保有者の投票で決まり、Tachyonについて確定していることはありません。

著者自身は、これを投機的研究ではなく実行可能な計画と位置づけていますが、Saplingに匹敵するエンジニアリング作業を必要とし、いくつかの難しい問題は意図的に後回しにされています。

関連する作業はすでに見え始めています。2026年7月にリリースされたフルノードの[Zakura](https://zechub.wiki/zcash-tech/zakura-node)は、Project TachyonとValar Groupの共同作業であり、これらのネットワークレベルの変更の一部を先取りしています。[プライベート情報検索](https://zechub.wiki/zcash-tech/private-information-retrieval)の研究は、異なる角度から同じスキャンのボトルネックに取り組んでいます。

## よくある誤解

- **Tachyonはまだ稼働していません。** 現在これを利用するウォレットはなく、有効化されたアップグレードもありません。
- **TachyonはIronwoodと同じものではありません。** Ironwoodは2026年7月に有効化され、Orchardプールとターンスタイルを扱いました。Tachyonはスケーリングに関する別個の、より後の提案です。
- **Tachyonはプライバシーの低下ではありません。** 目的は、プライバシーを速度と引き換えにするのではなく、台帳非識別性を維持しながらスケーリングのコストを取り除くことです。
- **zk-SNARK検証はボトルネックではありませんでした。** 提案では、遅い部分はウォレットが状態を発見・調整する方法であり、証明を検証するコストではないと明記されています。
- **「NU7を対象にしている」は確約ではありません。** NU7に含まれるものは投票で決まります。

## 用語集

| 用語 | 意味 |
|---|---|
| 試行復号 | 自分宛てのトランザクションを見つけるために、トランザクションを一つずつ復号しようと試みること |
| 帯域内秘密情報配布 | 現在のZcashのように、ブロックチェーン上のトランザクション内部に支払いの秘密情報を入れること |
| 帯域外支払い | チェーンを経由せず、送信者と受取人の間で支払い詳細を直接渡すこと |
| 秘匿同期 | どのデータが要求されたかを明かすことなく、ウォレットが必要なチェーンデータを取得すること |
| 証明付きデータ（PCD） | 自身の正しさの証明とともに移動するデータであり、証明を組み合わせて圧縮できるもの |
| シールドトランザクション集約 | シールド状態の変更をまとめるTachyonの方法であり、その伝達と署名の方法を変えるもの |
| 台帳非識別性 | シールドトランザクション同士を互いに見分けられないという性質 |

## FAQ

**これによりウォレットの同期は速くなりますか？** それが目標です。同期時間はチェーンの規模ではなく、自分自身の利用状況に連動するようになります。まだ何も実装・提供されていないため、引用できる測定値はありません。

**今、何かする必要はありますか？** いいえ。Tachyonは提案です。採用された場合は、通常の告知を伴うネットワークアップグレードを通じて導入されます。

**Viewing Keyを削除すると、読み取りアクセスを共有する機能は失われますか？** この提案では、その機能をコアプロトコルからウォレット層へ移します。実際にどのような形になるかは、未解決の問題の一つです。

**Tachyonが実装・提供された場合、資金は危険にさらされますか？** 導入にはOrchardアップグレードまたはターンスタイルのいずれかを用い、どちらも公開された会計ルールの下で価値が移動するよう設計されています。Ironwoodのページではターンスタイルの仕組みを説明しています。
