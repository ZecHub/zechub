# プロジェクト Tachyon

## 要約

- Tachyonは、Zcashウォレット（wallet）がシールドされた資金を見つけて使う方法を再設計する提案であり、ネットワークを非常に多くのユーザーへ拡張できるようにすることを目的としています
- 現在、ウォレットは自分宛ての支払いを見つけるためにブロックチェーンの大部分を復号しようとする必要があり、これがシールドされた同期が遅く感じられる主な理由です
- Tachyonはこれを**秘匿同期**に置き換え、ウォレットがすべてをスキャンすることなく、またサーバーにどの部分を必要としたかを明かすことなく、必要なものを取得できるようにします
- また、支払いの詳細をブロックチェーンから支払いリクエストそのものへ移すことで、プロトコルを簡素化する一方、責任をウォレットへ移します
- これは2025年4月に初めて公開された提案です。**NU7の一部ではなく**、**未実装**です。また、Saplingアップグレードと同規模のエンジニアリング作業が必要です

<br/>

## 対象読者

- シールドされたウォレットの同期を見て、なぜこれほど時間がかかるのかと思ったことがある人
- TachyonがNU7やZcashのスケーリングとともに言及されるのをよく目にする初心者
- まずアイデアを理解し、暗号技術はその後で学びたい読者

## Tachyonが解決する問題

Zcashは支払いの受取人を隠します。これこそが目的ですが、厄介な問題も生まれます。誰にも支払いの受取人が分からないなら、自分のウォレットはどうやって自分宛ての支払いを見つけるのでしょうか。

Bitcoinでは簡単です。アドレス（address）は公開されているため、ウォレットはサーバーに「このアドレスには何が送られましたか」と尋ね、回答を得られます。Zcashウォレットはその質問をできません。質問すること自体が、シールドされたプール（pool）が隠すよう設計されているものを正確に明らかにしてしまうためです。

そのため、Zcashは別の方法を取ります。送信者は支払いの詳細を暗号化（encryption）し、トランザクション（transaction）そのものに埋め込みます。その後、ウォレットはチェーン（chain）上のトランザクションを順に処理し、それぞれを復号しようとします。ほとんどの試行は失敗します。成功するわずかなものが自分宛ての支払いです。これは**試行復号**と呼ばれ、プライバシーを守り、正確ですが、遅いものです。

![Today a Zcash wallet downloads every shielded transaction and tries to decrypt each one, with almost every attempt failing, to find the few payments that belong to it](/content-images/tachyon-scanning-today.svg)

問題は、作業量が何に依存するかです。ウォレットが費やす作業量は、実際に受け取った支払いの数ではなく、チェーンの大きさで決まります。1回も支払いを受け取ったことがない人も、毎日受け取る人とほぼ同じだけの作業を行います。Zcashが成長するほど、これは全員にとって悪化します。提案書の言葉を借りれば、「まったくスケールしません」。

<br/>

## Tachyonが変えること

Tachyonは、支払いの秘密情報の配信チャネルとしてブロックチェーンを使うことをやめることで、問題を根本から解決しようとします。

代わりに、必要な詳細は帯域外で、支払いリクエストそのものとともに送られます。支払いリクエスト、URI、またはQRコードが、これまでトランザクションに暗号化されていた情報を運びます。Sean Boweはこれを、Zcashのシールドされたプロトコルで初めて**帯域外支払い**を採用することだと説明しています。

チェーンがその情報を保持しなくなれば、ウォレットがチェーンを検索する理由もなくなり、試行復号の問題は解消されます。

ただし、ウォレットは支出のために現在のチェーン状態を知る必要があります。これが設計の後半、**秘匿同期**です。これは、ウォレットが必要とする特定の情報を、サーバーにどの情報を要求したか明かさずに取得する方法です。

![With Tachyon the sender passes payment details to the recipient out of band, and the wallet uses oblivious synchronization to retrieve only the data it needs instead of scanning the whole chain](/content-images/tachyon-oblivious-sync.svg)

## ウォレットを使う人にとっての意味

- **同期はチェーンとともに増大しなくなります。** ウォレットが追いつくために費やす時間は、Zcashの規模ではなく、自分自身の活動に応じたものになります。
- **支払いは誰かに請求書を渡すことに近くなります。** 支払いリクエストには受取人が必要とする情報が含まれるため、送信者と受取人の間のやり取りは、現在よりも重要になります。
- **ウォレットがより多くの責任を担います。** チェーンには支払い詳細の暗号化されたコピーが残らなくなるため、ウォレットのデータを失うことの重要性が増します。バックアップと復元はプロトコルの機能ではなくなり、ウォレットソフトウェアが正しく実現すべきものになります。
- **馴染みのある要素の一部が移動または消失します。** Tachyonは、鍵の多様化、ビューイングキー（viewing key）、支払いアドレスをコアプロトコルから外し、ウォレット層に委ねます。これは提案の中でも特に重要な部分の1つであり、現在も検討が進められています。

<br/>

## 技術読者向けの詳しい説明

Tachyonは、Orchardプロトコルに対するリバース互換性のある変更として説明されています。既存のOrchardプールのアップグレードとして、または[ターンスタイル（turnstile）](https://zechub.wiki/zcash-tech/the-turnstile)を通じて到達する別個のシールドされたプールとして導入できます。これはZcashがIronwoodで使用したのと同じ仕組みです。選択は導入方法に影響しますが、設計には影響しません。

これはOrchardの複数の要素を維持します。RedPallasの鍵再ランダム化、準同型の値コミットメント（commitment）とバインディング署名（signature）、そして支出権限を渡すことなくデバイスがプルーフ（proof）の生成を委任できる、分割された鍵構造です。

スケーリング作業は**プルーフ随伴データ**に依拠しています。これは、データが自身の正しさのプルーフとともに移動し、他のプルーフ随伴データと組み合わせることで、それらのプルーフを継承して拡張するものを生み出す技術です。これにより、大量の検証済み作業を小さく迅速に確認できるものへ圧縮できます。Haloは、Zcashのチームによって発見され、プルーフ随伴データを構築に使えるほど実用的にしたものです。

3つ目の要素は**シールドされたトランザクション集約**であり、シールドされた状態変更の伝達方法を変え、署名の仕組みにも連鎖的な影響を及ぼします。

<br/>

## 作業の状況

Tachyonは**提案であり、実装済み機能ではありません**。2025年4月に公開され、2025年5月の続報ではコンセンサス（consensus）への影響が検討されました。NU7の候補として、Ironwoodの次のアップグレードに挙げられましたが、2026年9月17日に合意されたNU7の範囲には含まれていません。[ZIP 259](https://zips.z.cash/zip-0259)にはNU7が導入するものが列挙されており、[フォーラム発表](https://forum.zcashcommunity.com/t/nu7-timeline/57655)では、新しいトランザクション形式は含まれないと述べられています。Tachyonの有効化日は設定されていません。

著者自身は、これを投機的な研究ではなく実行可能な計画として位置付けています。ただし、Saplingに匹敵するエンジニアリング作業を必要とするものであり、より困難な問題の一部は意図的に後回しにされています。

関連する作業はすでに見られます。[Zakura](https://zechub.wiki/zcash-tech/zakura-node)は、2026年7月にリリースされたフルノード（full node）であり、プロジェクトTachyonとValar Groupの共同作業です。これは、こうしたネットワークレベルの変更の一部を先取りしています。[プライベート情報検索](https://zechub.wiki/zcash-tech/private-information-retrieval)の研究は、別の角度から同じスキャンのボトルネックを対象としています。

## よくある誤解

- **Tachyonは稼働していません。** 現在これを使用しているウォレットはなく、有効化されたアップグレードもありません。
- **TachyonはIronwoodと同じものではありません。** Ironwoodは2026年7月に有効化され、Orchardプールとターンスタイルを扱いました。Tachyonは、スケーリングに関する別個の後発提案です。
- **Tachyonはプライバシーの低下ではありません。** 目標は、プライバシーを速度と引き換えにすることではなく、台帳識別不能性を維持しながらスケーリングのコストを取り除くことです。
- **zk-SNARKの検証はボトルネックではありませんでした。** 提案では、遅い部分はウォレットが状態を発見し調整する方法であり、プルーフを確認するコストではないことが明確にされています。
- **TachyonはNU7に含まれていません。** かつて候補として挙げられましたが、2026年9月に合意された範囲は25秒ブロック、手数料の再循環、バージョン4トランザクションの終了を対象としており、新しいトランザクション形式はありません（[ZIP 259](https://zips.z.cash/zip-0259)）。

## 用語集

| 用語 | 意味 |
|---|---|
| Trial decryption | 自分宛てのトランザクションを見つけるために、トランザクションを1つずつ復号しようとすること |
| In-band secret distribution | 現在のZcashのように、支払いの秘密情報をブロックチェーン上のトランザクション内に入れること |
| Out-of-band payment | チェーンを通すのではなく、支払いの詳細を送信者と受取人の間で直接渡すこと |
| Oblivious synchronization | ウォレットが要求したデータを明かさずに、必要なチェーンデータを取得すること |
| Proof-carrying data (PCD) | 自身の正しさのプルーフとともに移動するデータで、プルーフを組み合わせて圧縮できます |
| Shielded transaction aggregate | Tachyonがシールドされた状態変更をまとめる方法であり、それらの伝達と署名の方法を変えます |
| ledger indistinguishability | シールドされたトランザクション同士を区別できないという性質 |

## FAQ

**これによりウォレットの同期は速くなりますか？** それが目標です。同期時間はチェーンの規模ではなく、自分自身の活動に応じたものになります。まだ何も実装されていないため、引用できる測定値はありません。

**今、何かする必要がありますか？** いいえ。Tachyonは提案です。採用された場合は、通常の告知を伴うネットワークアップグレード（network upgrade）を通じて導入されます。

**ビューイングキーを削除すると、読み取りアクセスを共有する機能は失われますか？** 提案では、その機能をコアプロトコルからウォレット層へ移します。実際にどのような形になるかは、未解決の問題の1つです。

**Tachyonが実装された場合、私の資金は危険にさらされますか？** 導入にはOrchardアップグレードまたはターンスタイルのいずれかが使用され、どちらも価値が公開された会計ルールの下で移動するよう設計されています。Ironwoodのページでは、ターンスタイルの仕組みを説明しています。
