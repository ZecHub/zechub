# ターンスタイル（turnstile）

## 要約

- ターンスタイルは、各シールドされたプールに出入りする価値の量を追跡する公開会計ルールです
- プール内のトランザクションがプライベートであっても、プールが投入された以上の価値を支払わないことを誰でも検証できます
- これにより、偽造コインはカウントを破らずにプールから出られないため、隠れたバグからZECの供給量を保護します
- プール内の支払いはプライベートなままです。プール間でZECを移動するトランザクションは、移動する金額を示します
- ターンスタイルがあるため、OrchardからIronwoodへの移行では、シールドされた供給量が健全であることを証明できます

<br/>

## 対象者

- Zcashがプライベートな供給量の信頼性をどのように維持しているかを理解したい人
- OrchardからIronwoodへの移行を追っており、それが供給量の実在をどのように証明するのか気になるユーザー
- プライベートな通貨システムがどのように監査可能であるかに関心を持つ初心者

<br/>

## 課題

シールドされたZcashは、金額、送信者、受信者を隠します。このプライバシー（privacy）こそが目的です。しかし、これは難しい問題を生みます。誰もシールドされたプールの中を見られないなら、総ZEC量が正しいことをどうやって知るのでしょうか。見えない通貨をどう監査するのでしょうか。

もしバグによって誰かがシールドされたプール内でコインを偽造できた場合、その偽造は正当なユーザーを保護する同じプライバシーによって隠されます。保護策がなければ、この不確実性は供給量全体への信頼を損ないます。ターンスタイルは、この問題を解決する保護策です。

<br/>

## ターンスタイルとは

各シールドされたプールを、カウントされる1つの出入口を持つ部屋だと考えてください。価値が外部からプールへ入るとき、またはプールから別の場所へ出るときは常に、その出入口を通過し、公開で集計されます。部屋の中のトランザクションはプライベートなままですが、出入口での累計は誰にでも見えます。

ルールは単純です。プールから出る価値が、入った価値を超えることは決してありません。ノード（node）は、プールの残高をゼロ未満にするブロックを拒否します。プール内にあると考えられる金額は、入った総額から出た総額を引いたものにすぎないため、常に分かります。この公開集計がターンスタイルです。

<br/>

## 仕組み

Zcashには、その歴史を通じてSprout、Sapling、Orchardなど、複数のシールドされたプールがあります。価値は公開型チェーン（chain）とこれらのプールの間を移動し、ときにはプール間でも移動します。ターンスタイルはこれらの移動を監視します。

1. ZECがシールドされたプールへ移動すると、その金額が当該プールの公開残高に加算されます
2. ZECがプールから移動すると、その金額が差し引かれます
3. ネットワークは、プール残高をマイナスにするブロック、すなわち入った総額を超える価値が出たことを意味するブロックを拒否します
4. 各トランザクションは、プールへの流入またはプールからの流出の純額、すなわち価値残高のみを示します。1つのプール内の支払いでは、これは手数料（fee）だけです

ネットワークは、Sprout、Sapling、Orchard、新しいIronwoodプール、公開型残高およびロックボックス残高を含む、すべての価値プールについてこのように残高を追跡します。このため、プールの正確な内容が隠されていても、出ていける最大額は入った額によって上限が設定されます。隠れたインフレーションが流通へ逃げ出すことはできません。

<br/>

## 価値残高の検証方法

出入口での集計が信頼できるのは、金額自体は隠されたままであっても、すべてのトランザクションが正しい金額を移動したことを証明するよう強制されるからです。各シールドされたトランザクションは、プールへの流入またはプールからの流出の純額という、1つの正しい数値を公開します。これは価値残高と呼ばれます。正の価値残高は資金がプールから公開型側へ出たことを、負の値は資金が入ったことを意味します。プライベートな詳細は封印されたままですが、この1つの純額は公開され、ターンスタイルが合計する対象です。

巧妙な点は、トランザクションがその背後にあるプライベートな金額を明かさずに、この公開数値が正しいことをどのように証明するかです。仕組みはプールごとに異なり、ここがターンスタイルの本当の機構です。

元のSproutプールでは、各トランザクションはJoinSplitを使用します。JoinSplitは2つの隠されたノート（note）を使用し、2つの新しいノートを作成します。また、公開フィールドを2つ持ちます。公開型側からシールドされたプールへ入る価値であるvpub_oldと、プールから公開型側へ戻る価値であるvpub_newです。すべてのJoinSplitは単独で均衡していなければならず、そのゼロ知識（zero-knowledge）プルーフは、隠された入力と出力が正しく合計されることを保証します。Sproutのプール残高は、チェーン全体におけるすべてのvpub_oldの累計から、すべてのvpub_newの累計を引いたものです。このため、後でSproutが有用な例になります。vpub_oldは価値がプールに入る唯一の方法であるため、これを無効にする単一のルールによってプールを永久に封じることができます。

Sapling、Orchard、Ironwoodでは、バインディング署名（signature）を使用して、より賢い方法で残高が証明されます。各送金が単独で均衡する代わりに、トランザクション全体が価値コミットメントを使用して各隠された金額にコミットします。価値コミットメントは数値の封印された封筒であり、特殊な性質を持つ準同型Pedersenコミットメントによって構築されます。つまり、封筒を開封せずに加算と減算ができます。ネットワークはすべての入力コミットメントを合計し、すべての出力コミットメントを差し引き、その結果をトランザクションが宣言する単一の純額、valueBalanceフィールドと比較します。隠された金額が公開されたvalueBalanceと本当に一致するトランザクションだけが、結合されたコミットメントに対する有効なバインディング署名を生成できます。誰かが宣言した以上の価値を移動しようとすると、コミットメントは合計が一致せず、バインディング署名は検証されず、トランザクションは拒否されます。Ironwoodは同じOrchardプロトコルを使用するため、同じ仕組みです。

これにより、プール間送金も安全に検証できます。たとえばOrchardからIronwoodへ資金が移動する場合、トランザクションは会計から金額を隠すことができません。各プールには独自の価値残高があり、それぞれのプルーフによって満たされなければなりません。Orchard側はバインディング署名を通じて対応する流出を示す必要があり、Ironwood側は独自の手段で対応する流入を示す必要があります。一方のプールから出る価値と他方のプールへ入る価値は、それぞれ独立して証明されます。そのため、プール間の移動は実際には1つのトランザクションで起きる2回のターンスタイル通過、すなわち1回の流出と1回の流入であり、基礎となる金額がプライベートなままでも、どちらも公開で集計されます。

したがって、ターンスタイルは信頼ではありません。すべてのトランザクションが自身の純効果を数学的に証明し、ネットワークはプールごとにそれらの証明済みの純効果を合計し、コンセンサス（consensus）ルール（ZIP 209）がプール残高をマイナスにするブロックを拒否します。トランザクションレベルでのプルーフ、チェーンレベルでの実施です。

<br/>

## なぜ重要か

ターンスタイルはZcashに3つのものを同時にもたらします。

第1に、リスクを区分します。1つのプールに暗号学的なバグがあっても、ターンスタイルが偽造された価値がより広い供給量へ渡るのを止めるため、そのプール内に封じ込められます。

第2に、コミュニティが供給量を遡って検証できるようにします。後でバグが発見された場合、ターンスタイルの記録は、プールに入った以上の価値が出たことがあるかを示します。記録が問題なければ、偽造が悪用されなかったことの強力な証拠になります。

第3に、これらすべてを行いながら、プール内の支払いをプライベートに保ちます。各トランザクションが公開するのはプールへの流入またはプールからの流出の純額だけであり、1つのプール内の支払いでは手数料だけです。OrchardからIronwoodへのようなプール間送金では、通過する金額が表示されます。監査可能性とプライバシーは共存しており、これは珍しいことで、Zcashの控えめな強みの1つです。

<br/>

## 実際のターンスタイル

ターンスタイルは新しいものではなく、Zcashの歴史における重要な局面で使われてきました。

Zcashが元のSproutプールから新しいSaplingプールへ移行した際、ターンスタイルがその移行を保護しました。Sproutプールは後に新規流入を受け取れないよう制限され、ターンスタイルが会計の正確性を保つ一方で、ユーザーの移行を促しました。数年後、Sproutから不適切に価値が出たことが一度もないという事実は、その初期の暗号技術が悪用に成功されなかったことの証拠となっています。

同じ設計が現在、OrchardからIronwoodへの移行を保護しています。2026年、Orchardプルービングシステムに健全性バグが発見され、修正されました。悪用された証拠はありませんが、シールドされた活動はプライベートであるため、確実に断定することは不可能でした。対応として、古いOrchardプールを封じ、修正済みプロトコルを使用する新しいIronwoodプールへ、全員がターンスタイルを通じて資金を移行します。資金をターンスタイルに通すことで、仮に偽造コインが残されていたとしても追従できず、移行が完了すれば、誰でもシールドされた供給量が健全であることを確認できます。

<br/>

## 一方向のプール廃止

ターンスタイルにより、供給量の保証を決して破ることなく、古いプールを一方向だけで安全に廃止できます。その方法は、出口を開いたまま入口を閉じることです。

Sproutが最も明確な例です。これを廃止するため、ZIP 211は単一のコンセンサスルールを追加しました。活性化ブロック高以降、すべてのJoinSplitのvpub_oldフィールドはゼロでなければなりません。vpub_oldは価値がSproutへ入る唯一の方法であるため、これをゼロに強制すると、新しい価値は二度と入れなくなります。一方で、価値は引き続き公開型側へ、またはSaplingへ出ていけます。プールは一方向になりました。満たされることはなく、排出されるだけです。ターンスタイルはその間ずっと数え続けるため、資金が出るにつれて残高は減少できますが、増加もマイナスになることもありません。

OrchardからIronwoodへの移行も、同じ考え方を使用します。NU6.3アップグレードで、Orchardプールは新規流入を受け付けなくなり、ウォレットはOrchard資金をターンスタイルを越えて新しいIronwoodプールへ送るよう案内されます。Orchardは空になることしかできない一方向プールになります。すべての出口は証明されなければならないターンスタイル通過であるため、Orchardに残された仮想的な偽造価値が、正当な資金に静かに追従して外へ出ることはできません。それは排出されるだけのプールに閉じ込められ、出入口で監視されます。時間とともに、これにより古いプールは空に近づき、出てきた価値が正当に入った価値を超えなかったことを誰でも確認できるようになります。

これが、単純な会計を超えてターンスタイルが重要である深い理由です。Zcashが、Sproutのように複雑性を減らすためであれ、Orchardのように発見されたバグから回復するためであれ、シールドされたプールを廃止しながら、供給量に関する継続的で公開され、証明可能な保証を維持できるようにする仕組みです。

<br/>

## よくある誤解

- ターンスタイルは、誰が誰に何を送ったかを明かしません。ただし、プール間でZECを移動するトランザクションの金額は示します
- 偽造者を名前で特定するものではありません。プールから出られる量に上限を設けることで、供給量を保護します
- これはIronwoodの新しい発明ではありません。Zcashの歴史におけるすべての主要なシールドされたプール移行を保護してきました
- 公開されたプール合計は、プール内の支払いのプライバシーを弱めません。プール間でZECを移動すると移動額が表示されるため、ZIP 318はウォレットに対し、時間をかけて標準的な金額で移行するよう求めています
