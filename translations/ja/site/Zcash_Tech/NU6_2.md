# NU6.2

> NU6.2 は Zcash メインネットのブロック 3,364,600（2026年6月3日 UTC）で有効化されました。

ここでわかること: NU6.2 が何を修正したのか、なぜ Zcash が約1日間シールドトランザクションを停止したのか、そして資金を失うことなくネットワークがどのように問題を塞いだのか。

NU6.2 は、[ZIP 257](https://zips.z.cash/zip-0257) で正式に定義された Zcash の[ネットワークアップグレード](../start-here/network-upgrades)であり、緊急停止の後に Orchard シールドプロトコルを再有効化しました。これは Orchard のゼロ知識回路にあった健全性のバグを修正し、[シールド](../using-zcash/shielded-pools)トランザクションを復旧させました。これは Orchard バグの物語における緊急修理の章だと考えてください。その後のアップグレードである [Ironwood (NU6.3)](../zcash-tech/ironwood) では、新しいプールと旧プールの公開監査が追加されました。

これが重要な理由。Orchard は、Zcash のプライベートな支払いの大半が行われる場所です。そのプールの健全性を保つ数理に欠陥が見つかったとき、ネットワークは難しい選択を迫られました。既知のリスクを抱えたままシールドトランザクションを動かし続けるのか、それとも修正の準備が整うまで停止するのか。NU6.2 は、Zcash が安全性を最優先し、それでも1日以内にプライバシー機能を復旧させた方法です。

![NU6.2 緊急タイムライン: Orchard バグは5月29日に発見され、6月2日に緊急ソフトフォークによって Orchard が停止され、6月3日に NU6.2 によって修正済み回路で再有効化されました](https://raw.githubusercontent.com/ZecHub/zechub/main/site/Zcash_Tech/assets/nu6-2-timeline.png)

## 何が起きたのか

発端は、Orchard の Action 回路における健全性バグでした。これは、すべてのシールドトランザクションがルールに従っていることを証明するはずの数理です。独立研究者の Taylor Hornby が [Shielded Labs](../zcash-organizations/shielded-labs) の監査中にこれを発見し、2026年5月下旬に責任ある開示を行いました。この問題は Orchard が 2022 年に立ち上がって以来見過ごされており、理論上は無効なトランザクションが有効なものとして通過できる可能性がありました。これは Orchard プール内で資金が盗まれたり二重支払いされたりすることを許しかねません。Zcash のターンスタイル会計は、Orchard から外へ出られる価値の総量に依然として上限を設けていたため、ZEC の総供給自体が水増しされることはありませんでした。しかし、シールド資金の健全性を保つ数理に欠陥があるのは重大であり、そのためネットワークは数日以内に対応しました。[Ironwood](../zcash-tech/ironwood) のページでは、このバグと、それがどのようにして価値を生み出し得たのかを詳しく説明しています。

## 緊急停止

2026年6月2日、緊急ソフトフォークにより、すべての Orchard トランザクションが一時的に無効化されました。これは zcashd v6.12.5 および zebra v4.5.3 のホットフィックスとして提供されました。

1. シールドされた Orchard の送受信は停止され、新しい Orchard 証明は作成も受理もできなくなりました。
2. Transparent と Sapling のトランザクションは通常どおり動作し続けました。
3. 資金が移動、凍結、喪失されたことはありません。この停止は、本当の修正が完了するまで新しい Orchard の活動だけを止めたものです。

![何が停止し、何が動き続けたか: transparent と Sapling のトランザクションは終始稼働し、Orchard だけが 6 月 2 日から 6 月 3 日までの約 1 日間停止しました](https://raw.githubusercontent.com/ZecHub/zechub/main/site/Zcash_Tech/assets/nu6-2-what-paused.png)

## NU6.2 が変更したこと

翌日の 2026年6月3日、NU6.2 のハードフォークがブロック 3,364,600 で有効化され、修正済み回路上で Orchard が再有効化されました。

![NU6.2 の回路修正: 問題のある回路には欠けていた制約と古い検証鍵があり、NU6.2 はその制約を追加して修正済み回路を生成し、不正な証明を拒否する新しい検証鍵を導入しました](https://raw.githubusercontent.com/ZecHub/zechub/main/site/Zcash_Tech/assets/nu6-2-the-fix.png)

1. 欠けていた制約を追加することで、Action 回路の variable-base scalar multiplication gadget を修正しました。
2. その結果、新しい検証鍵が生成され、古い不完全な回路の下で作られた証明はもはや有効ではなくなり、新しい証明はすべて修正済みのものを使わなければならなくなりました。
3. 正確な証明長をコンセンサスルールにし、以前は強制されていなかった隙間を塞ぎました。

修正済みコードは zcashd v6.20.0 および zebra v5.0.0 に搭載され、halo2_gadgets v0.5.0 と orchard crate v0.14.0 に基づいて構築されました。

## NU6.2 が行わなかったこと

NU6.2 は新しいすべてのトランザクションに対して回路を安全にしましたが、古いルールの下で作られた価値は依然として Orchard プール内に残っていました。その価値を監査し、クリーンなプールへ移すことは別の作業であり、それを [Ironwood (NU6.3)](../zcash-tech/ironwood) が新しいプールとターンスタイルで処理します。

## 何か失われたのか

いいえ。このバグが実際に悪用された証拠はなく、不正な価値の生成もなく、ユーザー資金への影響もありませんでした。Zcash のターンスタイル会計により、この一連の出来事を通して総供給量が保たれていたことが確認されています。

## 用語集

| 用語 | 平易な意味 |
|---|---|
| Shielded pool | 金額と所有者がゼロ知識暗号によって隠されている資金の集合 |
| Orchard | Zcash の現在のシールドプロトコルであり、ほとんどのプライベートトランザクションがここで行われる |
| Soundness bug | 無効なトランザクションが、あたかも有効であるかのように証明検証を通過してしまう欠陥 |
| Verifying key | ネットワークが証明の有効性を確認するために使う公開値。回路の修正によりこれが変わった |
| Soft fork | 後方互換性のあるルール変更であり、ネットワークを分岐させずに Orchard を停止したもの |
| Hard fork | すべてのノードがアップグレードしなければならない協調的なルール変更で、指定ブロックで有効化される |

## FAQ

ZEC へのアクセスを失いましたか？ いいえ。約1日の間、シールドされた Orchard トランザクションは停止されましたが、資金が失われたり危険にさらされたりしたことはなく、transparent と Sapling のトランザクションは動作し続けました。

なぜ静かにパッチを当てず、停止したのですか？ 健全性バグは、Orchard プール内で資金が盗まれたり二重支払いされたりすることを許す可能性があったため、修正済み回路が有効化されるまで新しい Orchard トランザクションを停止するのが安全な対応でした。

古いシールド証明はまだ使えますか？ 古い回路の下で作られた証明は、NU6.2 の後ではもはや有効ではありません。対応リリース上のウォレットは自動的に修正済み回路を使用します。

このバグは実際に使われたのですか？ その証拠はありません。これはセキュリティ研究によって発見され、既知の被害が出る前に修正されました。

NU6.2 と Ironwood はどう違うのですか？ NU6.2 は回路を修正し、Orchard を再有効化しました。その後、[Ironwood (NU6.3)](../zcash-tech/ironwood) は新しいプールと公開ターンスタイルを追加し、旧プールの価値を監査して移動できるようにしました。

## 理解度チェック

なぜ Zcash は、修正を書いている間も動かし続けるのではなく、Orchard トランザクションを1日停止したのでしょうか？

<details>
<summary>答え</summary>

その欠陥が健全性バグだったからです。つまり、無効なトランザクションが有効なものとして通ってしまう可能性がありました。Orchard を開いたままにしておくことは、プール内での盗難や二重支払いへの扉を開けたままにすることを意味します。新しい Orchard トランザクションを停止することで、NU6.2 で修正済み回路が有効化されるまでその扉を閉じました。
</details>
