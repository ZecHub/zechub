# ZIP 218：25秒ブロックが実際に変えること

2026年9月14日に締め切られたNU7のコイン保有者投票では、約2,397,669 ZECがZIP 218に賛成票を投じ、141.6 ZECが反対票を投じ、99.9%の結果となりました。多くの報道はこれを「Zcashのブロックが速くなる」と要約しました。それは正しいものの、この提案が行うことの大半と、意図的に変えないままにすることの大半が抜け落ちています。

このページでは、ZIP 218をその本文に基づいて解説します。何が変わるのか、何が変わらないのか、そしてそのコストは何かを説明します。

## 要約

| | 現在 | ZIP 218後 |
|---|---|---|
| ブロック目標間隔 | 75秒 | 25秒 |
| 1日あたりのブロック数 | 1,152 | 3,456 |
| ブロック報酬（現在の半減期） | 1.5625 ZEC | 0.52083333 ZEC |
| 1日あたりの新規ZEC | 変わらない | 変わらない |
| 半減期の間隔 | 1,680,000ブロック | 5,040,000ブロック |
| ブロックあたりのシールドアクション上限 | なし（2 MBのサイズ上限のみ） | 合計330、プール別上限あり |
| Orchardのスループット（2アクション取引） | 毎秒約2.9件 | 毎秒約6.6件 |

ブロック数は3倍になり、各ブロックの報酬は3分の1になります。供給スケジュールは従来どおりです。

## なぜブロック時間を変えるのか

主な目的は**待ち時間の短縮**です。現在、ネットワーク負荷にかかわらず、支払いは最初の承認まで平均75秒待ちます。25秒では平均25秒に短縮されます。ZIPは、この影響を最も感じる用途として、店頭決済、取引所への入金、クロスチェーンブリッジを挙げています。

ZIPにある次の2点は覚えておく価値があります。

- **誰かに承認回数を減らすよう求めるものではありません。** 現在と同じロールバックリスク許容度を維持する利用者について、ZIPは承認時間が3倍よりわずかに小さい倍率で改善すると見込んでいます。
- **ファイナリティに関する取り組みの代替ではありません。** ZIPは、Crosslinkのようなファイナリティ機構を補完するものだと説明しています。より高速なベースレイヤーのブロックは、将来ファイナリティレイヤーが追加されるかどうかにかかわらず役立ちます。

ZIPは、スループットの向上だけであればブロックサイズを大きくすることでも達成できたと指摘しています。代わりに短いブロックを選ぶ理由はレイテンシです。

## 変わること

### 発行量：1日あたりのZECは同じ

ブロック数を3倍にすると、ほかに変更がなければ日次発行量も3倍になります。ZIP 218は、NU7が有効化された後、ブロックあたりの報酬をさらに3分の1にすることでこれを防ぎます。

現在の半減期では、ブロック報酬は**1.5625 ZECから0.52083333 ZEC**（52,083,333 zatoshi）になります。156,250,000 zatoshiは3で割り切れないため、各ブロックでは3分の1 zatoshi分が切り捨てられます。5,040,000ブロックの半減期全体では、合計で約0.0168 ZECです。

報酬とは、各ブロックで新たに作られるZECの総量です。既存の開発資金の取り分は引き続きそこから差し引かれるため、マイナーが受け取る額は現在と同じくこの全額より少なくなります。

> **0.26041666 ZECという数値について。** ドラフトZIPの説明注記では、NU7後の報酬をfloor(156250000 / 6) = 0.26041666 ZECと記載しており、一部の報道もこれを繰り返しています。この注記は2倍の誤りです。156,250,000 zatoshiはすでにBlossom後の報酬であるため、これを6で割ると、NU7の3倍係数に加えてBlossomの2倍係数を二重に適用することになります。規範的な式では、現在の半減期インデックスにおいてfloor(1,250,000,000 / (2 · 3 · 4)) = 52,083,333 zatoshiとなります。この変更に関するZebraの実装issue（[#11463](https://github.com/ZcashFoundation/zebra/issues/11463)）では、この注記がBlossom係数を二重計上していると記録され、実装者に「注記ではなく式を実装する」よう指示し、ZIPに対する修正が提出済みであると述べています。有効化時の正しい数値は**0.52083333 ZEC**です。

### 半減期のタイミングは維持される

半減期の間隔は1,680,000ブロックから5,040,000ブロックへ3倍になります。ブロックは3倍の頻度で到来するため、半減期は変更がなかった場合とほぼ同じ時点に到来します。総供給量の上限に影響はありません。

これはNU7投票における別の発行量に関する問い、すなわちコイン保有者が半減期を滑らかな曲線に置き換えるのではなく維持することに投票した件とは別です。ZIP 218は既存の半減期モデルと共存し、それを変更しません。

### ブロックあたりのシールドアクションに新たな上限

ZIP 218は、単一のブロックに収められるシールド活動量に上限を加えます。

| 上限 | ブロックあたりの最大値 |
|---|---|
| すべてのシールドプールの合計 | 330（各Sprout JoinSplitは2として数える） |
| Orchardアクション | 330 |
| Saplingの入力と出力の合計 | 300 |
| Sprout JoinSplit | 25 |

取引の透明部分は影響を受けず、2 MBのブロックサイズ上限も引き続き適用されます。

この上限が設けられるのは、ブロック数の増加がウォレットとノードの作業量増加につながるためです。上限を設けることで、ブロック数が3倍になっても最悪ケースは実際には**現在より改善**します。

- **ウォレット同期：** ライトウォレットが1日にダウンロードを強いられうるデータ量の最大値は、約271 MBから約169 MBへと、およそ38%減少します。最悪時の試行復号回数は、1日あたり約480万回から約230万回へ減少します。
- **ブロック検証：** ZIPのベンチマークでは、新しい上限下での最悪ケースのOrchardブロックは約432 msであり、現在の最悪ケースの約770 msと比べて短くなっています。Saplingでは減少幅がさらに大きく、約3,175 msから約272 msになります。

SaplingとSproutの上限は意図的に厳しく設定されています。2026年5月時点で、OrchardはシールドZECの87.9%を占め、Saplingは11.6%、Sproutは0.5%でした。そのため、小規模なプールには実際の利用に十分な余地を与えつつ、攻撃者が悪用できる余地を減らしています。ZIP 317の手数料はすべてのプールで論理アクションあたり同額を課すため、攻撃者があるプールを別のプールよりスパムすることで得られる利点はありません。

### スループット

ブロックあたり330のOrchardアクションでは、標準的な2アクションのOrchard取引は⌊330 / 2⌋ = 165回、1ブロックに収まります。25秒ごとに1ブロックなら、これは**毎秒約6.6件の取引**であり、現在の約2.9件から増加します。ZIPはこれを通常のOrchardスループットにおける2.3倍の増加と呼んでいます。Saplingは毎秒約3.0件となり、現在のOrchardが処理する量をなお上回ります。

### 難易度調整

難易度アルゴリズムは、直近ブロックのウィンドウを平均します。ZIP 218はこのウィンドウを17ブロックから102ブロックへ増やすため、実時間で約2,550秒、すなわちZcashが150秒ブロックで開始した際にカバーしていたのと同じ期間を維持します。ZIPは理由を2つ挙げています。難易度操作攻撃を容易にしないこと（Litecoinの2026年4月のMWEB事案を引用しています）と、短期的なブロック時間の変動を平滑化することです。

有効化直後は、ブロック時間が新しい目標値に落ち着くまでしばらくかかります。これは想定内であり、BlossomでZcashが150秒から75秒になったときに起きたことと同様です。

### ノードとウォレットのデフォルト設定

これらはコンセンサスルールではなく、実装に対する推奨事項です。

- **取引の有効期限：** デフォルトの有効期限は40ブロックから120ブロックへ増え、約50分というほぼ同じ時間を維持します。
- **最大reorg深度：** Zebraの上限は99ブロックから600ブロックへ増えます。25秒では約4.2時間であり、開始時にカバーしていたのと同じ期間です。
- **シールド取引のアンカー深度：** 3ブロックのままであるため、遅延は3.75分から1.25分に短縮されます。ZIPはここでBlossomの先例に従っています。
- **いくつかのネットワーク定数**はブロック単位で測定されるため、同じ時間をカバーするよう3倍に拡大されます。

## 変わらないこと

- 1日あたりに発行されるZEC、半減期スケジュール、供給量上限
- 2 MBのブロックサイズ上限
- 新しいアクション上限の影響を受けない透明取引
- 100ブロックでのCoinbase成熟。これはブロック数であって時間ではないため、現在の約125分ではなく約42分を意味する点に注意してください。

## トレードオフ：ステールブロックの増加

より高速なブロックにはコストがかかります。ステールブロックとは、別のブロックが先にネットワークへ到達したため、チェーンに含まれる競争に敗れた有効なブロックです。ブロック間隔が短いほどこれが頻繁に起き、ZIPはステール率をブロック伝播、検証時間、マイニングの中央集権化リスクと結び付けています。

- **現在：** 約0.4%。ZIPは、ハッシュパワーがプールに集中しているため、これが実際の率を過小評価している可能性があると指摘しています。
- **25秒における理論値：** 測定されたZcashの伝播遅延に基づき、約3.26%です。
- **Devnetテスト：** 地理的に分散した99のZebraノードが、25秒間隔で完全な2 MBブロックを生成した結果、4.86%のステール率と0.37%のフォーク率が測定されました。必要だった調整はTCP設定のみでした。このdevnetは今日のメインネットより分散化されていたため、ZIPはこれらを最悪ケースに近い数値と見なしています。
- **基準点：** ZIPは、Ethereumの歴史的なプルーフ・オブ・ワークにおける5.4%のステール率を安全性の閾値として用いています。どちらのdevnet指標もこれを下回っています。

さらに小さなコストが2つあります。ライトウォレットはコンパクトブロックヘッダーについて、1日あたり約200 KB多くダウンロードします。また、ブロック数が3倍になるため、オフラインだったフルノードは追いつく際により多くのブロックを処理することになります。各ブロックの検証コストは低くなっているにもかかわらずです。ZIPは両方を受け入れています。

## ステータスとタイムライン

- **ZIPのステータス：** Draft。オーナーはDev OjhaとEvan Forbes。2026年3月13日作成。
- **コイン保有者投票：** 2026年9月14日に締め切られ、99.9%の支持を得ました。この投票は選好を示すものであり、それ自体でコンセンサスルールを変更するものではありません。
- **タイムライン：** 9月17日のZcash Community Forumでの発表において、開発組織は、9月30日までにコード完成、10月6日にテストネットでNU7、10月20日に最終決定およびメインネット有効化高度の決定、そして2026年11月5日頃を目標としたメインネット有効化というスケジュールに合意しました。高度が設定されるまでは、11月5日は固定日ではなく目標です。
- **実装：** Zebra（[#11440](https://github.com/ZcashFoundation/zebra/issues/11440)）およびZakura（[PR #1066](https://github.com/zakura-core/zakura/pull/1066)）で追跡されています。

## これがあなたに意味すること

- **ZECを保有している場合：** 何もする必要はありません。残高と供給スケジュールに影響はありません。
- **ウォレットを使う場合：** ウォレットがNU7対応を提供したら更新してください。最初の承認は約3倍早く到着します。
- **ノード、取引所、またはサービスを運用する場合：** 有効化前にアップグレードする計画を立て、ブロック単位で測定される設定を見直してください。固定ブロック数がカバーする時間は、以前の3分の1になります。
