## 1. なぜ気にするべきなのでしょうか？

学んだ各要素は、それぞれ単体でも巧妙です。しかし、Zcashの*魔法*は、それらがどのようにかみ合うかにあります。ヌリファイアだけではプライバシーを提供できません。コミットメントだけでは偽造を防げません。プルーフだけでは有用なことを何も証明できません。5つの構成要素を、プライベートでありながら信頼できるお金へと変えるのは、この**組み立て**なのです。

この記事がその組み立てです。最後には、「ネットワークは見えないトランザクションを検証する」という文は、パラドックスではなく、すでに理解している要素から導かれる明白な結果に感じられるでしょう。

## 3. 鍵はどこから来るのでしょうか

ユーザーができることはすべて、単一の秘密である**支出鍵（spending key）**から、一方向の階層を通じて生じます（各矢印は、記事2と3で扱ったトラップドアにより不可逆な導出です）。

![alt text](/content-images/image-32-f443f9bb72.webp)

以前の記事から導かれる、注目すべき点が2つあります。

- この分割により、支出する権限を与えずにトランザクションを公開する**ビューイングキー（viewing key）**を、たとえば監査人に渡せます。プライバシーは全か無かではなく、選択的です。
- 各導出は**一方向**です。ビューイングキーを持っていても、支出鍵を復元することは決してできません。これは記事2の楕円曲線トラップドアが役割を果たしているのです。

## 4. ノートの支出：4つの主張

ノートをプライベートに支出するには、**ノート、その価値、その位置、またはあなたの身元を明かさずに**、同時に4つのことをネットワークに納得させる必要があります。各主張は、すでに知っている構成要素によって満たされます。

![alt text](/content-images/image-31-86309af194.webp)

プルーフは、基礎となる事実（どのノートか、誰の鍵か、どの価値か）を**一切**明かしません。明かすのは、*4つの主張すべてが成立する*ということだけです。これがシールドされたZcashの仕組みのすべてであり、1つの図に示されています。

## 5. 価値残高の仕組み（温存してきた成果）

記事2と3では、Pedersenコミットメントが**加算できる**こと、すなわち`v_1`へのコミットメントと`v_2`へのコミットメントを足すと`v_1 + v_2`へのコミットメントになることに触れました。ここでその利点が発揮されます。

すべての入力ノートと出力ノートには**価値コミットメント（value commitment）**、すなわちその金額`v`を隠すPedersenコミットメント`v.G + r.H`があります。これらは加算できるため、ネットワークは次を計算できます。

```
(sum of input value commitments) − (sum of output value commitments)
```

トランザクションが均衡している場合（お金が生成も破棄もされない場合）、`v`の部分は正確に相殺され、残るのは余ったランダム性によってブラインドされた**ゼロの価値**へのコミットメントだけです。送信者は、**バインディング署名（binding signature）**と呼ばれる小さな署名を生成することで、その余ったランダム性を知っていることを示します。有効なバインディング署名は、価値が本当に均衡している場合にのみ可能であり、**しかも金額は1つも明かされません。**

> これは、なぜ準同型の曲線ベースのコミットメントが必要だったのかを示す、シリーズ全体で最も明快な例です。「入金額＝出金額」というルールは、**封印された封筒を足し合わせ**、結果がゼロに封印されることを確認することで強制されます。

## 6. 最初から最後まで見届ける完全なトランザクション

AliceがBobに支払う場面を組み立ててみましょう。教育モデルとして、Saplingの明快な「支出側／出力側」の構造を使います。

**シールドされたトランザクションは、2種類の記述をまとめたものです。**

| 支出記述（ノートを消費します） | 出力記述（ノートを作成します） |
|---|---|
| 入力の価値コミットメント | 出力の価値コミットメント |
| 証明の対象となる**アンカー（anchor）**（ツリーのルート） | 新しい**ノートコミットメント**（新しいリーフ） |
| 支出されたノートの**ヌリファイア** | 暗号化のための**エフェメラルキー** |
| 再ランダム化された公開鍵＋支出認可署名 | **暗号化されたノート**（受取人向けの暗号文） |
| 4つの主張を証明する**zk-SNARK** | 出力が適切に形成されていることを証明する**zk-SNARK** |

これに加え、バンドル全体に対する1つの**バインディング署名**があり、価値残高を強制します（セクション5）。

![alt text](/content-images/image-30-98511eb2d0.webp)

プライバシーをたどってみてください。ネットワークはアンカーを確認し、ヌリファイアが未使用であることを確認し、プルーフを検証し、残高を検証しました。ネットワークは、**金額も、アドレスも、どのノートが支出されたかも知らないまま**有効な支払いを受け入れました。一方で、支出済みノートの**ヌリファイア**（その死）とBobの新しい**コミットメント**（彼のノートの誕生）は、可視的なリンクなしに2つの異なる公開構造に存在しています。これは記事0で切り離されたリンクです。

## 7. 記事0からのすべてのループを閉じる

記事0では意図的に疑問を残しました。ここですべてを閉じます。

| 記事0で開いたループ | 閉じるもの |
|---|---|
| 封印されつつ偽造不可能な封筒は、どのように可能なのでしょうか？ | コミットメント：ランダム性による隠蔽性、衝突耐性／曲線トラップドアによる拘束性（記事3） |
| 鍵と秘密のレシピはどこから来るのでしょうか？ | 体の算術と楕円曲線スカラー乗算（記事1、2） |
| 「掲示板」とは正確には何でしょうか？ | ノートコミットメントのインクリメンタル・マークルツリーです。そのルートがアンカーです（記事4） |
| 虚無トークンが封筒とリンクできないのはなぜでしょうか？ | ヌリファイアは、コミットメントとは別の集合に保持される鍵付きハッシュです（記事2、3、4） |
| 何も明かさずに有効性を証明するにはどうすればよいのでしょうか？ | 4つの主張すべてをエンコードした算術回路上のzk-SNARKです（記事5） |
| 受取人は支払いを受けたことをどのように知るのでしょうか？ | ノートはそのアドレス向けに暗号化されます。受取人はビューイングキーで試行復号します（この記事） |
| 「入金額＝出金額」はどのようにプライベートに強制されるのでしょうか？ | 準同型価値コミットメント＋バインディング署名（セクション5） |

1ページ目のパラドックス、*見えないものを検証する*は、これで完全に解消されました。ネットワークが検証するのは、データそのものではなく、**隠されたデータについての主張**です。

## 8. SaplingとOrchardを一息で比較する

分割が最も明快であるため、Saplingの構造を用いて説明しました。現在の設計である**Orchard**は、これらの考え方を置き換えるのではなく洗練しています。

| | **Sapling** | **Orchard** |
|---|---|---|
| トランザクション単位 | 個別の**Spend**と**Output**の記述 | 統合された**Actions**（それぞれ1つの支出＋1つの出力を行います） |
| プルーフシステム | **Groth16**（トラステッドセットアップ） | **Halo 2**（トラステッドセットアップなし） |
| 曲線 | BLS12-381＋Jubjub | Pallas／Vesta（Pasta） |
| コミットメントハッシュ | Pedersen | Sinsemilla |

この記事のすべての概念は直接引き継がれます。Orchardは主に支出と出力をまとめ、儀式を必要としないプルーフシステムに置き換えています。5つの柱は変わりません。

## 9. 正直な注記

これはシリーズで最も完全な全体像ですが、依然としてモデルです。ノートの正確な体エンコーディング、厳密な鍵導出式、支出鍵の再ランダム化、多様化アドレス、メモフィールド、手数料処理、価値コミットメントとノートコミットメントの詳細な違い、そして各署名の正確な役割を圧縮しました。また、1つの標準的なフローを提示しましたが、実際のトランザクションは一度に多数の支出と出力を含むことができ、公開型部分とシールドされた部分を混在させる場合もあります。権威ある情報源はZcashプロトコル仕様です。ここで得たのは正しい形であり、仕様がすべての寸法を補います。

## 10. まとめ

- シールドされたトランザクションは、**ノート**（価値）、**ノートコミットメントツリー**内のその**コミットメント**、二重支出を防ぐ**ヌリファイア**、残高のための**価値コミットメント**、そしてそれらすべてを結びつける**zk-SNARK**という5つの構成要素を連動させます。
- 支出では、ノートが存在すること、自分に認可があること、そのヌリファイアが正しいこと、価値が均衡することという**4つの主張を同時に**、基礎となる事実を一切明かさずに**ゼロ知識**で証明します。
- **価値残高**は、**準同型コミットメントを加算**し、**バインディング署名**を通じてゼロに封印されることを確認することで、金額を開示せずに強制されます。
- ユーザーの権限は1つの**支出鍵**から**一方向の階層**を通じて流れ、支出権限を与えずに公開する**ビューイングキー**を可能にします。
- ネットワークは**隠されたデータについての主張を検証**するため、記事0の検証対プライバシーのパラドックスを解消します。そこで開いたすべてのループは、これで閉じられました。
- **Orchard**は、5つの柱を変えることなく、**Sapling**を洗練します（統合されたActions、トラステッドセットアップのないHalo 2、Pasta曲線、Sinsemilla）。

## 用語集

| 用語 | 平易な英語での意味 |
|---|---|
| **Spending key** | ユーザーのすべての鍵が導出される、唯一のルート秘密鍵 |
| **Viewing Key** | 保持者に支出を許可せずに、あなたのトランザクションを公開します |
| **Spend description** | ノートを消費するtxの部分です（ヌリファイア、アンカー、プルーフ） |
| **Output description** | ノートを作成するtxの部分です（コミットメント、暗号文、プルーフ） |
| **Action (Orchard)** | 1つの支出と1つの出力をまとめて行う統合単位です |
| **Value commitment** | 金額に対する準同型Pedersenコミットメントです |
| **Binding signature** | 価値を明かさずに均衡していることを証明する署名です |
| **Anchor** | 支出が所属を証明する対象となるツリーのルートです |
| **Trial decryption** | 受取人が新しいコミットメントをテストし、自分宛てのノートを見つけることです |

## FAQ

**ネットワークが金額や、誰が誰に支払ったかを見ることはありますか？**  
いいえ。ネットワークはプルーフ、ヌリファイアの未使用性、アンカー、バインディング署名を検証します。すべてのプライベートな価値は隠されたままです。

**ノートを2回支出することを防ぐものは何ですか？**  
ヌリファイアです。支出時に公開され、ネットワークはヌリファイア集合にすでに存在するあらゆるヌリファイアを拒否します。同じノートは常に同じヌリファイアを生成します。

**金額が隠されているのに、どのように残高を確認できるのでしょうか？**  
価値コミットメントは準同型的に加算されます。均衡したトランザクションのコミットメントはゼロへのコミットメントに相殺され、それをバインディング署名が証明します。

**制御を手放さずに、監査人へ自分のトランザクションを証明できますか？**  
はい。ビューイングキーを渡してください。これはシールドされた活動を公開しますが、一方向の鍵階層により支出を認可することはできません。

**Saplingは、Orchardが存在する現在では時代遅れですか？**  
どちらもネットワーク上に存在してきました。Orchardが現在の設計です。概念は共有されているため、一方を理解すればもう一方も理解できます。

<details><summary>答え</summary>

金額は隠されていますが、それぞれは準同型価値コミットメントで包まれており、ネットワークはすべての入力コミットメントを加算し、すべての出力コミットメントを減算します。隠された価値が均衡していなければ、結果はゼロに封印されず、**有効なバインディング署名を生成することはできません。** 泥棒は*どれだけ*かを隠せても、不均衡な価値を残高チェックに通すことはできないため、何も明かさずに無料のお金を作ろうとしても、算術によって捕捉されます。
