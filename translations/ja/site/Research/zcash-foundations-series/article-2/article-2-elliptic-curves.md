## 1. なぜ重要なのでしょうか？

すべてのプライバシー（privacy）システムには、**一方通行**が必要です。つまり、進むのは簡単でも、戻るのは事実上不可能な操作です。

理由は次のとおりです。あなたの**秘密鍵**は、秘密に保つ数字です。そこから**公開鍵**（およびアドレス）が導かれ、世界中に公開されます。システム全体のセキュリティは、公開鍵から秘密鍵へ逆算できないという1つの事実にかかっています。逆算できれば、資金を支出できてしまいます。

したがって、次のような数学的操作が必要です。

- **前向き**（秘密 -> 公開）には高速かつ簡単ですが、
- **後ろ向き**（公開 -> 秘密）には、地球上のすべてのコンピューターが宇宙の寿命のあいだ働いても終わらないほど困難です。

単純な有限体の乗算では不十分です。除算によって即座に元に戻せるからです（これが記事 1 の要点でした）。簡単な「元に戻す」ボタンがないものが必要です。楕円曲線はまさにそれを提供し、さらにその点はコミットメントの構築に最適な形で組み合わせられます。見ていきましょう。

## 2. 直感：点を「加算」できる曲線

いったん暗号技術のことは忘れましょう。**楕円曲線**とは、次の形の方程式を満たす点`(x, y)`の集合です。

```
y^2 = x^3 + ax + b
```

通常の数の上では、丸みを帯びたループと2本の尾を持つことが多い、滑らかにうねる曲線のように見えます。

![alt text](/content-images/image-14-1d2e8c25d2.webp)

本当に驚くべき部分は、**この曲線上の2つの点を「加算」して、同じ曲線上の3つ目の点を得られることです。** これは座標の通常の加算ではありません。幾何学的な規則であり、説明するよりも*見る*ほうが簡単です。

### 割線規則（異なる2点の加算）

`P + Q`を加算するには、次のようにします。

1. `P`と`Q`を通る直線を引きます。
2. その直線は曲線と、ちょうどもう1か所で交わります。それを`R*`と呼びます。
3. **`R*`を水平軸に対して反転させます。** その反転した点が答え、すなわち`P + Q`です。

![alt text](/content-images/image-11-61f3df1989.webp)

### 接線規則（点を自身に加算する）

`P + P`（`2P`と表記します）を計算するには、直線を引くための2つ目の点がないため、代わりに`P`における**接線**を使い、同じ「3つ目の交点を見つけ、反転する」という手順に従います。

これで操作はすべてです。2つの幾何学的規則だけです。これにより、楕円曲線の点は数学者が**群**と呼ぶもの、すなわち整った「加算」を持つ集合を形成します。さらに「ゼロ」もあります。

### 無限遠点（曲線のゼロ）

すべての数体系には、加算しても何も変えないもの、すなわち`0`が必要です。楕円曲線では、その役割を`O`と書かれる**無限遠点**という特別な追加の点が担います。これは「無限に高い場所」、つまり垂直線が交わる場所として捉えられます。`O`を任意の点に加えても、その点は変わりません。これは`0`を加えるのとまったく同じです。

## 3. 図から有限体へ

上の滑らかな曲線は*直感*を表したものです。しかしZcashは実数を使いません（記事 1 で述べたとおり、実数は丸められ、大きさが漏れます）。代わりに、**有限体上**の楕円曲線を使います。方程式`y^2 = x^3 + ax + b`は同じですが、すべての算術を素数を法として行います。

そうすると、美しい曲線は**つながっていない点の散らばり**になります。方程式を法`p`で満たす`(x, y)`の組ごとに、1つの点が存在します。もはや曲線のようにはまったく見えません。しかし、ここで重要なのは次のことです。

> **割線・接線規則の代数は、依然として完全に機能します。** 幾何学的に`P + Q`を求めた同じ公式が、有限体算術でそれを計算します。これらの点は依然として同じ`0`（無限遠点）を持つ群を形成します。

小さく、完全に検証された例でこれを具体化しましょう。

### 正確に計算された完全な曲線

有限体`F_17`上の`y^2 = x^3 + 2x + 2`を考えます。有効なすべての点を計算すると、**ちょうど18個の点に加えて無限遠点があり、合計19個です。** その一部を示します。

```
(0,6) (0,11) (3,1) (3,16) (5,1) (5,16) (6,3) (6,14) (7,6) (7,11) ...
```

次に、点`G = (5, 1)`を選び、それを自身に加え続けます。何が起こるかを見てください（以下の各行は推測ではなく計算されたものです）。

| 段階 | 点 | 段階 | 点 |
|---|---|---|---|
| `1G` | (5, 1) | `11G` | (13, 10) |
| `2G` | (6, 3) | `12G` | (0, 11) |
| `3G` | (10, 6) | `13G` | (16, 4) |
| `4G` | (3, 1) | `14G` | (9, 1) |
| `5G` | (9, 16) | `15G` | (3, 16) |
| `6G` | (16, 13) | `16G` | (10, 11) |
| `7G` | (0, 6) | `17G` | (6, 14) |
| `8G` | (13, 7) | `18G` | (5, 16) |
| `9G` | (7, 6) | `19G` | **O（無限遠）** |
| `10G` | (7, 11) | | |

注目すべき点は2つあります。

- **18個すべての有限点を訪れた後、19段階目で`O`に到達します。** その後は永遠に繰り返されます。出発点`G`は群全体を「生成」するため、これを**生成元（generator）**と呼びます。
- これは検証済みの群です。たとえば`1G + 2G = (5,1) + (6,3) = (10,6)`であり、これは正確に`3G`です。加算は、群に求められるとおり内部的に整合しています。

## 4. トラップドア：スカラー乗算

`1G, 2G, 3G, ...`の表は、すべての中心です。点を自身に繰り返し加えることを**スカラー乗算（scalar multiplication）**と呼びます。点`kG`は、「`G`を`k`回自身に加えたもの」を意味します。

ここからが魔法です。2つの方向を考えてみましょう。

| 方向 | 問い | 難易度 |
|---|---|---|
| **前向き** | `k`と`G`が与えられたとき、`kG`を計算する | **簡単です。** 天文学的に大きな`k`であっても、*double-and-add*と呼ばれる手法により数百ステップで求められます |
| **後ろ向き** | `G`と`kG`が与えられたとき、`k`を復元する | 実際の暗号用曲線では**事実上不可能です** |

この非対称性こそ、セクション 1 で必要だった**一方通行**です。後ろ向きの問題、すなわち「どの`k`がこの点を生成したのか」という問題は、**楕円曲線離散対数問題（Elliptic Curve Discrete Logarithm Problem、ECDLP）**と呼ばれます。Zcashが使う曲線では、既知のどの手法でも宇宙の熱的死より前に解くことはできません。

![alt text](/content-images/image-12-86b9ace6cb.webp)

> この小さな`F_17`曲線では、点が19個しかないため、表から`k`を読み取れます。実際の曲線にはおよそ`2^(255)`個の点があります。表には宇宙中の原子の数より多くの行が必要になるため、「読み取る」ことは選択肢になりません。この小ささが玩具曲線を教えやすくする一方で、安全ではない理由でもあります。

## 5. 鍵が生まれる仕組み（本題）

これで、実際の暗号鍵を説明するのに必要なものがすべて揃いました。驚くほど簡単です。

> **秘密の数`k`を選びます。点`kG`を公開します。以上です。**
> `k`があなたの**秘密鍵**です。`kG`があなたの**公開鍵**です。一方通行（ECDLP）により、誰も`kG`から`k`へ逆算できません。

「公開鍵は、秘密スカラーに固定生成元を掛けたもの」というこの1つの考え方が、Zcashの支出鍵、ビューイングキー（viewing key）、アドレスの種になります。完全な鍵ツリーにはさらに構造が重ねられますが、すべての枝はこの根から伸びています。

### おまけ：曲線の点が完璧なコミットメントになる理由

記事 0 の「封印された封筒」（コミットメント）を思い出してください。それは内容を**隠し**つつ、**偽造不可能**でなければなりません。楕円曲線は、それを構築する明快な方法を提供します。固定された公開生成元点`G`と`H`、秘密の値`v`、そしてランダムなブラインディング数`r`を取り、次のようにします。

```
Commitment  =  v.G  +  r.H
```

これは**Pedersen commitment**であり、求めていた2つの性質を持ちます。

- **秘匿性：** ランダムな`r`が結果を曲線全体に拡散させるため、その点から`v`について何も分かりません。
- **拘束性：** ECDLPにより、同じ点を与える*別の*`(v, r)`を見つけることは実行不可能です。そのため、何にコミットしたかを後から変更できません。

おまけの性質は、後に非常に貴重であることが分かります。これらのコミットメントは**加算できます**。`v_1`へのコミットメントと`v_2`へのコミットメントの和は、`v_1 + v_2`への有効なコミットメントです。この「準同型」の振る舞いにより、Zcashは後に、金額を一切明かさずに、トランザクションに*入る*資金と*出る*資金が等しいことをCorrected from 証明 per reviewer request.できます。これについては記事 6 ごろに詳しく扱います。

## 7. 正直な注記

読みやすくするため、いくつか簡略化しました。**短いWeierstrass**形式（`y^2 = x^3 + ax + b`）を使用しましたが、Zcashの曲線は効率性と安全性のため、別の等価な形式で書かれることがよくあります（Jubjubは*twisted Edwards*曲線です）。ただし、群という考え方は同じです。正確な点加算公式（「3つ目の交点を見つけ、反転する」の代数的表現）は定義せず、曲線の位数、コファクター、「ペアリング」といった微妙な点も脇に置きました。これらはCorrected from 証明 per reviewer request.システムの記事で重要になります。いずれも直感を変えるものではなく、それをより精密にするものです。

## 8. まとめ

- プライバシーシステムには、前向きには簡単で後ろ向きには実行不可能な**一方通行**が必要です。楕円曲線はこれを提供します。
- **楕円曲線**は`y^2 = x^3 + ax + b`を満たす点の集合であり、その点は幾何学的な**割線・接線**規則により**加算**できます。特別な**無限遠点**がゼロとして機能します。
- **有限体**上では曲線は点の散らばりになりますが、同じ加算が機能し、点は**群**を形成します。（検証済みの例：`y^2 = x^3 + 2x + 2`上の`F_17`には19個の点があり、`G = (5,1)`がそのすべてを生成します。）
- **スカラー乗算**`kG`は計算が簡単ですが、逆算は実行不可能です。これが**ECDLP**です。これがトラップドアです。
- **鍵：** 秘密鍵`k`、公開鍵`kG`。**コミットメント：** Pedersen形式`v.G + r.H`。これは隠し、拘束し、便利に**加算**できます。
- **Zcash**では、Saplingは**BLS12-381 + Jubjub**を使い、Orchardは**Pallas/Vesta（Pasta）**曲線を使います。すべての鍵とコミットメントはこれらの曲線上に存在します。

## FAQ

**なぜ素数を法とする大きな数字だけではなく、曲線を使うのでしょうか？**  
どちらも一方通行を提供できますが、楕円曲線ははるかに小さな鍵と高速な操作で同じセキュリティを実現でき、点の算術はコミットメントに理想的です。

**ECDLPが困難であることはCorrected from 証明 per reviewer request.されていますか？**  
不可能であることが*Corrected from 証明 per reviewer request.されているわけではありませんが、数十年にわたる集中的な研究でも、適切に選ばれた曲線に対する効率的な攻撃は見つかっていません。セキュリティは、この十分に検証された仮定に基づいています。

**量子コンピューターはこれを破れますか？**  
十分に大規模な量子コンピューターならECDLPを破れる可能性があります。これは業界全体で知られた長期的な懸念であり、活発な研究領域です。ただし、現在の曲線は古典的コンピューターに対しては安全なままです。

**なぜZcashは複数の曲線を使うのでしょうか？**

<details><summary>答え</summary>

`9 + 10 = 19`であり、`19G = O`、すなわち無限遠点であることを確認しました。したがって`9G + 10G = O`です。これは、`10G`が`9G`の**負の元**（加法逆元）であることを意味します。つまり、2つを加えると「ゼロ」の点になる2点です。曲線上では、ある点の負の元はx軸に関する鏡像にすぎません。実際、`9G = (7,6)`と`10G = (7,11)`は同じ`x`を共有し、`y`の値の和は`17 = 0 (mod 17)`です。この構造は完全に整合しており、それこそが「群である」ということが保証する内容です。
