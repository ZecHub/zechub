# <img src="/content-images/icons8-lock-2f8e221321.svg" width="24" height="24" alt="lock icon"/> Zcashでサインイン

<span className="inline-flex items-center gap-[6px]"><span className="inline-block w-[12px] h-[12px] bg-green-500 rounded-full"></span>中級 - 7分</span>

## 要点

- パスワードを使う代わりに、Zcashアドレスを自分が管理していることを証明してログインします
- 現在使われている設計は2つあります。**チャレンジに署名する**方法、または**メモにコードを入れたシールド支払いを送る**方法です
- シールドアドレスは残高と履歴を隠すため、管理を証明してもあなたの資産状況は公開されません
- このパターンはまだ初期段階です。承認済みの標準はまだなく、実装同士の相互運用性もありません

<br/>

## <img src="/content-images/user-svgrepo-com-21adf62b7c.svg" width="24" height="24" className="inline-block align-middle mr-1 p-[2px]" alt="user icon"/> これは誰向け？

- 個人データを集めずにパスワードレスログインを実現したい開発者
- どのサイトにもメールアドレスを渡したくないユーザー
- 金融履歴をアカウントに結び付けずにログインしたい人

<br/>

## <img src="/content-images/warning-error-svgrepo-com-b7ea8a50da.svg" width="24" height="24" className="inline-block align-middle mr-1 p-[2px]" alt="warning icon"/> 問題点

ほとんどのログイン手段は何かを漏らします。

- **パスワードとメールアドレス**は、あなたの身元に結び付いたアカウントを作り、しかもその両方が漏えいデータの山に含まれることになります
- **ソーシャルサインイン**は、どこにいつログインしたかを本人確認プロバイダーにすべて知らせてしまいます
- **透明なチェーンでのウォレットサインイン**は見た目以上に悪いものです。ウォレットを接続すると、サイトにあなたの残高全体と取引履歴を永久に渡してしまうことがあります

たいていの場合、利便性と情報開示のどちらかを選ばされます。

<br/>

## <img src="/content-images/celebration-spark-svgrepo-com-bc98dec7c1.svg" width="24" height="24" className="inline-block align-middle mr-1 p-[2px]" alt="spark icon"/> なぜZcashなのか？

Zcashは、*管理の証明*と*資産情報の開示*を切り分けます。

- **シールドアドレス**は残高と取引履歴を非公開に保つため、それを保有していると証明しても、何をどれだけ持っているかは分かりません
- **暗号化されたメモ**は、1回限りのログインコードをトランザクション内で非公開のまま運べます
- **Viewing keys**は選択的開示を可能にするため、アプリには必要なものだけを読み取れる権限を与え、それ以上は何も渡さずに済みます

<br/>

## <img src="/content-images/ladder-svgrepo-com-7232bf46ed.svg" width="24" height="24" className="inline-block align-middle mr-1 p-[2px]" alt="step icon"/> 仕組み

2つのアプローチが登場しています。どちらも最終的には、アプリがあなたの安定した識別子を保持し、パスワードは不要になります。

### アプローチ1: チャレンジに署名する

1. アプリがランダムな単回使用のチャレンジを生成します
2. あなたのウォレットが、そのアドレスの背後にある鍵でそのチャレンジに署名します
3. アプリが署名を検証してログインさせます

これは何もブロードキャストしないため、手数料もかからず、ブロックを待つ必要もありません。関連する仕様は[ZIP 304, Sapling Address Signatures](https://zips.z.cash/zip-0304)ですが、これはまだドラフトのため、メッセージ署名に対するウォレットの対応状況はさまざまです。

### アプローチ2: シールド支払いで証明する

1. アプリが1回限りのコードを生成し、支払いリクエストを表示します
2. あなたがそのコードをメモに入れて少額のシールドトランザクションを送信します
3. アプリがメモを監視し、コードを照合してログインさせます

これは、すでに現在メモをサポートしているウォレットで使えます。該当するウォレットは大半です。トレードオフとして、ネットワーク手数料がかかり、承認待ちが発生します。

### アドレスを非公開に保つ

アプリは、あなたを認識するために必ずしもあなたのアドレスを保存する必要はありません。実装によっては、アドレスをアプリ固有の値と組み合わせてハッシュ化し、同じユーザーに対してサイトごとに異なる安定した識別子を見せるようにしています。これにより、サイト同士が情報を突き合わせてアカウントを結び付けるのを防げます。

<br/>

## <img src="/content-images/icons8-toolbox-9bebbb1619.svg" width="24" height="24" className="inline-block align-middle mr-1 p-[2px]" alt="toolbox icon"/> トレードオフ

これを構築の土台にしたり、依存したりする前に理解しておく価値があります。

| | 署名付きチャレンジ | シールド支払い |
|---|---|---|
| コスト | 無料 | ログインごとにネットワーク手数料 |
| 速度 | 即時 | 承認待ち |
| ウォレット対応 | 限定的、ZIP 304はドラフト | 広い、メモがあればよい |
| チェーン上の記録が残るか | いいえ | はい、トランザクションが存在します |

共通の制約:

- **デフォルトではアカウント回復がありません。** アプリ側で回復手段を設計していない限り、鍵を失うことはアカウントを失うことを意味します
- **アドレスの使い回しはあなたを結び付けます。** 多数のサイトで同じアドレスを使うと追跡の問題が再現されるため、アプリ固有の識別子が重要になります
- **承認済みの標準がありません。** 各プロジェクトが独自方式を持っているため、あるもの向けに作られたログインは別のものでは動きません
- **それ自体で匿名性になるわけではありません。** アプリに対してあなたの資産情報は隠せますが、いったん中に入ればアプリはあなたの行動を依然としてプロファイリングできます

<br/>

## <img src="/content-images/icons8-cancel-7f786be3c1.svg" width="24" height="24" className="inline-block align-middle mr-1 p-[2px]" alt="cancel icon"/> 避けるべきよくある間違い

- チャレンジコードを再利用すること。すべてのコードは単回使用で、すぐに期限切れにすべきです。そうしないと、取得されたコードがリプレイされる可能性があります
- ログインのために意味のある金額を送るようユーザーに求めること。支払いは証明であるため、金額はごくわずかであるべきです
- アプリ固有の識別子で同じ役割を果たせるのに、生のアドレスを保存すること
- メッセージ署名がどこでも動くと思い込むこと。実際にユーザーが持っているウォレットを確認してください
- 後からメモを秘密情報として扱うこと。メモは送信者が行動した証明にはなりますが、パスワードではありません

## <img src="/content-images/checked-checkbox-svgrepo-com-7ea19022da.svg" width="28" height="28" className="inline-block align-middle mr-1 p-[2px]" alt="done icon"/> これを探っているプロジェクト

これらは[ZecHub Hackathon 3.0](https://zechub.wiki/hackathon)の**Zcash Login**トラック向けに作られたものです。完成品というより実験であり、同じアイデアでも実装方法が大きく異なることを示しています。

- **ZecAuth** - Zcash向けのウォレット接続プロトコルで、他の場所でWalletConnectが果たしている役割に近いものです。アプリは、サインイン、支払いリクエスト、または閲覧アクセスなど、要求している権限とチャレンジを含むQRコードまたは`zecauth://`リンクを表示します。トランザクション不要、手数料不要、チェーンとのやり取りも不要です。コードと並行して、書面化されたプロトコル仕様も提供されています
- **ZShield** - シールドアドレスをW3C DIDとOpenID Connectアイデンティティに変換します。ブラウザーが鍵ペアを生成し、サーバーがZIP 304風のインターフェース経由でnonceを発行し、ウォレットがそれに署名し、サーバーがJWTを返します。結果はOIDC互換であるため、既存のアプリは専用統合なしで利用できます
- **ZecPass** - 署名付きメモによって所有権を証明し、しかもアプリがユーザーのアドレスをまったく知ることがないように設計されています。安定した識別子として使うためのアプリスコープのハッシュを導出し、チャレンジを単回使用かつ時間制限付きに保ち、React用のドロップインボタンとNode用の検証ライブラリを提供しています
- **Portal** - メモに1回限りのコードを入れたシールドトランザクションを送ることでログインし、mainnet上で動作しています。同じフローは、有料コンテンツのロック解除や、リンクから送金・受金することにも再利用されています
- **ZcashMe** - 本人性の証明としてシールド支払いを使い、ノートPCからモバイルへのギャップに焦点を当てています。これにより、ノートPCでのサインインにブラウザー拡張機能が不要になります
- **ZBooks** - Zcashでのサインインを製品そのものではなく再利用可能な認証プリミティブとして扱う会計・支払いツールで、Unified Full Viewing Keyを通じてトレジャリーデータを読み取ります
