# Zcash ウォレットのトラフィックをNym Mixnet経由でルーティングする

> 最終確認日：2026年9月29日

Zcash のシールド化トランザクションはオンチェーン上のトランザクションデータを保護しますが、ウォレットは依然としてインターネット経由で通信します。ネットワークの監視者は、IPアドレス、ウォレットが接続する時刻、接続先のインフラといったメタデータを把握できる可能性があります。

Nymは、独立したネットワークプライバシー層を追加します。2026年9月時点では、最適な方法はウォレットによって異なります。

1. **利用可能な場合は、ウォレットのネイティブNym統合を優先してください。**
2. それ以外の場合は、**システムレベルの NymVPN Mixnetモード**を使用し、ウォレット固有のプロキシ対応に依存せず、ウォレットのネットワークトラフィックをNym経由でルーティングしてください。

一般的なVPNおよびdVPNの背景については、[VPN & dVPN](./VPN_and_DVPN.md) を参照してください。

## Nymが追加するもの、追加しないもの

シールド化された Zcash の支払いとネットワークプライバシーツールは、異なる問題を解決します。

- **Zcash のシールド化プール**は、オンチェーンのトランザクション詳細を保護します。
- **Nym mixnetルーティング**は、実際のネットワークIDとウォレットトラフィックを受信するサービスとの間の関連付け可能性を低減するよう設計されています。
- システムレベルの NymVPN トンネルを通じて接続された宛先には、自宅またはモバイル回線のIPではなく、Nymの出口が見えるはずです。

Nymのmixnetは、複数ホップ、パケット混合、ランダム化された遅延、カバートラフィック、オニオン暗号化を用いて、ネットワークメタデータの漏えいを減らします。

Nymは、侵害されたデバイス、悪意あるウォレットソフトウェア、漏えいしたリカバリーフレーズ、取引所アカウントを通じて自ら明かしたID、または透明な Zcash アクティビティによるプライバシー喪失からは保護しません。

## ネイティブNym対応：利用可能な場合はまずこれを使用する

Nymは2026年9月24日、Zcash Community Grantの作業が完了し、実際の Zcash ウォレットにネイティブmixnet対応が提供され始めていると発表しました。

### Zingo! ウォレット

Zingo PC にはネイティブNymトランスポートが含まれています。Zingo Mobileも、アプリ内Nymプロキシを使用したiOSおよびAndroid向けMixnet Modeを提供しています。

Zingo によって文書化された現在の動作：

- Nymの操作項目は **設定 → Nym Mixnet** にあります。
- 支払いの送信はmixnet経由でルーティングされます。
- Ironwood の移行送信は、同じ保護された送信経路に従います。
- ZEC の価格リクエストもmixnet経由でルーティングされます。
- Nymが有効な間、送信はフェイルクローズされます。mixnetトランスポートが利用できない場合、支払いがclearnet経由で密かに送信されることはありません。
- **チェーン同期は現在、Zingo PC ではmixnet経由でルーティングされません**。コンパクトブロック、nullifierクエリ、トランザクション取得、mempoolトラフィック、サーバー健全性チェックは、引き続き通常のサーバー接続を使用します。

この違いは重要です。Zingo のネイティブ統合は最も関連付けの強いブロードキャスト経路を保護しますが、まだデバイス全体のネットワークトンネルではありません。

脅威モデルでサーバーから同期トラフィックも隠す必要がある場合は、追加される遅延と複雑さを理解したうえで、NymVPN のようなシステムレベルのプライバシートンネルを併用してください。

情報源：

- https://github.com/zingolabs/zingo-pc#the-nym-mixnet
- https://github.com/zingolabs/zingo-mobile
- https://nym.com/blog/nym-mixnet-zcash-wallets

### Zkool

Nymは、**Zkool** がネイティブトグルを使用して、Nym mixnet経由で Zcash RPCインフラに接続できるようになったと報告しています。

Zkool は YWallet の積極的に保守されている後継です。このプロジェクトは、Zcash サーバー接続向けのTorプロキシおよびオニオンサービスにも対応しています。

文書化されていないプロキシ経路を使って古い YWallet ビルドを無理に通そうとするより、Zkool のネイティブNymオプションを優先してください。

情報源：

- https://nym.com/blog/nym-mixnet-zcash-wallets
- https://github.com/hhanh00/zkool2

### Nozy

NozyWallet にもNym対応のトランスポート経路があります。現在の実装では、送信トランザクションの提出をNym mixnet経由でルーティングすること、およびコンパクトブロック同期用の独立したNym dVPN経路がサポートされています。すべてのウォレットリクエストが自動的にmixnetを使用すると想定せず、これらを別個の保護として扱ってください。

情報源：

- https://github.com/LEONINE-DAO/Nozy-wallet
- https://github.com/LEONINE-DAO/Nozy-wallet/blob/master/docs/reference/NYM_SEND_EGRESS_CASE_BREAKDOWN.md
- https://github.com/LEONINE-DAO/Nozy-wallet/blob/master/docs/reference/NYM_DVPN_SYNC_CASE_BREAKDOWN.md

### ZODL

ZODLには現在、Zingo、Zkool、Nozy向けに上記で説明したネイティブNym統合とは異なる、組み込みの**Tor Protection**があります。

ZODLのTor機能は、トランザクション提出、トランザクションデータ取得、為替レートリクエスト、サードパーティAPI呼び出しをTor経由でルーティングできます。Nymは2026年9月24日、より広範なmixnet統合についてZODLチームと現在も積極的に協議していると述べました。

現在ZODLでは、次のいずれかを使用してください。

- ZODLで文書化されているTor Protection、または
- ウォレットの一般的なデバイストラフィックをNym経由でルーティングすることが目的であれば、システムレベルの NymVPN。

どちらもプライバシーネットワークだからといって、ウォレット内でTorとNymが交換可能なトランスポートであると考えないでください。

ZODLのTor設定：

**More → Advanced Features → Beta: Tor Protection → Enable → Save changes**

情報源：

- https://support.zodl.com/article/17-enabling-tor-protection
- https://nym.com/blog/nym-mixnet-zcash-wallets

## フォールバック：システムレベルの NymVPN

これは、ウォレットがNym固有のプロキシ設定を理解する必要がないため、最も幅広く互換性のあるNymオプションです。

### 1. NymVPN をインストールする

NymVPN は、Nymの公式ウェブサイトまたは公式プラットフォームストアからのみダウンロードしてください。

- https://nym.com/
- https://nym.com/blog/nymvpn-v2026.12

NymVPN はAndroid、iOS、Linux、Windows、macOSに対応しています。

### 2. Mixnetモードを選択する

NymVPN には、低遅延向けに最適化された2ホップdVPN経路である**Fast mode**と、より強力なネットワークメタデータ保護向けに最適化された5ホップmixnet経路である**Mixnet mode**があります。機密性の高いウォレット操作ではMixnet modeを選択し、ウォレットを開くまたは更新する前に、クライアントが接続確立を報告するまで待ってください。

### 3. ウォレットは通常のネットワーク設定のままにする

オペレーティングシステムがすでに NymVPN 経由でトラフィックをトンネリングしている場合、ほとんどのウォレットではカスタムプロキシ設定は不要です。

通常どおりウォレットを開き、同期させてください。

プラットフォーム上で NymVPN がスプリットトンネリングを提供している場合は、ウォレットがバイパスまたは除外リストに置かれず、**保護されたトンネルに含まれている**ことを確認してください。

### 4. ウォレットを使用する前にトンネルを確認する

簡単なシステムレベルの確認方法：

1. NymVPN を切断します。
2. 公開IP確認サービスにアクセスするか、デスクトップでは次を実行します。

   ```bash
   curl https://api.ipify.org
   ```

3. 表示されたIPを記録します。
4. Mixnetモードで NymVPN に接続します。
5. 確認を繰り返します。

表示される公開IPは変化するはずです。

これはシステムトンネルを確認するものです。アプリまたはOSに特別なルーティングルールがある場合、特定のウォレットによるすべてのリクエストが同じ経路をたどることを証明するものでは**ありません**。

デスクトップでより確実に確認するには：

- オペレーティングシステムのネットワークモニターでウォレットプロセスを確認する、
- スプリットトンネルの除外がないことを確認する、
- NymVPN が切断された場合に、想定どおりウォレットの動作が変わることを確認する。

トラブルシューティング中は、ウォレットアドレス、残高、トランザクションID、IPアドレス、またはリカバリー情報を含むスクリーンショットを投稿しないでください。

## NymVPN dApp / ウォレットプロキシモード

NymVPN は、mixnet経由のSOCKS5 / RPCルーティングを用いるアプリおよびウォレットのプロキシモードも提供しています。

Nymの公開セットアップ文書では、主にEthereum形式のRPC設定でこれを例示しています。互換性のある汎用プロキシ/RPC経路を明示的にサポートするソフトウェアには有用ですが、すべての Zcash ウォレットで動作すると想定すべきでは**ありません**。

この経路は、ウォレット自体の文書で互換性のあるプロキシまたはRPC対応が確認されている場合にのみ使用してください。

それ以外の場合は、次を優先してください。

- ウォレットのネイティブNym統合、または
- システムレベルの NymVPN。

## パフォーマンスとタイムアウトのトレードオフ

Mixnetは、より強いメタデータ保護のために、意図的に速度を犠牲にします。

以下に影響する可能性があります。

- 初回のウォレット同期、
- 大規模な追いつき同期、
- トランザクション履歴クエリ、
- RPCタイムアウト、
- サードパーティAPI呼び出し。

実践的な指針：

- まずデフォルトのNym設定から始めてください。
- 初回同期または長時間の追いつき同期には、より時間がかかることを想定してください。
- プライバシー設定を弱める前に、タイムアウトを再試行してください。
- 機密性の高いトランザクションの直前に、プライバシーモードを何度も切り替えないでください。
- 大量同期に高速な経路を使用する場合、その期間中に接続先インフラが実際のネットワークIDを観測できることを理解してください。
- 特に Zingo PC については、ネイティブNymトランスポートが現在は送信と価格検索を保護する一方、同期は直接行われることを覚えておいてください。

## モバイルに関する考慮事項

AndroidおよびiOSでは、通常、一般的なウォレットトラフィックを NymVPN 経由でルーティングする最も簡単な方法はオペレーティングシステムのVPNスロットです。先に NymVPN に接続してから、ウォレットを開いてください。

別のVPN、ファイアウォール、またはローカルVPNベースの広告ブロッカーがすでにシステムVPNインターフェースを使用している場合、2つの製品を同時に動作させられない可能性があります。ウォレットが保護されていると考える前に、オペレーティングシステムのVPNステータスを確認してください。

## 脅威モデルのチェックリスト

セットアップに依存する前に、以下を確認してください。

- 適切な場合にシールド化された Zcash アドレスを使用しているか？
- 自分のウォレットはネイティブNym対応か？
- 対応している場合、そのネイティブ統合は具体的にどのトラフィックを保護するか？
- より広い範囲が必要な場合、ウォレットがネットワークアクティビティを開始する前に NymVPN は接続されているか？
- ウォレットはスプリットトンネリングルールによって除外されていないか？
- ウォレットが実際に文書化しているプロキシモードに依存しているか？
- 取引所、ブラウザーセッション、サードパーティAPI、または透明アドレスを通じてIDを漏らしていないか？
- 同期の遅延や時折発生するタイムアウトに備えているか？
