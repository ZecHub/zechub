# **Arti: Torの次世代クライアント（Client）Rust**
![Atri Logo](/content-images/_unavailable.svg)

**Arti** は、**Rust** プログラミング言語を使用して次世代の **Tor** クライアントを構築するための Tor Project の取り組みです。Arti はモジュール式で埋め込み可能かつ本番環境対応となるよう設計されており、**Tor** 匿名化プロトコルの、より安全で効率的な実装を提供します。**Arti バージョン 1.4.0** では、いくつかの重要な更新が導入されています。

- 強化された操作のための**新しい RPC インターフェース**。
- **リレーサポート**に向けた準備作業。
- **サービス側オニオンサービスのサービス拒否攻撃耐性**の改善。

このリリースは、Tor Project が Tor ユーザーおよびdeveloperに、より優れたセキュリティ、パフォーマンス、モジュール性を提供するための取り組みを継続するものです。


---


## **Arti クライアントのインストール**

以下の手順に従って、システム上で **Arti** を SOCKS プロキシとしてインストールし、実行してください。

---

### **ステップ 1: Rust 開発環境をセットアップする**

ソースから Arti をビルドする前に、最新の安定版 **Rust** をインストールしておく必要があります。

#### Rust をインストールするには:

1. 公式の [Rust ウェブサイト](https://www.rust-lang.org/)にアクセスします。
2. 使用しているオペレーティングシステム向けのインストール手順に従います。
3. 次のコマンドを実行して、インストールを確認します。
   
   ```sh
   rustc --version
   ```

これにより、システムに Rust の最新安定版がインストールされていることを確認できます。

#### **Windows ユーザー向けノート（Note）**:
- Rust は、ツールチェーンインストーラーである Windows の [**rustup**](https://rustup.rs/) を介してインストールできます。互換性のあるビルド環境もセットアップしてください（Windows では **Visual Studio Build Tools** が必要になる場合があります）。
  
---

### **ステップ 2: Arti リポジトリをクローンする**

Arti クライアントの最新バージョンを取得するには、[**GitLab**](https://gitlab.torproject.org/tpo/core/arti) からリポジトリをクローンする必要があります。

#### 手順:
1. ターミナルを開きます（Windows ではコマンドプロンプト、PowerShell、または Git Bash）。
2. 次のコマンドを実行してリポジトリをクローンします。
   
   ```sh
   git clone https://gitlab.torproject.org/tpo/core/arti.git
   ```
4. 新しく作成された *arti* ディレクトリに移動します。
   
   ```sh
   cd arti
   ```

これにより、Arti のソースコードがローカルマシンに取得されます。

---

### **ステップ 3: Arti バイナリをビルドする**

リポジトリをクローンしたら、Rust のパッケージマネージャーおよびビルドツールである **Cargo** を使用して Arti をビルドする必要があります。

#### Arti をビルドするには:
1. ターミナルで次のコマンドを実行します。
   ```sh
   cargo build --release
   ```

このコマンドは Arti コードをコンパイルし、本番環境向けに最適化します（*--release* フラグ）。バイナリは *target/release* ディレクトリに作成されます。

#### コンパイル済みバイナリの場所:
- ビルド後、Arti バイナリは次の場所に配置されます。  
  ```sh
  target/release/arti
  ```

このバイナリはターミナルから直接実行できます。

---

### **ステップ 4: Arti SOCKS プロキシを実行する**

Arti を SOCKS プロキシとして使用するには（インターネットトラフィックを Tor ネットワーク経由でルーティングします）、プロキシを起動する必要があります。

#### SOCKS プロキシを起動するには:
1. 次のコマンドを実行します。
   ```sh
   ./target/release/arti proxy -p 9150
   ```

このコマンドは、SOCKS トラフィックに Tor が使用するデフォルトポートである **ポート 9150** で、Arti を **SOCKS5 プロキシ**として起動します。

---

### **ステップ 5: Arti を使用するようアプリケーションを設定する**

Arti が SOCKS プロキシとして実行されたら、Tor ネットワーク経由でトラフィックをルーティングするために、アプリケーションを設定する必要があります。

#### 手順:
1. アプリケーションの設定（例: ウェブブラウザ、ターミナルアプリケーション）で、**プロキシ設定**を探します。
2. **SOCKS5 プロキシ**を *localhost:9150* に設定します。

これにより、アプリケーションからのすべてのトラフィックは、Arti を仲介として使用し、**Tor ネットワーク**経由でルーティングされます。

---

## **Arti と Tor ネットワークの統合**

以下は、Arti が Tor ネットワークと連携してどのように動作するかを示す簡略図です。


```plaintext
[Application] --(SOCKS5)--> [Arti SOCKS Proxy] --(Tor Protocol)--> [Tor Network]
```

- **アプリケーション**は、**SOCKS5** プロトコルを使用して **Arti SOCKS プロキシ**に接続します。
- その後、Arti は **Tor ネットワーク**と通信し、ネットワークを通過するトラフィックが匿名化されるようにします。

## **GitLab リポジトリと貢献**

**Arti** の開発への貢献に関心がある場合は、コードを調べ、**GitLab** を通じて貢献できます。

- **リポジトリリンク**: [Arti GitLab リポジトリ](https://gitlab.torproject.org/tpo/core/arti)
- **リポジトリをクローンする**:
  ```sh
  git clone https://gitlab.torproject.org/tpo/core/arti.git
  ```

### **フォークと貢献**:
1. GitLab でリポジトリを**フォーク**します（GitLab アカウントが必要です）。
2. フォークしたリポジトリをローカル環境にリンクします。
   ```sh
   git remote add _name_ git@gitlab.torproject.org:_name_/arti.git
   git fetch _name_
   ```
   *_name_* を GitLab ユーザー名に置き換えます。

3. 変更をフォーク先に**プッシュ**します。
   ```sh
   git push _name_ main
   ```

4. GitLab で**マージリクエスト（MR）**を作成します。
   GitLab のフォーク内にあるマージリクエストセクションに移動します。
   ```plaintext
   https://gitlab.torproject.org/_name_/arti/-/merge_requests
   ```

### **マージリクエストのガイドライン**:
- **レビュー中にコミットをリベースおよびスカッシュしないでください**。
- 必要に応じて、コミットの自動スカッシュには *fixup!* または *squash!* を使用してください。
- レビューサイクル中にスカッシュするのではなく、**新しいコミットを追加する**ことを目指してください。
