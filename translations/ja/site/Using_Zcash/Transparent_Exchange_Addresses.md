# Zcash TEXアドレスとは？

## 要点

* TEXアドレスは、異なる形式で表記された透明なZcashアドレスです。`tex1`で始まり、[ZIP 320](https://zips.z.cash/zip-0320)で定義されています。
* これはウォレットに一つのことを伝えます。このアドレスには透明な資金のみを送金してください。
* 残高がシールドされている場合、対応ウォレットが二つの手順を実行します。金額を一時的な透明アドレスへ移動し、その後TEXアドレスへ送金します。
* 2023年、Binanceは、シールドされた入金を拒否して返金する方法をZcashコミュニティに求めました。TEXアドレスがその答えであり、BinanceはZecHubの[Custodial Exchanges](/using-zcash/custodial-exchanges)一覧でTEX入金を受け付ける取引所です。
* TEXアドレスへの支払いは、あらゆる透明な支払いと同様にブロックチェーン上で公開されます。シールドされた残高の残りは非公開のままです。

## 基本解説

Zcash TEXアドレスは、特別な種類の受取アドレスです。TEXは「Transparent Exchange」の略です。単一のp2pkh透明アドレスをBech32mで再エンコードしたものです。TEXアドレスは`tex1`で始まり、Unified Addressとは別の種類です。

TEXアドレスは、対応ウォレットに透明のみ（T -> T）のトランザクションを作成するよう指示します。 

仕組みは次のとおりです。対応ウォレットがTEXアドレスを検出すると、それをデコードして含まれる透明な受信者を取得します。その後ウォレットは、txに必要な資金をシールドプールから、ユーザーが管理する別の一時的な透明アドレスへ送ります（Z -> T）。続いて、その資金をTEXアドレスからデコードした透明な受信者へ送ります（T -> T）。  

TEXアドレスの技術提案はZcash [ZIP 320](https://zips.z.cash/zip-0320)で説明されており、透明アドレスからの資金受取専用のアドレス種別を定義しています。

![TEX](/content-images/ZashiTex-b1cbec5f07.webp)

TEXアドレスは、まだ広く採用されていません。Zcashユーザーは、いずれ利用を求められる可能性があります。

### TEXアドレスが必要になるとき

#### 透明アドレスへ直接送金できないウォレットを使って、透明アドレスに資金を送る場合はTEXアドレスが必要です。

一部のウォレットでは透明アドレスへ直接送金できず、受取人がTEX形式のアドレスを提供していない場合があります。そのため、透明アドレスからTEXアドレスへの変換が必要になることがあります。これは[zip-320](https://zips.z.cash/zip-0320#reference-implementation)で示されているリファレンス実装を実行することで、手動で行えます。

#### 資金が透明な送信元から来ることを要求する中央集権型取引所へ送金する場合は、TEXアドレスが必要です。

[Binance](https://www.binance.com/)が、TEXアドレスが存在する理由です。2023年11月、同社はZcashコミュニティに対し、シールドアドレスからの入金を拒否して預金者へ返金する方法がなければZECが上場廃止される可能性があると伝えました（[ZIP 320、背景](https://zips.z.cash/zip-0320#background)）。ZIP 320では、支払いの送信元アドレスを把握する必要がない限り、他の取引所がTEXアドレスを発行することは想定していません。Binanceは、当サイトの[Custodial Exchanges](/using-zcash/custodial-exchanges)一覧でTEXアドレスへの入金を受け付ける取引所です。
TEXアドレスは、対応ウォレットに対し、そのアドレスに送られるすべての資金が透明でなければならず、あらゆるシールドされた価値をそのアドレスへの送金から除外することを伝えます。
Binanceのような取引所が送付された価値を拒否した場合、その価値を送信元アドレスへ返却するために必要な手段を持っています。また、Binanceのような組織が政府やその他の当局によって課される法律や規制を遵守する助けにもなります。

### TEXアドレスに対応しているウォレットは？

最新の一覧は、当サイトの[wallets](/using-zcash/wallets)ページで確認できます。TEX Addressフィルターを使用してください。

## 図解 / たとえ

シールドされた残高を、自宅にある施錠された金庫の中のお金だと考えてください。外部の誰にも、中にどれだけ入っているかは見えません。

Binanceのような取引所は、カウンターに次のような掲示を出しています。現金の出所を確認し、必要なら返却できるよう、透明な封筒での支払いのみ受け付けます。TEXアドレスは、その掲示です。

ウォレットがこの掲示を見ると、金庫から金額を取り出し、あなたの返送先アドレスが記された透明な封筒（一時的な透明アドレス）に入れ、その封筒をカウンターまで運びます。金庫は施錠されたままで、そのほかに何が入っているかを誰も知ることはありません。

## 詳細解説

### TEXアドレスの作り方

`t1`で始まる通常の透明アドレスには、Base58Checkで記述された20バイトのキーハッシュが格納されています。TEXアドレスには同じ20バイトが格納され、接頭辞`tex`（テストネットでは`textest`）を用いてBech32mで再エンコードされます。両者の変換には数行のコードしか必要なく、ZIP 320のリファレンス実装で示されています。

この単純な設計はBinanceによる要件でした。変換は、取引所のフロントエンドコードでBase58CheckおよびBech32mライブラリだけを用いて実行できなければなりませんでした。ZIP 320の初期ドラフトではこの仕組みをUnified Addressに組み込んでいましたが、この理由からその版は取り下げられました。

### シールドされた残高からTEXアドレスへ支払う

ZIP 320は、対応ウォレットがここで二つのトランザクションを作成することを要求しています。最初のトランザクションでは、シールドされた残高から新しい一時的な透明アドレスへ資金を移動します。二つ目では、そのアドレスからTEXアドレスへ資金を送ります。

取引所が入金を拒否した場合、資金は一時的なアドレスへ返金されます。ウォレットはそれを見つけて使用できなければならないため、ZIP 320ではウォレットにシードフレーズから一時的なアドレスを導出するよう求めています。また、別々の支払いを相互に関連付けられないよう、毎回新しい一時的なアドレスを使用することも求めています。

### ブロックチェーンに表示されるもの

TEXのルールはウォレットに存在します。ノードはこれを検証しないため、コンセンサスルールは変わりません。オンチェーンでは、TEXアドレスへの支払いは、対応する`t1`アドレスへの支払いと同じように見えます。あらゆる透明なトランザクションと同様に、金額、一時的なアドレス、および取引所のアドレスは公開されます。
