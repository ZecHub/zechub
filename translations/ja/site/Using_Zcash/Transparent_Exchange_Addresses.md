# Zcash TEX アドレスとは？

## TL;DR

* TEX アドレスは、異なる形式で記述された公開型（transparent）の Zcash アドレス（address）です。`tex1` で始まり、[ZIP 320](https://zips.z.cash/zip-0320) で定義されています。
* これはウォレット（wallet）に1つのことを伝えます。つまり、このアドレスには公開型の資金のみで支払うことです。
* 残高がシールドされた（shielded）ものである場合、対応ウォレットが2つの手順を実行します。まず金額を一時的な公開型アドレスへ移動し、その後 TEX アドレスへ送信します。
* 2023年、Binance はシールドされた入金を拒否して返金する手段を Zcash コミュニティに求めました。TEX アドレスがその答えであり、Binance は ZecHub の [Custodial Exchanges](/using-zcash/custodial-exchanges) リストで TEX 入金を受け付ける取引所（exchange）です。
* 送信側での対応も広がっています。Coinbase は利用者が ZEC を TEX アドレスへ送れるようにしており、ウォレット用ツールキットにも ZIP 320 の対応が追加されています。
* TEX アドレスへの支払い（payment）は、他の公開型支払いと同様にブロックチェーン（blockchain）上で公開されます。シールドされた残高の残りは非公開のままです。

## 基本的な説明

Zcash TEX アドレスは、特別な種類の受取アドレスです。TEX は「Transparent Exchange」の略です。単一の p2pkh 公開型アドレスを Bech32m で再エンコードしたものです。TEX アドレスは `tex1` で始まり、統合アドレスとは別の種類です。

TEX アドレスは、対応ウォレットに公開型のみ（T -> T）のトランザクション（transaction）を作成するよう指示します。 

ロジックは次のとおりです。対応ウォレットが TEX アドレスを検出すると、それをデコードして含まれる公開型受取先を取得します。その後、ウォレットはトランザクションに必要な資金をシールドされたプール（pool）から、ユーザーが管理する別の一時的な公開型アドレスへ送ります（Z -> T）。次に、それらの資金を TEX アドレスからデコードされた公開型受取先へ送信します（T -> T）。  

TEX アドレスの技術提案は Zcash [ZIP 320](https://zips.z.cash/zip-0320) で示されており、公開型アドレスからの資金受取専用のアドレス種別を定義しています。

### TEX アドレスはどの程度利用されていますか？

採用はまだ部分的ですが、もはや単一の取引所に限定されていません。区別すべき2つの役割があります。

* **TEX 入金アドレスの発行。** Binance は、入金用に TEX アドレスを発行する、当サイトの [Custodial Exchanges](/using-zcash/custodial-exchanges) リスト上の取引所です。これにより、資金は公開型の送信元から到着します（[ZIP 320、背景](https://zips.z.cash/zip-0320#background)）。ZIP 320 は、支払いの送信元アドレスを知る必要がない限り、他の取引所が TEX アドレスを発行することを想定していません。
* **TEX アドレスへの送信。** こちらの対応が拡大しています。2024年10月、Coinbase は、Coinbase.com の利用者が Zcash を TEX アドレスへ送信できると発表しました（[Coinbase Assets の発表](https://x.com/CoinbaseAssets/status/1844428577921507416)）。ウォレット用ツールキットにも ZIP 320 の対応が追加されています。KeepKey はファームウェア 7.15 で TEX トランザクションの署名を追加し（[keepkey/hdwallet #75](https://github.com/keepkey/hdwallet/pull/75)）、XChainJS `zcash-js` ライブラリは、有効な `tex1` 受取先を拒否した後に修正されました（詳細は後述します）。

したがって TEX アドレスは普遍的ではありませんが、Binance だけで使われていると考えるべきではなくなりました。

### TEX アドレスが必要になる場合

#### 公開型アドレスへ直接送信できないウォレットを使用して、公開型アドレスへ資金を送る場合は TEX アドレスが必要です。

一部のウォレットでは公開型アドレスへ直接送信できず、受取側が TEX 相当のアドレスを提供していない場合があります。そのため、公開型アドレスから TEX アドレスへの変換が必要になることがあります。これは [zip-320](https://zips.z.cash/zip-0320#reference-implementation) で示された参照実装を実行することで、手動で行えます。

#### 資金が公開型の送信元から来ることを求める中央集権型取引所へ送金する場合は、TEX アドレスが必要です。

[Binance](https://www.binance.com/) が TEX アドレスが存在する理由です。2023年11月、同社は、シールドされたアドレスからの入金を拒否し、入金者へ返金する方法がなければ、Zcash コミュニティに対して ZEC が上場廃止になる可能性があると伝えました（[ZIP 320、背景](https://zips.z.cash/zip-0320#background)）。ZIP 320 は、支払いの送信元アドレスを知る必要がない限り、他の取引所が TEX アドレスを発行することを想定していません。Binance は、当サイトの [Custodial Exchanges](/using-zcash/custodial-exchanges) リストで TEX アドレスへの入金を受け付ける取引所です。
TEX アドレスは、対応ウォレットに対して、そのアドレスへ送るすべての資金を公開型にし、シールドされたすべての価値が当該アドレスへ送られないように指示します。
Binance のような取引所が送信された価値を拒否した場合、その価値を送信元アドレスへ返すために必要な手段を備えています。また、Binance のような組織が政府その他の当局による法律および規制を遵守する助けにもなります。

### TEX アドレスに対応しているウォレットはどれですか？

最新のリストは、当サイトの [wallets](/using-zcash/wallets) ページで確認できます。TEX Address フィルターを使用してください。

## 図解 / たとえ

シールドされた残高を、自宅にある施錠された金庫のお金だと考えてください。外部の誰にも中にいくら入っているかは見えません。

Binance のような取引所は、窓口に次のような掲示をしています。「支払いは、中身が見える封筒に入れたものだけ受け付けます。そうすれば窓口係はお金の送信元を確認でき、必要なら返却できます」。TEX アドレスはその掲示です。

ウォレットがその掲示を見ると、金庫から金額を取り出し、返送先アドレスが書かれた中身が見える封筒（一時的な公開型アドレス）に入れて窓口へ運びます。金庫は施錠されたままであり、他に何が入っているかを誰かに知られることはありません。

## 詳細解説

### TEX アドレスの構成

`t1` で始まる通常の公開型アドレスには、Base58Check で記述された 20 バイトの鍵ハッシュが含まれます。TEX アドレスには同じ 20 バイトが含まれ、プレフィックス `tex`（テストネットでは `textest`）を用いて Bech32m で再エンコードされています。両者の変換には数行のコードしか必要なく、ZIP 320 は参照実装でこれを示しています。

この単純な設計は Binance からの要件でした。変換は、取引所のフロントエンドコードにある Base58Check と Bech32m のライブラリだけで実行できなければなりませんでした。ZIP 320 の初期ドラフトではこの考え方を統合アドレスに組み込んでいましたが、この理由からそのバージョンは廃止されました。

TEX アドレスは統合アドレス形式から Bech32m エンコーディングを借用していますが、その構造はほとんど持ちません。Bech32m や Zcash アドレスの検証方法に馴染みがない場合は、[Unified Addresses](/using-zcash/unified-addresses) ページで、[ZIP 316](https://zips.z.cash/zip-0316) の基本を説明しています。TEX アドレスと統合アドレスには、次の4つの具体的な違いがあります。

| | 統合アドレス（ZIP 316） | TEX アドレス（ZIP 320） |
|---|---|---|
| 含まれるもの | 複数の受取先をまとめたもの | 単一の P2PKH 公開型受取先 |
| 人間が読めるプレフィックス（HRP） | `u`（メインネット） | `tex`（テストネットでは `textest`） |
| F4Jumble による難読化 | はい | いいえ |
| 各受取先のタイプコード | はい | いいえ |

要するに、TEX アドレスは可能な限り単純な Bech32m ラッパーです。1つの公開型鍵ハッシュ、`tex` プレフィックス、そしてそれ以外は何もありません。

### ウォレットおよび統合実装における処理規則

ここは実装で誤りが生じている部分なので、明確に述べる価値があります。TEX アドレスを検出した際、ウォレットまたは統合実装は、**シールドされたプールから TEX の宛先へ直接支出してはなりません。** ZIP 320 は TEX 支払いへのすべての入力が公開型であることを要求しているため、支払いは次の2段階で構築されます。

1. **シールド解除。** シールドされたプールから、ウォレットが所有する新しい、ユーザー管理の一時的な公開型アドレスへ金額を移動します（Z -> T）。
2. **公開型から公開型への送信。** その一時的な出力を、TEX アドレス内でデコードされた P2PKH 受取先へ支出します（T -> T）。

次の規則はすべて ZIP 320 に基づいており、安全性を確保します。

* 一時的なアドレスはシードフレーズ（seed phrase）から導出する必要があります。これにより、取引所が資金を返金した場合でも、ウォレットはその資金を見つけて支出できます。
* 支払い同士を関連付けられないよう、毎回新しい一時的なアドレスを使用する必要があります。
* 2番目のトランザクションでは公開型入力のみを支出する必要があります。これにより、取引所にはクリーンな公開型から公開型への入金として表示されます。

変換と2段階のフローは、[ZIP 320 の参照実装](https://zips.z.cash/zip-0320#reference-implementation) に示されています。これを誤ることは現実に起きた最近の問題です。2026年10月、XChainJS `zcash-js` ライブラリは、有効な `tex1` 受取先を「Invalid 'to' address」エラーで拒否しました。これは、そのバリデーターが Base58Check の `t1` 形式しか受け付けず、`tex1` アドレスを公開するサービスへの ZEC 入金を妨げたためです（[issue #1782](https://github.com/xchainjs/xchainjs-lib/issues/1782)）。この問題は、バリデーターが ZIP 320 エンコーディングを受け付けるようにして修正されました（[PR #1783](https://github.com/xchainjs/xchainjs-lib/pull/1783)）。

### TEX 送信で明らかになること

TEX 支払いは公開型支払いであるため公開されますが、観測者に何が見え、何が見えないかを正確に理解することが重要です。

オンチェーン（on-chain）で**見える**もの：

* 一時的な公開型アドレス。シールド解除ステップの出力および最終送信の入力として現れるためです。
* 両方の金額。Z -> T ステップでシールドされたプールから出た価値と、T -> T ステップで届けられた価値です。
* 取引所の公開型受取先。これは TEX アドレスにエンコードされた P2PKH アドレスです。

**隠されたままのもの：**

* シールドされた残高の残り、およびどの特定のシールドされたノート（note）が支払いの資金源となったかです。シールド解除ステップは、プール内のどこから来たかではなく、*何らかの*価値がプールから一時的なアドレスへ出たことを明らかにします。

したがって観測者は、一時的なアドレスを取引所への支払いと関連付けることができ（同じ資金が公開型から公開型へ移動するため）、さらにそのアドレスがシールドされた引き出しから補充されたことも確認できます。しかし、他のシールドされた資金や活動と結び付けることはできません。オンチェーン上で支払いが実際に「TEX」送信として印付けされることはありません。ZIP 320 が指摘するように、TEX アドレスへの支払いは対応する `t1` アドレスへの支払いと区別できません。コンセンサス（consensus）規則は変更されず、規則全体がウォレット内にあるためです。

![On-chain footprint of a TEX send: funds leave the shielded pool to an ephemeral transparent address, then go transparent-to-transparent to the exchange; the ephemeral address, both amounts and the exchange address are visible, while the rest of the shielded balance stays hidden](/content-images/tex-onchain-footprint.webp)

### ブロックチェーンに表示されるもの

TEX の規則はウォレット内にあります。ノード（node）はこれを検証しないため、コンセンサス規則は変わりません。オンチェーンでは、TEX アドレスへの支払いは対応する `t1` アドレスへの支払いと同じに見えます。金額、一時的なアドレス、取引所のアドレスは、あらゆる公開型トランザクションと同様に公開されます。
