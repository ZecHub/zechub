# 統合アドレス（Unified Addresses）

> Zcashのすべてに対応する1つのアドレスです。これを共有すれば、送信者のウォレット（Wallet）が最もプライバシー性の高い方法であなたに支払いを行います。

## 要約

* 統合アドレス（UA）は、Zcashの複数の受信者を保持する1つのアドレスです。受信者にはIronwood、Sapling、公開型があります。
* メインネットのUAは`u1`で始まります。ZIP 316で定義され、2022年5月31日のNU5アップグレードとともに導入されました。
* 送信者のウォレットは、両方のウォレットが対応する最もプライバシー性の高いプールを選びます。自分でプールを選ぶ必要はありません。
* 2026年7月にIronwoodプールが稼働開始した後も、UAはそのまま機能し続けました。新しいアドレスを共有する必要はありませんでした。
* ウォレットでは送信者ごとに新しいUAを作成できますが、すべて同じアカウントに支払われます。

## 基本的な説明

統合アドレス（UA）は、複数の受信者を1つにまとめた単一のZcashアドレスです。受信者とは、特定の価値プールで資金を受け取るアドレスの部分です。Ironwood、Sapling、公開型があります。UAはメインネットでは`u1`で始まり、[ZIP 316](https://zips.z.cash/zip-0316)で定義され、2022年5月31日のNU5ネットワークアップグレード（network upgrade）で導入されました。

統合アドレス以前は、ZECを受け取る際にアドレスの種類を考慮する必要がありました。`zs`アドレスはSapling資金を受け取り、`t`アドレスは公開型資金を受け取り、種類間で送金するには追加の手順が必要でした。UAはそれを解消します。共有するアドレスは1つだけで、残りはウォレットが処理します。

### 仕組み

誰かがあなたのUAへ送金すると、その人のウォレットは内部の受信者を読み取り、両方のウォレットが対応する最もプライバシー性の高いプールを選びます。

1. 両方のウォレットが現在のシールドされた（shielded）プールに対応している場合、支払いはシールドされた状態で届きます。公開情報がチェーン（chain）に触れることはありません。
2. 送信者が古いプールからしか送金できない場合、ウォレットはSaplingなど、両者が共有する最適な受信者へフォールバックします。
3. 送信者が公開型資金しか送金できない場合、支払いはUAの公開型受信者に届き、ウォレットからシールドできます。

これを自分で管理する必要はありません。アドレスは変わらず、内部でルーティングが行われます。

### 現在重要な理由

Zcashは継続的にアップグレードされています。2026年7月28日にIronwoodプールがNU6.3で有効化された際、UAの保有者は新しいアドレスを必要としませんでした。ウォレットが、すでに保持していたアドレス内のIronwood受信者を選び始めただけです。古い単独アドレスを保有するユーザーは移行する必要がありました。UAの保有者は何もする必要がありませんでした。

これが設計上の目標です。将来のネットワークアップグレードで新しいプールが追加されても、統合アドレスは誰もアドレスを再共有したり、手作業で資金を移動したりせずにそれらを取り込みます。現在のプール構成については、[Zcash価値プール](/using-zcash/shielded-pools)を参照してください。

### 送信者ごとに新しいアドレス

ウォレットは、1つのアカウントに対して多数の多様化された統合アドレスを生成できます。どのアドレスも同じ資金に支払われますが、オンチェーン（on-chain）ではそれらのどの2つも関連付けられません。支払いを行う人物またはサービスごとに異なるUAを渡せば、どの組み合わせでも、同じウォレットに支払っていることをアドレス比較から知ることはできません。

## 図解 / たとえ

3つの郵便受け口がある玄関ドアを想像してください。最も新しい受け口は手紙を施錠された金庫に入れます（Ironwood）。2つ目は施錠された引き出しに入れます（Sapling）。3つ目は、窓越しに誰でも読める開放されたトレーに置きます（公開型）。

郵便配達員は送信者のウォレットです。通過できる中で最もプライバシー性の高い受け口を使います。ドアには1つのアドレスだけを掲示し、家に新しい金庫が追加されても、ドアのアドレスは変わりません。

## 詳細

### 関連ツール

- **ビューイングキー（Viewing keys）。** すべてのアカウントには統合ビューイングキーがあり、支出権限を共有せずに、UAが受け取る内容（または送信するすべての内容）を共有できます。プレフィックスは`uview`および`uivk`です。[ビューイングキー](/zcash-tech/viewing-keys)を参照してください。
- **TEXアドレス。** 現在はBinanceなど一部の取引所（exchange）で、入金が公開型の送信元から届くことが求められます。TEXアドレス（[ZIP 320](https://zips.z.cash/zip-0320)）は、まさにそのケースのための、UAに付随する公開型専用アドレスです。[公開型取引所アドレス](/using-zcash/transparent-exchange-addresses)を参照してください。
- **支払いリクエスト。** UAは、金額とメモ（memo）があらかじめ入力された支払いリクエストURIに埋め込めます。[支払いリクエストURI](/using-zcash/payment-request-uris)を参照してください。

### クイックファクト

| | |
|---|---|
| プレフィックス | `u1`（メインネット） |
| エンコーディング | bech32m |
| 定義 | [ZIP 316](https://zips.z.cash/zip-0316) |
| 導入 | NU5、2022年5月31日 |
| 含まれるもの | Ironwood、Sapling、および公開型受信者 |
| 支出鍵（spending key） | アカウントごとに1つで、そのすべてのUAで共有されます |

統合アドレスに対応するウォレットは、[ウォレット](/wallets)ページで確認してください。

## よくある間違い

- **古い`zs`または`t`アドレスを共有すること。** 単独アドレスは1つのプールにしか到達せず、新しいプールを取り込みません。UAを共有してください。
- **全員に同じUAを渡すこと。** あなたに支払いをする2人はメモを照合し、同じアドレスであることを確認できます。送信者ごとにウォレットから新しいUAを渡してください。
- **UAへのすべての支払いがプライベートだと期待すること。** 公開型資金しか送れない送信者は、あなたの公開型受信者に支払います。その支払いは公開されます。後でウォレットからシールドしてください。
