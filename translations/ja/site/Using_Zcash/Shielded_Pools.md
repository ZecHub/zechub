# Zcashのバリュープール

## 要点

- Zcash には現在、**5つのバリュープール**があります: Sprout（旧式）、Sapling、Orchard（支出専用）、Ironwood、Transparent。
- **Ironwood** は現在の主要なシールドプールで、2026年7月28日の NU6.3 アップグレード以降に稼働しています。
- **Orchard** は現在 **支出専用** です: 新たな価値を流入させることはできず、既存の資金は Ironwood へ移行しています。
- **Sapling**（`zs` で始まる z-address）は引き続き広くサポートされており、かなりの量のシールドされた ZEC を保護し続けています。
- **Transparent** アドレス（t...）は取引プライバシーを提供せず、Bitcoin と同様に動作します。
- **Sprout** はレガシーなシールドプールであり、すでに現役利用から退いています。
- Orchard から Ironwood への移行は**進行中**であり、turnstile によって公開監査されています。
- 最も強力なプライバシー保証を得るには、可能な限り **シールドからシールドへの取引（z → z）** を優先し続けるべきです。


<br/>

## Zcashのバリュープールを理解する

Zcash は資金を、バリュープールとして知られる個別の会計システムに分けています。各プールは独自の暗号学的ルールとプライバシー特性を持ち、同時にプロトコルはそれらの間を移動する総価値を追跡しています。

現在、ネットワークには5つの主要なバリュープールがあります:

- Transparent — 公開されており、オンチェーンですべて可視です。
- Sapling — 最初に広く採用された近代的なシールドプールで、現在もアクティブです。
- Orchard — 以前の主要なシールドプールで、現在は支出専用です。
- Ironwood — 現在の主要なシールドプールで、NU6.3 で導入されました。
- Sprout — 2016年の Zcash ローンチ時に導入された元祖シールドプールです。
  


Zcash が進化するにつれて、既存資金との互換性を維持しながら、セキュリティ、プライバシー、使いやすさ、監査可能性を向上させるために、新たなシールドプールが導入される可能性があります。

## シールドプール


1. <h3 id="ironwood" class="text-3xl font-bold my-4">Ironwood プール</h3>

Ironwood は現在の主要なシールドプールです。2026年7月28日、ブロック 3,428,143 で NU6.3 ネットワークアップグレードの一環として有効化され、新しいシールドされた価値は現在ここに存在します。

これは、2026年5月に Orchard の証明システムで脆弱性が発見されたために存在します。実際に悪用された証拠はありませんが、この欠陥により、シールド供給が証明だけで健全だと証明できなくなりました。その場で修正する代わりに、ネットワークは修正済み回路を備えた新しいプールを作成し、すべてのコインを公開で数える turnstile を通じて価値を移動させました。この会計処理によって、シールド供給が完全に裏付けられているという保証が回復されます。

Ironwood は Orchard の Action モデルと Halo 2 証明を再利用しているため、日常的な振る舞いは同じです。新しい点は2つあります: 取引が v6 形式を使用すること、そして Ironwood のノートが [ZIP 2005](https://zips.z.cash/zip-2005) の下で **quantum-recoverable** であることです。つまり、将来の量子コンピューターが今日の暗号を破った場合でも、コインのオンチェーン記録は復旧可能なままです。これは復旧経路であり、量子耐性そのものではなく、古いプールには適用されません。

新しいアドレスは必要ありません。Unified addresses は複数の受信先を束ねており、ウォレットが適切なプールを自動的に選択します。

____

2. <h3 id="orchard" class="text-3xl font-bold my-4">Orchard プール</h3>


![img2](/content-images/a672e001-6dbc-4e76-ab31-0ed7d7d2ff72-93b5a23e5d.webp)
図2: 2025年10月時点の Orchard プールを示すチャート

<br/>

Orchard Shielded Pool は、NU5 ネットワークアップグレードの一環として 2022年5月31日に有効化されました。Orchard は trusted setup を不要にする新しいシールドプロトコルを導入し、Unified Addresses（UA）で使用される主要なシールドプールになりました。

Orchard は、取引メタデータの漏えいを減らし、従来のシールドされた入力と出力ではなく Actions に基づく、より柔軟なトランザクションモデルを導入することで、使いやすさ、効率、プライバシーを大幅に改善しました。

2026年7月28日に Ironwood アップグレードが有効化されて以来、**Orchard は支出専用**です。新たな価値をこのプールに入れることはできません。すでにそこに保管されている資金は引き続き支出可能であり、turnstile を通じて Ironwood へ移行しています。ウォレットがこれを処理してくれますが、多くのウォレットではそのペースをある程度コントロールできます。

Orchard の資金を保有している場合は、[Ironwood](/zcash-tech/ironwood) を参照して、この移行が実際に何を意味するのか確認してください。

____

3. <h3 id="sapling" class="text-3xl font-bold my-4">Sapling プール</h3>


![img3](/content-images/b1c6bb71-9356-45eb-8e4a-19d7cf1790ae-5e3051b082.webp)
図3: 2025年10月時点の Sapling プールを示すチャート

<br/>

[Zcash Sapling](https://z.cash/upgrade/sapling) は、2018年10月28日に導入された Zcash プロトコルのアップグレードです。これは Sprout として知られる以前のバージョンに対する大幅な改善であり、Sprout にはプライバシー、効率、使いやすさの面でいくつかの制限がありました。 

アップグレード内容には、シールドアドレスのパフォーマンス向上、ユーザーの秘密鍵を公開せずに入出金取引を確認できるようにする improved viewing keys、そしてハードウェアウォレットで取引署名を行う際の独立したゼロ知識鍵などが含まれます。 

Zcash Sapling によって、ユーザーは Sprout 系列で必要だったより長い時間と比べて、わずか数秒でプライベート取引を実行できるようになりました。 

取引のシールド化はプライバシーを強化し、第三者が取引を結び付けたり、送金される ZEC の量を特定したりすることを不可能にします。Sapling はまた、プライベート取引生成に必要な計算量を減らすことで使いやすさを向上させ、より多くのユーザーが利用しやすくしています。

Sapling ウォレットアドレスは "zs" で始まり、これは Sapling アドレスを内蔵した、サポート対象の Zcash Shielded Wallet（YWallet、Zingo Wallet、Nighthawk など）すべてで確認できます。Zcash Sapling は、取引のプライバシーと効率の面で技術的に重要な進歩を表しており、プライバシーとセキュリティを重視するユーザーにとって、Zcash を実用的で効果的な暗号通貨にしています。

____

4. <h3 id="sprout" class="text-3xl font-bold my-4">Sprout プール</h3>


![img4](/content-images/956eceed-f4d6-4087-99d0-32a770449dda-a3cc45305e.webp)
図4: 2025年10月時点の Sprout プールを示すチャート

Sprout は、これまでにローンチされた最初のオープンかつパーミッションレスなゼロ知識プライバシープロトコルでした。2016年10月28日にローンチされました。

Sprout アドレスは先頭2文字が常に "zc" であることで識別されます。"Sprout" という名前は、このソフトウェアが若く、芽吹いたばかりの、大きな成長可能性を持ち、開発に向けて開かれたブロックチェーンであることを強調することを主な目的として付けられました。 

Sprout は、[Zcash slow start Mining](https://electriccoin.co/blog/slow-start-and-mining-ecosystem/) の初期ツールとして使用され、これによって ZEC とマイナーへのブロック報酬の分配が行われました。 

Zcash エコシステムが拡大を続け、シールド取引の数が増加するにつれて、Zcash Sprout 系列はユーザープライバシー、取引のスケーラビリティ、処理効率の面で制限があり、効率も低いことが明らかになりました。これがネットワークの改良と Sapling アップグレードにつながりました。 

---
5. <h3 id="transparent" class="text-3xl font-bold my-4">Transparent プール</h3>
<br/>

![img5](/content-images/01de2907-b62d-4421-83d7-ea4908faa828-6f74b724ed.webp)
図5: 2025年10月時点の Transparent プールを示すチャート

<br/>

Zcash の Transparent プールは非シールドであり、プライベートではありません。Zcash の Transparent ウォレットアドレスは "t" で始まり、このアドレスタイプを取引に使用する場合のプライバシーは非常に低いです。

Zcash における Transparent 取引は Bitcoin の取引に似ており、マルチシグ取引をサポートし、標準的な公開アドレスを使用します。

Zcash の Transparent は主に中央集権型取引所で使用されており、ユーザー間で ZEC を送受信する際に、高い透明性とネットワーク確認を確保するために使われています。

また、Zcash のシールドアドレスは取引時に高いプライバシーを提供する一方で、取引処理により多くの計算リソースを必要とする点にも注意が必要です。そのため、一部のユーザーは同程度のプライバシーを必要としない取引には Transparent アドレスを採用することがあります。

<br/>

## プール間転送の推奨プラクティス

Zcash ネットワーク上で取引時に高いレベルのプライバシーを重視する場合は、以下のプラクティスに従うことが推奨されます。

Zcash ブロックチェーン上で "z から z" のウォレット間で行われる取引は、ほとんどがシールドされており、高いレベルのプライバシーが得られることから Private Transaction と呼ばれることもあります。これは通常、プライバシーが必要な場合に $ZEC を送受信するための最良かつ最も推奨される方法です。 

---

ZEC を "Z-address" から "T-address" に送る場合、それは単に Deshielding transaction の一形態を意味します。このタイプの取引では、ZEC を Transparent Address に送る影響により、いくつかの情報がブロックチェーン上で可視になるため、プライバシーレベルは常に高いとは限りません。高いプライバシーが必要な場合、Deshielding transaction は常に推奨されるわけではありません。 

---

Transparent Address（T-address）から Z-address へ ZEC を転送することは、単に Shielding として知られています。このタイプの取引では、z-z 取引と比較するとプライバシーレベルは常に高いとは限りませんが、プライバシーが必要な場合にはこれも推奨されます。 

---

Zcash ネットワーク上で Transparent Address（T-address）から別の Transparent Address（T-address）へ ZEC を送ること（T-T transaction）は、Bitcoin の取引に非常によく似ています。このため、Zcash における T-T 取引は常に Public transactions と呼ばれます。送信者と受信者の取引詳細がどちらも公開されるため、この種の取引におけるプライバシーレベルは非常に低くなります。 

ほとんどの暗号通貨の中央集権型取引所は、Zcash ブロックチェーン上で取引する際に Transparent Address（"T-address"）を使用していますが、このタイプの取引（T-T）にはプライベートな性質はまったくありません。

<br/>

## Orchard から Ironwood への移行

移行は現在進行中です。Orchard は新規預け入れに対して封鎖されており、そこに残っている価値は、1取引ずつ Ironwood へ移っています。集計値は [ironwood.live](https://ironwood.live/) で確認できます。

これが何を意味するかは、資金がどこにあるかによって異なります:

1. **新しいシールド活動** は自動的に Ironwood に入ります。何もする必要はありません。
2. **既存の Orchard 資金** は移行が必要です。メンテナンスされているウォレットがこれを代行し、通常は一度に全部ではなく段階的に行います。
3. **Sapling は影響を受けません**。引き続き資金を受け入れます。封鎖されたのは Orchard だけです。
4. **turnstile はすべてを数えます**。プール間を移動するすべての価値を数えることで、途中でコインが新たに作られていないことを証明します。

> **知っておくべきプライバシー上の注意点が1つあります。** turnstile は、プール間を移動する *金額* をブロック高とともに公開します。送信者と受信者は通常どおり隠されたままですが、特徴的な金額はあなたに結び付けられる可能性があります。このため、ウォレットは残高全体を一度に識別可能な塊として動かすのではなく、標準的な額面を使って段階的に移行します。ウォレットにそのペース配分を任せ、さらに IP が移動額と結び付けられないように Tor や VPN の利用も検討してください。

アップグレード自体については [Ironwood](/zcash-tech/ironwood) を、会計の仕組みについては [The Turnstile](/zcash-tech/the-turnstile) を参照してください。

<br/>

## 避けるべきよくあるミス

- **t-address から t-address へ送ること** — 完全に公開され、プライバシーはありません。必ず先に資金をシールドしてください。
- **Orchard がまだ資金を受け入れると思い込むこと** — 2026年7月28日以降は支出専用です。価値は出ていけますが、新たな価値は入りません
- **Sapling と Unified addresses を混同すること** — Sapling アドレスは `zs` で始まります。Unified addresses は `u1` で始まり、複数の受信先を束ねているため、そのアドレスがどの受信先を持つかによって、支払いが着地するプールが決まります
- **資金を Sprout プールに置いたままにすること** — Sprout は何年も前から非推奨です。資金をそこから移してください
- **移行が完全に見えないものだと期待すること** — turnstile を通過する金額は公開されます。送信者と受信者は公開されないとしても同様です
- **t → z（shielding）が完全にプライベートだと思い込むこと** — シールド化という行為自体はオンチェーンで見えます。中身は見えません
