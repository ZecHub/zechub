# Zcash ウォレット（Wallet）資金の復旧

**なぜ復旧用の情報を保管しておくのですか？**

シード、支出鍵（spending key）、ビューイングキー（viewing key）、ウォレットファイルは互換的に使えるものではありません。シードフレーズ（seed phrase）は多くのウォレットの鍵を導出できますが、すべてのレガシー鍵やウォレットファイルの代わりにはなりません。ビューイングキーはシールドされた（shielded）アクティビティを確認できますが、支出を承認することはできません。

復旧には、正しい支出権限と、資金を保有するプール（pool）に対応した現在サポートされている経路が必要です。復旧用の情報は非公開に保ち、信頼できない相手にシード、支出鍵、またはウォレットファイルを決して共有しないでください。

# セキュリティと責任

ユーザーが秘密鍵を扱うことに伴うリスクを理解し、これらの鍵を不正アクセスから保護することは極めて重要です。資金のセキュリティは、ユーザーが自身の秘密鍵を安全に保護する責任にかかっています。

## レガシーのシールドされた資金: Sprout、Sapling、およびOrchard

古いシールドされたZECは、復旧の一環として移行が必要になる場合があります。経路は、現在どのシールドされたプールが資金を保有しているかによって異なります。

> **NU7は2026年11月5日に予定されています。** 有効化されると、レガシーのSproutプールから移行する現在の経路は機能しなくなります。
>
> SproutプールにZECがまだある場合は、アップグレード前に移行してください。有効化後は、既存のツールではSprout資金をSapling、公開型（transparent）アドレス、またはその他の宛先へ移動できなくなります。
>
> このページを**NU7**の有効化後に見ている場合、**Sproutは氷の中で凍結されています**。将来の復旧方法が利用可能になるまで動かせませんが、現時点ではその予定はありません。

## 1ページで分かる答え

| あなたの資金がある場所 | 移行経路 | 行うこと |
| --- | --- | --- |
| **Sprout** | **Sprout → Sapling → Ironwood** | `wallet.dat`または単独のSprout支出鍵がある場合は、まず現在のArgos復旧経路を試してください。Argosが適していない場合は、完全なフィールドガイドにあるレガシーサイドカー経路を使用してください。SproutはまずSaplingに到達し、その後Ironwoodへ移動する必要があります。この経路はNU7のため時間的制約があります。 |
| **Sapling** | **Sapling → Ironwood** | Sproutの復旧環境は必要ありません。特定のSaplingアカウントを復旧または支出でき、Ironwoodトランザクション（transaction）を構築できる現在のウォレットを使用してください。Ironwoodのサポートだけでは、レガシーSaplingの復旧サポートを証明しません。 |
| **Orchard** | **Orchard → Ironwood** | Orchardは退出専用です。現在対応しているウォレットの組み込みOrchardからIronwoodへの移行フローを使用してください。[復旧済み資金とIronwoodプール](#recovered-funds-and-the-ironwood-pool)を参照してください。 |

### 5つの質問による判断フロー

1. **Sproutですか？** シードフレーズだけでは、Sproutではなく後期のSapling/Orchard時代の復旧経路を示します。`zc...`アドレス、またはSprout残高を報告する復元済みウォレットは、Sproutを示します。
2. **どのような復旧用の情報がありますか？** `wallet.dat`、古いコンピューターまたはdatadir、`z_exportwallet`バックアップ、またはエクスポート済みのSprout支出鍵を探してください。`zc...`アドレスだけでは不十分です。
3. **Argosかレガシーサイドカーか？** `wallet.dat`または単独のSprout支出鍵があり、単に資金を引き出したい場合は、まず[Argos](#zecwallet-lite-and-legacy-wallet-recovery-with-argos)を試してください。Argosがその情報を処理できない場合、または完全な復旧スタックを自分で管理したい場合は、完全なフィールドガイドにあるレガシーサイドカー経路を使用してください。
4. **すでに同期済みでプルーニングされていないzcashd datadirがありますか？** これはレガシーサイドカー経路でのみ重要です。既存のノード（node）データは正常にシャットダウンした後にのみコピーしてください。そうでない場合、フィールドガイドでスナップショットまたはゼロから開始する選択肢を説明しています。
5. **資金は最終的にどこへ行きますか？** **Ironwood。** Sproutは、単一の直接的なSproutからIronwoodへのトランザクションがないため、まずSaplingを通過します。Saplingで止めないでください。

> **開始前に:** まず、**何を復旧するのか、またどの復旧用情報がまだあるのか**を確認してください。現在のウォレットシードまたはサポートされている非Sprout支出鍵なら、通常の復元だけで済む可能性があります。Zecwallet Liteシード、レガシー`wallet.dat`、または単独のSaplingあるいはSprout支出鍵など、古い情報には専用の復旧経路が必要な場合があります。
>
> 資金が**Sprout**にあると思う場合は、復旧に時間を割く前に、支出権限がまだあることを確認してください。`zc...`アドレスまたはビューイング用の情報だけでは、資金を移動できません。
>
> **YWalletは、Ironwood以降、Zcashをサポートしていません。** サポートされているシードおよび鍵から通常の非Sprout復元を行うには**Zkool**を使用してください。Zecwallet Liteの復旧、レガシーウォレットファイル、および単独のSapling/Sprout支出鍵には**Argos**を使用してください。Sproutについては、まずArgosを試す経路です。完全なフィールドガイドでレガシーサイドカーへのフォールバックを扱っています。
>
> 覚えている復旧ツールではなく、**実際に持っているもの**に基づいて下表を使用してください。

| 持っているもの | ここから始める |
| --- | --- |
| 現在または最近まで保守されていたウォレットのシードフレーズ、またはサポートされている**非Sprout支出鍵**。古いYWalletZcashの情報を含みます | [Zkool](#fund-recovery-with-zkool) |
| **ビューイングキーのみ** | Zkoolは、読み取り専用アクセスのために対応しているビューイングキーをインポートできますが、ビューイングキーは復旧時の支出を承認できません。対応するシードまたは支出鍵を見つけてください。 |
| 24語の**Zecwallet Lite**シード | [Argos](#zecwallet-lite-and-legacy-wallet-recovery-with-argos) |
| Zecwallet Liteまたはzcashd`wallet.dat`、あるいは単独のSapling / Sprout支出鍵 | [Argos](#zecwallet-lite-and-legacy-wallet-recovery-with-argos)。2026年9月18日時点でv1.3.0が最新かつ推奨です。`wallet.dat`およびSproutの復旧にはv1.2.0以降を使用してください。 |
| Argosが処理できないSprout情報、またはレガシーコンポーネントを自分で管理したい復旧 | [完全なフィールドガイド](/research/zec-pool-migration/view)にあるレガシーサイドカー経路を使用してください。 |
| 有効なシードまたは支出鍵はないが、ロックされたデバイス、忘れたパスワード、または故障したディスクがある | [専門的な復旧](#professional-recovery-when-you-do-not-have-the-seed)。依頼していないのに連絡してくる人には、有効なシードまたは支出鍵を決して送らないでください。 |

## Zkoolによる資金の復旧

[Zkool](https://github.com/hhanh00/zkool2/releases)は、同じdeveloper（developer）によるYWalletの保守されているZcash後継です。レガシーSapling鍵を含む公開型および現代のシールドされた復旧経路をサポートしますが、**Sprout**はサポートしません。

ここでは2つの状況を扱います。

1. シードフレーズ、秘密鍵、またはビューイングキーからの**アカウントの復元**
2. 公開型アドレスのみをサポートしていたウォレットからの**資金のスイープ**

### 1) アカウントの復元

1. [リリースページ](https://github.com/hhanh00/zkool2/releases)からZkoolをインストールし、開きます
2. **アカウントマネージャー**（メインページ）で、**+**ボタンをタップして**新規アカウント**画面に進みます
3. このアカウントを識別するための**アカウント名**を入力します
4. **アカウントを復元しますか？**をオンにします。これにより、鍵と開始ブロック高のフィールドが表示されます
5. **鍵（シードフレーズ、秘密鍵、またはViewing Key）**に鍵を貼り付けます。Zkoolはシードフレーズ、Sapling秘密鍵、公開型拡張鍵、およびサポートされているビューイングキーを受け入れます。ビューイングキーは読み取り専用であり、支出を承認できません。
6. 古いアカウントには**開始ブロック高**を入力します。Zkoolはこの高さより前のブロックをスキャンしないため、不明な場合はウォレットの最初のアクティビティより前の高さを選んでください。開始ブロック高を遅すぎる値にすると、実際のトランザクションが見つからないように見える場合があります。

![Zkool New Account screen with Restore Account and Advanced Options both turned on](/content-images/zkool-restore-account-60b1d2777e.webp)

7. アカウントを保存してから同期します

### 別のウォレットからのシードの復元

シードが、ZODL（旧Zashi）、Zingo、またはzcashdを含むZIP 316に従うウォレットから来た場合は、保存前に**詳細オプション**をオンにして**内部変更を使用**を有効にしてください。

ZIP 316は、別個の内部/変更アドレスを使用します。**内部変更を使用**せずにこれらのアカウントを復元すると、資金が残っているにもかかわらず変更出力が見つからないように見える場合があります。

さらに2つのフィールドが**詳細オプション**にあります。

- 元のウォレットで使用した場合のみ、**追加パスフレーズ（任意）**
- 元のウォレットが1つのシードに複数のアカウントを保有していた場合の**アカウントインデックス**。資金が別のインデックスにある可能性があります

> **この2つは、鍵フィールドに有効なシードフレーズがある場合にのみ表示されます。** フィールドが空の場合、または秘密鍵やビューイングキーが入力されている場合、Zkoolには**内部変更を使用**と**H/W Ledger**のみが表示されます。まずシードを貼り付け、それから詳細オプションを開いてください。

### 2) 公開型専用ウォレットからの資金のスイープ

古いウォレットまたはアカウントが**公開型ZECのみ**を保有していた場合は、最初にアカウントを復元し、使用済みの公開型アドレスをすべて見つけてから、管理下にある現在のシールドされた宛先へ資金を移動してください。古いウォレットブランド（brand）が常に公開型専用だったとは考えないでください。一部の製品は後のバージョンでシールドされたサポートを追加しました。

1. 上記の手順でアカウントを復元します
2. アカウントを開き、**資金を受け取る**ページに進みます
3. 上部バーの虫眼鏡（**他の公開型アドレスを検索**）をタップします。LedgerやExodusのようにアドレスをローテーションするウォレットは、1つのシードから多くの公開型アドレスを生成します。これにより資金を保有するアドレスを見つけられます
4. その後、**アカウントをリセットして同期してください。** 新しく見つかったアドレスは次のスキャンでのみ残高を取得するため、これを省略するとスイープで何も見つからなかったように見えます
5. **送信**ページに進みます。残高の横に3つのアイコンボタンがあります。テキストラベルはないため、ホバーまたは長押しして名前を確認してください。
   - **Shield One**（輪郭だけの盾）は、一度に1つの公開型アドレスを移動します
   - **Shield All**（塗りつぶされた盾）は、すべての公開型アドレスから一度にすべてを移動します
   - **Unshield All**（開いた南京錠）は逆方向、つまり公開型アドレスへ移動します

> **Shield Oneのほうがよりプライベートな選択です。** 複数のアドレスを1つのトランザクションでシールドすると、それらが同一人物に属することが公開上結び付けられます。Zkool自身も、Shield Allを実行する前にこれについて警告します。

6. トランザクションを確認して送信します

Unshield Allは、公開型アドレスしか受け付けない取引所（exchange）へ出金するときに役立ちます。シールド用ボタンはアカウントにシールドされたアドレスがある場合にのみ表示され、Unshield Allは公開型アドレスがある場合にのみ表示されます。

## Zecwallet LiteおよびレガシーウォレットのArgosによる復旧

[Zecwallet Lite](https://github.com/adityapk00/zecwallet-lite)は現在保守されておらず、そのリポジトリはアーカイブされています。そのシード導出は現在のウォレットが使用するレイアウトとは異なるため、同じフレーズを現代のウォレットにインポートすると、Zecwallet Liteの追加導出アドレスに保有されている資金を見逃す場合があります。[Argos](https://argos.sovright.com)は、Sovrightによる、このケースおよびその他のレガシー復旧ケース向けに作られたデスクトップ復旧ワークスペースです。

Argosは、Zecwallet Liteのシードとウォレットファイル、zcashd`wallet.dat`、単独のSapling拡張支出鍵、およびSprout支出用情報を読み取ります。Sproutでは、それらの鍵は別個に生成されていたため、Zecwallet Liteシードだけでは不十分です。Argosは日常利用のウォレットではなく復旧ツールです。ソース情報をローカルで確認し、スキャンしてから、管理下にある保守済みウォレットへスイープしてください。

Least Authorityはこのツールを[監査しました](https://argos.sovright.com/assets/least-authority-argos-audit-2026-06-29.pdf)。復旧自体は無料です。スイープ時にSovrightへの任意の寄付が表示される場合があります。

> **ウェブサイトにシードを入力しないでください。** Argosサイトはダウンロードと[ユーザーガイド](https://argos.sovright.com/guide.html)のためだけのものです。鍵は署名済みデスクトップアプリ内に留まります。検証はBIP-39チェックサムに対してローカルで行われます。スキャンが開始されるとシードフィールドは消去されます。「資金の復旧を手伝う」としてそのシードを求めるメッセージを送る者は、すべて詐欺です。

### Argosを開く前に

1. [公式Argosサイト](https://argos.sovright.com)または[GitHubリリースページ](https://github.com/sovright/argos/releases)からデスクトップアプリをダウンロードしてください。公開されている場合はチェックサムまたは署名を検証してください。
2. 現在のArgosリリースを使用してください。2026年9月18日時点で、**v1.3.0**が最新かつ推奨です。**`wallet.dat`およびSproutの復旧にはv1.2.0以降を使用してください。** 1.1.0より古いビルドでもスキャンは可能ですが、ネットワークが拒否するIronwood以前のスイープを構築します。更新して再試行してください。
3. 信頼できるマシンで作業してください。フルディスク暗号化（encryption）を推奨します。シード、パスフレーズ、または支出鍵が表示されている間は画面共有を行わないでください。
4. [ZODL](https://zodl.com/)など、管理下にある保守済みウォレットから宛先の統合アドレスを準備してください。Argosに貼り付ける前に、そのウォレット内でアドレスを確認してください。

### シードの復旧

1. Argosを開き、**24語のシードフレーズを持っています**を選択します。シード復旧にはウォレットファイルは不要です。
2. フレーズを貼り付け、**シードを検証**をクリックします。シードが有効と表示された場合は続行してください。
3. **誕生日ブロック高**、またはウォレットが作成された時期に最も近い推定値を入力します。早い高さは遅すぎる推測よりも遅くなりますが安全です。
4. サーバーコントロールでは、現在のサーバープリセットを使用するか、lightwalletd URLを入力してください。カンマ区切りのURLは順番に試行されます。公開例:

   `https://zec.rocks:443,https://zec-node.cakewallet.com:443,https://na.zec.rocks:443`

5. 宛先の統合アドレスを貼り付けます。
6. **スキャン開始**をクリックします。誕生日ブロック高によっては、数分から数日かかる場合があります。同じワークスペースを終了して再び開くことができ、スキャンは再開されます。
7. スキャンが完了したら、残高、推定手数料、宛先を確認し、**スイープ**をクリックします。

スイープのブロードキャストは取り消せません。関連するすべてのプールがスイープされ、宛先ウォレットに想定どおりの資金が表示されるまで、元のウォレットファイルを保管してください。復旧が完了したら、新しいアクティビティに使い続けるのではなく、レガシーの秘密情報を退役させてください。

### ウォレットファイルと単独の鍵

ウェルカム画面の**ウォレットファイルを持っています**は、Zecwallet Liteファイル、zcashd`wallet.dat`、または単独のSapling拡張支出鍵を対象にします。単独のSprout支出鍵の復旧は、ArgosのSprout復旧経路/CLIで処理されます。

Argosはウォレットファイルを変更せずに読み取ります。ウォレットが暗号化されている場合は、求められたときにパスフレーズを入力してください。これはメモリ内で使用され、ディスクには書き込まれません。スキャンを開始する前に、公開型、Sapling、およびSproutの鍵の数を確認してください。

ビューイングキーは支出を承認できないため、スイープには使用できません。

### Sproutに関する注意

Zecwallet LiteシードはSprout鍵を導出しません。これらの鍵は別個に生成されていました。Sproutは、zcashd`wallet.dat`から、またはCLI内の単独支出鍵から復旧してください。

ファイルにすでに支出可能なノート（note）データとキャッシュ済みのwitnessがある場合、Argosはチェーン（chain）スキャンなしで**Sprout資金をスイープ**できる場合があります。そうでない場合は、P2Pネットワーク上で再開可能なフルブロックスキャンを実行できます。このスキャンは大規模で低速です。書き込まれるチェックポイントは支出可能であるため、元のウォレットと同様に保護してください。

Sproutの価値はSaplingにのみ到達できます。Sapling資金が確認され支出可能になった後、復旧済みのSaplingアカウントをサポートする現在のウォレットを使用して、**Ironwood**へさらに移動してください。Saplingで止めないでください。

## 復旧済み資金とIronwoodプール

Ironwood（NU6.3）アップグレードが2026年7月28日に有効化されて以降、Orchardプールは支出専用です。新たな価値は入れられず、既存の価値はターンスタイル（turnstile）を通じてIronwoodへ出ていきます。

復旧した資金がOrchardにある場合は、**現在のウォレットの組み込み移行フロー**を使用してIronwoodへ移動してください。OrchardはNU6.3以降、退出専用です。

Zkool 6.30.0は2026年9月18日時点で最新であり、Ironwoodをサポートします。その移行設計はプライバシー重視ですが、ZIP 318への準拠を主張することとは別です。他の現在のウォレットはZIP 318スタイルの段階的移行を使用する場合があります。手動で金額やスケジュールを作り出すのではなく、インストール済みウォレットの現在の移行画面とリリースノートに従ってください。

段階的な移行では複数のトランザクションを使用する場合があるため、合計手数料は一括転送より高くなる可能性があります。

> **移行額は公開されます。** 価値がターンスタイルを通過すると、送信者と受信者はシールドされたままであっても、金額とブロック高はオンチェーン（on-chain）で確認できます。プライバシーが重要な場合は、ウォレットの組み込みプライベート/段階的移行ポリシーを使用し、適切な場合はTorまたは別の信頼できるプライバシーレイヤーなどのネットワークレベルのプライバシーを使用してください。ネットワークプライバシーはIPとの関連を隠せますが、公開される通過金額は隠しません。

## ZExCavatorによる深い復旧

[ZExCavator](https://github.com/zingolabs/zexcavator)は、現在Zecwallet Liteウォレットファイルおよびウォレット形式の移行に焦点を当てている、**開発中**のZingo Labs復旧プロジェクトです。そのREADMEは、より完全なZeWIFサポートが開発中である間、資金復旧のユーザーを**Zingolib**エクスポートオプションへ案内しています。

デフォルトの復旧経路ではなく、高度なエッジケース向けツールとして扱ってください。通常のZecwallet Liteシード、ウォレットファイル、zcashd`wallet.dat`、およびサポートされている単独支出鍵については、まずArgosを試してください。ZExCavatorによって復旧されたものは、それを信頼する前に保守済みウォレットで検証してください。

## シードがない場合の専門的な復旧

シードまたは鍵が失われた場合、セルフホスト型の復元は開始できません。この状況にある一部の人は、忘れたパスワード、ハードウェア障害、または読み取れないディスクのために専門の復旧会社を利用します。

この経路は、まだ保有しているシードを復元することとは異なります。「復旧」すると申し出る相手に、有効なシードを渡してはいけません。このサービスの詐欺版は一般的です。

[Unciphered](https://unciphered.com)は、この作業を社内で行っており、Wiredなどで取り上げられた会社の1つです。同社は一般的な暗号資産復旧サービスであり、Zcash固有のツールではなく、作業には料金がかかります。ZecHubはいかなる復旧会社も推奨しません。この経路を選ぶ場合は、公式ドメインを自分で確認し、最初にDMしてくる人は詐欺師だと考えてください。

有効なシードまたは支出鍵がまだある場合は、代わりに自身のマシンでZkoolやArgosなどのセルフホスト型復旧経路から始めてください。

## YWalletは現在保守されていません

YWalletは長い間このページで推奨される復旧ツールであり、多くの古いガイドはいまもこれを指しています。

そのdeveloperは現在、YWalletはIronwoodアップデート以降Zcashをサポートしていないと述べ、Zcashユーザーを保守されている後継の**Zkool**へ案内しています。古いYWalletシード/鍵の情報は保管してください。ただし、YWalletで新しいZcash移行を開始しないでください。

YWalletからのZcash復旧用情報をすでに持っている場合は、上記のサポートされているシード/鍵経路を使用してZkoolで復元してください。
