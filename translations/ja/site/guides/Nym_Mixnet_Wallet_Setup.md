# Zcash ウォレット（Wallet）のトラフィックをNym ミックスネット（Mixnet）経由でルーティングする

> 最終確認日: 2026年9月29日

Zcashのシールドされた（shielded）トランザクション（transaction）はオンチェーンのトランザクションデータを保護しますが、ウォレットは依然としてインターネット経由で通信します。ネットワークの観測者は、IPアドレス、ウォレットが接続する時点、接続先のインフラストラクチャなどのメタデータを把握できる可能性があります。

Nymは、独立したネットワーク・プライバシー（privacy）レイヤーを追加します。2026年9月時点で、最適なアプローチはウォレットによって異なります。

1. **利用可能な場合は、ウォレットにネイティブのNym統合があるものを優先してください。**
2. それ以外の場合は、**システムレベルのNymVPN Mixnetモード**を使用し、ウォレット固有のプロキシ対応に依存せず、ウォレットのネットワークトラフィックをNym経由でルーティングしてください。

一般的なVPNおよびdVPNの背景については、[VPN & dVPN](../Privacy_Tools/VPN_and_DVPN.md)を参照してください。

## Nymが追加するものと、追加しないもの

シールドされたZcashの支払い（payment）とネットワーク・プライバシーツールは、異なる問題を解決します。

- **Zcashのシールドされたプール（pool）**は、オンチェーンのトランザクション詳細を保護します。
- **Nymのミックスネット・ルーティング**は、実際のネットワークIDと、ウォレットトラフィックを受信するサービスとの間の関連付け可能性を低減するよう設計されています。
- システムレベルのNymVPNトンネル経由で接続される宛先には、自宅またはモバイル回線のIPではなく、Nymの出口が見えるはずです。

Nymのミックスネットは、複数ホップ、パケットミキシング、ランダム化された遅延、カバートラフィック、およびオニオン暗号化（encryption）を使用して、ネットワークメタデータの漏洩を低減します。

Nymは、侵害されたデバイス、悪意あるウォレットソフトウェア、露出したリカバリーフレーズ、取引所（exchange）アカウントを通じて明かしたID、または公開型（transparent）のZcash活動によるプライバシーの喪失からは**保護しません**。

## ネイティブNymサポート: 利用可能な場合はまずこれを使用してください

Nymは2026年9月24日、Zcash Community Grantの作業が完了し、ネイティブのミックスネットサポートが実際のZcashウォレットで提供開始されていると発表しました。

### Zingo! ウォレット

Zingo PCにはネイティブのNymトランスポートが含まれています。Zingo Mobileも、アプリ内のNymプロキシを使用して、iOSおよびAndroidでMixnet Modeを提供しています。

Zingoにより文書化されている現在の動作:

- Nymコントロールは、**Settings → Nym Mixnet**にあります。
- 支払いの送信はミックスネット経由でルーティングされます。
- Ironwoodの移行送信も、同じ保護された送信経路に従います。
- ZECの価格リクエストもミックスネット経由でルーティングされます。
- Nymが有効な間、送信はフェイルクローズします。ミックスネットトランスポートが利用できない場合、支払いは通常のインターネット経由で暗黙的に送信されません。
- **チェーン（chain）の同期は現在、Zingo PCではミックスネット経由でルーティングされません**。コンパクトブロック、ヌリファイア（nullifier）クエリ、トランザクションの取得、メモリプールトラフィック、サーバー健全性チェックは、依然として通常のサーバー接続を使用します。

この違いは重要です。Zingoのネイティブ統合は、最も関連付けやすいブロードキャスト経路を保護しますが、まだデバイス全体のネットワークトンネルではありません。

脅威モデルでサーバーから同期トラフィックも隠す必要がある場合は、NymVPNなどのシステムレベルのプライバシートンネルを使用するとともに、これにより追加されるレイテンシーと複雑さを理解してください。

情報源:

- https://github.com/zingolabs/zingo-pc#the-nym-mixnet
- https://github.com/zingolabs/zingo-mobile
- https://nym.com/blog/nym-mixnet-zcash-wallets

### Zkool

Nymは、**Zkool**がネイティブトグルを使用して、Nymミックスネット経由でZcash RPCインフラストラクチャへ接続できるようになったと報告しています。

ZkoolはYWalletの積極的に保守されている後継です。そのプロジェクトは、Zcashサーバー接続向けのTorプロキシおよびオニオンサービスもサポートしています。

文書化されていないプロキシ経路で古いYWalletビルドを無理に使用しようとするより、ZkoolのネイティブNymオプションを優先してください。

情報源:

- https://nym.com/blog/nym-mixnet-zcash-wallets
- https://github.com/hhanh00/zkool2

### Nozy

NozyWalletにもNym対応のトランスポート経路があります。現在の実装では、送信トランザクションの送信をNymミックスネット経由でルーティングし、コンパクトブロック同期には別個のNym dVPN経路を使用できます。すべてのウォレットリクエストが自動的にミックスネットを使用するとは考えず、これらを異なる保護として扱ってください。

情報源:

- https://github.com/LEONINE-DAO/Nozy-wallet
- https://github.com/LEONINE-DAO/Nozy-wallet/blob/master/docs/reference/NYM_SEND_EGRESS_CASE_BREAKDOWN.md
- https://github.com/LEONINE-DAO/Nozy-wallet/blob/master/docs/reference/NYM_DVPN_SYNC_CASE_BREAKDOWN.md

### Zodl

Zodlには現在、組み込みの**Tor Protection**があります。これは、上記でZingo、Zkool、Nozy向けに説明したネイティブNym統合とは異なります。

ZodlのTor機能は、トランザクション送信、トランザクションデータの取得、為替レートリクエスト、サードパーティAPI呼び出しをTor経由でルーティングできます。Nymは2026年9月24日、より広範なミックスネット統合についてZodlチームと引き続き積極的に協議していると述べました。

現在のZodlでは、次のいずれかを使用してください。

- Zodlにより文書化されたTor Protection、または
- ウォレットの一般的なデバイストラフィックをNym経由でルーティングすることが目的であれば、システムレベルのNymVPN。

どちらもプライバシーネットワークだからといって、TorとNymがウォレット内で交換可能なトランスポートであるとは考えないでください。

ZodlのTor設定:

**More → Advanced Features → Beta: Tor Protection → Enable → Save changes**

情報源:

- https://support.zodl.com/article/17-enabling-tor-protection
- https://nym.com/blog/nym-mixnet-zcash-wallets

## フォールバック: システムレベルのNymVPN

これは、ウォレットがNym固有のプロキシ設定を理解する必要がないため、最も幅広く互換性のあるNymオプションです。

### 1. NymVPNをインストールする

NymVPNは、Nymの公式ウェブサイトまたは公式プラットフォームストアからのみダウンロードしてください。

- https://nym.com/
- https://nym.com/blog/nymvpn-v2026.12

NymVPNは、Android、iOS、Linux、Windows、およびmacOSをサポートしています。

### 2. Mixnetモードを選択する

NymVPNは、より低いレイテンシー向けに最適化された2ホップdVPN経路である**Fast mode**と、より強力なネットワークメタデータ保護向けに最適化された5ホップミックスネット経路である**Mixnet mode**を提供しています。センシティブなウォレット活動ではMixnet modeを選択し、ウォレットを開くまたは更新する前に、クライアントが接続確立を報告するまで待ってください。

### 3. ウォレットは通常のネットワーク設定のままにする

オペレーティングシステムがすでにNymVPN経由でトラフィックをトンネリングしている場合、ほとんどのウォレットにはカスタムプロキシ設定は必要ありません。

ウォレットを通常どおり開き、同期させてください。

NymVPNがプラットフォーム上でスプリットトンネリングを提供している場合、ウォレットがバイパスまたは除外リストに置かれておらず、**保護されたトンネルに含まれている**ことを確認してください。

### 4. ウォレットを使用する前にトンネルを確認する

簡単なシステムレベルの確認方法:

1. NymVPNを切断します。
2. 公開IP確認サービスにアクセスするか、デスクトップでは次を実行します。

   ```bash
   curl https://api.ipify.org
   ```

3. 表示されるIPを記録します。
4. MixnetモードでNymVPNに接続します。
5. 確認を繰り返します。

表示される公開IPは変わるはずです。

これはシステムトンネルを確認します。ただし、アプリまたはOSに特別なルーティングルールがある場合、特定のウォレットによるすべてのリクエストが同じ経路に従うことを証明するものでは**ありません**。

デスクトップでより確実に確認するには:

- OSのネットワークモニターでウォレットプロセスを調べます。
- スプリットトンネルの除外がないことを確認します。
- NymVPNが切断された場合に、想定どおりウォレットの動作が変わることを確認します。

トラブルシューティング中は、ウォレットアドレス、残高、トランザクションID、IPアドレス、またはリカバリー情報を含むスクリーンショットを投稿しないでください。

## NymVPN dApp / ウォレットプロキシモード

NymVPNは、ミックスネット経由のSOCKS5 / RPCルーティングを使用するアプリおよびウォレットプロキシモードも提供しています。

Nymの公開セットアップ文書では、主にEthereum形式のRPC設定でこれを示しています。互換性のある汎用プロキシ/RPC経路を明示的にサポートするソフトウェアには有用ですが、すべてのZcashウォレットで動作すると想定すべきでは**ありません**。

ウォレット自身の文書が互換性のあるプロキシまたはRPCサポートを確認している場合にのみ、この経路を使用してください。

それ以外の場合は、次を優先してください。

- ウォレットのネイティブNym統合、または
- システムレベルのNymVPN。

## パフォーマンスとタイムアウトのトレードオフ

ミックスネットは、より強力なメタデータ保護のために意図的に速度を犠牲にします。

次の項目に影響が生じる可能性があります。

- 初回ウォレット同期、
- 大規模な追いつき同期、
- トランザクション履歴クエリ、
- RPCタイムアウト、
- サードパーティAPI呼び出し。

実用的な指針:

- デフォルトのNym設定から始めてください。
- 初回同期または長時間の追いつき同期には時間がかかることを想定してください。
- プライバシー設定を弱める前に、タイムアウトを再試行してください。
- センシティブなトランザクションの直前に、プライバシーモードを繰り返し切り替えないでください。
- 大量同期に高速な経路を使用する場合、その期間中に接続先インフラストラクチャが実際のネットワークIDを観測できる可能性があることを理解してください。
- 特にZingo PCについては、そのネイティブNymトランスポートが現在保護するのは送信と価格検索であり、同期は直接接続のままであることを覚えておいてください。

## モバイルに関する考慮事項

AndroidおよびiOSでは、一般的なウォレットトラフィックをNymVPN経由でルーティングする最も簡単な方法は、通常、OSのVPNスロットを使用することです。まずNymVPNに接続してから、ウォレットを開いてください。

別のVPN、ファイアウォール、またはローカルVPNベースの広告ブロッカーがすでにシステムVPNインターフェースを使用している場合、2つの製品は同時に動作できない可能性があります。ウォレットが保護されていると考える前に、OSのVPN状態を確認してください。

## 脅威モデルのチェックリスト

設定に依存する前に、次を確認してください。

- 適切な場面でシールドされたZcashアドレス（address）を使用していますか？
- 私のウォレットはネイティブNymサポートを備えていますか？
- 備えている場合、そのネイティブ統合は具体的にどのトラフィックを保護しますか？
- より広範な保護が必要な場合、ウォレットがネットワーク活動を開始する前にNymVPNは接続されていますか？
- ウォレットはスプリットトンネリングルールによって除外されていますか？
- ウォレットが実際に文書化しているプロキシモードに依存していますか？
- 取引所、ブラウザーセッション、サードパーティAPI、または公開型アドレスを通じてIDを漏らしていませんか？
- 同期の遅延や時折発生するタイムアウトに備えていますか？
