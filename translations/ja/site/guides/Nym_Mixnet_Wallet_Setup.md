# Zcash ウォレットのトラフィックを Nym Mixnet 経由でルーティングする

> 最終確認日: 2026年9月29日

Zcash のシールド取引はオンチェーンの取引データを保護しますが、ウォレットは依然としてインターネット経由で通信します。ネットワーク監視者は、IP アドレス、ウォレットが接続する時刻、接続先インフラなどのメタデータを把握できる可能性があります。

Nym は、独立したネットワークプライバシー層を追加します。2026年9月時点で、最適な方法はウォレットによって異なります。

1. **利用可能な場合は、ウォレットにネイティブ搭載された Nym 統合を優先してください。**
2. それ以外の場合は、**システムレベルの NymVPN Mixnet モード**を使用し、ウォレット固有のプロキシ対応に依存せず、ウォレットのネットワークトラフィックを Nym 経由でルーティングしてください。

一般的な VPN および dVPN の背景については、[VPN と dVPN](./VPN_and_DVPN.md) を参照してください。

## Nym が追加するものと、追加しないもの

シールドされた Zcash 支払いとネットワークプライバシーツールは、異なる問題を解決します。

- **Zcash のシールドプール**は、オンチェーンの取引詳細を保護します。
- **Nym の mixnet ルーティング**は、実際のネットワーク ID とウォレットトラフィックを受信するサービスとのリンク可能性を低減するよう設計されています。
- システムレベルの NymVPN トンネル経由で接続した宛先には、自宅またはモバイルの IP ではなく Nym の出口が表示されるはずです。

Nym の mixnet は、複数ホップ、パケットミキシング、ランダム化された遅延、カバートラフィック、オニオン暗号化を使用して、ネットワークメタデータの漏えいを減らします。

Nym は、侵害されたデバイス、悪意あるウォレットソフトウェア、流出したリカバリーフレーズ、取引所アカウント経由で開示する ID、または透明な Zcash アクティビティによるプライバシー損失からは**保護しません**。

## ネイティブ Nym サポート: 利用可能な場合はまずこれを使用する

Nym は2026年9月24日、Zcash Community Grant の作業が完了し、ネイティブ mixnet サポートが実際の Zcash ウォレットに提供されていると発表しました。

### Zingo! Wallet

Zingo PC にはネイティブの Nym トランスポートが含まれています。Zingo Mobile も、アプリ内 Nym プロキシを使用する iOS および Android 向け Mixnet Mode を提供しています。

Zingo が文書化した現在の挙動:

- Nym コントロールは、**Settings → Nym Mixnet** にあります。
- 支払いの送信は mixnet 経由でルーティングされます。
- Ironwood の移行送信も、同じ保護された送信経路に従います。
- ZEC の価格リクエストも mixnet 経由でルーティングされます。
- Nym 有効中は送信がフェイルクローズします。mixnet トランスポートが利用できない場合、支払いが clearnet 経由で暗黙に送信されることはありません。
- Zingo PC では、**チェーン同期は現在 mixnet 経由でルーティングされません**。コンパクトブロック、nullifier クエリ、取引の取得、mempool トラフィック、サーバーヘルスチェックは、引き続き通常のサーバー接続を使用します。

この違いは重要です。Zingo のネイティブ統合はリンク可能性が最も高いブロードキャスト経路を保護しますが、まだフルデバイスのネットワークトンネルではありません。

脅威モデル上、サーバーから同期トラフィックを隠す必要もある場合は、追加されるレイテンシーと複雑さを理解したうえで、NymVPN などのシステムレベルのプライバシートンネルを併用してください。

情報源:

- https://github.com/zingolabs/zingo-pc#the-nym-mixnet
- https://github.com/zingolabs/zingo-mobile
- https://nym.com/blog/nym-mixnet-zcash-wallets

### Zkool

Nym は、**Zkool** がネイティブトグルを使用して、Nym mixnet 経由で Zcash RPC インフラへ接続できるようになったと報告しています。

Zkool は YWallet の積極的に保守されている後継です。そのプロジェクトは、Zcash サーバー接続向けの Tor プロキシおよびオニオンサービスもサポートしています。

文書化されていないプロキシ経路を介して古い YWallet ビルドを無理に使用しようとするより、Zkool のネイティブ Nym オプションを優先してください。

情報源:

- https://nym.com/blog/nym-mixnet-zcash-wallets
- https://github.com/hhanh00/zkool2

### Nozy

NozyWallet にも Nym 対応のトランスポート経路があります。現在の実装は、発信取引の送信を Nym mixnet 経由でルーティングし、コンパクトブロック同期には別個の Nym dVPN 経路を使用できます。すべてのウォレットリクエストが自動的に mixnet を使用すると仮定せず、これらを別個の保護として扱ってください。

情報源:

- https://github.com/LEONINE-DAO/Nozy-wallet
- https://github.com/LEONINE-DAO/Nozy-wallet/blob/master/docs/reference/NYM_SEND_EGRESS_CASE_BREAKDOWN.md
- https://github.com/LEONINE-DAO/Nozy-wallet/blob/master/docs/reference/NYM_DVPN_SYNC_CASE_BREAKDOWN.md

### Zodl

Zodl には現在、Zingo、Zkool、Nozy について上述したネイティブ Nym 統合とは異なる、組み込みの **Tor Protection** があります。

Zodl の Tor 機能では、取引送信、取引データ取得、為替レートリクエスト、サードパーティ API 呼び出しを Tor 経由でルーティングできます。Nym は2026年9月24日、より広範な mixnet 統合について Zodl チームと引き続き積極的に協議していると述べました。

現在の Zodl では、次のいずれかを使用してください。

- Zodl が文書化した Tor Protection、または
- 目的がウォレットの一般的なデバイストラフィックを Nym 経由でルーティングすることである場合は、システムレベルの NymVPN。

どちらもプライバシーネットワークだからといって、ウォレット内で Tor と Nym が交換可能なトランスポートであると考えないでください。

Zodl の Tor 設定:

**More → Advanced Features → Beta: Tor Protection → Enable → Save changes**

情報源:

- https://support.zodl.com/article/17-enabling-tor-protection
- https://nym.com/blog/nym-mixnet-zcash-wallets

## フォールバック: システムレベルの NymVPN

これは、ウォレットが Nym 固有のプロキシ設定を理解する必要がないため、最も幅広く互換性のある Nym オプションです。

### 1. NymVPN をインストールする

NymVPN は、Nym の公式ウェブサイトまたは公式プラットフォームストアからのみダウンロードしてください。

- https://nym.com/
- https://nym.com/blog/nymvpn-v2026.12

NymVPN は、Android、iOS、Linux、Windows、macOS をサポートしています。

### 2. Mixnet モードを選択する

NymVPN には、低レイテンシー向けに最適化された2ホップ dVPN 経路である**Fast mode**と、より強力なネットワークメタデータ保護向けに最適化された5ホップ mixnet 経路である**Mixnet mode**があります。機密性の高いウォレット操作では Mixnet mode を選択し、ウォレットを開くまたは更新する前に、クライアントが接続確立を報告するまで待ってください。

### 3. ウォレットは通常のネットワーク設定のままにする

オペレーティングシステムがすでにトラフィックを NymVPN 経由でトンネリングしている場合、ほとんどのウォレットでカスタムプロキシ設定は不要です。

通常どおりウォレットを開き、同期させてください。

プラットフォーム上で NymVPN がスプリットトンネリングを提供している場合、ウォレットがバイパスまたは除外リストに置かれるのではなく、**保護されたトンネルに含まれている**ことを確認してください。

### 4. ウォレットを使用する前にトンネルを確認する

簡単なシステムレベルの確認方法:

1. NymVPN を切断します。
2. 公開 IP 確認サービスにアクセスするか、デスクトップでは次を実行します。

   ```bash
   curl https://api.ipify.org
   ```

3. 表示された IP を記録します。
4. Mixnet mode で NymVPN に接続します。
5. 確認を繰り返します。

表示される公開 IP は変化するはずです。

これはシステムトンネルを確認するものです。アプリまたは OS に特別なルーティング規則がある場合、特定のウォレットによるすべてのリクエストが同じ経路を通ることを証明するものでは**ありません**。

デスクトップでさらに確信を得るには:

- オペレーティングシステムのネットワークモニターでウォレットプロセスを調べる
- スプリットトンネルの除外がないことを確認する
- NymVPN が切断された場合に、想定どおりウォレットの挙動が変わることを確認する

トラブルシューティング中に、ウォレットアドレス、残高、取引 ID、IP アドレス、またはリカバリー情報を含むスクリーンショットを投稿しないでください。

## NymVPN dApp / ウォレットプロキシモード

NymVPN は、mixnet 経由の SOCKS5 / RPC ルーティングを使用するアプリおよびウォレット向けプロキシモードも提供しています。

Nym の公開セットアップ文書では、主に Ethereum 形式の RPC 設定でこれを示しています。これは、互換性のある汎用プロキシ/RPC 経路を明示的にサポートするソフトウェアには有用ですが、すべての Zcash ウォレットで動作すると想定すべきではありません。

ウォレット自身の文書が互換性のあるプロキシまたは RPC サポートを確認している場合にのみ、この経路を使用してください。

それ以外の場合は、次を優先してください。

- ウォレットのネイティブ Nym 統合、または
- システムレベルの NymVPN。

## パフォーマンスとタイムアウトのトレードオフ

Mixnet は意図的に、より強力なメタデータ保護のために速度を犠牲にします。

次の項目に影響する可能性があります。

- 初回のウォレット同期
- 大規模な追いつき同期
- 取引履歴のクエリ
- RPC タイムアウト
- サードパーティ API 呼び出し

実践的なガイダンス:

- デフォルトの Nym 設定から始めてください。
- 初回同期または長時間の追いつき同期には、より時間がかかることを想定してください。
- プライバシー設定を弱める前に、タイムアウトを再試行してください。
- 機密性の高い取引の直前に、プライバシーモードを繰り返し切り替えないでください。
- 大量同期に高速な経路を使用する場合、その間に接続先インフラが実際のネットワーク ID を観測する可能性があることを理解してください。
- 特に Zingo PC では、そのネイティブ Nym トランスポートは現在、送信と価格検索を保護する一方、同期は直接接続のままであることを覚えておいてください。

## モバイルに関する考慮事項

Android および iOS では、通常、OS の VPN スロットが一般的なウォレットトラフィックを NymVPN 経由でルーティングする最も簡単な方法です。まず NymVPN に接続し、その後ウォレットを開いてください。

別の VPN、ファイアウォール、またはローカル VPN ベースの広告ブロッカーがすでにシステム VPN インターフェースを使用している場合、2つの製品を同時に動作させられないことがあります。ウォレットが保護されていると判断する前に、OS の VPN ステータスを確認してください。

## 脅威モデルのチェックリスト

セットアップに依存する前に、次を確認してください。

- 必要に応じてシールドされた Zcash アドレスを使用しているか?
- ウォレットはネイティブ Nym サポートを備えているか?
- そうである場合、そのネイティブ統合は正確にどのトラフィックを保護するのか?
- より広範な保護が必要な場合、ウォレットがネットワークアクティビティを開始する前に NymVPN は接続されているか?
- ウォレットはスプリットトンネリング規則によって除外されていないか?
- ウォレットが実際に文書化しているプロキシモードに依存しているか?
- 取引所、ブラウザーセッション、サードパーティ API、または透明アドレスを通じて ID を漏らしていないか?
- より遅い同期と、時折発生するタイムアウトに備えているか?
