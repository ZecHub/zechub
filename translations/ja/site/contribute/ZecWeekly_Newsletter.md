# ZecWeekly ニュースレター（Newsletter）

ZecWeeklyは、毎週日曜日の朝に配信されるニュースレターです。Zcashエコシステムでその週に起きたすべてのニュースを掲載しています。ニュースは毎週コミュニティメンバーによって選定され、関連するすべてのリンクがニュースレターに追加されます。ニュースレターへの登録は、[こちら](https://zechub.substack.com/)からお願いします。

## 貢献

ニュースレターへの貢献は、1人の貢献者が該当週の版を準備し、現在のバウンティまたは調整スレッドに従い、週ごとのリンクがそろった後にプルリクエストを提出する方法が最も円滑です。ZecHubがその版の日付を投稿または確認する前に、将来の版を提出しないでください。早期のプルリクエストでは、週後半の更新が漏れたり、担当キュレーターと競合したり、締め切りを誤ったりすることがよくあります。

### 1. 現在の版を確認する

執筆を始める前に、以下を行ってください。

- 現在のニュースレタータスクについて、[ZEC Bounties](https://bounties.zechub.wiki/)を確認してください。
- 担当に割り当てられるまで待ってください。
- ニュースレターの各版は、[バウンティ金額ポリシー](https://bounties.zechub.wiki/docs/bounty-amounts)のXS区分に属します。公開中のバウンティに記載されているZECの数値が金額であり、貢献ガイド内の古い見出しではありません。

### 2. リポジトリをフォークする

GitHubを初めて利用する場合は、次のワークフローを使用してください。

1. [ZecHubリポジトリ](https://github.com/ZecHub/zechub)を開きます。
2. **Fork**をクリックし、GitHubアカウントの下にフォークを作成します。
3. フォーク内で、その版用の新しいブランチを作成します。`digest-may-30-2026`のような分かりやすいブランチ名が役立ちます。
4. プルリクエストのベースリポジトリが`ZecHub/zechub`、ベースブランチが`main`になることを確認してください。

コマンドラインを使用する場合、同じワークフローは次のようになります。

```bash
git clone https://github.com/YOUR-USERNAME/zechub.git
cd zechub
git checkout -b digest-month-day-year
```

`YOUR-USERNAME`を自分のGitHubユーザー名に置き換えてください。上記のURLはプレースホルダーであり、そのままでは解決されません。

### 3. ニュースレターファイルを作成する

[ニュースレターテンプレート](https://github.com/ZecHub/zechub/blob/main/newsletter/newslettertemplate.md)を出発点として使用してください。ニュースレターの各版は、[`newsletter`](https://github.com/ZecHub/zechub/tree/main/newsletter)フォルダーに配置します。

ファイルを作成する際は、以下を行ってください。

- issueで指定された、または最近受理された版で使用されているファイル名形式に合わせてください。
- タスクで別の形式が求められていない限り、テンプレートと同じセクション順を維持してください。
- 該当週のリンクのみを追加してください。
- 読者が重要性を理解できるよう、各リンクに短く明確な説明を記載してください。
- 必要に応じて、英語以外の情報源を英語に翻訳または要約してください。
- プルリクエストを開く前に、すべてのリンクを確認してください。

### 4. 適切な時期にリンクを収集する

ZecWeeklyは通常、当週のZcashエコシステム活動を扱い、週の終わり頃に公開されます。最も安全なタイミングは以下のとおりです。

- 現在のニュースレターissueまたはタスクが投稿された後にリンクの収集を開始してください。
- その週がまだ進行中の間は下書きを維持してください。
- 週後半の更新を確認した後、指定された提出日に近い時期にプルリクエストを提出してください。
- その日付のタスクが存在する、またはZecHubが準備すべきであると確認するまで、将来の週のニュースレターを提出しないでください。

issueで特定の日付までの提出が指定されている場合は、その日付に従ってください。このページと現在のissueに矛盾がある場合は、現在のissueに従ってください。

### 5. プルリクエストを開く

ニュースレターファイルの準備ができたら、以下を行ってください。

1. 変更をフォークにコミットします。
2. `main`ブランチの`ZecHub/zechub`に対してプルリクエストを開きます。
3. `Zcash Ecosystem Digest | May 30th`のように、その版に一致するタイトルを使用してください。
4. レビュアーが作業とタスクを結び付けられるよう、プルリクエスト本文にissueへのリンクを追加してください。

プルリクエスト本文の例：

```md
Closes #ISSUE_NUMBER

Summary:
- Adds the Zcash Ecosystem Digest for Month Day.
- Uses the newsletter template and the current issue deadline.
- Checks links and descriptions for the requested week.
```

プルリクエストを開いた後は、レビューコメントを確認してください。ZecHubから編集を求められた場合は、同じ版に対して2つ目のプルリクエストを開くのではなく、同じブランチを更新してください。

### 実例

受理された提出物の例として、マージ済みの以下のニュースレタープルリクエストを使用してください。

- [Zcashエコシステム・ダイジェスト | 4月11日](https://github.com/ZecHub/zechub/pull/1551)
- [Zcashエコシステム・ダイジェスト | 3月28日](https://github.com/ZecHub/zechub/pull/1544)
- [Zcashエコシステム・ダイジェスト | 2月14日](https://github.com/ZecHub/zechub/pull/1474)


![Merged ZecWeekly newsletter pull request example](/content-images/9230d68d-6406-4c8a-992c-df84e0d318d8-8893d2de55.webp)

作業を例と比較する際は、ファイルの場所、タイトル形式、セクション順、リンクの説明、およびプルリクエストが正しいタスクに接続されているかに注目してください。

### 避けるべき一般的な間違い

- 版の日付またはタスクが確認される前にプルリクエストを開くこと。
- すでに関連するプルリクエストがあるissueに取り組むこと。
- `ZecHub/zechub`ではなく自分のフォークにプルリクエストを提出すること。
- ファイル名を間違える、または`newsletter`フォルダーの外にファイルを置くこと。
- 古い版をコピーし、すべての日付、リンク、説明を更新しないこと。
- 間違った週のリンクを追加すること。
- 壊れたリンク、重複したリンク、またはテンプレートのプレースホルダーテキストを残すこと。
- レビューコメント後に元のブランチを更新せず、新しいプルリクエストを開くこと。

### 最終チェックリスト

レビューを依頼する前に、以下を確認してください。

- issueまたはタスクの日付がニュースレターファイルと一致していること。
- 同じissueまたは版を対象とする、他のオープンなプルリクエストが存在しないこと。
- ファイルが`newsletter`フォルダー内にあること。
- テンプレートのセクションがすべて完成していること。
- すべてのリンクが機能し、有用な説明が付いていること。
- プルリクエスト本文が正しいissueにリンクしていること。
- レビュアーから変更を求められた場合に編集できること。
