# ZecWeekly ニュースレター

ZecWeekly は毎週日曜日の朝に配信されるニュースレターです。Zcash エコシステムでその週に起きたすべてのニュースを取り上げます。ニュースはコミュニティメンバーが毎週厳選し、関連リンクをすべてニュースレターに追加します。ニュースレターの購読は[こちら](https://zechub.substack.com/)からお願いします。

## 貢献する

ニュースレターへの貢献は、1 人の寄稿者が該当週の版を準備し、現在のバウンティまたは調整スレッドに従い、週ごとのリンクの準備ができた後にプルリクエストを提出する形が最適です。ZecHub がその版の日付を公開または確認する前に、将来の版を提出しないでください。早すぎるプルリクエストでは、週後半の更新が漏れたり、担当キュレーターと競合したり、締切を誤ったりすることがよくあります。

### 1. 現在の版を確認する

執筆を始める前に：

- 現在のニュースレタータスクを[ZEC Bounties ](https://bounties.zechub.wiki/)で確認してください。
- 担当に割り当てられるまで待ってください

![ss](/content-images/149a802c-b64f-4969-ad89-e83ffecf568e-d5d8387145.webp)



### 2. リポジトリをフォークする

GitHub を初めて使う場合は、次の手順に従ってください：

1. [ZecHub リポジトリ](https://github.com/ZecHub/zechub)を開きます。
2. **Fork** をクリックし、GitHub アカウント配下にフォークを作成します。
3. フォーク内で、その版用の新しいブランチを作成します。`digest-may-30-2026` のように分かりやすいブランチ名にすると便利です。
4. プルリクエストのベースリポジトリが `ZecHub/zechub`、ベースブランチが `main` になっていることを確認してください。

コマンドラインを使う場合、同じワークフローは次のようになります：

```bash
git clone https://github.com/YOUR-USERNAME/zechub.git
cd zechub
git checkout -b digest-month-day-year
```

`YOUR-USERNAME` はご自身の GitHub ユーザー名に置き換えてください。上記の URL はプレースホルダーであり、そのままでは解決されません。

### 3. ニュースレターファイルを作成する

開始点として[ニュースレーターテンプレート](https://github.com/ZecHub/zechub/blob/main/newsletter/newslettertemplate.md)を使用してください。ニュースレターの各版は [`newsletter`](https://github.com/ZecHub/zechub/tree/main/newsletter) フォルダーに置きます。

ファイル作成時：

- issue で指定された、または最近受け入れられた版で使われているファイル名形式に合わせてください。
- タスクで別の形式が求められていない限り、テンプレートと同じセクション順を維持してください。
- 関連する週のリンクのみを追加してください。
- 読者が重要性を理解できるよう、各リンクに短く明確な説明を書いてください。
- 必要に応じて、英語以外のソースを英語で翻訳または要約してください。
- プルリクエストを開く前に、すべてのリンクを確認してください。

### 4. 適切なタイミングでリンクを集める

ZecWeekly は通常、当週の Zcash エコシステムの活動を扱い、週の終わり頃に公開されます。最も安全なタイミングは以下のとおりです：

- 現在のニュースレター issue またはタスクが公開された後にリンクの収集を始めてください。
- 週の活動が続いている間は下書きを維持してください。
- 週後半の更新を確認した後、指定された提出日に近いタイミングでプルリクエストを提出してください。
- その日付のタスクが存在しない、または ZecHub から準備するよう確認されていない限り、将来の週のニュースレターを提出しないでください。

issue で特定の日付までの提出を求められた場合は、その日付に従ってください。このページと現在の issue の内容が競合する場合は、現在の issue に従ってください。

### 5. プルリクエストを開く

ニュースレターファイルの準備ができたら：

1. 変更をフォークにコミットします。
2. `main` ブランチの `ZecHub/zechub` 宛てにプルリクエストを開きます。
3. `Zcash Ecosystem Digest | May 30th` のように、版に合ったタイトルを使用してください。
4. レビュアーが作業とタスクを結び付けられるよう、プルリクエスト本文に issue をリンクしてください。

プルリクエスト本文の例：

```md
Closes #ISSUE_NUMBER

Summary:
- Adds the Zcash Ecosystem Digest for Month Day.
- Uses the newsletter template and the current issue deadline.
- Checks links and descriptions for the requested week.
```

プルリクエストを開いた後は、レビューコメントを確認してください。ZecHub から編集を求められた場合は、同じ版に対して 2 つ目のプルリクエストを開くのではなく、同じブランチを更新してください。

### 実例

受け入れられた提出例として、マージ済みの以下のニュースレタープルリクエストを参照してください：

- [Zcash エコシステムダイジェスト | 4月11日](https://github.com/ZecHub/zechub/pull/1551)
- [Zcash エコシステムダイジェスト | 3月28日](https://github.com/ZecHub/zechub/pull/1544)
- [Zcash エコシステムダイジェスト | 2月14日](https://github.com/ZecHub/zechub/pull/1474)


![マージ済み ZecWeekly ニュースレタープルリクエストの例](/content-images/9230d68d-6406-4c8a-992c-df84e0d318d8-8893d2de55.webp)

自分の作業を例と比較する際は、ファイルの場所、タイトル形式、セクション順、リンクの説明、およびプルリクエストが正しいタスクに紐付いているかに注目してください。

### 避けるべきよくある間違い

- 版の日付またはタスクが確認される前にプルリクエストを開くこと。
- すでにリンクされたプルリクエストがある issue に取り組むこと。
- `ZecHub/zechub` ではなく自分のフォークに対してプルリクエストを提出すること。
- 間違ったファイル名を使用する、または `newsletter` フォルダー外にファイルを置くこと。
- 古い版をコピーしても、すべての日付、リンク、説明を更新しないこと。
- 間違った週のリンクを追加すること。
- 壊れたリンク、重複リンク、またはテンプレートのプレースホルダーテキストを残すこと。
- レビューコメント後に元のブランチを更新せず、新しいプルリクエストを開くこと。

### 最終チェックリスト

レビューを依頼する前に、以下を確認してください：

- issue またはタスクの日付がニュースレターファイルと一致している。
- 同じ issue または版を対象とする、別のオープンなプルリクエストがない。
- ファイルが `newsletter` フォルダー内にある。
- テンプレートのセクションがすべて完成している。
- すべてのリンクが機能し、有用な説明が付いている。
- プルリクエスト本文が正しい issue にリンクしている。
- レビュアーから変更を求められた場合に編集できる。
