# ZecHub ハッカソン・ビルダーズガイド

## 要点

- コードを書き始める前に、なぜ作るのかを理解すること。複雑さよりも有用性が勝る
- シンプルに保つこと。未完成のまま残る大きなアイデアより、小さくても上手く仕上げたアイデアの方が優れている
- 早い段階で Zcash のインフラスタックを学ぶこと。そこが最も急な登り坂だからだ
- あなたのアプリが資金を動かすなら、mainnet で動作しなければならない。testnet で構築し、その後 mainnet で証明すること
- ドキュメントと明確なデモは、製品そのもの以上に重要になることがある
- 勝利はスタートラインであり、あなたの評判を築き、コミュニティで扉を開く

<br/>

## これは誰のためのものか

- ZecHub または Zcash のハッカソンに初めて参加するビルダー
- Zcash が初めての、他のエコシステム出身の開発者
- ハッカソンのプロジェクトを長く残るものにしたいすべての人

<br/>

## まず「なぜ」から始める

エディタを開く前に、どんな問題を解決しようとしているのか、そしてなぜ誰かがそれを気にかけるのかを理解しておきましょう。よい判断基準はシンプルです。もしあなたが作っているものが存在しなかったら、誰かがそれを惜しむでしょうか。自分自身が使いたいと思えるものを作りましょう。プライバシーは Zcash が存在する理由です。ですから、あなたが作る相手にとってなぜプライバシーが重要なのかを理解し、それがプロジェクト全体の形を決めるようにしてください。

<br/>

## まずスタックを学ぶ

他のチェーンから来たビルダーにとって最もよくある驚きは、コーディングではなく Zcash インフラの学習曲線です。アプリを設計する前に、各要素がどう組み合わさっているのかを理解する時間を取りましょう。まずは中核となるスタック、しばしば Z to the third と呼ばれるものから始めてください。つまり、zebrad、ライトサーバー、そしてウォレットです。その後、開発者向けツールにも慣れていきましょう。

1. [zechub.wiki/developers](https://zechub.wiki/developers) にある wiki の開発者ページを読むこと。ここが推奨される最初の立ち寄り先です
2. zingolib と zingo-cli を調べること。これらの呼び出しは、各トラックにまたがってプロジェクトに必要なことの大半をカバーします
3. さらに低レベルな構築要素として、librustzcash とリファレンスウォレットである ZODL を確認すること
4. FROST のプロジェクトでは、crates.io にある Zcash Foundation の frostd と frost-core を使い、定義の理解には AI の助けを借りること。ただし、FROST を安全に使うには依然として本当の努力と時間が必要です

<br/>

## mainnet の意味を理解する

いくつかのトラックでは、あなたのアプリが Zcash mainnet と相互作用することが求められます。実際にはこれは、あなたのプロジェクト、あるいはそれを使う誰かが、AI エージェントを含めて、mainnet 上で実際の資金を送受信するか、あるいはそれを可能にするツールを構築・改善することを意味します。もしあなたのアプリがトランザクションを行うなら、提出物の中でそれを mainnet 上で実演しなければなりません。

開発中は testnet で構築しましょう。mainnet での活動には実際の ZEC がかかり、時間とともにますます高価になるだけなので、反復作業には testnet が推奨されます。最終的な証明のために mainnet に切り替えましょう。フローを設計する際に、ひとつ覚えておくべき細部があります。資金が shielded address に届いたとき、ウォレットはそれをスキャンして見つけ、使えるようにしなければならず、そのスキャンには少し時間がかかります。入金された資金がすぐ使えると想定するのではなく、その短い待ち時間をアプリに組み込んでください。

<br/>

## シンプルに保つ

シンプルでうまく実行されたアイデアは、複雑なアイデアに何度も勝ってきました。審査員は、同じイベントで、より技術的に野心的なプロジェクトよりも基本的なコンセプトの方が勝つのを見てきました。それは現実の問題を解決し、理解しやすかったからです。自分が終えられると思う量よりも少なく引き受けましょう。細部の見落とし、スコープの広げすぎ、リサーチ不足は、ビルダーが賞を逃す原因となるミスです。中核となるコンセプトから最初のコマンドまで、あなたのプロジェクトを理解しやすく、実行しやすいものにしてください。

<br/>

## 最初の30秒で勝負を決める

レビューする人たちはすぐに強い印象を抱くので、プレゼンテーション、テーマ、ビジュアルは、あなたの解決策がどれだけ新規性を持つかと並んで、現実的に大きな重みを持ちます。ドキュメントと明確なデモは後回しにするものではありません。あなたのアイデアを伝えることは、ときにアイデアそのもの以上に重要です。なぜなら、誰もあなたが作ったものを理解できなければ、それは成功できないからです。審査では、技術的な深さ、ユーザー体験、独創性、実用性のバランスが取られる傾向があり、優れたドキュメントはそのすべてを底上げします。

<br/>

## より難しく、競争の薄いトラックを見る

競争相手の少ない場を望むなら、難しいトラックにはそもそも挑戦する人が少ないため、応募数も少ないことがよくあります。Accounting トラックは、オンチェーンのトランザクション作業を避けたい初心者にとってよい選択肢です。FROST は強力で、まだ十分に活用されておらず、プロジェクトの強固な土台になります。コミュニティは何を作るべきかを規定していないので、ゼロから始めるのではなく、エコシステムがすでに持っている有能なツールの上に構築するのは賢いやり方です。

<br/>

## ハッカソンの後

勝利は道の終わりではありません。勝利はあなたのポートフォリオと評判を築き、コミュニティで扉を開き、提案を通じた資金調達につながる可能性があります。

1. 強いプロジェクトは、ロードマップ、マイルストーン、予算の根拠を添えて、ZecHub DAO または Zcash Community Grants への提案としてさらに発展させること
2. フォーラム、Discord、X でコミュニティに積極的に関わり続けること
3. Arborist R and D ミーティングに参加し、アイデアを投稿し、フィードバックを求めること
4. たとえ勝てなくても作り続け、次のハッカソンに目を向けること
