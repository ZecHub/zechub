# Zaino индексатор

## Кратко

* **Zebra** проверяет цепочку Zcash.
* **Zaino** индексирует данные цепочки Zebra и предоставляет API для клиентских приложений.
* **Zallet** — компонент кошелька в стеке Z3. В конфигурации Z3 по умолчанию Zallet напрямую взаимодействует с Zebra, поэтому отдельная служба Zaino не требуется.
* Отдельная служба Zaino полезна, если операторам нужна совместимая с lightwalletd конечная точка gRPC, прокси JSON-RPC или инфраструктура для лёгких кошельков, обозревателей блоков, кранов и подобных сервисов.
* Zaino — действующая часть инфраструктуры, но перед запуском в производственной среде операторам следует проверить актуальные сведения о развертывании в официальной документации Zaino и Z3.

## Основное объяснение

Zaino — индексатор Rust для блокчейна Zcash. Он получает данные цепочки от полного узла Zebra. Он предоставляет данные, необходимые кошелькам, обозревателям блоков, кранам и другим сервисам, не возлагая на Zebra ответственность за индексацию данных для каждого клиента.

### Что делает Zaino

Zaino находится между Zebra и клиентским ПО. Zebra — узел консенсуса: он загружает блокчейн Zcash, проверяет его и следует ему. Zaino использует Zebra как источник данных цепочки, а затем подготавливает индексированные представления, к которым клиентские приложения могут быстро обращаться с запросами.

Такое разделение помогает четко разграничить роли:

| Компонент | Роль |
|:--|:--|
| Zebra | Полный узел и валидатор |
| Zaino | Индексатор и API-служба для клиентских приложений |
| Zallet | Служба кошелька |
| lightwalletd | Устаревший сервер для лёгких кошельков, который Zaino призван заменить или дополнить |

Zaino предоставляет функциональность для лёгких клиентов, полных клиентов или кошельков и обозревателей блоков. Он открывает доступ к финализированной цепочке, лучшей нефинализированной цепочке и данным мемпула, хранящимся в Zebra.

### Как это вписывается в текущий стек Zcash Stack

Текущий стек Z3 построен на Zebra, Zallet и необязательном Zaino.

В развертывании Z3 по умолчанию Zebra и Zallet работают вместе. Zallet напрямую обращается к Zebra, поэтому оператору, который запускает только локальный стек кошелька, не нужно запускать отдельную службу Zaino.

Zaino добавляют, когда оператору нужно обслуживать внешних клиентов. В Z3 он запускается с профилем Compose `indexer` и предоставляет:

* конечную точку gRPC, совместимую с lightwalletd, для клиентов лёгких кошельков
* прокси JSON-RPC для обозревателей блоков, кранов и серверной инфраструктуры сервисов
* базу данных индексатора, отдельную от состояния цепочки Zebra

Поэтому Zaino особенно актуален для серверной инфраструктуры кошельков, операторов публичной инфраструктуры, обозревателей блоков, кранов и разработчиков, тестирующих сервисы, которым нужны индексированные данные цепочки Zcash.

### Zaino и lightwalletd

lightwalletd — исходный сервер для лёгких кошельков. Zaino — основанный на Rust преемник для этой роли. Его цель — по возможности предоставлять совместимые API, чтобы кошельки и сервисы могли перейти на него без необходимости сразу полностью переписывать их.

Это не означает, что все развертывания lightwalletd уже перешли на Zaino. Операторам следует считать Zaino частью текущего стека на основе Zebra и сверяться с актуальной документацией проекта, выпусками и панелями мониторинга сервисов, прежде чем решать, что запускать.

## Наглядное объяснение / аналогия

Представьте блокчейн Zcash как огромный архив страниц реестра.

Zebra — архивариус. Он получает каждую новую страницу, проверяет, соответствует ли она правилам, и помещает ее в нужное место.

Zaino — справочная стойка перед архивом. Она читает то, что поместил в архив Zebra, составляет каталоги для быстрого поиска и оперативно отвечает посетителям. Лёгкие кошельки, обозреватели блоков и краны обращаются к этой стойке с вопросами вроде «что находится в этом блоке?» или «какие транзакции ожидают обработки в мемпуле?». Справочная стойка не решает, какие страницы подлинные. Это задача архивариуса.

Zallet в конфигурации Z3 по умолчанию работает в том же здании и обращается напрямую к архивариусу. Справочная стойка ему не нужна.

## Подробный разбор

### Примечания для операторов

Самый простой и авторитетный способ развертывания — репозиторий Z3. В Z3 Zaino включен как необязательный сервис:

```bash
docker compose --env-file .env.<network> --profile indexer up -d
```

Сначала выполните обычную настройку Z3 и дождитесь синхронизации Zebra, прежде чем запускать зависящие от него сервисы в основной или тестовой сети.

Zaino предоставляет два типа сетевых сервисов. Сервис gRPC — это API для лёгких кошельков. Сервис JSON-RPC предназначен для работы через loopback или в доверенных частных сетях, если защита не обеспечивается внешним уровнем. Не открывайте неаутентифицированную или незашифрованную конечную точку JSON-RPC для публичного доступа через интернет.

## Распространённые ошибки

**Считать Zaino полным узлом.** Zaino не является валидатором. Zebra проверяет цепочку; Zaino индексирует данные из Zebra.

**Полагать, что в каждом развертывании Z3 нужен отдельный Zaino.** В стеке Z3 по умолчанию Zallet может напрямую обращаться к Zebra. Запускайте Zaino, когда для внешних клиентов нужна отдельная служба индексатора.

**Представлять запланированные функции как уже развернутые.** Zaino активно разрабатывается, поэтому перед тем, как утверждать, что функция доступна, проверяйте актуальные примечания к выпускам и документацию.

**Неосторожно открывать JSON-RPC.** Интерфейс JSON-RPC Zaino предназначен для работы через loopback или в доверенных частных сетях, если он не защищен другим уровнем.
