# Скрытый поиск данных

## Кратко

- Скрытый поиск данных (PIR) позволяет устройству получить одну запись из базы данных сервера, не раскрывая серверу, какую именно запись оно запросило
- Zcash это необходимо, потому что приватный кошелёк не может спросить сервер, какие транзакции принадлежат ему, не раскрыв себя
- Сегодня кошельки скачивают и сканируют намного больше данных, чем им нужно, и это одна из главных причин медленной синхронизации
- PIR позволил бы кошельку приватно получать только собственные данные, устранив это узкое место и сохранив приватность
- Это активная область исследований для Zcash: теоретически она обладает большими возможностями, а на практике её адаптируют для реальных кошельков
- Уже доступна работающая демонстрация: [ZecBlock Private](https://private.zecblock.com) — первый полноценный обозреватель блоков Zcash на основе PIR (транзакции, блоки и адреса)

## Для кого эта статья

- Для всех, кто задумывался, как приватный кошелёк находит собственные монеты, не раскрывая, какие именно
- Для новичков, которые часто встречают упоминания PIR в связи с работами по масштабированию Zcash
- Для читателей, которым сначала важно понять саму идею, а уже потом — лежащую в её основе криптографию
- Для всех, кому интересно посмотреть на работающий обозреватель блоков на основе PIR

## Какую проблему решает PIR для Zcash

Zcash скрывает, кому предназначена транзакция. Из-за этого возникает непростой вопрос: если сеть не может определить, какие транзакции принадлежат вам, как ваш кошелёк их находит?

Сегодня ответ прост: кошелёк не может спросить сервер, какие транзакции принадлежат мне, потому что такой вопрос раскрыл бы именно то, что Zcash пытается скрыть. Поэтому кошелёк скачивает большой объём данных и локально проверяет каждую запись, чтобы выяснить, относится ли она к нему. Это работает и сохраняет приватность, но требует много времени и ресурсов. Такое сканирование — одна из главных причин медленной синхронизации кошелька.

В идеале кошелёк мог бы запросить у сервера только собственные данные и получить их, не раскрывая серверу, что именно было запрошено. Именно это и обеспечивает скрытый поиск данных.

## Что такое PIR

Скрытый поиск данных — это криптографический метод, который позволяет клиенту прочитать одну запись из базы данных сервера, не раскрывая серверу, какую запись он прочитал.

Представьте библиотеку, где вы можете получить нужную книгу, а библиотекарь никогда не узнает, какую именно книгу он вам выдал. Вы получаете нужное, а ваш интерес остаётся приватным. PIR — математическое воплощение этой идеи, применённое к любой базе данных.

Криптографы изучают эту концепцию уже несколько десятилетий. Впервые её описали в 1995 году Chor, Goldreich, Kushilevitz и Sudan: они предложили подход с несколькими серверами. Первая версия с одним сервером появилась в 1997 году благодаря Kushilevitz и Ostrovsky. PIR изобрела не Zcash: это устоявшаяся область, которую Zcash теперь применяет для решения реальной и непростой задачи.

## Как работает PIR: первый уровень понимания

Существует два основных способа построить PIR, и различие между ними важно.

Первый использует несколько серверов. Клиент отправляет каждому из нескольких серверов часть запроса, а затем объединяет ответы локально. Ни один сервер по отдельности не видит достаточно, чтобы понять, что именно было запрошено. Такой подход эффективен, но предполагает, что серверы не вступают в сговор друг с другом, а в реальном мире это трудно гарантировать.

Второй способ использует один сервер и хитроумную криптографию вместо нескольких участников. В этом случае клиент полагается на специальный инструмент — гомоморфное шифрование. Это направление лучше подходит для реального внедрения, поскольку не требует нескольких серверов, которые не сговариваются друг с другом.

## Механизм: гомоморфное шифрование

Гомоморфное шифрование — это вид шифрования, позволяющий серверу выполнять вычисления над данными, пока они остаются зашифрованными. Сервер формирует корректный зашифрованный ответ, ни разу не увидев исходных значений.

Вот принцип работы PIR с одним сервером на основе этого метода. Клиенту нужен третий элемент из списка. Он формирует запрос, который по сути содержит зашифрованный ответ «да» для третьей позиции и зашифрованный ответ «нет» для каждой другой. Для сервера этот запрос — бессмысленный набор данных: он не может определить, в какой позиции находится «да».

Затем сервер, используя особые свойства гомоморфного шифрования, объединяет базу данных с этим зашифрованным запросом: умножает каждый сохранённый элемент на соответствующее зашифрованное «да» или «нет» и складывает результаты. На выходе получается один зашифрованный пакет, содержащий ровно тот элемент, который нужен клиенту, и ничто не раскрывает, какой именно. Клиент расшифровывает пакет и читает нужный элемент. Сервер ответил на вопрос, даже не узнав, в чём он состоял.

Усиленная версия, называемая симметричным PIR, добавляет ещё одну гарантию: клиент узнаёт только запрошенный элемент и ничего о других записях базы данных. Это защищает не только клиента, но и базу данных.

## Подробнее для технических читателей

Современные схемы с одним сервером основаны на решёточной криптографии, чаще всего — на предположении о сложности обучения с ошибками. Запрос клиента — это вектор шифротекстов: шифрование единицы для целевого индекса и нулей для остальных. Шифрование аддитивно-гомоморфно, поэтому сервер может складывать шифротексты и умножать их на открытые записи базы данных, не расшифровывая их.

Сервер представляет базу данных в виде матрицы, применяет зашифрованный вектор выбора и возвращает один шифротекст, который после расшифровки даёт нужную строку. Поскольку запрос невозможно отличить от случайного шума, сервер не получает никакой информации об индексе.

Исторически главным препятствием всегда были затраты. При наивной реализации сервер должен обращаться к каждой записи базы данных для каждого запроса, что требует больших вычислительных ресурсов. Кроме того, шифротексты велики и требуют большой пропускной способности сети. В недавних исследованиях эту проблему решают с помощью предварительной обработки: схемы, такие как SimplePIR и FrodoPIR, позволяют серверу заранее подготовить базу данных и передать каждому клиенту небольшую подсказку. Это переносит значительную часть работы на автономный этап, благодаря чему запросы в реальном времени обрабатываются быстро. Полезное дополнительное свойство: конструкции на основе решёток также считаются устойчивыми к квантовым атакам, что согласуется с общим курсом Zcash на постквантовую приватность.

## PIR в Zcash

PIR — часть работы по созданию масштабируемого Zcash, который был бы одновременно приватным и быстрым.

Цель — устранить описанное выше узкое место, связанное со сканированием данных кошельком. В Valar Group разрабатывают методы скрытого поиска данных, чтобы кошелёк мог получать собственные данные с сервера, не раскрывая, какие записи были запрошены. Один из конкретных вариантов применения — приватная проверка нуллификаторов. Нуллификатор — это уникальный маркер, который публикуется при расходовании ноты и не позволяет потратить одни и те же средства дважды. Кошельку часто нужно проверить, появился ли определённый нуллификатор, то есть была ли нота уже потрачена. Сегодня такая проверка через сервер может раскрыть, о какой ноте идёт речь. Скрытый поиск данных позволяет кошельку задать этот вопрос, не раскрывая, какой нуллификатор его интересует. Это дополняет другие работы по масштабированию, включая Project Tachyon и новое программное обеспечение для узлов, которые призваны снять ограничения производительности, мешающие работе приватных кошельков.

Важно реалистично оценивать текущий этап. Это активная работа в области исследований и разработки, а не готовая функция, уже выпущенная для пользователей. Концепция хорошо изучена, и направление определено, но сейчас решается именно сложная задача: сделать PIR достаточно эффективным для повседневного использования на обычных устройствах.

## Пример в работе: ZecBlock Private

В ноябре 2026 года ZecBlock запустил **ZecBlock Private** (private.zecblock.com) — версию своего обозревателя, использующую скрытый поиск данных для поиска транзакций, блоков и адресов.

Это первый полноценный обозреватель блоков Zcash (с поиском транзакций, блоков и адресов) на основе PIR. Более ранние демонстрации обозревателей с PIR поддерживали только более узкий круг запросов, например проверку баланса адреса.

### Как работают приватные запросы

- Запрос (идентификатор транзакции, высота или хеш блока либо адрес) полностью шифруется в браузере до отправки.
- Сервер обрабатывает весь опубликованный набор данных, не узнавая, какая запись была запрошена.
- Сервер возвращает один зашифрованный ответ, который может расшифровать только браузер.
- Поиск существующей записи неотличим от поиска несуществующей: размер и форма запроса одинаковы.

После каждого поиска сайт показывает краткое описание того, что именно было отправлено, чтобы было легко проверить свойство приватности.

### Проверка подлинности

Каждая публикация данных подписана. Браузер проверяет подпись каждого результата перед отображением, поэтому вредоносный сервер или сервер с ошибками не сможет подменить данные.

### Актуальность данных

Новые блоки публикуются каждые несколько секунд. Данные в приватном обозревателе обычно отстают от обычного обозревателя ZecBlock примерно на 20 секунд.

### Затраты на передачу данных

PIR обходится дороже обычного запроса, поскольку сервер должен обработать весь набор данных:

- Поиск транзакции: отправляется примерно 1,2 МБ
- Поиск адреса: отправляется примерно 0,4 МБ

Такова цена того, что сервер ничего не узнаёт о запросе.

### Реализация клиента

Клиент для браузера — это обёртка Rust → WebAssembly (сейчас она находится в репозитории ZecBlock под `prototype/pir-browser`). Она построена на базе библиотек с открытым исходным кодом для PIR от Valar Group. Обёртка пока не опубликована как отдельный пакет npm, но это запланировано.

### Отличие от PIR для кошельков

ZecBlock Private демонстрирует PIR для **публичных** данных блокчейна: можно найти известную транзакцию, блок или адрес, не раскрывая, что именно ищешь. Но это **не** решает более сложную задачу кошелька — приватно определять, какие ноты принадлежат ключу просмотра, или проверять, не потрачены ли ноты, с помощью нуллификаторов. Эти направления всё ещё активно исследуются.

## Распространённые заблуждения

- PIR скрывает, какой элемент вы запросили, но не обязательно скрывает сам факт обращения к серверу; метаданные сетевого уровня — отдельный вопрос
- PIR — не уникальная особенность Zcash, а универсальный криптографический инструмент, который Zcash применяет для защиты приватности кошельков
- Ускорение синхронизации с помощью PIR — цель текущей работы, а не функция, уже доступная в кошельках
- Скачивание всех данных с последующим локальным сканированием — нынешний подход. Он сохраняет приватность, но работает медленно; PIR призван сохранить приватность и устранить задержки
