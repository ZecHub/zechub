# Viewing Key

Экранированные адреса позволяют вам проводить транзакции, раскрывая как можно меньше информации в блокчейне Zcash. Но что происходит, когда вам *нужно* показать определённой стороне, чем вы владеете или что отправили? У каждого экранированного адреса есть viewing key, предоставляющий доступ для чтения, но не возможность тратить средства. Viewing key были представлены в [ZIP 310](https://zips.z.cash/zip-0310) и добавлены в протокол с обновлением сети Sapling.

Viewing key — это инструмент выборочного раскрытия: вы выбираете, кто и что увидит, и при этом никогда не передаёте полномочия на расходование средств.

## Зачем использовать viewing key?

В материалах Electric Coin Company по этой теме изложены наиболее часто возникающие ситуации, и сегодня они остаются типичными:

- **Биржа отслеживает депозиты.** Биржа загружает incoming viewing key на подключённый к интернету узел обнаружения, чтобы замечать депозиты клиентов на экранированный адрес, в то время как ключ расходования средств остаётся на оборудовании, которое никогда не подключается к сети.
- **Кастодиан подтверждает свои активы.** Кастодиан передаёт аудитору полный viewing key для каждого экранированного адреса. Аудитор может проверить эти балансы и изучить прошлую активность по этим адресам и с них, но не может делать ничего другого.
- **Комплексная проверка контрагента.** Если бирже необходимо изучить экранированную историю клиента в рамках усиленной комплексной проверки, она может запросить viewing key, а не средства.

## Что viewing key раскрывает, а что — нет

Существует несколько типов ключей, и различие между ними определяет объём раскрываемой информации.

| Ключ | Префикс | Предоставляет |
|---|---|---|
| Unified full viewing key (UFVK) | `uview…` | Позволяет видеть входящие **и** исходящие транзакции во всех пулах учётной записи |
| Unified incoming viewing key (UIVK) | `uivk…` | Позволяет видеть только входящие транзакции во всех пулах учётной записи |
| Sapling extended full viewing key | `zxviews…` | Позволяет видеть входящую и исходящую активность Sapling для адресов ключа |

Ни один из них не позволяет тратить средства. Все они постоянны в важном смысле: выданный ключ нельзя отозвать; его можно лишь сделать неактуальным, переместив средства на учётную запись, ключами которой другая сторона не располагает.

Перед тем как чем-либо поделиться, следует знать о двух ловушках раскрытия информации.

**Incoming не означает узко ограниченный.** Унифицированный incoming viewing key относится ко всей учётной записи, а не к одному адресу, о котором вас спросили. Экспорт UIVK для одного адреса Sapling всё равно предоставляет видимость входящих транзакций во всех пулах этой учётной записи, поэтому раскрывает больше, чем адрес, который он обозначает. В [книге Zallet](https://zcash.github.io/zallet/zcashd/json_rpc.html) это указано прямо.

**Опубликованный адрес уже раскрывает свой incoming viewing key будущему противнику.** В [ZIP 326](https://zips.z.cash/zip-0326) отмечается, что противник с квантовым компьютером сможет восстановить incoming viewing key из опубликованного диверсифицированного адреса; это осуществимо в отличие от восстановления nullifier key. Публикация адреса сегодня не равнозначна публикации viewing key, но на достаточно долгом горизонте они становятся значительно ближе друг к другу.

## Viewing key после Ironwood

NU6.3 представил экранированный пул Ironwood и сделал пул Orchard предназначенным только для расходования, поэтому со временем средства перемещаются из одного в другой. О самом обновлении см. [Ironwood](/zcash-tech/ironwood) и [Турникет](/zcash-tech/the-turnstile).

**Viewing key, выданный до Ironwood, продолжает работать после миграции.** ZIP 326 определяет, что получатель и соответствующий ему incoming viewing key относятся к *протоколу* Orchard, а не к пулу: один и тот же incoming viewing key пробно расшифровывает шифротексты примечаний как пула Orchard, так и пула Ironwood. Zallet реализует это именно так, описывая примечания Ironwood как имеющие форму Orchard и пробно расшифровываемые viewing key Orchard учётной записи в домене шифрования примечаний Ironwood.

Три последствия для каждого, кто хранит или выдаёт ключ:

1. **Балансы перемещаются между пулами, и наблюдатель видит это.** [ZIP 318](https://zips.z.cash/zip-0318) задаёт миграцию как серию небольших намеренно единообразных транзакций Orchard-to-Ironwood, транслируемых по рандомизированному расписанию; каждая из них тратит одно примечание Orchard и создаёт один выход Ironwood канонического номинала. Аудитор, наблюдающий с помощью viewing key, видит, как активы перемещаются из одного пула в другой поэтапно в течение недель, а не одним переводом. Кошелёк может восстановить собственный ход миграции из данных цепочки, используя свои viewing key.
2. **Каждый этап миграции раскрывает перемещаемую стоимость.** Это неотъемлемо при прохождении через турникет и именно это делает миграцию аудируемой. Разделение баланса на канонические номиналы означает, что ни одна транзакция не раскрывает весь баланс пула Orchard.
3. **Учётные записи, созданные после Ironwood, могут выводить свои ключи иначе.** [ZIP 2005](https://zips.z.cash/zip-2005) добавляет флаг `use_qsk` для квантово-восстанавливаемых ключей и изменяет способ вывода incoming, outgoing и diversifier ключей, поэтому ключи с `use_qsk = true` действительно являются другими ключами. ZIP 326 требует, чтобы флаг был единообразным для всей учётной записи, и запрещает генерировать ключи с `use_qsk = true` до активации NU6.3 в Mainnet. Поэтому ключ, экспортированный из учётной записи, существовавшей до Ironwood, является ключом `use_qsk = false` и остаётся корректным для этой учётной записи. Не предполагайте, что ключ, экспортированный из одной учётной записи, описывает другую.

## Экспорт viewing key

### Zallet

[Zallet](https://github.com/zcash/zallet) — это кошелёк полного узла, заменивший кошелёк внутри zcashd. Экспорт и импорт viewing key появились в **v0.1.0-beta.2 (28 июля 2026 года)**, поэтому сначала проверьте версию; в более ранних сборках этих методов нет. Каждый аргумент после имени метода должен быть корректным JSON, то есть строковые значения сохраняют собственные двойные кавычки. [Краткое справочное руководство Zallet](/using-zcash/zallet-quick-reference-guide) описывает общий стиль команд.

Выведите список того, что хранит кошелёк:

```bash
zallet rpc listaddresses
```

Экспортируйте унифицированный полный viewing key учётной записи, передав унифицированный адрес:

```bash
zallet rpc z_exportviewingkey '"<unified address>"'
```

Вместо этого экспортируйте унифицированный incoming viewing key учётной записи, используя необязательный аргумент `ivk`:

```bash
zallet rpc z_exportviewingkey '"<unified address>"' true
```

Передача адреса Sapling возвращает расширенный полный viewing key Sapling этой учётной записи (`zxviews…`), что соответствует прежнему поведению zcashd. Существуют два задокументированных ограничения: адреса Sprout отклоняются, а расширенный полный viewing key Sapling нельзя экспортировать из учётной записи, которая сама была импортирована только для просмотра, поскольку кошелёк не может его восстановить. Однако форма с `ivk` работает для импортированных учётных записей только для просмотра.

### Кошельки, экспортирующие viewing key через собственный интерфейс

На странице [Кошельки](/using-zcash/wallets) отслеживается поддержка viewing key и готовность к Ironwood для каждого кошелька. На момент написания кошельки, в которых указаны и поддержка viewing key, и **Ironwood: Ready**, включают ZODL, Zingo!, Zkool, Cake, Zallet, Zecd и Nozy. Прежде чем полагаться на какой-либо конкретный кошелёк, проверяйте эту страницу, а не данную, поскольку статус готовности меняется.

## Импорт viewing key как учётной записи только для просмотра

### Zkool

[Zkool](https://github.com/hhanh00/zkool2) — наиболее гибкий вариант здесь, поскольку он принимает как унифицированные, так и устаревшие ключи. В его README описаны учётные записи только для просмотра, созданные из **унифицированного viewing key** или **расширенного viewing key Sapling**, наряду с устаревшими экранированными расширенными ключами, экспортированными из zcashd. Добавьте новую учётную запись, выберите путь только для просмотра и вставьте ключ `uview…` или `zxviews…`; затем учётная запись синхронизируется и сообщает о балансах и истории без полномочий на расходование средств.

Поддержка протокола Ironwood и миграция Orchard-to-Ironwood появились в Zkool 6.24.0 (20 июля 2026 года), а в 6.26.1 (2 августа 2026 года) было исправлено обнаружение транзакций Ironwood в mempool. Используйте версию 6.26.1 или новее.

### Zallet

```bash
zallet rpc z_importviewingkey '"<zxviews… key>"' '"whenkeyisnew"' 0
```

Второй аргумент — политика повторного сканирования: `"whenkeyisnew"` (по умолчанию), `"yes"` или `"no"`. Третий — высота блока, с которой следует выполнить повторное сканирование. Zallet импортирует ключ как учётную запись только для просмотра и отслеживает входящие и исходящие транзакции для её адресов без полномочий на расходование средств.

**Zallet импортирует только расширенные полные viewing key Sapling.** Он не импортирует унифицированный полный viewing key `uview…`, хотя может его экспортировать. Чтобы предоставить доступ для чтения ко всей унифицированной учётной записи, экспортируйте UFVK из Zallet и импортируйте его в кошелёк, принимающий унифицированные ключи, например Zkool.

Чтобы преобразовать импортированный ключ в полный файл истории транзакций с txid, комиссиями и мемо, см. [Экспорт истории транзакций из Viewing Key](/guides/viewing-key-transaction-export).

## Что изменилось и что больше не следует искать

Если вы следовали более старой версии этой страницы или её переводу, три способа больше не работают.

- **`zcash-cli z_exportviewingkey` и `z_importviewingkey`.** zcashd достиг остановки поддержки 18 июля 2026 года и больше не запускается. Одноимённые методы Zallet являются заменой; см. [руководство по миграции](/guides/migration-guide-zcashd-to-zebrad-zallet).
- **Инструкцию для Ywallet.** На странице кошельков Ywallet отмечен как **Ironwood: Not Ready**, поэтому это не тот кошелёк, который следует рекомендовать для viewing key эпохи Ironwood. Zkool от того же разработчика принимает тот же диапазон ключей и отмечен как Ready.
- **zcashblockexplorer.com/vk.** Сервис возвращает HTTP 503 с недействительным сертификатом и был удалён без замены. Вставка viewing key на веб-сайт передаёт всю вашу историю транзакций тому, кто управляет этим сайтом, что всегда было самым слабым из трёх вариантов на старой странице. Вместо этого импортируйте ключ в кошелёк, которым управляете вы.
