# Опубликуйте веб-сайт в IPFS

![](/content-images/IPFS-40c2e22732.webp)

## Введение в IPFS

IPFS (InterPlanetary File System) — это одноранговый протокол и сеть, предназначенные для создания децентрализованного способа хранения и обмена файлами.

В отличие от традиционной клиент-серверной модели интернета, IPFS позволяет пользователям обмениваться файлами напрямую друг с другом, а не полагаться на централизованный сервер для хранения и распространения контента.

Файлы в IPFS адресуются с использованием *content-addressing*, то есть каждому файлу присваивается уникальный хеш или CONTENT IDENTIFIER (CID) на основе его содержимого, и этот хеш используется для получения файла из сети.

IPFS хранит содержимое в виде блоков, идентифицируемых CID. При добавлении файла он сохраняется на вашем узле; он не копируется автоматически на другие узлы. Держите доступную копию в сети или настройте удалённое закрепление, чтобы другие читатели могли его получить. См. [IPFS persistence](https://docs.ipfs.tech/concepts/persistence/).

Прочитайте [Введение в IPFS](https://blog.infura.io/post/an-introduction-to-ipfs)



## Создание вашего сайта

В этом примере мы создаём простой веб-сайт.

[Пример сайта](https://squirrel.surf)


**Шаг 1:** Если вы не знакомы с веб-дизайном, напишите основной контент для вашего сайта, включая заголовок, основной текст, ссылки на другие страницы/сайты и футеры.

**Шаг 2:** Используйте [HTML-шаблон!](https://nicepage.com/html-templates) Вставьте написанный вами текст соответствующим образом. Также по желанию можно создать таблицу стилей .CSS для вашего сайта.

**Шаг 3:** Поместите домашнюю страницу в `index.html` в корне папки сайта. Добавьте её изображения и CSS, используя относительные пути, например `style.css`, чтобы они работали и по URL-адресу шлюза IPFS.

## Настройка узла

[IPFS Desktop](https://docs.ipfs.tech/install/ipfs-desktop/) управляет узлом за вас. Не закрывайте его, пока делитесь своим сайтом.

Для [варианта с командной строкой](https://docs.ipfs.tech/how-to/command-line-quick-start/) один раз инициализируйте новый репозиторий:

```sh
ipfs init
```

Затем запустите узел и оставьте этот терминал открытым:

```sh
ipfs daemon
```

Выполните остальные команды во втором терминале. Не запускайте второй демон, если IPFS Desktop уже управляет этим репозиторием.

**Добавьте папку сайта в IPFS**:

В IPFS Desktop выберите папку с файлами вашего сайта с помощью опции «Добавить папку» (Add Folder).

![](/content-images/ipfs-site-folder-2c96524d98.webp)

--

Для варианта через CLI выполните эту команду из родительского каталога папки вашего сайта:

```sh
ipfs add -r folder_name
```

Замените `folder_name` на имя вашей папки (имена, содержащие пробелы, заключайте в кавычки). Сохраните CID из последней строки `added ... folder_name`: он идентифицирует весь каталог, а не только `index.html`.

### Закрепите сайт в IPFS:

Команда CLI `ipfs add` по умолчанию локально закрепляет (pin) импортированное содержимое. Проверьте закрепление папки с помощью:

```sh
ipfs pin ls YOUR_FOLDER_CID
```

Замените `YOUR_FOLDER_CID` на CID из предыдущего шага; в выводе должно быть `recursive`. Закрепление (pinning) защищает копию на этом узле от сборки мусора, но не держит выключенный компьютер в сети. Чтобы данные оставались доступными, пока ваш узел не в сети, настройте [удалённое закрепление](https://docs.ipfs.tech/how-to/work-with-pinning-services/) и убедитесь, что удалённый сервис завершил закрепление.

### Доступ к вашему сайту в IPFS:

Сначала проверьте свой сайт через локальный шлюз по адресу `http://127.0.0.1:8080/ipfs/YOUR_FOLDER_CID/` (если ваш демон вывел другой порт шлюза, используйте его). Завершающая косая черта позволяет относительным ссылкам разрешаться внутри каталога.

Публичный шлюз, например `https://ipfs.io/ipfs/YOUR_FOLDER_CID/`, сможет отдавать его, как только сможет получить содержимое с доступного узла. Успешный локальный предпросмотр не доказывает публичную доступность.

В нашем случае CID = "QmW2UEfap1vrRRvS5H9wed8qmsx4WsvXBk3GPGVVfWx3r3"


## IPNS

Interplanetary Naming System (IPNS) позволяет вам обновлять CID IPFS, связанные с вашим сайтом, и при этом по-прежнему использовать статическую ссылку. Он предоставляется в виде ключа.

![](/content-images/dns-query.a0134a75-9ef7817f80.webp)

В меню настроек для папки вашего сайта в настольном приложении IPFS выберите Publish to IPNS.

![](/content-images/IPNS-2fe62cc369.webp)

Ключ: "k51qzi5uqu5di670a6uxywo17b2be1eyhoa2cl0qlwpfxn5p9ypcu8jbzgnj4n"

Его также можно использовать для просмотра нашего сайта через шлюз: https://ipfs.io/ipns/k51qzi5uqu5di670a6uxywo17b2be1eyhoa2cl0qlwpfxn5p9ypcu8jbzgnj4n


## DNS Link

Сайт создан, теперь нам нужен способ направить URL на этот контент.

Для `example.com` добавьте эту DNS-запись, заменив `YOUR_FOLDER_CID` на CID вашего каталога:

| Тип | Имя | Значение |
|---|---|---|
| TXT | `_dnslink.example.com` | `dnslink=/ipfs/YOUR_FOLDER_CID` |

Некоторые DNS-провайдеры добавляют зону автоматически; в этом случае введите только `_dnslink`. Если используется имя IPNS, указанное выше, значением может быть `dnslink=/ipns/YOUR_IPNS_NAME`. См. [DNSLink](https://docs.ipfs.tech/concepts/dnslink/).

![](/content-images/example-c2a9edb28b.webp)

После распространения DNS попробуйте `https://ipfs.io/ipns/example.com/`. Для работы сайта напрямую по адресу `https://example.com/` также нужны шлюз с поддержкой DNSLink и настройка HTTPS: одна только TXT-запись их не настраивает. Следуйте [руководству по пользовательскому домену](https://docs.ipfs.tech/how-to/websites-on-ipfs/custom-domains/).

Поздравляем! Вы настроили сайт, устойчивый к цензуре.
