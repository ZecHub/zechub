# Новостная рассылка ZecWeekly

ZecWeekly — это новостная рассылка, которая выходит каждое воскресное утро. Она включает все новости, произошедшие за неделю в экосистеме Zcash. Новости еженедельно отбираются участниками сообщества, и в рассылку добавляются все relevant ссылки. Пожалуйста, подпишитесь на рассылку [здесь](https://zechub.substack.com/).

## Участие

Вклад в рассылку работает лучше всего, когда один участник подготавливает выпуск для нужной недели, следит за текущей bounty или координационной веткой и отправляет pull request после того, как еженедельные ссылки будут готовы. Пожалуйста, не отправляйте будущий выпуск до того, как ZecHub опубликует или подтвердит дату этого выпуска. Ранние pull request часто пропускают обновления конца недели, конфликтуют с назначенным куратором или используют неверный крайний срок.

### 1. Подтвердите текущий выпуск

Перед тем как начать писать:

- Проверьте [ZEC Bounties ](https://bounties.zechub.wiki/) на наличие текущей задачи по рассылке.
- Дождитесь назначения

![ss](/content-images/149a802c-b64f-4969-ad89-e83ffecf568e-d5d8387145.webp)



### 2. Сделайте fork репозитория

Если вы новичок в GitHub, используйте этот рабочий процесс:

1. Откройте [репозиторий ZecHub](https://github.com/ZecHub/zechub).
2. Нажмите **Fork** и создайте fork в своей учетной записи GitHub.
3. В своем fork создайте новую ветку для выпуска. Понятное имя ветки будет полезно, например `digest-may-30-2026`.
4. Убедитесь, что ваш pull request будет нацелен на `ZecHub/zechub` как базовый репозиторий и на `main` как базовую ветку.

Если вы используете командную строку, тот же рабочий процесс выглядит так:

```bash
git clone https://github.com/YOUR-USERNAME/zechub.git
cd zechub
git checkout -b digest-month-day-year
```

Замените `YOUR-USERNAME` на свое имя пользователя GitHub. URL выше является заполнителем и не будет работать в указанном виде.

### 3. Создайте файл рассылки

Используйте [шаблон рассылки](https://github.com/ZecHub/zechub/blob/main/newsletter/newslettertemplate.md) как отправную точку. Выпуски рассылки должны находиться в папке [`newsletter`](https://github.com/ZecHub/zechub/tree/main/newsletter).

При создании файла:

- Используйте формат имени файла, указанный в issue или используемый в недавних принятых выпусках.
- Сохраняйте тот же порядок разделов, что и в шаблоне, если только в задаче не требуется другой формат.
- Добавляйте ссылки только за соответствующую неделю.
- Пишите краткое и понятное описание для каждой ссылки, чтобы читатели понимали, почему она важна.
- При необходимости переводите или кратко излагайте неанглоязычные источники на английском.
- Проверьте каждую ссылку перед открытием pull request.

### 4. Собирайте ссылки в правильное время

ZecWeekly обычно освещает активность в экосистеме Zcash за текущую неделю и публикуется ближе к концу недели. Самое безопасное время для этого:

- Начинайте собирать ссылки после публикации текущего выпуска рассылки или задачи.
- Ведите черновик, пока неделя еще продолжается.
- Отправляйте pull request ближе к запрошенной дате отправки, после проверки обновлений конца недели.
- Не отправляйте рассылку на будущую неделю до появления задачи на эту дату или до подтверждения от ZecHub, что именно вам следует ее подготовить.

Если в issue указано, что отправить нужно к определенной дате, следуйте этой дате. Если между этой страницей и текущим issue есть противоречие, следуйте текущему issue.

### 5. Откройте pull request

Когда файл вашей рассылки готов:

1. Зафиксируйте изменения в своем fork.
2. Откройте pull request в `ZecHub/zechub` в ветку `main`.
3. Используйте заголовок, соответствующий выпуску, например `Zcash Ecosystem Digest | May 30th`.
4. Укажите ссылку на issue в тексте pull request, чтобы проверяющие могли связать работу с задачей.

Пример текста pull request:

```md
Closes #ISSUE_NUMBER

Summary:
- Adds the Zcash Ecosystem Digest for Month Day.
- Uses the newsletter template and the current issue deadline.
- Checks links and descriptions for the requested week.
```

После открытия pull request следите за комментариями ревью. Если ZecHub попросит внести правки, обновите ту же ветку вместо открытия второго pull request для того же выпуска.

### Распространенные ошибки, которых следует избегать

- Открытие pull request до подтверждения даты выпуска или задачи.
- Работа над issue, у которого уже есть связанный pull request.
- Отправка pull request в собственный fork вместо `ZecHub/zechub`.
- Использование неправильного имени файла или размещение файла вне папки `newsletter`.
- Копирование старого выпуска без обновления всех дат, ссылок и описаний.
- Добавление ссылок не за ту неделю.
- Наличие неработающих ссылок, дублирующихся ссылок или текста-заполнителя из шаблона.
- Открытие нового pull request после комментариев ревью вместо обновления исходной ветки.

### Финальный контрольный список

Перед запросом ревью убедитесь, что:

- Дата issue или задачи соответствует вашему файлу рассылки.
- Ни один другой открытый pull request уже не охватывает тот же issue или выпуск.
- Файл находится в папке `newsletter`.
- Разделы шаблона заполнены полностью.
- Каждая ссылка работает и имеет полезное описание.
- В тексте pull request есть ссылка на правильный issue.
- Вы готовы внести правки, если ревьюеры попросят изменения.
