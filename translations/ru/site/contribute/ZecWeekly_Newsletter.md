# Рассылка ZecWeekly

ZecWeekly — это рассылка, которая выходит каждое воскресное утро. Она включает все новости, произошедшие за неделю в экосистеме Zcash. Новости еженедельно отбираются участниками сообщества, а все актуальные ссылки добавляются в рассылку. Пожалуйста, подпишитесь на рассылку [здесь](https://zechub.substack.com/).

## Внести вклад

Вклад в рассылку наиболее эффективен, когда один участник готовит выпуск для нужной недели, следует актуальной теме баунти или координации и отправляет pull request после того, как еженедельные ссылки готовы. Пожалуйста, не отправляйте будущий выпуск до того, как ZecHub опубликует или подтвердит дату этого выпуска. Ранние pull request часто упускают обновления конца недели, конфликтуют с назначенным куратором или используют неверный дедлайн.

### 1. Подтвердите текущий выпуск

Прежде чем начать писать:

- Проверьте [ZEC Bounties ](https://bounties.zechub.wiki/), чтобы найти текущую задачу рассылки.
- Дождитесь назначения

![ss](/content-images/149a802c-b64f-4969-ad89-e83ffecf568e-d5d8387145.webp)



### 2. Сделайте форк репозитория

Если вы новичок в GitHub, используйте этот рабочий процесс:

1. Откройте [репозиторий ZecHub](https://github.com/ZecHub/zechub).
2. Нажмите **Fork** и создайте форк в своей учётной записи GitHub.
3. В своём форке создайте новую ветку для выпуска. Понятное имя ветки будет полезным, например `digest-may-30-2026`.
4. Убедитесь, что ваш pull request будет направлен в `ZecHub/zechub` в качестве базового репозитория и в ветку `main` в качестве базовой ветки.

Если вы используете командную строку, тот же рабочий процесс выглядит так:

```bash
git clone https://github.com/YOUR-USERNAME/zechub.git
cd zechub
git checkout -b digest-month-day-year
```

Замените `YOUR-USERNAME` на своё имя пользователя GitHub. Указанный выше URL является заполнителем и в таком виде не будет работать.

### 3. Создайте файл рассылки

Используйте [шаблон рассылки](https://github.com/ZecHub/zechub/blob/main/newsletter/newslettertemplate.md) как отправную точку. Выпуски рассылки должны находиться в папке [`newsletter`](https://github.com/ZecHub/zechub/tree/main/newsletter).

При создании файла:

- Соблюдайте формат имени файла, запрошенный в issue или использованный в последних принятых выпусках.
- Сохраняйте тот же порядок разделов, что и в шаблоне, если задача не требует другого формата.
- Добавляйте ссылки только за соответствующую неделю.
- Напишите краткое и понятное описание для каждой ссылки, чтобы читатели понимали её значимость.
- При необходимости переводите или резюмируйте неанглоязычные источники на английском языке.
- Проверьте каждую ссылку перед открытием pull request.

### 4. Собирайте ссылки в нужное время

ZecWeekly обычно охватывает активность экосистемы Zcash за текущую неделю и публикуется ближе к концу недели. Самый безопасный график:

- Начинайте собирать ссылки после публикации текущего выпуска или задачи рассылки.
- Ведите черновик, пока неделя ещё продолжается.
- Отправляйте pull request ближе к запрошенной дате подачи после проверки обновлений конца недели.
- Не отправляйте рассылку за будущую неделю до появления задачи на эту дату или до подтверждения ZecHub, что вы должны её подготовить.

Если в issue указано, что нужно отправить работу к определённой дате, следуйте этой дате. Если между этой страницей и текущим issue есть противоречие, следуйте текущему issue.

### 5. Откройте pull request

Когда файл рассылки готов:

1. Закоммитьте изменения в свой форк.
2. Откройте pull request в `ZecHub/zechub` для ветки `main`.
3. Используйте заголовок, соответствующий выпуску, например `Zcash Ecosystem Digest | May 30th`.
4. Укажите issue в теле pull request, чтобы проверяющие могли связать работу с задачей.

Пример тела pull request:

```md
Closes #ISSUE_NUMBER

Summary:
- Adds the Zcash Ecosystem Digest for Month Day.
- Uses the newsletter template and the current issue deadline.
- Checks links and descriptions for the requested week.
```

После открытия pull request следите за комментариями к проверке. Если ZecHub попросит внести изменения, обновите ту же ветку, а не открывайте второй pull request для того же выпуска.

### Реальные примеры

Используйте эти объединённые pull request рассылки в качестве примеров принятых отправок:

- [Zcash Ecosystem Digest | March 28th](https://github.com/ZecHub/zechub/pull/1544)

Сравнивая свою работу с примером, сосредоточьтесь на расположении файла, формате заголовка, порядке разделов, описаниях ссылок и на том, связан ли pull request с правильной задачей.

### Распространённые ошибки, которых следует избегать

- Открытие pull request до подтверждения даты выпуска или задачи.
- Работа над issue, для которого уже есть связанный pull request.
- Отправка pull request в собственный форк вместо `ZecHub/zechub`.
- Использование неправильного имени файла или размещение файла вне папки `newsletter`.
- Копирование старого выпуска без обновления всех дат, ссылок и описаний.
- Добавление ссылок не за ту неделю.
- Оставление неработающих или дублирующихся ссылок либо текста-заполнителя из шаблона.
- Открытие нового pull request после комментариев к проверке вместо обновления исходной ветки.

### Итоговый контрольный список

Перед запросом проверки убедитесь, что:

- Дата issue или задачи совпадает с вашим файлом рассылки.
- Ни один другой открытый pull request уже не охватывает тот же issue или выпуск.
- Файл находится в папке `newsletter`.
- Разделы шаблона заполнены полностью.
- Каждая ссылка работает и имеет полезное описание.
- В теле pull request указана правильная issue.
- Вы готовы внести правки, если проверяющие запросят изменения.
