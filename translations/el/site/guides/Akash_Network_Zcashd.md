# Ανάπτυξη του zcashd στο Akash μέσω Console

> **Απαρχαιωμένο. Μην ακολουθήσεις αυτόν τον οδηγό για να αναπτύξεις έναν κόμβο που σκοπεύεις να χρησιμοποιήσεις.**
>
> Το zcashd έφτασε στην αυτόματη παύση Τέλους Υποστήριξης στις 18 Ιουλίου 2026. Ένας κόμβος zcashd που αναπτύσσεται σήμερα δεν θα συγχρονιστεί με την κορυφή της αλυσίδας, επομένως η ανάπτυξη κοστίζει χρήματα κάθε μήνα και δεν παράγει τίποτα.
>
> Ανάπτυξε **Zebra** αντί αυτού: [Πώς να εκτελέσεις το Zebra στο Akash Network](/guides/akash-network-zebra), που καλύπτει την ίδια ροή εργασίας του Akash Console και χρειάζεται περίπου το ένα τρίτο του χώρου δίσκου. Αν μεταφέρεις μια υπάρχουσα ρύθμιση, δες τον [οδηγό μετάβασης από το zcashd στο Zebra και το Zallet](/guides/migration-guide-zcashd-to-zebrad-zallet).
>
> Αυτή η σελίδα διατηρείται ως ιστορικό αρχείο της ανάπτυξης του zcashd.

Οδηγός για την ανάπτυξη ενός πλήρους κόμβου zcashd Zcash (υλοποίηση Electric Coin Co) με τη χρήση του [Akash Console](https://console.akash.network). Παρακάτω υπάρχει ένα βίντεο με οδηγίες. Ένας πιο αναλυτικός οδηγός βρίσκεται πιο κάτω.

## Τι αναπτύσσεις

Έναν πλήρη κόμβο zcashd που θα:

-> Συγχρονίσει ολόκληρο το blockchain Zcash (350GB+ για mainnet, ~ 40GB για testnet)

-> Κοστίζει περίπου $15/μήνα, ανάλογα με τις τιμές των token AKT

-> Χρειαστεί από αρκετές ώρες έως ημέρες για να συγχρονιστεί πλήρως

-> Χρησιμοποιεί 4 vCPU, 16GB RAM, 350GB αποθηκευτικού χώρου (mainnet) ή 2 vCPU, 8GB RAM, 50GB (testnet)

-> Κατεβάσει κρυπτογραφικές παραμέτρους κατά την πρώτη εκτέλεση (~ 2GB, μία φορά)

**zcashd έναντι Zebra:**

-> Το zcashd ήταν η αρχική υλοποίηση κόμβου Zcash από το Electric Coin Co και έχει σταματήσει από τις 18 Ιουλίου 2026

-> Το Zebra, από το Zcash Foundation, είναι ο πλήρης κόμβος που χρησιμοποιείται σήμερα

-> Μόνο το Zebra ακολουθεί την τρέχουσα αλυσίδα· ένας κόμβος zcashd δεν μπορεί να φτάσει στην κορυφή

-> Το πορτοφόλι του zcashd έχει αντικατασταθεί από το [Zallet](/using-zcash/zallet-quick-reference-guide)

-> Χρησιμοποίησε το zcashd αν χρειάζεσαι λειτουργικότητα πορτοφολιού ή συγκεκριμένα API RPC


### **Σημαντικό: Αντιστοίχιση θυρών στο Akash**

Όταν εκθέτεις μια θύρα στο Akash (π.χ. τη θύρα 8233 για P2P του zcashd), αυτή **ΔΕΝ δεσμεύεται στην ακριβή θύρα** της δημόσιας IP του παρόχου. Αντίθετα, ο πάροχος εκχωρεί μια τυχαία υψηλή θύρα (όπως 31234 ή 42567) και τη συνδέει μέσω αντίστροφου proxy με τη θύρα 8233 του container σου.

Αυτό γίνεται εκ σχεδιασμού - οι πάροχοι εκτελούν πολλαπλές αναπτύξεις και θα υπήρχαν συγκρούσεις αν όλοι προσπαθούσαν να χρησιμοποιήσουν απευθείας τη θύρα 8233.

**Τι σημαίνει αυτό για εσένα:**

-> Ρυθμίζεις τη θύρα 8233 στο SDL (την τυπική θύρα P2P του zcashd)

-> Το Akash σου δίνει ένα URI όπως *provider.com:31234*

-> Άλλοι κόμβοι Zcash συνδέονται μαζί σου στο *provider.com:31234*

-> Μέσα στο container σου, το zcashd εξακολουθεί να ακούει στη θύρα 8233


Αυτό διαχειρίζεται αυτόματα. Απλώς χρησιμοποίησε το URI που σου δίνει το Akash.

## Προαπαιτούμενα

-> Εγκατεστημένη επέκταση προγράμματος περιήγησης **Keplr Wallet** (Chrome/Brave/Firefox)

-> **Token AKT** - Απόκτησε 50-100 AKT από ένα ανταλλακτήριο (Coinbase, Kraken, Osmosis)

-> **5 λεπτά** για να ολοκληρώσεις τα κλικ στο UI του Console


## Βήμα 1: Σύνδεσε το πορτοφόλι σου

-> Μετάβαλε στο [https://console.akash.network](https://console.akash.network)

-> Κάνε κλικ στο **«Connect Wallet»** επάνω δεξιά

-> Επίλεξε **Keplr** (ή το πορτοφόλι Cosmos που προτιμάς)

-> Έγκρινε τη σύνδεση όταν εμφανιστεί το Keplr


Το υπόλοιπο AKT σου θα πρέπει να εμφανιστεί επάνω δεξιά. Αν είναι μηδενικό, πρόσθεσε πρώτα κεφάλαια στο πορτοφόλι σου.

## Βήμα 2: Δημιούργησε ανάπτυξη

-> Κάνε κλικ στο κουμπί **«Deploy»** (μεγάλο μπλε κουμπί, στο κέντρο της σελίδας)

-> Επίλεξε **«Build your template»** (ή παράλειψέ το για να μεταφορτώσεις απευθείας SDL)

### Επιλογή Α: Μεταφόρτωση αρχείου SDL (συνιστάται)

> **Αυτό το κουμπί αναπτύσσει έναν σταματημένο κόμβο.** Χρεώνει το υπόλοιπο AKT σου για έναν κόμβο που δεν μπορεί να συγχρονιστεί. Χρησιμοποίησε αντί αυτού τον οδηγό [Zebra](/guides/akash-network-zebra).

[![Deploy on Akash](/content-images/deploy-with-akash-btn-74abb88d44.svg)](https://console.akash.network/new-deployment?step=edit-deployment&templateId=akash-network-awesome-akash-zcash-zcashd)

### Επιλογή Β: Χρήση του επεξεργαστή SDL

Αν θέλεις να επικολλήσεις το SDL χειροκίνητα:

-> Αντέγραψε τα περιεχόμενα του *zcashd-akash.yml*

-> Επικόλλησέ τα στον επεξεργαστή SDL

-> Τροποποίησέ τα όπως χρειάζεται (δες την ενότητα ρυθμίσεων παρακάτω)

-> Κάνε κλικ στο **«Create Deployment»**


## Βήμα 3: Έλεγξε και έγκρινε την κατάθεση

Το Console θα σου δείξει:

-> **Κατάθεση ανάπτυξης**: ~ 5 AKT (θα τα πάρεις πίσω όταν κλείσεις την ανάπτυξη)

-> **Εκτιμώμενο κόστος**: Με βάση την τιμολόγηση του SDL σου


Κάνε κλικ στο **«Approve»** και υπέγραψε τη συναλλαγή στο Keplr.

## Βήμα 4: Επίλεξε πάροχο

Μετά από ~ 30 δευτερόλεπτα, θα δεις προσφορές από παρόχους. Κάθε προσφορά δείχνει:

-> **Τιμή ανά μπλοκ** (σε AKT ή USDC)

-> **Εκτιμώμενο μηνιαίο κόστος**

-> **Στοιχεία παρόχου** (χρόνος λειτουργίας, περιοχή κ.λπ.)


**Μην επιλέξεις απλώς τον φθηνότερο.** Έλεγξε:

-> Ποσοστό χρόνου λειτουργίας (στόχευσε σε > 95%)

-> Περιοχή (όσο πιο κοντά σου = καλύτερη καθυστέρηση, αλλά δεν έχει μεγάλη σημασία για κόμβους blockchain)

-> Κατάσταση ελεγμένου παρόχου (πράσινο σημάδι ελέγχου = πιο αξιόπιστος)


Κάνε κλικ στο **«Accept Bid»** για τον πάροχο που επέλεξες και υπέγραψε στο Keplr.

## Βήμα 5: Περίμενε την ανάπτυξη

Το Console θα:

-> Δημιουργήσει τη μίσθωση με τον πάροχο που επέλεξες

-> Στείλει το manifest (λέει στον πάροχο τι να εκτελέσει)

-> Εκκινήσει το container σου


Αυτό διαρκεί 1-2 λεπτά. Θα δεις ενημερώσεις κατάστασης στο UI.

## Βήμα 6: Επιβεβαίωσε ότι εκτελείται

Μόλις αναπτυχθεί, θα δεις:

-> Καρτέλα **Services**: Εμφανίζει την υπηρεσία σου *zcashd* με την κατάστασή της

-> Καρτέλα **Logs**: Ζωντανά αρχεία καταγραφής από τον κόμβο zcashd

-> Καρτέλα **Leases**: Λεπτομέρειες για την ανάπτυξή σου (DSEQ, πάροχος, κόστος)


### Έλεγξε τα αρχεία καταγραφής

Κάνε κλικ στο **Logs** και θα πρέπει να δεις το zcashd να εκκινεί:

```bash
[zcashd]: ZCASHD_NETWORK=mainnet
[zcashd]: Starting: zcashd -printtoconsole -showmetrics=1
...
```

**Η πρώτη εκτέλεση θα κατεβάσει το zcash-params (~2GB).** Αυτή είναι μια εφάπαξ ενέργεια και διαρκεί 5-10 λεπτά, ανάλογα με το εύρος ζώνης του παρόχου. Οι επόμενες επανεκκινήσεις θα το παραλείψουν.

Ο συγχρονισμός θα διαρκέσει **από ώρες έως ημέρες**, ανάλογα με το δίκτυο. Πρόσεξε για:

-> Αυξανόμενα ύψη μπλοκ

-> Συνδέσεις ομότιμων (θα πρέπει να είναι 10-30 ομότιμοι)

-> Καμία επαναλαμβανόμενη σφάλμα


## Βήμα 7: Βρες τη διεύθυνση του κόμβου σου

Κάνε κλικ στην καρτέλα **Leases**, έπειτα στο **URIs**.

Θα δεις κάτι όπως:

```
zcashd-8233: provider-hostname.com:31234
```

Αυτό είναι το **δημόσιο τελικό σημείο P2P** του κόμβου σου. Άλλοι κόμβοι Zcash θα συνδέονται μαζί σου σε αυτή τη διεύθυνση.

**Σημείωσε την αντιστοίχιση θυρών:** Ρύθμισες τη θύρα 8233 στο SDL, αλλά το Akash την εκχώρησε σε διαφορετική δημόσια θύρα (31234 σε αυτό το παράδειγμα). Αυτό είναι φυσιολογικό - δες την ενότητα «Αντιστοίχιση θυρών στο Akash» στην κορυφή αν σε μπερδεύει. Ο κόμβος σου είναι προσβάσιμος από όποια θύρα δείχνει εδώ το Akash, όχι απαραίτητα από τη 8233.

Αν ενεργοποίησες RPC (είναι σχολιασμένο από προεπιλογή στο SDL), θα δεις επίσης εδώ το τελικό σημείο RPC με τη δική του αντιστοιχισμένη θύρα.

## Επιλογές ρυθμίσεων

### Μετάβαση σε Testnet

Το SDL χρησιμοποιεί από προεπιλογή Mainnet. Για να χρησιμοποιήσεις Testnet:

-> **Άλλαξε δίκτυο στην ενότητα *env*:**

   ```yaml
   # - "ZCASHD_NETWORK=mainnet"
   - "ZCASHD_NETWORK=testnet"
   ```

-> **Ενημέρωσε την εκτεθειμένη θύρα** στην ενότητα *expose*:

   ```yaml
   # Comment out Mainnet port:
   # - port: 8233
   #   as: 8233
   #   to:
   #     - global: true
   #   proto: tcp

   # Uncomment Testnet port:
   - port: 18233
     as: 18233
     to:
       - global: true
     proto: tcp
   ```

-> **Προαιρετικά: Μείωσε τους πόρους** για Testnet στο *profiles.compute.zcashd.resources*:

   ```yaml
   cpu:
     units: 2  # Down from 4
   memory:
     size: 8Gi  # Down from 16Gi
   storage:
     - size: 50Gi  # Down from 150Gi
   ```

-> **Προαιρετικά: Μείωσε την τιμολόγηση** στο *profiles.placement.akash.pricing*:

   ```yaml
   amount: 5000  # Down from 10000
   ```

> Σημείωσε ότι η μείωση των τιμών μπορεί να αποκλείσει παρόχους από την υποβολή προσφορών. Πειραματίσου με αυτή την τιμή ή χρησιμοποίησε το τελικό σημείο του παρόχου για να ελέγξεις αν θα υπέβαλλαν προσφορά. (Δες την τεκμηρίωση του API του παρόχου)

### Ενεργοποίηση πρόσβασης RPC

Το RPC είναι απενεργοποιημένο από προεπιλογή για λόγους ασφάλειας. Για να το ενεργοποιήσεις:

**ΚΡΙΣΙΜΟ: Όρισε ισχυρά διαπιστευτήρια.** Το RPC του zcashd μεταδίδει όνομα χρήστη/κωδικό πρόσβασης μέσω HTTP (όχι HTTPS). Έκθεσε το RPC μόνο αν κατανοείς τις επιπτώσεις στην ασφάλεια.

-> Αφαίρεσε το σχόλιο στην ενότητα *env*:

   ```yaml
   - "ZCASHD_RPCUSER=yourusername"
   - "ZCASHD_RPCPASSWORD=your_very_strong_password_here"  # Use a real password
   - "ZCASHD_RPCBIND=0.0.0.0"
   - "ZCASHD_RPCPORT=8232"  # Mainnet
   # - "ZCASHD_RPCPORT=18232"  # Testnet
   - "ZCASHD_ALLOWIP=0.0.0.0/0"  # Allow from anywhere (use with caution)
   ```

-> Αφαίρεσε το σχόλιο από τη θύρα RPC στο *expose*:

   **Για Mainnet:**

   ```yaml
   - port: 8232
     as: 8232
     to:
       - global: false  # Keep internal for security
     proto: tcp
   ```

   **Για Testnet:**

   ```yaml
   - port: 18232
     as: 18232
     to:
       - global: false
     proto: tcp
   ```

**Προειδοποίηση**: Αν ορίσεις *global: true* για RPC, το εκθέτεις στο διαδίκτυο με βασικό έλεγχο ταυτότητας. Αυτή είναι κακή ιδέα. Χρησιμοποίησε *global: false* και πρόσβασε το RPC μέσω του εσωτερικού δικτύου του Akash ή ρύθμισε ένα ασφαλές tunnel.

**Υπενθύμιση αντιστοίχισης θυρών**: Ακόμη και αν εκθέσεις το RPC καθολικά, το Akash θα το αντιστοιχίσει σε μια τυχαία υψηλή θύρα (όχι 8232/18232). Έλεγξε τα URI στην ανάπτυξή σου για να δεις το πραγματικό δημόσιο τελικό σημείο. Για *global: false* (συνιστάται), το τελικό σημείο RPC είναι προσβάσιμο μόνο εντός του δικτύου ανάπτυξης Akash και όχι από το δημόσιο διαδίκτυο.

### Ενεργοποίηση ευρετηρίου συναλλαγών

Το ευρετήριο συναλλαγών σου επιτρέπει να αναζητάς οποιαδήποτε συναλλαγή βάσει του ID της μέσω RPC. Χρησιμοποιεί περισσότερο αποθηκευτικό χώρο (~ 20% αύξηση).

Αφαίρεσε το σχόλιο στο *env*:

```yaml
- "ZCASHD_TXINDEX=1"
```

**Προειδοποίηση**: Η ενεργοποίηση του txindex σε έναν υπάρχοντα συγχρονισμένο κόμβο απαιτεί επαναδημιουργία ευρετηρίου για ολόκληρο το blockchain, κάτι που διαρκεί ώρες.

### Ενεργοποίηση Insight Explorer

Το Insight Explorer παρέχει επιπλέον τελικά σημεία REST API για δεδομένα blockchain (χρήσιμα για block explorers).

Αφαίρεσε το σχόλιο στο *env*:

```yaml
- "ZCASHD_INSIGHTEXPLORER=1"
```

Αυτό ενεργοποιεί αυτόματα το txindex και προσθέτει επιπλέον μεθόδους RPC.

### Ενεργοποίηση μετρικών Prometheus

Για να συλλέγεις μετρικές για παρακολούθηση:

-> Αφαίρεσε το σχόλιο στο *env*:

   ```bash
   - "ZCASHD_PROMETHEUSPORT=9969"
   - "ZCASHD_METRICSIP=0.0.0.0/0"
   ```

-> Αφαίρεσε το σχόλιο από τη θύρα μετρικών στο *expose*:

   ```bash
   - port: 9969
     as: 9969
     to:
       - global: false
     proto: tcp
   ```
   
Οι μετρικές θα είναι διαθέσιμες στο http://yourendpoint:9969/metrics σε μορφή Prometheus.

### Προσαρμογή πόρων/τιμολόγησης

Αν δεν λαμβάνεις προσφορές ή θέλεις να βελτιστοποιήσεις το κόστος:

**Για παρόχους χαμηλότερων προδιαγραφών**, μείωσε στην ενότητα *profiles.compute.zcashd.resources*:

-> CPU: *units: 2* (ελάχιστο για λογική ταχύτητα συγχρονισμού)

-> Μνήμη: *size: 12Gi* (ελάχιστο για σταθερότητα)

-> Αποθηκευτικός χώρος: *size: 120Gi* (ελάχιστο για mainnet)


**Για να προσελκύσεις περισσότερες προσφορές**, αύξησε στο *profiles.placement.akash.pricing*:

-> Mainnet: Δοκίμασε *amount: 15000* uakt/block

-> Testnet: Δοκίμασε *amount: 7500* uakt/block


Οι τιμές SDL έχουν οριστεί συντηρητικά υψηλά. Οι περισσότεροι πάροχοι θα υποβάλουν χαμηλότερη προσφορά.

## Ενημέρωση της ανάπτυξής σου

Χρειάζεται να αλλάξεις ρυθμίσεις μετά την ανάπτυξη;

-> Μετάβαλε στο **My Deployments** στο Console

-> Βρες την ανάπτυξη zcashd

-> Κάνε κλικ στο **«Update Deployment»**

-> Επεξεργάσου το SDL

-> Κάνε κλικ στο **«Update»** και έγκρινε στο Keplr


**Σημείωση**: Η ενημέρωση θα επανεκκινήσει το container σου. Ο κόμβος θα συνεχίσει από την αποθηκευμένη κατάστασή του (μόνιμος αποθηκευτικός χώρος), αλλά περίμενε 1-2 λεπτά διακοπής λειτουργίας.

## Παρακολούθηση

### Μέσω Console

-> Καρτέλα **Logs**: Ζωντανά αρχεία καταγραφής container

-> Καρτέλα **Shell**: Απόκτησε shell μέσα στο container (χρήσιμο για αποσφαλμάτωση)

-> Καρτέλα **Events**: Συμβάντα Kubernetes (ως επί το πλείστον άχρηστα εκτός αν κάτι έχει χαλάσει)


### Μέσω RPC (αν είναι ενεργοποιημένο)

Αν ενεργοποίησες RPC, μπορείς να υποβάλεις ερωτήματα στον κόμβο σου ως κανονικό πλήρη κόμβο zcashd (επειδή είναι!)

### Εναλλακτική zcash-cli

Αν έχεις πρόσβαση shell μέσω Console, μπορείς να χρησιμοποιήσεις απευθείας το *zcash-cli*:

```bash
# From the Shell tab in Console
zcash-cli getblockchaininfo
zcash-cli getpeerinfo
zcash-cli getinfo
```

## Κλείσιμο της ανάπτυξής σου

Όταν τελειώσεις ή θέλεις να σταματήσεις να πληρώνεις:

-> Μετάβαλε στο **My Deployments**

-> Βρες την ανάπτυξη zcashd

-> Κάνε κλικ στο **«Close Deployment»**

-> Επιβεβαίωσε και υπέγραψε στο Keplr


Η κατάθεσή σου των 5 AKT θα επιστραφεί. Ο **μόνιμος αποθηκευτικός χώρος** θα πρέπει να διατηρείται από τον πάροχο, αλλά μην βασίζεσαι σε αυτόν - αντιμετώπισέ τον όπως κάθε άλλο πάροχο cloud.

## Αντιμετώπιση προβλημάτων

### Σφάλμα «Insufficient funds»

Χρειάζεσαι περισσότερα AKT. Πρόσθεσε κεφάλαια στο πορτοφόλι Keplr σου.

### Δεν εμφανίζονται προσφορές

Ισχύει ένα από τα εξής:

-> Η τιμολόγησή σου είναι πολύ χαμηλή (αύξησε το *amount* στο SDL)

-> Οι απαιτήσεις πόρων σου είναι υπερβολικά υψηλές για τους διαθέσιμους παρόχους (μείωσε CPU/μνήμη/αποθηκευτικό χώρο)

-> Περίμενε περισσότερο (μερικές φορές χρειάζονται 60-90 δευτερόλεπτα για να εμφανιστούν προσφορές)


### Η ανάπτυξη έχει κολλήσει στο «pending»

Ο πάροχος ίσως αντιμετωπίζει προβλήματα. Κλείσε την ανάπτυξη και δοκίμασε διαφορετικό πάροχο.

### Τα αρχεία καταγραφής του zcashd δείχνουν «No peers connected»

Από την παύση Τέλους Υποστήριξης στις 18 Ιουλίου 2026, αυτή είναι η αναμενόμενη μόνιμη κατάσταση και όχι καθυστέρηση εκκίνησης, και καμία αναμονή ή εκ νέου ανάπτυξη δεν θα το διορθώσει. Ανάπτυξε αντί αυτού το [Zebra](/guides/akash-network-zebra).

### Σφάλματα «Out of memory» στα αρχεία καταγραφής

Έκανες οικονομία στη RAM. Κλείσε την ανάπτυξη και ανέπτυξέ την ξανά με τουλάχιστον 12Gi μνήμης (συνιστώνται 16Gi).

### Ο συγχρονισμός διαρκεί για πάντα

Όρισε το «για πάντα»:

-> **Ώρες**: Φυσιολογικό

-> **Ημέρες**: Επίσης φυσιολογικό για mainnet από την αρχή

-> **Εβδομάδες**: Κάτι δεν πάει καλά, έλεγξε τα αρχεία καταγραφής για σφάλματα


### «Error fetching zcash-params»

Ο πάροχος ίσως έχει προβλήματα δικτύου ή αργό εύρος ζώνης. Αυτό συνήθως επιλύεται από μόνο του. Αν επιμένει για περισσότερο από 30 λεπτά, δοκίμασε να αναπτύξεις ξανά σε διαφορετικό πάροχο.

### Αποτυχίες ελέγχου ταυτότητας RPC

-> Έλεγξε ότι τα `ZCASHD_RPCUSER` και `ZCASHD_RPCPASSWORD` έχουν οριστεί σωστά

-> Επιβεβαίωσε ότι χρησιμοποιείς τη σωστή θύρα (8232 για mainnet, 18232 για testnet)

-> Θυμήσου ότι οι θύρες αντιστοιχίζονται από το Akash - χρησιμοποίησε το URI από την ανάπτυξή σου, όχι απευθείας το 8232


## Διαχείριση κόστους

Παρακολούθησε τις δαπάνες σου στο Console:

-> **My Deployments** -> Η ανάπτυξή σου -> Εμφανίζει εκτίμηση «Cost per month»

-> Το υπόλοιπο του πορτοφολιού Keplr σου θα μειώνεται με την πάροδο του χρόνου


Όταν το υπόλοιπό σου μειωθεί πολύ, το Akash θα κλείσει αυτόματα την ανάπτυξή σου. **Κάνε ανανέωση στο πορτοφόλι σου περιοδικά** ή ρύθμισε ειδοποιήσεις.

### Μείωση κόστους

-> **Χρησιμοποίησε Testnet** για δοκιμές εκτός παραγωγής (50% φθηνότερα)

-> **Μείωσε CPU/μνήμη** αν δεν χρειάζεσαι γρήγορο συγχρονισμό

-> **Επίλεξε φθηνότερους παρόχους** (δεν είναι πάντοτε σοφό - ο χρόνος λειτουργίας έχει σημασία)

-> **Χρησιμοποίησε USDC αντί για AKT** αν η τιμή του AKT είναι ασταθής (απαιτεί αλλαγή στην τιμολόγηση SDL)

-> **Απενεργοποίησε το txindex** αν δεν το χρειάζεσαι (εξοικονομεί ~ 20% αποθηκευτικού χώρου)

## Τελικές σημειώσεις

- **Ο μόνιμος αποθηκευτικός χώρος έχει σημασία.** Μην παραλείψεις το *persistent: true* και μη χρησιμοποιήσεις κλάση *beta2*. Χρησιμοποίησε *beta3*.
- **Ο αρχικός συγχρονισμός είναι αργός.** Να είσαι υπομονετικός. Αυτό είναι φυσιολογικό για κόμβους blockchain.
- **Κράτησε το πορτοφόλι σου χρηματοδοτημένο.** Οι αναπτύξεις κλείνουν αυτόματα όταν εξαντλήσεις τα AKT.
- **Τα αντίγραφα ασφαλείας δεν είναι αυτόματα.** Αν σε ενδιαφέρουν τα δεδομένα, υπέθεσε ότι μπορεί να εξαφανιστούν και σχεδίασε ανάλογα.
- **Η ασφάλεια RPC είναι κρίσιμη.** Μην εκθέτεις το RPC στο διαδίκτυο χωρίς κατάλληλα μέτρα ασφάλειας.
- **Τα zcash-params αποθηκεύονται στην cache.** Η πρώτη εκτέλεση κατεβάζει ~2GB κρυπτογραφικών παραμέτρων. Αυτό είναι φυσιολογικό και συμβαίνει μόνο μία φορά.
