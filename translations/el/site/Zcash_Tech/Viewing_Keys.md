# Viewing Keys

Οι θωρακισμένες διευθύνσεις σου επιτρέπουν να πραγματοποιείς συναλλαγές αποκαλύπτοντας όσο το δυνατόν λιγότερα στο blockchain Zcash. Τι συμβαίνει, λοιπόν, όταν *χρειάζεται* να δείξεις σε ένα συγκεκριμένο μέρος τι κατέχεις ή τι έστειλες; Κάθε θωρακισμένη διεύθυνση έχει ένα viewing key που παρέχει πρόσβαση ανάγνωσης χωρίς να δίνει τη δυνατότητα δαπάνης. Τα viewing keys εισήχθησαν στο [ZIP 310](https://zips.z.cash/zip-0310) και προστέθηκαν στο πρωτόκολλο με την αναβάθμιση δικτύου Sapling.

Ένα viewing key είναι το εργαλείο για επιλεκτική αποκάλυψη: επιλέγεις ποιος βλέπει τι και ποτέ δεν παραδίδεις εξουσία δαπάνης για να το κάνεις.

## Συνοπτικά

Ένα viewing key παρέχει πρόσβαση **μόνο για ανάγνωση** στη δραστηριότητα μιας θωρακισμένης διεύθυνσης ή ενός λογαριασμού Zcash: όποιος το κατέχει μπορεί να δει εισερχόμενες (και, για πλήρη viewing keys, εξερχόμενες) συναλλαγές, αλλά ποτέ δεν μπορεί να δαπανήσει.

- **Τι είναι:** το εργαλείο επιλεκτικής αποκάλυψης των θωρακισμένων pools. Εισήχθη στο [ZIP 310](https://zips.z.cash/zip-0310) και προστέθηκε στο πρωτόκολλο με την αναβάθμιση δικτύου Sapling.
- **Τι παρέχει:** ανίχνευση καταθέσεων (εισερχόμενα keys `uivk…`) ή πλήρη ορατότητα εισερχόμενων/εξερχόμενων για έναν λογαριασμό (ενοποιημένα πλήρη viewing keys `uview…`), καθώς και παλαιά keys Sapling `zxviews…`.
- **Τι δεν παρέχει:** εξουσία δαπάνης. Τίποτα από όσα κάνει ο κάτοχος ενός viewing key δεν μπορεί να μετακινήσει κεφάλαια.
- **Πού λειτουργεί σήμερα:** εξαγωγή/εισαγωγή στο [Zallet](https://github.com/zcash/zallet) (v0.1.0-beta.2+, `z_exportviewingkey` / `z_importviewingkey`) και λογαριασμοί μόνο για παρακολούθηση σε πορτοφόλια όπως το Zkool· δες τη σελίδα [Πορτοφόλια](/using-zcash/wallets) για τον τρέχοντα πίνακα υποστήριξης.
- **Ο βασικός κανόνας:** προτίμησε το στενότερο key που απαντά στην ερώτηση που τίθεται και θυμήσου ότι ένα key που έχεις δώσει δεν μπορεί να ανακληθεί — μπορεί μόνο να ξεπεραστεί χρονικά μετακινώντας τα κεφάλαια.

## Γιατί να χρησιμοποιήσεις ένα viewing key;

Το κείμενο του Electric Coin Company για το θέμα παρουσιάζει τις καταστάσεις που προκύπτουν συχνότερα και εξακολουθούν να είναι οι συνήθεις σήμερα:

- **Ένα ανταλλακτήριο που παρακολουθεί καταθέσεις.** Το ανταλλακτήριο φορτώνει ένα εισερχόμενο viewing key σε έναν κόμβο ανίχνευσης συνδεδεμένο στο διαδίκτυο, ώστε να εντοπίζει καταθέσεις πελατών σε μια θωρακισμένη διεύθυνση, ενώ το spending key παραμένει σε hardware που δεν αγγίζει ποτέ το δίκτυο.
- **Ένας θεματοφύλακας που αποδεικνύει τα υπόλοιπά του.** Ο θεματοφύλακας δίνει σε έναν ελεγκτή ένα πλήρες viewing key για κάθε θωρακισμένη διεύθυνση. Ο ελεγκτής μπορεί να ελέγξει αυτά τα υπόλοιπα και να εξετάσει την προηγούμενη δραστηριότητα από και προς αυτές τις διευθύνσεις, και δεν μπορεί να κάνει τίποτε άλλο.
- **Δέουσα επιμέλεια για έναν αντισυμβαλλόμενο.** Όταν ένα ανταλλακτήριο πρέπει να εξετάσει το θωρακισμένο ιστορικό ενός πελάτη στο πλαίσιο ενισχυμένης δέουσας επιμέλειας, μπορεί να ζητήσει το viewing key αντί για τα κεφάλαια.

## Τι αποκαλύπτει και τι δεν αποκαλύπτει ένα viewing key

Υπάρχουν περισσότερα από ένα είδη keys και η διαφορά καθορίζει πόσα αποκαλύπτεις.

| Key | Πρόθεμα | Παρέχει |
|---|---|---|
| Ενοποιημένο πλήρες viewing key (UFVK) | `uview…` | Βλέπει εισερχόμενες **και** εξερχόμενες συναλλαγές για κάθε pool του λογαριασμού |
| Ενοποιημένο εισερχόμενο viewing key (UIVK) | `uivk…` | Βλέπει μόνο εισερχόμενες συναλλαγές, για κάθε pool του λογαριασμού |
| Εκτεταμένο πλήρες viewing key Sapling | `zxviews…` | Βλέπει εισερχόμενη και εξερχόμενη δραστηριότητα Sapling για τις διευθύνσεις του key |

Κανένα από αυτά δεν μπορεί να δαπανήσει. Όλα είναι μόνιμα με τον τρόπο που έχει σημασία: ένα key που έχεις δώσει δεν μπορεί να ανακληθεί, μόνο να ξεπεραστεί χρονικά, μετακινώντας κεφάλαια σε έναν λογαριασμό του οποίου τα keys δεν κατέχει το άλλο μέρος.

Δύο παγίδες αποκάλυψης αξίζει να γνωρίζεις προτού μοιραστείς οτιδήποτε.

**Εισερχόμενο δεν σημαίνει στενό.** Ένα ενοποιημένο εισερχόμενο viewing key αφορά ολόκληρο τον λογαριασμό, όχι τη μία διεύθυνση για την οποία ερωτήθηκες. Η εξαγωγή ενός UIVK για μία μόνο διεύθυνση Sapling εξακολουθεί να παρέχει ορατότητα εισερχόμενων σε κάθε pool αυτού του λογαριασμού, επομένως αποκαλύπτει περισσότερα από τη διεύθυνση που αναφέρει. Το βιβλίο [Zallet Book](https://zcash.github.io/zallet/zcashd/json_rpc.html) το δηλώνει ρητά.

**Μια δημοσιευμένη διεύθυνση εκθέτει ήδη το εισερχόμενο viewing key της σε έναν μελλοντικό αντίπαλο.** Το [ZIP 326](https://zips.z.cash/zip-0326) σημειώνει ότι ένας αντίπαλος με κβαντικό υπολογιστή θα μπορούσε να ανακτήσει το εισερχόμενο viewing key από μια δημοσιευμένη διαφοροποιημένη διεύθυνση, κάτι εφικτό με τρόπο που δεν είναι η ανάκτηση του nullifier key. Η δημοσίευση μιας διεύθυνσης δεν είναι το ίδιο με τη δημοσίευση ενός viewing key σήμερα, αλλά τα δύο βρίσκονται πιο κοντά μεταξύ τους σε αρκετά μακρύ χρονικό ορίζοντα.

## Viewing keys μετά το Ironwood

Το NU6.3 εισήγαγε το θωρακισμένο pool Ironwood και έκανε το pool Orchard μόνο για δαπάνη, επομένως τα κεφάλαια μεταφέρονται με τον χρόνο από το ένα στο άλλο. Δες τα [Ironwood](/zcash-tech/ironwood) και [Το turnstile](/zcash-tech/the-turnstile) για την ίδια την αναβάθμιση.

**Ένα viewing key που εκδόθηκε πριν από το Ironwood συνεχίζει να λειτουργεί μετά τη μεταφορά.** Το ZIP 326 ορίζει ότι ένας δέκτης, και το αντίστοιχο εισερχόμενο viewing key του, αφορά το *πρωτόκολλο* Orchard και όχι ένα pool: το ίδιο εισερχόμενο viewing key αποκρυπτογραφεί δοκιμαστικά ciphertexts note τόσο του pool Orchard όσο και του pool Ironwood. Το Zallet το υλοποιεί έτσι, περιγράφοντας τα notes Ironwood ως διαμορφωμένα σαν Orchard και αποκρυπτογραφούμενα δοκιμαστικά με τα viewing keys Orchard του λογαριασμού, κάτω από το πεδίο κρυπτογράφησης note Ironwood.

Τρεις συνέπειες για οποιονδήποτε κατέχει ή εκδίδει ένα key:

1. **Τα υπόλοιπα μετακινούνται μεταξύ pools και ο θεατής βλέπει να συμβαίνει.** Το [ZIP 318](https://zips.z.cash/zip-0318) ορίζει τη μεταφορά ως σειρά μικρών, σκόπιμα ομοιόμορφων συναλλαγών από Orchard προς Ironwood που μεταδίδονται σε τυχαιοποιημένο χρονοδιάγραμμα, καθεμία από τις οποίες δαπανά ένα note Orchard και παράγει μία έξοδο Ironwood κανονικής ονομαστικής αξίας. Ένας ελεγκτής που παρακολουθεί με viewing key βλέπει τα υπόλοιπα να μετατοπίζονται από το ένα pool στο άλλο σε βήματα επί εβδομάδες, όχι σε μία μόνο κίνηση. Ένα πορτοφόλι μπορεί να ανασυνθέσει τη δική του πρόοδο μεταφοράς από δεδομένα της αλυσίδας χρησιμοποιώντας τα viewing keys του.
2. **Κάθε βήμα μεταφοράς αποκαλύπτει την αξία που μετακινεί.** Αυτό είναι εγγενές στη διέλευση ενός turnstile και είναι αυτό που καθιστά τη μεταφορά ελέγξιμη. Ο διαχωρισμός του υπολοίπου σε κανονικές ονομαστικές αξίες σημαίνει ότι καμία μεμονωμένη συναλλαγή δεν αποκαλύπτει ολόκληρο το υπόλοιπο του pool Orchard.
3. **Οι λογαριασμοί που δημιουργούνται μετά το Ironwood μπορεί να παράγουν τα keys τους διαφορετικά.** Το [ZIP 2005](https://zips.z.cash/zip-2005) προσθέτει μια σημαία `use_qsk` για keys ανακτήσιμα μετά από κβαντική επίθεση και αλλάζει τον τρόπο με τον οποίο παράγονται τα εισερχόμενα, εξερχόμενα και diversifier keys, επομένως τα keys `use_qsk = true` είναι πράγματι διαφορετικά keys. Το ZIP 326 απαιτεί η σημαία να είναι ομοιόμορφη σε έναν λογαριασμό και απαγορεύει τη δημιουργία keys `use_qsk = true` πριν ενεργοποιηθεί το NU6.3 στο Mainnet. Ένα key που εξάγεται από λογαριασμό ο οποίος υπήρχε πριν από το Ironwood είναι επομένως key `use_qsk = false` και παραμένει σωστό για αυτόν τον λογαριασμό. Μην υποθέτεις ότι ένα key που εξάγεται από έναν λογαριασμό περιγράφει άλλον.

## Εξαγωγή ενός viewing key

### Zallet

Το [Zallet](https://github.com/zcash/zallet) είναι το πορτοφόλι πλήρους κόμβου που αντικατέστησε το πορτοφόλι μέσα στο zcashd. Η εξαγωγή και εισαγωγή viewing key έφτασε στην **v0.1.0-beta.2 (28 Ιουλίου 2026)**, επομένως έλεγξε πρώτα την έκδοσή σου· οι παλαιότερες εκδόσεις δεν διαθέτουν αυτές τις μεθόδους. Κάθε όρισμα μετά το όνομα της μεθόδου πρέπει να είναι έγκυρο JSON, πράγμα που σημαίνει ότι οι τιμές συμβολοσειρών διατηρούν τα δικά τους διπλά εισαγωγικά. Ο [Οδηγός γρήγορης αναφοράς Zallet](/using-zcash/zallet-quick-reference-guide) καλύπτει το γενικό στυλ εντολών.

Κατάγραψε όσα κατέχει το πορτοφόλι:

```bash
zallet rpc listaddresses
```

Εξήγαγε το ενοποιημένο πλήρες viewing key του λογαριασμού περνώντας μια ενοποιημένη διεύθυνση:

```bash
zallet rpc z_exportviewingkey '"<unified address>"'
```

Εξήγαγε αντ' αυτού το ενοποιημένο εισερχόμενο viewing key του λογαριασμού, χρησιμοποιώντας το προαιρετικό όρισμα `ivk`:

```bash
zallet rpc z_exportviewingkey '"<unified address>"' true
```

Η παροχή μιας διεύθυνσης Sapling επιστρέφει το εκτεταμένο πλήρες viewing key Sapling αυτού του λογαριασμού (`zxviews…`), αντιστοιχώντας στην παλιά συμπεριφορά του zcashd. Δύο τεκμηριωμένοι περιορισμοί: οι διευθύνσεις Sprout απορρίπτονται και ένα εκτεταμένο πλήρες viewing key Sapling δεν μπορεί να εξαχθεί από λογαριασμό που εισήχθη ο ίδιος ως μόνο για προβολή, επειδή το πορτοφόλι δεν μπορεί να το ανασυνθέσει. Η μορφή `ivk` λειτουργεί για εισαγόμενους λογαριασμούς μόνο για προβολή.

### Πορτοφόλια που εξάγουν viewing keys από τη δική τους διεπαφή

Η σελίδα [Πορτοφόλια](/using-zcash/wallets) παρακολουθεί την υποστήριξη viewing key και την ετοιμότητα Ironwood για κάθε πορτοφόλι. Κατά τον χρόνο συγγραφής, πορτοφόλια που αναφέρουν τόσο υποστήριξη viewing key όσο και **Ironwood: Έτοιμο** περιλαμβάνουν τα ZODL, Zingo!, Zkool, Cake, Zallet, zecd και Nozy. Έλεγξε αυτήν τη σελίδα αντί για την παρούσα προτού βασιστείς σε οποιοδήποτε μεμονωμένο πορτοφόλι, επειδή η ετοιμότητα αλλάζει.

## Εισαγωγή ενός viewing key ως λογαριασμού μόνο για παρακολούθηση

### Zkool

Το [Zkool](https://github.com/hhanh00/zkool2) είναι η πιο ευέλικτη επιλογή εδώ, επειδή δέχεται ενοποιημένα keys καθώς και παλαιά. Το README του τεκμηριώνει λογαριασμούς μόνο για προβολή που δημιουργούνται από ένα **ενοποιημένο viewing key** ή ένα **εκτεταμένο viewing key Sapling**, μαζί με παλαιά θωρακισμένα εκτεταμένα keys που εξάγονται από το zcashd. Πρόσθεσε έναν νέο λογαριασμό, επίλεξε τη διαδρομή μόνο για προβολή και επικόλλησε το key `uview…` ή `zxviews…`· ο λογαριασμός συγχρονίζεται έπειτα και αναφέρει υπόλοιπα και ιστορικό χωρίς εξουσία δαπάνης.

Η υποστήριξη πρωτοκόλλου Ironwood και η μεταφορά από Orchard σε Ironwood έφτασαν στο Zkool 6.24.0 (20 Ιουλίου 2026), ενώ η 6.26.1 (2 Αυγούστου 2026) διόρθωσε την ανίχνευση συναλλαγών Ironwood στο mempool. Χρησιμοποίησε την 6.26.1 ή νεότερη.

### Zallet

```bash
zallet rpc z_importviewingkey '"<zxviews… key>"' '"whenkeyisnew"' 0
```

Το δεύτερο όρισμα είναι η πολιτική επανασάρωσης: `"whenkeyisnew"` (η προεπιλογή), `"yes"` ή `"no"`. Το τρίτο είναι το ύψος μπλοκ από το οποίο θα γίνει επανασάρωση. Το Zallet εισάγει το key ως λογαριασμό μόνο για προβολή και παρακολουθεί εισερχόμενες και εξερχόμενες συναλλαγές για τις διευθύνσεις του χωρίς εξουσία δαπάνης.

**Το Zallet εισάγει μόνο εκτεταμένα πλήρη viewing keys Sapling.** Δεν θα εισαγάγει ένα ενοποιημένο πλήρες viewing key `uview…`, παρότι μπορεί να εξαγάγει ένα. Για να παραδώσεις πρόσβαση ανάγνωσης σε ολόκληρο έναν ενοποιημένο λογαριασμό, εξήγαγε το UFVK από το Zallet και εισήγαγέ το σε πορτοφόλι που δέχεται ενοποιημένα keys, όπως το Zkool.

Για να μετατρέψεις ένα εισαγόμενο key σε πλήρες αρχείο ιστορικού συναλλαγών, με txids, τέλη και σημειώματα, δες το [Εξαγωγή ιστορικού συναλλαγών από ένα Viewing Key](/guides/viewing-key-transaction-export).

## Τι άλλαξε και τι πρέπει να σταματήσεις να αναζητάς

Αν ακολούθησες μια παλαιότερη έκδοση αυτής της σελίδας ή μετάφρασή της, τρεις διαδρομές δεν λειτουργούν πλέον.

- **`zcash-cli z_exportviewingkey` και `z_importviewingkey`.** Το zcashd έφτασε στη διακοπή υποστήριξής του στις 18 Ιουλίου 2026 και δεν λειτουργεί πλέον. Οι ομώνυμες μέθοδοι του Zallet είναι η αντικατάσταση· δες τον [οδηγό μεταφοράς](/guides/migration-guide-zcashd-to-zebrad-zallet).
- **Ο οδηγός Ywallet.** Η σελίδα Πορτοφόλια επισημαίνει το Ywallet ως **Ironwood: Μη έτοιμο**, επομένως δεν είναι το πορτοφόλι προς το οποίο πρέπει να κατευθύνεις ανθρώπους για viewing keys της εποχής Ironwood. Το Zkool, από τον ίδιο προγραμματιστή, δέχεται το ίδιο εύρος keys και επισημαίνεται ως Έτοιμο.
- **zcashblockexplorer.com/vk.** Η υπηρεσία επιστρέφει HTTP 503 με μη έγκυρο πιστοποιητικό και έχει αφαιρεθεί αντί να αντικατασταθεί. Η επικόλληση ενός viewing key σε έναν ιστότοπο παραδίδει ολόκληρο το ιστορικό συναλλαγών σου σε όποιον διαχειρίζεται αυτόν τον ιστότοπο, κάτι που ήταν ανέκαθεν η ασθενέστερη από τις τρεις επιλογές στην παλιά σελίδα. Εισήγαγε το key σε ένα πορτοφόλι που εκτελείς εσύ.

## Οπτικοποίηση / Αναλογία

### Το παράθυρο του ελεγκτή

Σκέψου έναν θωρακισμένο λογαριασμό ως έναν χώρο θυρίδων σε τράπεζα:

- Το **spending key** είναι το κλειδί του χώρου. Όποιος το κατέχει μπορεί να ανοίγει θυρίδες και να αφαιρεί το περιεχόμενό τους.
- Ένα **viewing key** είναι το παράθυρο του ελεγκτή προς αυτόν τον χώρο. Ο ελεγκτής μπορεί να παρακολουθεί κάθε θυρίδα που μπαίνει και βγαίνει, να διαβάζει τις ετικέτες και να διατηρεί ένα καθολικό — αλλά το παράθυρο δεν έχει λαβή. Τίποτα μέσα στον χώρο δεν μπορεί να μετακινηθεί από το άτομο που κοιτάζει μέσα από αυτό.

### Τι δεν μπορεί να δείξει το παράθυρο

Το παράθυρο βλέπει προς τον χώρο, όχι προς τον έξω κόσμο. Δείχνει τη θωρακισμένη δραστηριότητα του παρακολουθούμενου λογαριασμού· δεν μετατρέπει τον παρατηρητή σε παρατηρητή ολόκληρου του blockchain, ούτε του επιτρέπει να συσχετίσει τη δραστηριότητα του λογαριασμού με το μη θωρακισμένο ιστορικό οποιουδήποτε άλλου. Και επειδή το παράθυρο εγκαθίσταται σε επίπεδο λογαριασμού, αν δώσεις σε κάποιον μια οπή παρατήρησης για μία θυρίδα κατάθεσης (μία μόνο διεύθυνση), του δίνεις και πάλι την εισερχόμενη οπτική ολόκληρου του χώρου — ακριβώς γι' αυτό υπάρχει ο κανόνας του στενότερου key.

### Γιατί δεν μπορείς να πάρεις πίσω το παράθυρο

Ένα viewing key είναι πληροφορία, όχι καταχώριση άδειας. Μόλις αντιγραφεί, υπάρχει μέχρι τα κεφάλαια να φύγουν από τον λογαριασμό που παρακολουθεί. Η πρακτική λύση είναι η εναλλαγή: μετακίνησε τα υπόλοιπα σε έναν νέο λογαριασμό του οποίου τα keys δεν έλαβε ποτέ το άλλο μέρος και το παλιό παράθυρο θα βλέπει έναν άδειο χώρο.

## Αναλυτική εξέταση

### Δοκιμαστική αποκρυπτογράφηση: πώς λειτουργεί στην πραγματικότητα η προβολή

Κάθε θωρακισμένη συναλλαγή κρυπτογραφεί τα απλά κείμενα των notes για τον προοριζόμενο παραλήπτη. Ένα πορτοφόλι που κατέχει viewing key εκτελεί **δοκιμαστική αποκρυπτογράφηση**: για κάθε συναλλαγή που βρίσκει στην αλυσίδα, επιχειρεί να αποκρυπτογραφήσει ciphertexts note με το key. Οι επιτυχίες αποκαλύπτουν την αξία του note, το diversifier παραλήπτη και το σημείωμα· οι αποτυχίες δεν κοστίζουν τίποτα. Γι' αυτό το ίδιο εισερχόμενο viewing key συνεχίζει να λειτουργεί στα pools Orchard και Ironwood — το [ZIP 326](https://zips.z.cash/zip-0326) αφορά έναν δέκτη στο *πρωτόκολλο* Orchard, επομένως τα ciphertexts note Ironwood είναι διαμορφωμένα σαν Orchard και αποκρυπτογραφούνται δοκιμαστικά με τα viewing keys Orchard του λογαριασμού, κάτω από το πεδίο κρυπτογράφησης note Ironwood.

### Πλήρες έναντι εισερχόμενου: τι αποφασίζει η παραγωγή

Ένα **πλήρες** viewing key μπορεί να παράγει τη δυνατότητα προβολής εξερχόμενων, η οποία επιτρέπει σε έναν ελεγκτή να ανασυνθέσει την πλευρά του *αποστολέα* μιας μεταφοράς μόλις αποκρυπτογραφηθεί η συναλλαγή. Ένα **εισερχόμενο** viewing key σκόπιμα σταματά νωρίτερα: ανιχνεύει και αποκρυπτογραφεί εισερχόμενα notes, αλλά δεν μπορεί να ανασυνθέσει εξερχόμενες συνδέσεις. Η παραγωγή μεταξύ αυτών των δυνατοτήτων είναι μονόδρομη — το εισερχόμενο key παράγεται *από* το πλήρες key, ποτέ αντίστροφα — και αυτό είναι που καθιστά το «μόνο εισερχόμενο» πραγματικό περιορισμό αντί για υπόσχεση. Η σημαία `use_qsk` από το [ZIP 2005](https://zips.z.cash/zip-2005) αλλάζει την ίδια την παραγωγή, επομένως τα keys που είναι ανακτήσιμα μετά από κβαντική επίθεση αποτελούν εντελώς διαφορετική οικογένεια keys, όχι παραλλαγή της παλιάς.

### Πώς φαίνεται η μεταφορά σε έναν θεατή

Επειδή η μεταφορά [ZIP 318](https://zips.z.cash/zip-0318) είναι μια τυχαιοποιημένη σειρά μικρών, ομοιόμορφων συναλλαγών από Orchard προς Ironwood, ένας θεατής που κατέχει το key βλέπει μια σκάλα: πολλά βήματα αξίας κανονικής ονομαστικής αξίας αντί για ένα άλμα. Κανένα μεμονωμένο βήμα δεν αποκαλύπτει το συνολικό υπόλοιπο που μεταφέρεται, αλλά το *μοτίβο* είναι αναγνωρίσιμο — που είναι το επιδιωκόμενο αντάλλαγμα ενός ελέγξιμου turnstile.

## Πρακτικές επιπτώσεις

- **Για ανταλλακτήρια και επεξεργαστές πληρωμών:** φόρτωσε το εισερχόμενο viewing key του λογαριασμού (ή UFVK για πλήρη κάλυψη) σε έναν κόμβο ανίχνευσης και συμφώνησε αυτόματα τις καταθέσεις πελατών, ακριβώς όπως θα έκανες με μια διαφανή διεύθυνση — αλλά το spending key του πελάτη δεν φεύγει ποτέ από cold storage.
- **Για ελεγκτές και απόδειξη αποθεματικών:** ένα πλήρες viewing key μετατρέπει το «εμπιστέψου μας» σε «επαλήθευσε αυτό»: υπόλοιπα και πλήρες ιστορικό συναλλαγών για τους παρακολουθούμενους λογαριασμούς, με μηδενική δυνατότητα να τους αγγίξεις. Συνδύασέ το με τις [Γνωστοποιήσεις πληρωμών](/zcash-tech/payment-disclosures) για μεμονωμένες αποδείξεις σχετικά με μία μόνο πληρωμή.
- **Για δέουσα επιμέλεια:** δώσε σε έναν αντισυμβαλλόμενο το key του λογαριασμού που σχετίζεται με τη συνεργασία, όχι ολόκληρο το πορτοφόλι σου. Αν η σχέση τελειώσει, άλλαξε τον λογαριασμό.
- **Για επιλογές εργαλείων:** το Zallet εξάγει UFVKs και εισάγει εκτεταμένα πλήρη viewing keys Sapling· το Zkool δέχεται ενοποιημένα και παλαιά keys ως λογαριασμούς μόνο για παρακολούθηση. Έλεγξε τη σελίδα [Πορτοφόλια](/using-zcash/wallets) για τον τρέχοντα πίνακα ετοιμότητας Ironwood προτού τυποποιήσεις ένα πορτοφόλι.
- **Το κόστος της αποκάλυψης είναι μόνιμο:** κάθε πρόσθετος κάτοχος ενός key είναι μια μόνιμη πιστωτική γραμμή ιδιωτικότητας που δεν μπορείς να κλείσεις. Έκδιδε keys ανά σχέση, περιόρισέ τα σε έναν λογαριασμό και τεκμηρίωνε ποιος κατέχει τι.
