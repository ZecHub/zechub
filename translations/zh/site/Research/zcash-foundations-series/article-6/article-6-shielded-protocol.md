## 1. 你为什么要关心？

单独来看，你学到的每个部分都很巧妙。但 Zcash 的*魔力*在于它们如何彼此咬合。单独的 nullifier 并不能带来隐私 [privacy]。单独的 commitment 不能防止伪造。单独的证明不能证明任何有用的事。正是这种**组装**，将五个组件变成了既私密又可信赖的货币。

本文就是这套组装。读完后，"网络验证一笔它无法看见的交易"这句话将不再像一个悖论，而会成为你已理解的各部分带来的显然结果。

## 3. 密钥从何而来

用户能够进行的一切操作，都源自单一秘密，即**花费密钥 [spending key]**，并通过单向层级结构延伸（每个箭头都是不可逆的派生，这得益于第 2 和第 3 篇文章中的陷门）：

![alt text](/content-images/image-32-f443f9bb72.webp)

有两点值得注意，两者都是前文的结果：

- 这种拆分让你可以交出一个 **viewing key**（例如交给审计员），使其看到你的交易，**却不**授予其花费权力。隐私是可选择的，而非非此即彼。
- 每次派生都是**单向的**：持有 viewing key 永远无法让任何人恢复花费密钥，这正是第 2 篇文章中的椭圆曲线陷门在发挥作用。

## 4. 花费一个 note：四项声明

要私密地花费一个 note，你必须同时向网络证明四件事，**而不能透露该 note、其价值、其位置或你的身份。** 每项声明均由你已了解的一个组件满足。

![alt text](/content-images/image-31-86309af194.webp)

证明不会透露**任何**底层事实（哪个 note、谁的密钥、何种价值）。它只透露*四项声明都成立。* 这就是屏蔽 Zcash 的全部诀窍，并在一张图中得到说明。

---

## 5. 价值平衡技巧（我们留下的回报）

在第 2 和第 3 篇文章中，我们注意到 Pedersen commitment 可以**相加**：对 `v_1` 的 commitment 加上对 `v_2` 的 commitment，就是对 `v_1 + v_2` 的 commitment。这正是其价值所在。

每个输入和输出 note 都携带一个**价值 commitment**：一个隐藏其金额 `v` 的 Pedersen commitment `v.G + r.H`。由于这些 commitment 可以相加，网络能够计算：

```
(sum of input value commitments) − (sum of output value commitments)
```

如果交易保持平衡（没有凭空创造或销毁货币），`v` 部分会恰好相互抵消，只留下一个由剩余随机性盲化的**零价值** commitment。发送者通过生成一个称为**绑定签名 [binding signature]**的小型签名，证明其知道该剩余随机性。有效的绑定签名只有在价值真正平衡时才可能生成，**但没有透露任何一个金额。**

> 这是整个系列中最清晰地说明我们*为何*需要同态、基于曲线的 commitment 的例子。通过**将密封信封相加**并检查结果是否密封为零，"流入资金等于流出资金"规则得以执行。

## 6. 完整交易：端到端观察

让我们组装 Alice 向 Bob 支付的过程。我们将使用 Sapling 清晰的"花费侧 / 输出侧"结构作为教学模型。

**一笔屏蔽交易包含两类描述：**

| 花费描述（消耗一个 note） | 输出描述（创建一个 note） |
|---|---|
| 输入的价值 commitment | 输出的价值 commitment |
| 它所证明的 **anchor**（一个树根） | 新的 **note commitment**（一个新叶节点） |
| 已花费 note 的 **nullifier** | 用于加密的**临时密钥** |
| 重新随机化的公钥 + 花费授权签名 | **加密 note**（供接收者使用的密文） |
| 证明四项声明的 **zk-SNARK** | 证明输出格式正确的 **zk-SNARK** |

此外，还有一个覆盖整个组合的**绑定签名**，用于执行价值平衡（第 5 节）。

![alt text](/content-images/image-30-98511eb2d0.webp)

追踪隐私性：网络检查了 anchor，检查 nullifier 是否为新值，验证了证明，并验证了余额。它接受了一笔有效支付，**却没有得知金额、地址，也不知道花费了哪个 note。** 同时，已花费 note 的 **nullifier**（它的死亡）和 Bob 的新 **commitment**（他 note 的诞生）位于两个不同的公共结构中，二者之间没有可见连接，这正是第 0 篇文章中被切断的关联。

## 7. 闭合第 0 篇文章中的每个循环

第 0 篇文章刻意提出了问题。现在，所有问题都已得到解答。

| 第 0 篇文章中提出的循环 | 由此闭合 |
|---|---|
| 如何实现既密封又不可伪造的信封？ | Commitment：来自随机性的隐藏性，来自碰撞抗性 / 曲线陷门的绑定性（第 3 篇） |
| 密钥和秘密配方从何而来？ | 域算术和椭圆曲线标量乘法（第 1、2 篇） |
| "公告板"究竟是什么？ | 一棵 note commitment 的增量式 Merkle 树；其根即为 anchor（第 4 篇） |
| 为什么虚空代币不能与其信封关联？ | nullifier 是带密钥哈希，保存在与 commitment 分离的集合中（第 2、3、4 篇） |
| 如何在不透露任何信息的情况下证明有效性？ | 对编码所有四项声明的算术电路进行的 zk-SNARK（第 5 篇） |
| 接收者如何得知自己收到了支付？ | note 被加密至其地址；他们使用 viewing key 进行试探解密（本文） |
| 如何私密地执行"流入资金 = 流出资金"？ | 同态价值 commitment + 绑定签名（第 5 节） |

第一页中的悖论，即*验证你看不见的东西*，如今已完全消解。网络验证的是**关于隐藏数据的声明**，而非数据本身。

## 8. Sapling 与 Orchard：一句话说明

我们使用 Sapling 的结构进行教学，因为它的拆分最清晰。当前设计 **Orchard** 对这些理念进行了完善，而非取代：

| | **Sapling** | **Orchard** |
|---|---|---|
| 交易单元 | 独立的 **Spend** 和 **Output** 描述 | 统一的 **Actions**（每个执行一次花费 + 一次输出） |
| 证明系统 | **Groth16**（可信设置 [trusted setup]） | **Halo 2**（无可信设置） |
| 曲线 | BLS12-381 + Jubjub | Pallas / Vesta（Pasta） |
| Commitment 哈希 | Pedersen | Sinsemilla |

本文中的每个概念都可直接沿用；Orchard 主要是将花费和输出捆绑在一起，并换用无需仪式的证明系统。五大支柱未变。

## 10. 总结

- 一笔屏蔽交易将全部五个组件彼此咬合：一个**note**（价值）、其位于**note commitment 树**中的 **commitment**、用于防止双重花费的 **nullifier**、用于平衡的**价值 commitment**，以及将它们全部绑定在一起的 **zk-SNARK**。
- 花费会**同时证明四项声明**：note 存在、你已获授权、其 nullifier 正确、价值平衡；这一过程处于**零知识**中，不透露任何底层事实。
- **价值平衡**通过**相加同态 commitment**并借助**绑定签名**检查其是否密封为零来执行，不会披露金额。
- 用户的权力从一个**花费密钥**经由**单向层级结构**流动，使得 **viewing key** 可以在不授予花费权力的情况下进行披露。
- 网络**验证关于隐藏数据的声明**，从而消解第 0 篇文章中的验证与隐私悖论。那里提出的每个循环如今都已闭合。
- **Orchard** 对 **Sapling** 进行了完善（统一 Actions、无可信设置的 Halo 2、Pasta 曲线、Sinsemilla），但没有改变五大支柱。

## 常见问题

**网络是否会看到金额或谁向谁付款？**  
不会。它验证证明、nullifier 的新鲜性、anchor 和绑定签名。所有私密价值始终保持隐藏。

**什么阻止我两次花费同一个 note？**  
nullifier。花费时会公布它；网络拒绝 nullifier 集合中已有的任何 nullifier。同一个 note 始终产生相同的 nullifier。

**金额隐藏时，如何检查余额？**  
价值 commitment 可以同态相加；一笔平衡交易的 commitment 会抵消为一个零 commitment，绑定签名会对此进行证明。

**我能否向审计员证明我的交易，同时不放弃控制权？**  
可以。交出一个 viewing key。它会透露你的屏蔽活动，但由于单向密钥层级结构，无法授权花费。

**既然 Orchard 已存在，Sapling 是否已过时？**  
两者都曾存在于网络上；Orchard 是当前设计。其概念是共享的，因此理解其中一个就能理解另一个。

### 测试你的直觉

一位朋友说："既然证明隐藏了金额，窃贼就可以声称其输出比输入更有价值，并凭空印出免费货币。"请使用第 5 节，用两句话解释为什么这无法实现。*（答案如下。）*

<details><summary>答案</summary>

金额是隐藏的，但每个金额都被包装在一个同态价值 commitment 中，网络会将所有输入 commitment 相加并减去所有输出 commitment；如果隐藏价值不平衡，结果就不会密封为零，且**无法生成有效的绑定签名。** 窃贼可以隐藏*多少*，却无法让不平衡的价值通过余额检查，因此不可能在什么都不透露的同时仍被算术捕获的情况下印出免费货币。
</details>
