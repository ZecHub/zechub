# ZecHub 黑客松构建者指南

## TL;DR

- 在写代码之前先明确你为什么要构建它，有用性胜过复杂性
- 保持简单，把一个小想法做好，胜过留下一个未完成的大想法
- 尽早学习 Zcash 基础设施栈，这是最陡峭的学习阶段
- 如果你的应用会转移资金，它就必须能在 mainnet 上运行；先在 testnet 上构建，再在 mainnet 上证明它可行
- 文档和清晰的演示可能比产品本身更重要
- 获胜只是起跑线，它会建立你的声誉，并为你打开社区中的大门

<br/>

## 这篇指南适合谁

- 首次参加 ZecHub 或 Zcash 黑客松的构建者
- 来自其他生态、刚接触 Zcash 的开发者
- 任何想把黑客松项目做成长期成果的人

<br/>

## 从“为什么”开始

在你打开编辑器之前，先弄清楚你要解决什么问题，以及为什么会有人在意。一个很好的检验标准很简单：如果你正在构建的这个东西并不存在，会有人怀念它吗？去构建一个你自己也会使用的东西。隐私是 Zcash 存在的原因，所以要理解隐私为什么对你所服务的人重要，然后让这一点塑造整个项目。

<br/>

## 先学习技术栈

对来自其他链的构建者来说，最常见的意外不是编码本身，而是 Zcash 基础设施的学习曲线。先给自己一些时间，理解各个部分是如何组合在一起的，然后再去设计你的应用。从核心栈开始，通常被称为“三个 Z”：zebrad、一个轻量服务器，以及一个钱包。然后再熟悉开发者工具：

1. 阅读 wiki 上的开发者页面 [zechub.wiki/developers](https://zechub.wiki/developers)，这是推荐的第一站
2. 研究 zingolib 和 zingo-cli，它们的调用覆盖了大多数赛道中项目所需的功能
3. 查看 librustzcash 和参考钱包 ZODL，了解更底层的构建模块
4. 如果是 FROST 项目，可使用 Zcash Foundation 的 frostd 和 crates.io 上的 frost-core，并借助 AI 帮助理解相关定义，不过要安全地使用 FROST 仍然需要真正投入精力和时间

<br/>

## 理解 mainnet 的含义

有些赛道要求你的应用与 Zcash mainnet 交互。实际来说，这意味着你的项目，或者使用它的人——包括 AI 代理——会在 mainnet 上发送或接收真实资金，或者你的项目是在构建和改进使这一切成为可能的工具。如果你的应用会发起交易，你必须在提交作品时演示它们在 mainnet 上运行。

在开发过程中请在 testnet 上构建。mainnet 活动会消耗真实的 ZEC，而且随着时间推移只会越来越昂贵，因此 testnet 是推荐的迭代场所。最后再切换到 mainnet 做最终证明。设计流程时请记住一个细节：当资金到达一个屏蔽地址后，你的钱包必须先扫描并发现这些资金，然后它们才能被花费，而这个扫描会花一点时间。把这段短暂等待纳入你的应用流程中，而不要假设收到的资金立刻就能使用。

<br/>

## 保持简单

一个简单但执行良好的想法，很多次都战胜了复杂的想法。评审们曾在同一场活动中看到，一个基础概念打败了一个技术上更有野心的项目，因为它解决了真实问题，而且易于理解。承担比你认为自己能完成的更少一些。忽视细节、范围定得过大，以及跳过调研，都是让构建者错失奖项的错误。让你的项目从核心概念到第一条命令，都易于理解、易于运行。

<br/>

## 赢下前 30 秒

评审会很快形成强烈印象，因此展示方式、主题和视觉效果都非常重要，同时也要看你的解决方案有多新颖。文档和清晰演示并不是事后补充。有时候，传达你的想法比想法本身更重要，因为如果没有人理解你构建了什么，它就不可能成功。评审通常会在技术深度、用户体验、原创性和实际效用之间取得平衡，而强有力的文档会提升这四个方面的表现。

<br/>

## 关注更难但更冷门的赛道

如果你想面对没那么拥挤的竞争，更难的赛道通常参赛作品更少，原因只是尝试的人更少。Accounting 赛道对于想避开链上交易工作的初学者来说是个不错的选择。FROST 功能强大但使用不足，而且它能为项目打下坚实基础。社区不会规定你必须构建什么，因此与其从零开始，不如基于生态系统中已经存在、能力成熟的工具来构建，这是个明智的选择。

<br/>

## 黑客松之后

获胜并不是终点。获胜会充实你的作品集并建立声誉，为你打开社区中的机会之门，还可能通过提案带来资助。

1. 把一个强有力的项目进一步发展成提交给 ZecHub DAO 或 Zcash Community Grants 的提案，包含路线图、里程碑和预算依据
2. 在论坛、Discord 和 X 上持续活跃于社区
3. 参加 Arborist R and D 会议，发布想法，并征求反馈
4. 即使没有获胜也继续构建，并关注下一场黑客松
