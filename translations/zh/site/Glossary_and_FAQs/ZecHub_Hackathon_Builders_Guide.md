# ZecHub 黑客松构建者指南

## TL;DR

- 在编写代码前明确自己为何构建，有用性胜过复杂性
- 保持简单，做好一个小想法胜过留下一个未完成的大想法
- 尽早学习 Zcash 基础设施栈，这是最陡峭的一段攀登
- 如果你的应用会转移资金，它必须在主网 [mainnet] 上运行；先在测试网构建，再在主网上证明它
- 文档和清晰的演示可能比产品本身更重要
- 获胜只是起跑线，它会建立你的声誉，并在社区中打开机会之门

<br/>

## 适合谁

- 首次参加 ZecHub 或 Zcash 黑客松的构建者
- 来自其他生态系统、刚接触 Zcash 的开发者 [developers]
- 希望将黑客松项目变成长久成果的任何人

<br/>

## 从原因开始

在打开编辑器之前，先了解你要解决什么问题，以及为什么有人会在意。一个简单的检验方法是：如果你正在构建的东西不存在，会有人想念它吗？构建你自己会使用的东西。隐私 [Privacy] 是 Zcash 存在的原因，因此请理解隐私为何对你为之构建的人很重要，然后让这一点塑造整个项目。

<br/>

## 先学习技术栈

来自其他链 [chains] 的构建者最常见的意外不是编码，而是 Zcash 基础设施的学习曲线。在设计应用之前，留出时间理解各部分如何配合。先从核心技术栈开始，通常称为 Z to the third：zebrad、一个轻服务器和一个钱包 [wallet]。然后熟悉开发者工具 [developer tools]：

1. 阅读维基中位于 [zechub.wiki/developers](https://zechub.wiki/developers) 的开发者页面，这是推荐的第一站
2. 探索 zingolib 和 zingo-cli，其调用涵盖了项目在各赛道中的大部分需求
3. 查看 librustzcash 和 ZODL 参考钱包，以获取更底层的构建模块
4. 对于 FROST 项目，使用 Zcash Foundation 的 frostd 以及 crates.io 中的 frost-core，并借助 AI 理解定义；不过，安全地使用 FROST 仍需要真正投入精力和时间

<br/>

## 理解主网的含义

多个赛道要求你的应用与 Zcash 主网交互。实际上，这意味着你的项目或使用它的人（包括 AI 智能体）会在主网上发送或接收真实资金，或者构建和改进使这成为可能的工具。如果你的应用创建交易 [transactions]，你必须在提交作品中展示它们在主网上运行。

开发期间请在测试网上构建。主网活动需要花费真实的 ZEC，并且随着时间推移只会变得更昂贵，因此测试网是推荐的迭代场所。最后证明时再切换到主网。设计流程时请记住一个细节：当资金到达屏蔽 [shielded] 地址 [address] 时，你的钱包必须扫描并找到它们，才能花费这些资金，而扫描需要一点时间。请将这段短暂等待纳入应用，而不要假设收到的资金可以立刻使用。

<br/>

## 保持简单

一个简单且执行良好的想法多次战胜过复杂的想法。评委曾见证一个基础概念在同一活动中胜过技术上更有雄心的项目，因为它解决了真实问题且易于理解。承担比你认为自己能完成的更少的工作。忽视细节、范围定得过大和跳过调研，是让构建者错失奖项的错误。从核心概念到第一条命令，让你的项目易于理解且易于运行。

<br/>

## 赢得前 30 秒

评审者会迅速形成强烈印象，因此除了你的解决方案有多新颖之外，展示、主题和视觉效果也具有真正分量。文档和清晰的演示并非事后补充。传达你的想法有时比想法本身更重要，因为如果没有人理解你构建了什么，它就无法成功。评审通常会平衡技术深度、用户体验、原创性和实际效用，而优秀文档会提升所有这些方面。

<br/>

## 关注更难且更小众的赛道

如果你希望竞争不那么拥挤，较难的赛道往往参赛作品更少，仅仅因为尝试它们的人更少。会计赛道是希望避免链上 [on-chain] 交易工作的初学者的好选择。FROST 功能强大但未被充分利用，并且能为项目提供坚实基础。社区不会规定要构建什么，因此，在生态系统已有的强大工具上构建，而非从零开始，是明智之举。

<br/>

## 黑客松之后

获胜并非道路的终点。获胜会建立你的作品集和声誉，在社区中打开机会之门，并可能通过提案获得资金。

1. 将一个强大的项目进一步发展为向 ZecHub DAO 或 Zcash Community Grants 提交的提案，包含路线图、里程碑和预算依据
2. 在论坛、Discord 和 X 上保持活跃
3. 参加 Arborist R and D 会议，发布想法，并寻求反馈
4. 即使没有获胜也继续构建，并关注下一场黑客松
