# 交易

ZEC 是一种广泛用于支付的数字资产，具备强大的隐私功能，适用于向朋友付款、购物或捐赠等各种交易。为了最大限度地保护隐私和安全，了解 Zcash 中不同类型交易的运作方式至关重要。

## 简要说明

- Zcash 支持两种交易：**屏蔽交易**，可保持交易细节私密；以及**透明交易**，会公开记录交易细节。
- 屏蔽地址以 `u` 或 `z` 开头。透明地址以 `t` 开头，其行为与 Bitcoin 地址十分相似。
- 每笔付款都由你自行选择。隐私是 Zcash 提供给你的选项，而不是由他人为你决定的设置。
- 从交易所提现是人们最常失去隐私的环节。如果交易所仅支持透明提现，请在资金到账后自行将其屏蔽。
- 手续费遵循 [ZIP 317](https://zips.z.cash/zip-0317)，并会随交易规模增长。仍使用旧版固定手续费的钱包可能导致交易延迟。
- 根据 [ZIP 203](https://zips.z.cash/zip-0203)，大多数 Zcash 交易都有到期区块高度。如果交易在被挖入区块前到期，则无法在该到期高度之后确认，可能需要重新发送。

当你将 ZEC 转入屏蔽钱包时，就会发生屏蔽交易。你的屏蔽钱包地址以 `u` 或 `z` 开头。发送屏蔽交易时，你和交易对象可以获得默认公开的支付网络无法提供的隐私保护程度。

使用支持当前 Zcash 网络及当前屏蔽资金池的钱包，最容易发送屏蔽交易。在依赖某个钱包保护隐私前，请确认其是否支持屏蔽发送、屏蔽接收以及你计划使用的资金池。从交易所提现 ZEC 时，请确认交易所支持屏蔽提现还是透明提现。若仅支持透明提现，请在资金到账后将其转入支持屏蔽功能的钱包。

使用屏蔽交易收发资金，是保护隐私并降低支付数据泄露风险的最佳方式。

## 透明交易

透明交易的运作方式与 Bitcoin 交易类似。交易细节会在 blockchain 上公开可见，包括透明地址和透明金额。当隐私是首要考虑因素时，应避免使用透明交易。

透明地址在某些情况下仍然有用，尤其是交易所或服务不支持屏蔽地址时。如果你在透明地址收到 ZEC，请考虑在后续付款前将其屏蔽。

## 一个简单的比喻

透明交易就像一张明信片。邮递员会投递它，但任何在途中经手的人都能阅读内容、看到发送者和接收者。

屏蔽交易则像一个密封信封。邮政系统仍可确认一封附有真实邮资的真实信件通过了系统，且没人能够伪造它或将同一封信寄出两次。信封内的内容只属于发送者和接收者。

重要的是，Zcash 让你可以逐笔付款决定要发送哪一种交易。

## Zcash 手续费

Zcash 不使用 Ethereum 风格的 gas 单位。Zcash 交易手续费以 ZEC 支付，通常以 **zatoshis** 为单位计量。一个 ZEC 等于 100,000,000 zatoshis。

[ZIP 317](https://zips.z.cash/zip-0317) 定义了一种会随交易复杂度变化的标准手续费机制。不同于每笔交易均使用旧版 1,000-zatoshi 固定手续费，标准手续费基于输入、输出和屏蔽操作等“逻辑操作”计算。简单交易通常从约 10,000 zatoshis，即 0.0001 ZEC 开始；更复杂的交易可能需要更高的手续费。

在大多数当前钱包中，用户无需手动计算 ZIP 317 手续费。钱包应自动选择适当的手续费。如果钱包仍使用旧版固定手续费，或者允许你设置远低于 ZIP 317 标准手续费的费用，交易可能会延迟、被降低优先级、被某些节点丢弃，或无法可靠地传播。

## 排查卡住的交易

Zcash 交易显示在你的钱包中，并不代表其已经最终确定。对于一般使用而言，交易在被挖入区块并获得足够确认后才会最终确定。交易所和服务可能要求的确认数高于钱包默认显示的数量。

重新发送前，请使用以下决策树：

1. **你的钱包是否显示交易 ID？**
   - 如果没有，钱包可能尚未创建或广播该交易。请检查同步状态、互联网连接、钱包版本及任何钱包错误信息。
   - 如果有，请复制交易 ID 并继续。
2. **交易是否已在区块中确认？**
   - 如果是，请等待你的钱包、交易所、商家或服务所要求的确认数量。
   - 如果否，请继续。
3. **交易是否已达到到期区块高度？**
   - 如果没有，请暂时不要手动重新发送同一笔付款。原交易仍可能确认。
   - 如果已经达到，该交易无法在该到期高度之后被挖入区块。你的钱包可能会将其标记为已到期或失败，你可能需要创建一笔新交易。
4. **交易是否出现在一个服务器或区块浏览器中，却未出现在另一个中？**
   - 应将其视为网络可见性问题，而非交易失败的证据。不同节点可能具有不同的内存池视图。
   - 请等待、重新同步钱包，或在钱包支持的情况下切换至另一台可信服务器。
5. **交易在显示已确认后是否消失？**
   - 短暂的链重组可能会暂时将交易从最佳链中移除。
   - 请等待更多区块。如果交易重新出现，请继续等待确认；如果未重新出现且之后到期，请创建一笔新交易。
6. **钱包是否要求你重新发送？**
   - 仅在确认前一笔交易已到期、失败或不再有效后，才遵循钱包当前的指引。
   - 如果不确定，请在再次发送前联系支持团队。

## 待处理、已到期、已丢弃和已重组

- **待处理**表示交易已创建或广播，但尚未被挖入区块。
- **已到期**表示交易的到期区块高度已过。根据 ZIP 203，具有到期区块高度的交易无法在该高度之后被挖入区块。
- **已丢弃**表示一个或多个节点不再在其内存池中保留该交易。这可能是由于到期、手续费过低、内存池策略、重启行为或传播差异所致。
- **已重组**表示此前包含该交易的区块不再属于最佳链。该交易之后可能再次被挖入区块；若其仍有效，也可能重新回到待处理状态。

## 不应重新发送的情况

不要仅因交易处于待处理状态、速度缓慢，或未出现在某个区块浏览器中，就立即重新发送。过早重新发送可能造成混乱；取决于钱包如何构建新付款，也可能导致重复付款的风险。

遇到以下情况时，请先等待或寻求支持：

- 交易具有交易 ID 且尚未到期。
- 一个服务器显示该交易，另一个却未显示。
- 交易近期被挖入区块，但在可能发生重组后失去了确认。
- 接收服务尚未完成确认计数。
- 你的钱包仍在同步。

通常，只有在钱包明确将交易标记为已到期或失败后，或支持团队确认原交易无法确认后，重新发送才更安全。

## 保护隐私的检查方式

你可以在不暴露超出必要范围的信息的情况下检查基本交易状态：

- 检查你的钱包是否已完全同步。
- 检查钱包应用是否为最新版本。
- 检查交易是否具有交易 ID。
- 检查交易是已确认、待处理、已到期还是失败。
- 如果钱包显示该信息，请检查当前区块高度并将其与交易到期区块高度比较。
- 对于透明交易，区块浏览器可以显示公开的交易、地址、金额和确认数。
- 对于屏蔽交易，区块浏览器可以显示交易存在，但无法显示屏蔽的发送者、接收者、金额或备注细节。

## 不应公开分享的信息

绝不要在公开聊天、社交媒体或问题追踪器中发布以下内容：

- 助记词或恢复短语
- 支出密钥、私钥或钱包备份
- 完整查看密钥
- 显示余额、完整地址、备注、QR 码或交易所账户详情的截图
- 个人身份证明文件或账户恢复记录

交易 ID 在链上是公开的，但它仍可能将你的支持请求与身份关联。若隐私很重要，请仅通过可信的支持渠道分享它。

## 支持团队需要的信息

向钱包、交易所或服务支持团队寻求帮助时，仅分享最低限度的有用信息：

- 钱包或服务名称
- 应用版本和操作系统
- 交易是屏蔽交易、透明交易，还是在屏蔽地址和透明地址之间进行
- 交易 ID，前提是你愿意分享它
- 大致发送时间
- 钱包是否已完全同步
- 钱包显示的当前状态
- 已移除私密数据的准确错误信息
- 隐藏余额、地址、备注和账户详情的截图

支持团队不需要你的助记词、支出密钥、私钥或完整查看密钥。

## 常见错误

- **认为所有列出 ZEC 的钱包都能私密发送它。** 一些多币种钱包仅支持 Zcash 的透明部分。在依赖钱包保护隐私前，请检查其支持的资金池。[钱包](https://zechub.wiki/using-zcash/wallets)页面列出了每种选择的相关信息。
- **提现至透明地址后将资金留在那里。** 提现本身是公开的，之后从该地址进行的每次资金移动也都会保持公开。资金到账后请将其屏蔽。
- **将隐私视为只需开启一次的功能。** 每笔交易都是独立的选择。今天发送屏蔽交易，并不会撤销你上周进行的透明付款。
- **将同一透明地址用于所有用途。** 由于透明活动永久可见，一个反复使用的地址会逐渐关联起本无理由相互关联的付款。
- **使用过时的默认手续费发送交易。** 尚未采用 ZIP 317 的钱包可能仍会发送旧版固定手续费，从而导致交易一直无法确认。
- **在到期前重新发送。** 待处理交易在到期前仍可能确认。创建另一笔付款前，请检查到期状态。

## 注意

请注意，最安全的 ZEC 使用方式是在发送者、接收者、钱包和服务均支持的情况下，始终使用屏蔽交易。部分钱包和交易所支持[统一地址](https://electriccoin.co/blog/unified-addresses-in-zcash-explained/#:~:text=The%20unified%20address%20(UA)%20is,within%20the%20broader%20Zcash%20ecosystem.)，可将多种 Zcash 接收方类型合并至一个地址中。
