# 交易 [Transactions]

ZEC 是一种广泛使用的支付数字资产，提供强大的隐私 [privacy] 功能，使其适用于向朋友付款、购物或捐赠等各种交易。为了最大程度地保障隐私和安全，了解不同类型的交易如何在 Zcash 中运作至关重要。

## TL;DR

- Zcash 支持两种交易：**屏蔽 [shielded]**，可将详细信息保持私密；以及 **透明 [transparent]**，会公开记录详细信息。
- 屏蔽地址 [address] 以 `u` 或 `z` 开头。透明地址以 `t` 开头，其行为与 Bitcoin 地址十分相似。
- 每一笔支付 [payment] 都由你选择。隐私是 Zcash 赋予你的选项，而非由他人为你决定的设置。
- 从交易所 [exchange] 提款是人们最常失去隐私的环节。如果交易所仅支持透明提款，资金到账后请自行将其转入屏蔽状态。
- 手续费 [fee] 遵循 [ZIP 317](https://zips.z.cash/zip-0317)，并随交易规模增长。仍发送旧固定手续费的钱包 [wallet] 可能会导致其交易延迟。
- 大多数 Zcash 交易在 [ZIP 203](https://zips.z.cash/zip-0203) 下都设有到期高度。如果交易在挖矿 [mining] 前过期，则无法在该到期高度后确认，可能需要重新发送。

当你将 ZEC 转入屏蔽钱包时，就会发生屏蔽交易。你的屏蔽钱包地址以 `u` 或 `z` 开头。发送屏蔽交易时，你和与你交易的人可以获得默认公开的支付网络无法提供的隐私水平。

使用支持当前 Zcash 网络和当前屏蔽池 [pools] 的钱包，发送屏蔽交易最为简单。在依赖钱包保障隐私前，请确认它支持屏蔽发送、屏蔽接收以及你计划使用的 pool。从交易所提取 ZEC 时，请确认交易所是否支持屏蔽或透明提款。若其仅支持透明提款，请在资金到账后将其转入支持屏蔽功能的钱包。

使用屏蔽交易收发资金，是保护隐私并降低支付数据泄露风险的最佳方式。

## 透明交易

透明交易的运作方式与 Bitcoin 交易类似。交易详细信息会在 blockchain 上公开可见，包括透明地址和透明金额。隐私优先时，应避免使用透明交易。

透明地址在某些情况下仍然有用，尤其是当交易所或服务不支持屏蔽地址时。如果你在透明地址收到 ZEC，请考虑在后续支付前将其转为屏蔽状态。

## 一种简单的理解方式

透明交易就像一张明信片。邮递员会投递它，但沿途经手的任何人都可以阅读信息、看到寄件人以及收件人。

屏蔽交易则像一个密封信封。邮政服务仍可确认一封附有真实邮资的真实信件已通过系统，而且无人能伪造它或重复发送同一封信。信封里的内容仅由发送者和接收者知晓。

重要的是，Zcash 让你可以逐笔支付决定发送哪一种。

## Zcash 手续费

Zcash 不使用 Ethereum 风格的 gas 单位。Zcash 交易手续费以 ZEC 支付，通常以 **zatoshis** 为单位。1 个 ZEC 等于 100,000,000 zatoshis。

[ZIP 317](https://zips.z.cash/zip-0317) 定义了一种会随交易复杂度变化的常规手续费机制。不同于每笔交易都使用旧有的 1,000-zatoshi 固定手续费，常规手续费基于输入、输出和屏蔽操作等“逻辑操作”。简单交易通常从约 10,000 zatoshis，即 0.0001 ZEC 起，更复杂的交易可能需要更多。

在大多数当前钱包中，用户无需手动计算 ZIP 317 手续费。钱包应自动选择合适的手续费。如果钱包仍使用旧固定手续费，或允许你设定远低于 ZIP 317 常规手续费的费用，交易可能被延迟、降低优先级、被某些节点 [node] 丢弃，或无法可靠地中继。

## 排查卡住的交易

Zcash 交易仅仅显示在你的钱包中并不代表它已最终确定。对于一般使用场景，它在被挖入区块 [block] 并获得足够的确认后才算最终确定。交易所和服务所要求的确认数量可能高于钱包默认显示的数量。

重新发送前，请使用以下决策树：

1. **你的钱包是否显示交易 ID？**
   - 如果没有，钱包可能尚未创建或广播交易。请检查同步状态、互联网连接、钱包版本以及任何钱包错误信息。
   - 如果有，请复制交易 ID 并继续。
2. **交易是否已在区块中确认？**
   - 如果是，请等待你的钱包、交易所、商家或服务所要求的确认数量。
   - 如果否，请继续。
3. **交易是否已达到其到期高度？**
   - 如果没有，请暂时不要手动重新发送同一笔支付。原交易仍可能确认。
   - 如果已达到，交易无法在该到期高度后被挖入。你的钱包可能会将其标记为已过期或失败，而你可能需要创建一笔新交易。
4. **交易是否在一个服务器或浏览器中显示，但在另一个中不显示？**
   - 请将此视为网络可见性问题，而非交易失败的证明 [proof]。不同节点可能具有不同的内存池视图。
   - 请等待、重新同步钱包，或者在钱包支持时切换到另一台可信服务器。
5. **交易在显示已确认后是否消失？**
   - 短暂的链 [chain] 重组可能会暂时从最佳链中移除一笔交易。
   - 请等待更多区块。如果交易重新出现，请继续等待确认；如果它未重新出现且之后过期，请创建一笔新交易。
6. **钱包是否要求你重新发送？**
   - 只有在确认之前的交易已过期、失败或不再有效后，才遵循钱包当前的指引。
   - 如果你不确定，请在再次发送前咨询支持团队。

## 待处理、已过期、已丢弃和已重组

- **待处理** 表示交易已创建或广播，但尚未被挖入区块。
- **已过期** 表示交易的到期高度已过。根据 ZIP 203，设有到期高度的交易无法在该高度后被挖入。
- **已丢弃** 表示一个或多个节点不再将交易保留在其内存池中。这可能因过期、低手续费、内存池策略、重启行为或中继差异而发生。
- **已重组** 表示此前包含该交易的区块不再是最佳链的一部分。该交易之后可能再次被挖入，或者若它仍然有效，则可能重新变为待处理状态。

## 不应重新发送的情况

不要仅因交易待处理、缓慢，或在某个浏览器中缺失就立即重新发送。过早重新发送可能造成混乱，而且取决于钱包构建新支付的方式，可能存在重复支付的风险。

在以下情况下，请先等待或寻求支持：

- 交易具有交易 ID 且尚未过期。
- 一台服务器显示该交易，而另一台没有。
- 它最近被挖入，但在可能发生重组后失去了确认。
- 接收服务尚未完成确认计数。
- 你的钱包仍在同步。

通常，只有在钱包明确将交易标记为已过期或失败，或支持团队确认原交易无法确认后，重新发送才更安全。

## 注重隐私的检查

你可以在不暴露超出必要范围的信息的情况下检查基本交易状态：

- 检查你的钱包是否已完全同步。
- 检查钱包应用是否为最新版本。
- 检查交易是否具有交易 ID。
- 检查交易是已确认、待处理、已过期还是失败。
- 如果钱包显示，请检查当前区块高度并与交易到期高度比较。
- 对于透明交易，区块链浏览器可以显示公开交易、地址、金额和确认数。
- 对于屏蔽交易，区块链浏览器可以显示交易存在，但无法显示屏蔽的发送者、接收者、金额或备忘录 [memo] 详细信息。

## 不应公开分享的内容

切勿在公开聊天、社交媒体或问题跟踪器中发布以下内容：

- 助记词 [seed phrase] 或恢复短语
- 花费密钥 [spending key]、私钥或钱包备份
- Full Viewing Key
- 显示余额、完整地址、备忘录、QR 码或交易所账户详细信息的截图
- 个人身份证明文件或账户恢复记录

交易 ID 在链上是公开的，但它仍可能将你的支持请求与你的身份关联。如果隐私很重要，请仅通过可信支持渠道分享它。

## 支持团队需要的信息

向钱包、交易所或服务支持团队寻求帮助时，仅分享最低限度的有用信息：

- 钱包或服务名称
- 应用版本和操作系统
- 交易是屏蔽、透明，还是在屏蔽与透明地址之间进行
- 如果你愿意分享，提供交易 ID
- 大致发送时间
- 钱包是否已完全同步
- 钱包显示的当前状态
- 删除私密数据后的准确错误信息
- 隐藏余额、地址、备忘录和账户详细信息的截图

支持团队不需要你的助记词、花费密钥、私钥或完整 viewing key。

## 常见错误

- **认为任何列出 ZEC 的钱包都能私密地发送它。** 一些多币种钱包仅支持 Zcash 的透明端。依赖钱包保护隐私前，请检查其支持的 pool。[钱包](https://zechub.wiki/using-zcash/wallets) 页面列出了每个选项的相关信息。
- **提取到透明地址并将资金留在那里。** 提款本身是公开的，之后从该地址进行的每次转移也都会保持公开。资金到账后请将其转为屏蔽状态。
- **将隐私视为只需开启一次的功能。** 每笔交易都是独立选择。今天发送屏蔽交易并不能撤销你上周进行的透明支付。
- **将透明地址用于一切。** 由于透明活动永久可见，一个重复使用的地址会逐渐关联原本没有理由关联的支付。
- **使用过时的默认手续费发送。** 尚未采用 ZIP 317 的钱包可能仍发送旧固定手续费，从而导致交易一直处于未确认状态。
- **在过期前重新发送。** 待处理交易在过期前仍可能确认。创建另一笔支付前，请检查过期状态。

## 注意

请注意，在发送者、接收者、钱包和服务均支持时，使用 ZEC 最安全的方式是始终使用屏蔽交易。某些钱包和交易所支持 [统一地址](https://web.archive.org/web/20260823012524/https://electriccoin.co/blog/unified-addresses-in-zcash-explained/#:~:text=The%20unified%20address%20(UA)%20is,within%20the%20broader%20Zcash%20ecosystem.)，它可以将多种 Zcash 接收者类型组合为一个地址。
