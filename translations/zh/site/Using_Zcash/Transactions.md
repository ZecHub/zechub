# 交易

ZEC 是一种广泛用于支付的数字资产，具备强大的隐私特性，因此适用于多种交易场景，例如给朋友转账、购物或捐赠。为了最大限度地保障隐私和安全，理解 Zcash 中不同类型交易的运作方式至关重要。

## TL;DR

- Zcash 支持两种交易：**屏蔽交易**和**透明交易**。前者会将交易细节保持私密，后者则会将其公开记录。
- 屏蔽地址以 `u` 或 `z` 开头。透明地址以 `t` 开头，行为方式与 Bitcoin 地址非常相似。
- 每一笔付款都由你自己决定如何发送。隐私是 Zcash 提供给你的选择，而不是别人替你决定的设置。
- 从交易所提币是人们最常丢失隐私的场景。如果交易所只支持透明提币，请在资金到账后自行将其转入屏蔽池。
- 手续费遵循 [ZIP 317](https://zips.z.cash/zip-0317)，并会随着交易大小而增加。仍在使用旧版固定手续费的钱包，可能会导致交易延迟。
- 大多数 Zcash 交易在 [ZIP 203](https://zips.z.cash/zip-0203) 下都具有过期区块高度。如果交易在被打包前就已过期，那么在该过期高度之后它将无法确认，且可能需要重新发送。

当你将 ZEC 转入屏蔽钱包时，就会发生屏蔽交易。你的屏蔽钱包地址以 `u` 或 `z` 开头。发送屏蔽交易时，你和与你交易的人都能获得一种在默认公开的支付网络中无法实现的隐私级别。

使用支持当前 Zcash 网络和当前屏蔽池的钱包，是发送屏蔽交易最简单的方式。在依赖某个钱包提供隐私之前，请先确认它是否支持屏蔽发送、屏蔽接收，以及你计划使用的池。从交易所提取 ZEC 时，也要检查交易所支持的是屏蔽提币还是透明提币。如果它只支持透明提币，请在资金到账后将其转入支持屏蔽的钱包。

使用屏蔽交易来收发资金，是保护隐私并降低支付数据泄露风险的最佳方式。

## 透明交易

透明交易的工作方式与 Bitcoin 交易类似。交易细节会公开显示在 blockchain 上，包括透明地址和透明金额。当隐私是优先事项时，应尽量避免使用透明交易。

透明地址在某些情况下仍然有用，特别是当某个交易所或服务不支持屏蔽地址时。如果你通过透明地址接收了 ZEC，建议在后续付款前先将其转入屏蔽池。

## 一个简单的比喻

透明交易就像明信片。邮递员会投递它，但沿途任何接触到它的人都能读到内容、看到是谁寄出的，也能看到收件人是谁。

屏蔽交易则像一个密封信封。邮政系统仍然可以确认，确实有一封贴了真实邮资的真实信件通过了系统，而且没有人能伪造它，也不能把同一封信寄两次。至于信封里装了什么，只有寄件人与收件人知道。

重要的是，Zcash 让你可以一笔付款一笔付款地决定发送哪一种。

## Zcash 手续费

Zcash 不使用 Ethereum 风格的 gas 单位。Zcash 交易手续费以 ZEC 支付，通常用 **zatoshis** 表示。1 ZEC 等于 100,000,000 zatoshis。

[ZIP 317](https://zips.z.cash/zip-0317) 定义了一种会随着交易复杂度扩展的常规手续费机制。与旧版每笔交易统一使用 1,000 zatoshi 固定手续费不同，常规手续费基于“逻辑操作”计算，例如输入、输出和屏蔽操作。简单交易通常从约 10,000 zatoshis，也就是 0.0001 ZEC 起步，而更复杂的交易可能需要更高费用。

在当前大多数钱包中，用户通常不需要手动计算 ZIP 317 手续费。钱包应自动选择合适的费用。如果某个钱包仍然使用旧版固定手续费，或允许你设置远低于 ZIP 317 常规手续费的费用，交易可能会延迟、被降低优先级、被某些节点丢弃，或无法可靠地被中继。

## 卡住交易的排查方法

Zcash 交易并不会因为出现在你的钱包里就算最终完成。对于日常使用来说，只有当它被打包进区块并获得足够多、适合你场景的确认后，才算最终完成。交易所和服务所要求的确认数，可能比钱包默认显示的更多。

在重新发送之前，请先使用下面这个判断流程：

1. **你的钱包是否显示了交易 ID？**
   - 如果没有，钱包可能尚未创建或广播这笔交易。请检查同步状态、网络连接、钱包版本以及任何钱包错误信息。
   - 如果有，复制交易 ID 并继续。
2. **这笔交易是否已在区块中确认？**
   - 如果是，请等待你的钱包、交易所、商家或服务所要求的确认数。
   - 如果没有，继续。
3. **这笔交易是否已经达到其过期高度？**
   - 如果没有，请先不要手动重新发送同一笔付款。原始交易仍有可能确认。
   - 如果已经达到，则该交易在该过期高度之后无法再被打包。你的钱包可能会将其标记为已过期或失败，此时你可能需要创建一笔新交易。
4. **这笔交易是否出现在某一个服务器或区块浏览器上，但在另一个上没有？**
   - 这应被视为网络可见性问题，而不是交易失败的证据。不同节点可能拥有不同的 mempool 视图。
   - 请等待、重新同步钱包，或者如果你的钱包支持，切换到另一个可信服务器。
5. **这笔交易是否在显示已确认后又消失了？**
   - 短暂的链重组可能会暂时将一笔交易从最佳链中移除。
   - 请等待更多区块。如果交易重新出现，继续等待确认。如果它没有回来且之后过期了，请创建一笔新交易。
6. **钱包是否要求你重新发送？**
   - 只有在确认上一笔交易已经过期、失败或不再有效后，再遵循钱包当前的指引。
   - 如果你不确定，请先联系支持，再次发送前先确认情况。

## 待处理、过期、被丢弃和被重组

- **待处理** 表示交易已经创建或广播，但尚未被打包进区块。
- **已过期** 表示交易的过期高度已经过去。根据 ZIP 203，设置了过期高度的交易在该高度之后无法再被打包。
- **被丢弃** 表示一个或多个节点不再将该交易保留在它们的 mempool 中。这可能是由于过期、手续费过低、mempool 策略、重启行为或中继差异造成的。
- **被重组** 表示此前包含该交易的区块已不再属于最佳链。该交易可能稍后再次被打包，或者如果它仍然有效，也可能重新回到待处理状态。

## 什么时候不要重发

不要仅仅因为交易仍在待处理、速度较慢，或在某一个浏览器上查不到，就立刻重新发送。过早重发可能会造成混乱，而且取决于钱包如何构建新的付款，还可能带来重复付款的风险。

在以下情况下，最好先等待或先联系支持：

- 该交易已有交易 ID，且尚未过期。
- 一个服务器显示了它，而另一个没有。
- 它最近刚被打包，但在可能发生重组后失去了确认数。
- 收款服务尚未完成确认计数。
- 你的钱包仍在同步。

通常来说，只有在钱包明确将该交易标记为已过期或失败，或者支持团队确认原交易不可能再确认之后，再重新发送会更安全。

## 保护隐私的检查方式

你可以在不过度暴露信息的前提下，检查基本的交易状态：

- 检查你的钱包是否已完全同步。
- 检查钱包应用是否为最新版本。
- 检查该交易是否有交易 ID。
- 检查交易当前是已确认、待处理、已过期还是失败。
- 如果你的钱包显示过期高度，请检查当前区块高度，并将两者进行比较。
- 对于透明交易，区块浏览器可以显示公开交易、地址、金额和确认数。
- 对于屏蔽交易，区块浏览器可以显示某笔交易确实存在，但无法显示屏蔽发送方、接收方、金额或 memo 细节。

## 不要公开分享的内容

绝不要在公开聊天、社交媒体或 issue tracker 中发布以下内容：

- 助记词或恢复短语
- Spending key、私钥或钱包备份
- 完整 viewing key
- 显示余额、完整地址、memo、二维码或交易所账户详情的截图
- 个人身份证明文件或账户恢复记录

交易 ID 在链上是公开的，但它仍可能将你的支持请求与你的身份关联起来。如果隐私对你很重要，请仅通过可信的支持渠道分享它。

## 支持团队需要什么

向钱包、交易所或服务的支持团队寻求帮助时，只需分享最少且有用的信息：

- 钱包或服务名称
- 应用版本和操作系统
- 交易是屏蔽交易、透明交易，还是在屏蔽地址与透明地址之间进行
- 交易 ID，如果你愿意分享
- 大致发送时间
- 钱包是否已完全同步
- 钱包显示的当前状态
- 去除私密数据后的精确错误信息
- 已隐藏余额、地址、memo 和账户详情的截图

支持团队不需要你的助记词、Spending key、私钥或完整 viewing key。

## 常见错误

- **以为任何列出支持 ZEC 的钱包都能私密发送。** 不少多币种钱包只支持 Zcash 的透明侧。在你依赖某个钱包保护隐私之前，请先检查它支持哪些池。[钱包](https://zechub.wiki/using-zcash/wallets) 页面列出了每个选项的相关信息。
- **提币到透明地址后一直把资金留在那里。** 提币本身就是公开的，而该地址之后的每一次资金移动也都会继续公开。请在资金到账后将其转入屏蔽池。
- **把隐私当作一次性打开的选项。** 每一笔交易都是一次独立选择。今天发送屏蔽交易，并不会撤销你上周发出的透明付款。
- **所有用途都重复使用同一个透明地址。** 由于透明活动会被永久公开，一个被重复使用的地址会逐渐把原本没有必要关联的付款联系起来。
- **使用过时的默认手续费发送交易。** 尚未采用 ZIP 317 的钱包可能仍会使用旧版固定手续费，这可能导致交易长时间无法确认。
- **在过期前就重发。** 待处理交易在过期之前仍有可能确认。创建另一笔付款前，请先检查过期状态。

## 注意

请注意，在发送方、接收方、钱包和服务都支持的情况下，使用 ZEC 最安全的方式，是尽可能使用屏蔽交易。一些钱包和交易所支持 [Unified Address](https://electriccoin.co/blog/unified-addresses-in-zcash-explained/#:~:text=The%20unified%20address%20(UA)%20is,within%20the%20broader%20Zcash%20ecosystem.)，它可以将多种 Zcash 接收类型组合到一个地址中。
