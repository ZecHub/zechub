# 交易 [Transactions]

ZEC 是一种广泛使用的支付数字资产，提供强大的隐私 [privacy] 功能，使其适用于向朋友付款、购物或捐赠等各种交易。为了最大程度地保障隐私和安全，了解不同类型的交易如何在 Zcash 中运作至关重要。

## TL;DR

- Zcash 支持两种交易：**屏蔽 [shielded]**，可将详细信息保持私密；以及 **透明 [transparent]**，会公开记录详细信息。
- 屏蔽地址 [address] 以 `u` 或 `z` 开头。透明地址以 `t` 开头，其行为与 Bitcoin 地址十分相似。
- 每一笔支付 [payment] 都由你选择。隐私是 Zcash 赋予你的选项，而非由他人为你决定的设置。
- 从交易所 [exchange] 提款是人们最常失去隐私的环节。如果交易所仅支持透明提款，资金到账后请自行将其转入屏蔽状态。
- 手续费 [fee] 遵循 [ZIP 317](https://zips.z.cash/zip-0317)，并随交易规模增长。仍发送旧固定手续费的钱包 [wallet] 可能会导致其交易延迟。
- 大多数 Zcash 交易在 [ZIP 203](https://zips.z.cash/zip-0203) 下都设有到期高度。如果交易在挖矿 [mining] 前过期，则无法在该到期高度后确认，可能需要重新发送。

当你将 ZEC 转入屏蔽钱包时，就会发生屏蔽交易。你的屏蔽钱包地址以 `u` 或 `z` 开头。发送屏蔽交易时，你和与你交易的人可以获得默认公开的支付网络无法提供的隐私水平。

使用支持当前 Zcash 网络和当前屏蔽池 [pools] 的钱包，发送屏蔽交易最为简单。在依赖钱包保障隐私前，请确认它支持屏蔽发送、屏蔽接收以及你计划使用的 pool。从交易所提取 ZEC 时，请确认交易所是否支持屏蔽或透明提款。若其仅支持透明提款，请在资金到账后将其转入支持屏蔽功能的钱包。

使用屏蔽交易收发资金，是保护隐私并降低支付数据泄露风险的最佳方式。

## 透明交易

透明交易的运作方式与 Bitcoin 交易类似。交易详细信息会在 blockchain 上公开可见，包括透明地址和透明金额。隐私优先时，应避免使用透明交易。

透明地址在某些情况下仍然有用，尤其是当交易所或服务不支持屏蔽地址时。如果你在透明地址收到 ZEC，请考虑在后续支付前将其转为屏蔽状态。

## 一种简单的理解方式

透明交易就像一张明信片。邮递员会投递它，但沿途经手的任何人都可以阅读信息、看到寄件人以及收件人。

屏蔽交易则像一个密封信封。邮政服务仍可确认一封附有真实邮资的真实信件已通过系统，而且无人能伪造它或重复发送同一封信。信封里的内容仅由发送者和接收者知晓。

重要的是，Zcash 让你可以逐笔支付决定发送哪一种。

## Zcash 手续费

让你的钱包计算网络手续费，并在发送前进行核对。手续费以 ZEC 支付：**1 ZEC = 100,000,000 zatoshis**。以美元计算的手续费还取决于 ZEC 的汇率。

### 为什么两笔支付的手续费可能不同

[ZIP 317](https://zips.z.cash/zip-0317#fee-calculation) 根据**逻辑操作（logical actions）**计算常规手续费，而不是按发送金额的百分比计算：

```text
fee in zatoshis = marginal fee × max(2, logical actions)
```

逻辑操作（logical actions）用于衡量交易的组成部分。例如，仅含 Orchard 的交易使用其 Orchard 操作的数量；仅含 Sapling 的交易则使用其花费数与输出数中较大的那个。来自不同 pool 的贡献会相加。透明组件采用基于大小的计算方式。完整公式请参见 ZIP 317，其中包括 Ironwood 和旧版 Sprout。

因此，花费许多小额接收的 note 或使用多个 pool，可能比同等金额的简单支付花费更多。仅凭接收方数量无法计算手续费（fee）：找零和填充也会产生影响。

这些示例以已经计算出的逻辑操作数量为起点：

| 逻辑操作数 | 每个操作 5,000 zatoshis | 每个操作 1,000 zatoshis |
| --- | --- | --- |
| 2 | 10,000 zatoshis / 0.0001 ZEC | 2,000 zatoshis / 0.00002 ZEC |
| 3 | 15,000 zatoshis / 0.00015 ZEC | 3,000 zatoshis / 0.00003 ZEC |
| 10 | 50,000 zatoshis / 0.0005 ZEC | 10,000 zatoshis / 0.0001 ZEC |

### 适用哪种边际手续费

**2026年11月11日核实：**ZIP 317 列出了修订版 2，以及处于提议状态的[ZIP 2009](https://zips.z.cash/zip-2009)。在修订版 2 之前，边际手续费（marginal fee）为 5,000 zatoshis。修订版 2 将其规定为 1,000，因此最低手续费为 2,000 zatoshis，而不是 10,000。

该提案规定主网（Mainnet）激活高度为 **3,590,000**（预计在 2026 年 11 月 19 日前后），测试网（Testnet）激活高度为 **4,465,026**。日历上的预估日期并不是激活条件。对钱包而言，相关高度是交易预计被打包进的那个区块的高度；节点则使用下一个区块的高度。随着部署情况变化，请重新查阅相关链接的规范以及你所用钱包的发布指引。

不要仅仅因为某个提案或软件版本提到了较低的手续费，就手动强制使用它。ZIP 2009 要求节点先部署新的中继策略，钱包才能采用该手续费；使用旧参数的节点可能会拒绝中继较低手续费的交易。Testnet 和 Mainnet 的激活高度也不相同。

### 如果估算看起来不对

请确认你的钱包已更新到最新版本并已完成同步。请将钱包的网络手续费与发送服务的提现费用分开比较：服务报价并不是 ZIP 317 公式。对于待处理的支付，请在重新发送之前先按照[下方的故障排除步骤](#troubleshooting-stuck-transactions)进行操作。

ZIP 317 是一项钱包和节点策略，而非要求精确支付该手续费的共识（consensus）规则。支付常规手续费可以提高交易中继的兼容性，但并不保证确认时间。

## 排查卡住的交易

Zcash 交易仅仅显示在你的钱包中并不代表它已最终确定。对于一般使用场景，它在被挖入区块 [block] 并获得足够的确认后才算最终确定。交易所和服务所要求的确认数量可能高于钱包默认显示的数量。

过期时间是一个**区块高度**，而不是固定的倒计时。对于过期高度不为零的普通支付，该高度就是它能被打包进的最后一个区块。例如，在高度 3539 过期的支付可以被包含在区块 3539 中；到区块 3540 就太晚了。对于普通支付，过期高度为 0 表示永不过期。参见 [ZIP 203](https://zips.z.cash/zip-0203)。

默认值并非通用的截止期限。ZIP 203 规定在 Blossom 之后 40 个区块，按 75 秒的目标出块间隔计算约为 50 分钟。拟议的 NU7 变更建议在 25 秒的目标出块间隔下设为 120 个区块，同样约为 50 分钟（[ZIP 218](https://zips.z.cash/zip-0218)）。钱包设置和实现可能有所不同，实际区块间隔也会有所变化。请检查具体交易的过期高度，而不要靠计时来决定何时重新发送。

过期不会撤销已被挖出的支付，也不会创建退款交易。如果原交易在过期前未被挖出，它就从未在链上 [on-chain] 结算。您的钱包可能需要先完成同步，才会再次将相关资金显示为可花费。

重新发送前，请使用以下决策树：

1. **你的钱包是否显示交易 ID？**
   - 如果没有，钱包可能尚未创建或广播该交易。请检查同步状态、网络连接、钱包版本以及任何钱包错误信息。
   - 如果有，请复制交易 ID 并继续。
2. **该交易是否已在区块中确认？**
   - 如果是，请等待你的钱包、交易所、商家或服务所要求的确认数。
   - 如果否，请继续。
3. **未被打包的交易是否已超过其非零的过期高度（expiry height）？**
   - 如果否，请暂时不要手动重新发送同一笔支付。原始交易仍可能被确认。
   - 如果是，请让钱包完成同步，并核实原始交易未在该高度或之前被打包。然后在需要时按照钱包的指引创建替代交易。
4. **该交易是否在某个服务器或浏览器上可见，而在另一个上不可见？**
   - 请将此视为网络可见性问题，而不是交易失败的证明。不同的节点可能有不同的内存池（mempool）视图。
   - 请等待、重新同步你的钱包，或者在钱包支持的情况下切换到另一个可信的服务器。
5. **该交易在显示已确认后是否消失了？**
   - 短暂的链重组（chain reorganization）可能会暂时将交易从最佳链中移除。
   - 请等待更多区块。如果交易重新出现，请继续等待确认。如果交易没有重新出现并随后过期，请创建一笔新交易。
6. **钱包是否在要求你重新发送？**
   - 只有在确认之前的交易已过期、失败或不再有效之后，才按照钱包当前的指引操作。
   - 如果不确定，请在再次发送之前咨询支持团队。

## 待处理、已过期、已丢弃和已重组

- **待处理** 表示交易已创建或广播，但尚未被挖入区块。
- **已过期** 表示交易的到期高度已过。根据 ZIP 203，设有到期高度的交易无法在该高度后被挖入。
- **已丢弃** 表示一个或多个节点不再将交易保留在其内存池中。这可能因过期、低手续费、内存池策略、重启行为或中继差异而发生。
- **已重组** 表示此前包含该交易的区块不再是最佳链的一部分。该交易之后可能再次被挖入，或者若它仍然有效，则可能重新变为待处理状态。

## 不应重新发送的情况

不要仅因交易待处理、缓慢，或在某个浏览器中缺失就立即重新发送。过早重新发送可能造成混乱，而且取决于钱包构建新支付的方式，可能存在重复支付的风险。

在以下情况下，请先等待或寻求支持：

- 交易具有交易 ID 且尚未过期。
- 一台服务器显示该交易，而另一台没有。
- 它最近被挖入，但在可能发生重组后失去了确认。
- 接收服务尚未完成确认计数。
- 你的钱包仍在同步。

通常，只有在钱包明确将交易标记为已过期或失败，或支持团队确认原交易无法确认后，重新发送才更安全。

## 注重隐私的检查

你可以在不暴露超出必要范围的信息的情况下检查基本交易状态：

- 检查你的钱包是否已完全同步。
- 检查钱包应用是否为最新版本。
- 检查交易是否具有交易 ID。
- 检查交易是已确认、待处理、已过期还是失败。
- 如果钱包显示，请检查当前区块高度并与交易到期高度比较。
- 对于透明交易，区块链浏览器可以显示公开交易、地址、金额和确认数。
- 对于屏蔽交易，区块链浏览器可以显示交易存在，但无法显示屏蔽的发送者、接收者、金额或备忘录 [memo] 详细信息。

## 不应公开分享的内容

切勿在公开聊天、社交媒体或问题跟踪器中发布以下内容：

- 助记词 [seed phrase] 或恢复短语
- 花费密钥 [spending key]、私钥或钱包备份
- Full Viewing Key
- 显示余额、完整地址、备忘录、QR 码或交易所账户详细信息的截图
- 个人身份证明文件或账户恢复记录

交易 ID 在链上是公开的，但它仍可能将你的支持请求与你的身份关联。如果隐私很重要，请仅通过可信支持渠道分享它。

## 支持团队需要的信息

向钱包、交易所或服务支持团队寻求帮助时，仅分享最低限度的有用信息：

- 钱包或服务名称
- 应用版本和操作系统
- 交易是屏蔽、透明，还是在屏蔽与透明地址之间进行
- 如果你愿意分享，提供交易 ID
- 大致发送时间
- 钱包是否已完全同步
- 钱包显示的当前状态
- 删除私密数据后的准确错误信息
- 隐藏余额、地址、备忘录和账户详细信息的截图

支持团队不需要你的助记词、花费密钥、私钥或完整 viewing key。

## 常见错误

- **认为任何列出 ZEC 的钱包都能私密地发送它。** 一些多币种钱包仅支持 Zcash 的透明端。依赖钱包保护隐私前，请检查其支持的 pool。[钱包](https://zechub.wiki/using-zcash/wallets) 页面列出了每个选项的相关信息。
- **提取到透明地址并将资金留在那里。** 提款本身是公开的，之后从该地址进行的每次转移也都会保持公开。资金到账后请将其转为屏蔽状态。
- **将隐私视为只需开启一次的功能。** 每笔交易都是独立选择。今天发送屏蔽交易并不能撤销你上周进行的透明支付。
- **将透明地址用于一切。** 由于透明活动永久可见，一个重复使用的地址会逐渐关联原本没有理由关联的支付。
- **使用过时的默认手续费发送。** 尚未采用 ZIP 317 的钱包可能仍发送旧固定手续费，从而导致交易一直处于未确认状态。
- **在过期前重新发送。** 待处理交易在过期前仍可能确认。创建另一笔支付前，请检查过期状态。

## 注意

请注意，在发送者、接收者、钱包和服务均支持时，使用 ZEC 最安全的方式是始终使用屏蔽交易。某些钱包和交易所支持 [统一地址](https://web.archive.org/web/20260823012524/https://electriccoin.co/blog/unified-addresses-in-zcash-explained/#:~:text=The%20unified%20address%20(UA)%20is,within%20the%20broader%20Zcash%20ecosystem.)，它可以将多种 Zcash 接收者类型组合为一个地址。
