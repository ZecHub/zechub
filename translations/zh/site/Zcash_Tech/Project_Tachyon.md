# Project Tachyon

## TL;DR

- Tachyon 是对 Zcash 钱包查找和花费屏蔽资金方式的一项拟议重新设计，旨在让网络能够扩展至极大量用户
- 如今，钱包必须尝试解密区块链中很大一部分内容，才能发现哪些付款属于自己；这正是屏蔽交易同步感觉缓慢的主要原因
- Tachyon 以**无感同步**取而代之，使钱包无需扫描全部内容即可获取所需数据，同时不会向服务器透露它想要哪些部分
- 它还将付款详情从区块链移至付款请求本身，这简化了协议，但将更多责任转移给钱包
- 这是一项提案，最初于 2025 年 4 月发布，并被列为 NU7 的候选方案。它**尚未上线**，且需要与 Sapling 升级同等规模的工程投入

<br/>

## 适合哪些读者

- 曾看着屏蔽钱包同步，并疑惑为何如此耗时的任何人
- 经常看到 Tachyon 与 NU7 和 Zcash 扩容一同被提及的新手
- 希望先理解理念、再了解密码学的读者

## Tachyon 解决的问题

Zcash 隐藏付款的接收方。这正是其核心所在，却也带来了一个棘手问题：如果没人能知道一笔付款属于谁，你自己的钱包如何找到属于你的付款？

在 Bitcoin 中这很容易。地址是公开的，因此钱包可以询问服务器：“发送到这个地址的资金有哪些？”并得到答案。Zcash 钱包无法提出这个问题，因为这样做会暴露屏蔽池本应隐藏的内容。

因此，Zcash 采用了不同做法。发送方会加密付款详情，并将其置于交易本身之中。随后，你的钱包会逐笔处理链上的交易，并尝试解密每一笔。几乎所有尝试都会失败。少数成功的便是你的付款。这称为**试探性解密**，它兼具隐私性和正确性，但速度很慢。

![如今，Zcash 钱包会下载每一笔屏蔽交易并尝试逐笔解密；几乎所有尝试都会失败，以找出少数属于自己的付款](/content-images/tachyon-scanning-today.svg)

问题在于这项工作取决于什么。钱包所花费的工作量由链的规模决定，而非你实际收到的付款数量。一个从未收到过任何付款的人，所做的工作几乎与每天收到付款的人一样多。随着 Zcash 增长，这对所有人都会愈发严重。正如提案所言，它“根本无法扩展”。

<br/>

## Tachyon 改变了什么

Tachyon 从根源上解决这一问题：它不再将区块链用作付款秘密的传递通道。

取而代之的是，你所需的详情会随付款请求本身在带外传递。付款请求、URI 或二维码会携带过去加密在交易中的信息。Sean Bowe 将其描述为首次在 Zcash 屏蔽协议中采用**带外付款**。

一旦链不再携带这些信息，你的钱包也就不再需要搜索它，试探性解密问题随之消失。

不过，你的钱包仍需了解当前链状态才能花费资金。这正是设计的另一半：**无感同步**，即让钱包获取其所需的特定内容，而不向服务器透露它请求了哪些内容的方法。

![通过 Tachyon，发送方会以带外方式向接收方传递付款详情，钱包则使用无感同步仅检索所需数据，而非扫描整条链](/content-images/tachyon-oblivious-sync.svg)

<br/>

## 这对钱包用户意味着什么

- **同步不再随链的规模增长。** 你的钱包追赶进度所花费的时间将取决于你自己的活动，而不是 Zcash 的规模。
- **付款会更像把账单交给对方。** 付款请求会携带接收方所需的信息，因此发送方和接收方之间的交互会比现在更重要。
- **钱包承担更多责任。** 由于链上不再保存付款详情的加密副本，丢失钱包数据的影响会更大。备份和恢复将从协议功能转变为钱包软件必须妥善处理的事项。
- **一些熟悉的组成部分会迁移或消失。** Tachyon 将密钥多样化、Viewing Key 和付款地址移出核心协议，交由钱包层处理。这是该提案影响更深远的部分之一，仍在进一步研究中。

<br/>

## 面向技术读者的深入介绍

Tachyon 被描述为对 Orchard 协议的一项反向兼容变更。它既可以作为现有 Orchard 池的升级部署，也可以作为通过 [turnstile](https://zechub.wiki/zcash-tech/the-turnstile) 访问的独立屏蔽池部署；这与 Zcash 为 Ironwood 使用的机制相同。选择会影响部署方式，而不影响设计本身。

它保留了 Orchard 的若干特性：RedPallas 密钥重新随机化、同态价值承诺和绑定签名，以及允许设备委托证明而不交出花费权限的分区密钥结构。

扩容工作依赖于**携带证明的数据**，这项技术让数据附带其自身正确性的证明，因此将其与其他携带证明的数据结合后，会产生继承并扩展这些证明的结果。这使得大量已验证工作能够被压缩为小巧且可快速检查的内容。由 Zcash 背后团队发现的 Halo，使携带证明的数据变得足够实用，能够据此构建系统。

第三条主线是**屏蔽交易聚合**，它改变了屏蔽状态变更的传递方式，并对签名机制产生连锁影响。

<br/>

## 工作进展

Tachyon 是一项**提案，而非已上线功能**。它于 2025 年 4 月发布，2025 年 5 月的后续文章探讨了其共识层面的影响。它被列为 NU7 的候选方案；NU7 是 Ironwood 之后的下一次重大升级，但 NU7 的内容将由持币者投票决定，Tachyon 的任何内容都尚未确定。

作者自己的表述是，这是一项可执行的计划，而不是推测性研究；但它需要与 Sapling 相当的工程投入，同时一些更困难的问题被有意留待之后处理。

相关工作已经初现端倪。[Zakura](https://zechub.wiki/zcash-tech/zakura-node) 是一个于 2026 年 7 月发布的完整节点，由 Project Tachyon 与 Valar Group 共同开发，并预览了其中一些网络层面的变更。[私有信息检索](https://zechub.wiki/zcash-tech/private-information-retrieval)研究则从不同角度瞄准同一钱包扫描瓶颈。

<br/>

## 常见误解

- **Tachyon 尚未上线。** 目前没有钱包使用它，也没有任何升级激活它。
- **Tachyon 不等同于 Ironwood。** Ironwood 于 2026 年 7 月激活，涉及 Orchard 池和 turnstile。Tachyon 是一项独立且更晚提出的扩容提案。
- **Tachyon 不会削弱隐私。** 目标是在消除扩容成本的同时保持账本不可区分性，而非以隐私换取速度。
- **zk-SNARK 验证从来不是瓶颈。** 提案明确指出，缓慢之处在于钱包如何发现并协调状态，而非验证证明的成本。
- **“面向 NU7”并非承诺。** NU7 中包含哪些内容由投票决定。

## 术语表

| 术语 | 含义 |
|---|---|
| 试探性解密 | 逐笔尝试解密交易，以找出发送给你的交易 |
| 带内秘密分发 | 如今 Zcash 所采用的做法：将付款秘密置于区块链上的交易内部 |
| 带外付款 | 不通过链，而是直接在发送方和接收方之间传递付款详情 |
| 无感同步 | 获取钱包所需的链上数据，而不透露请求了哪些数据 |
| 携带证明的数据（PCD） | 附带自身正确性证明的数据，因此证明可以被组合和压缩 |
| 屏蔽交易聚合 | Tachyon 打包屏蔽状态变更的方式，改变了它们的传递和签名方式 |
| 账本不可区分性 | 无法将屏蔽交易彼此区分开的性质 |

## 常见问题

**这会让我的钱包同步更快吗？** 这是目标。同步时间将取决于你自己的活动，而不是链的规模。目前尚未上线，因此还没有可引用的实测数据。

**我现在需要做什么吗？** 不需要。Tachyon 是一项提案。如果它被采纳，将会通过网络升级发布，并遵循通常的通知流程。

**移除 Viewing Key 是否意味着失去共享读取权限的能力？** 提案将这一能力从核心协议移至钱包层。其实际形式将会如何，是尚未解决的问题之一。

**如果 Tachyon 上线，我的资金会有风险吗？** 部署将使用 Orchard 升级或 turnstile，两者都经过设计，确保价值会在公开的记账规则下流动。Ironwood 页面解释了 turnstile 的运作方式。
