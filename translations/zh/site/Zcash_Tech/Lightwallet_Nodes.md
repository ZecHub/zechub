# Zcash 轻钱包节点

## TL;DR

* 大多数人通过轻钱包 [light wallet] 使用 Zcash，它不会下载整个 blockchain。相反，它会与已完成该工作的服务器通信。
* 如今有两款软件为轻钱包提供服务：以 Go 编写的原始服务 **lightwalletd**，以及以 Rust 编写的较新索引器 **Zaino**。
* 您的密钥绝不会离开您的设备，服务器也无法花费您的资金，或读取完全屏蔽 [shielded] 交易中的金额和备忘录。
* 服务器特别容易获知的是您的 IP 地址及活动时间——屏蔽交易保护的是 blockchain 上发生的事情，而不是您与服务器之间的连接。
* Tor 会移除 IP 标识符；它可用于基于 `zcash_client_backend` 构建的钱包中，在 ZODL 中则是"高级设置"中的一项设置。
* 您可以更改钱包使用的服务器，或自行运行服务器——lightwalletd 和 Zaino 都是开源的。

## 核心说明

大多数人通过轻钱包使用 Zcash，它不会下载整个 blockchain。相反，它会与已完成该工作的服务器通信。本页说明这些服务器是什么、它们能和不能看到您的哪些信息、如何通过 Tor 路由您的连接，以及如何更改钱包使用的服务器。

如今有两款软件为轻钱包提供服务。**lightwalletd** 是以 Go 编写的原始服务。**Zaino** 是以 Rust 编写的较新索引器，作为 zcashd 弃用工作的一部分构建。

### 轻钱包服务器的作用

轻钱包服务器位于您的钱包与 Zcash blockchain 之间，为其提供节省带宽的链 [chain] 视图。它为您完成三项工作。

它提供紧凑区块。它不会发送完整区块，而是发送一种紧凑形式，其中仅包含钱包检测到向其屏蔽地址的支付、检测其 note 的花费，以及更新其见证所需的信息。

它转发您的交易。当您发送交易时，您的钱包会将完成的交易交给服务器，服务器再将其广播到网络。

它回答链查询，例如当前高度以及您的钱包所需的手续费信息。

您的钱包仍会在本地完成私密工作。它持有您的密钥，对区块进行试解密以寻找您的 note，并在您的设备上构建和签署交易。

### 服务器能看到什么，不能看到什么

这是一个很容易理解错误的部分。您的密钥绝不会离开您的设备，但这并不等于服务器不会获知您的任何信息。

此处参考的是 [Zcash 钱包应用威胁模型](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)，如果您在意这一点，值得完整阅读。它列出了几类对手。与本页相关的是能够监视您的钱包与互联网之间，以及服务器与互联网之间流量的对手。无论谁运行服务器，都必然在某种程度上处于这一位置，因为您的钱包会直接连接到他们。

先从受到保护的内容说起。面对模型中的任何对手，包括已攻破服务器的对手，它"无法获知用户的任何加密密钥材料（花费密钥、viewing key、助记词等）"，无法窃取您的资金，也无法让您发送并非您本意要发送的资金。完全屏蔽交易中的金额和备忘录会保持加密。

接下来是不受保护的内容。威胁模型将以下内容列为面对流量观察型对手时的已知弱点：

| 弱点 | 方式 |
|:--|:--|
| 判断您是谁 | "对手知道用户的 IP 地址，这可能会导致其获知用户的真实身份" |
| 大致判断您的所在地 | 在"地理定位数据库中查询"您的 IP，以大致估计您的位置 |
| 判断您是否以及何时发送或接收了屏蔽交易 | 发送交易"会使用更多带宽，即使连接经过加密，这一点也是可见的"。该模型指出，发送和接收这一行为本身对服务器可见 |
| 统计您随时间推移完成了多少交易 | 在更长时间内观察相同的带宽模式 |
| 发现重复出现的支付模式 | 观察活动发生的时间 |
| 判断某个地址是否属于您 | 已知某个地址的对手"可以向该地址发送资金，并观察您的钱包获取它时是否出现带宽峰值" |

该模型还指出，普通情形假设"用户与 lightwalletd 服务器运营者之间存在信任关系"。

因此，诚实的总结是：轻钱包服务器无法花费您的资金，也无法读取屏蔽交易中的金额或备忘录。它特别容易获知的是您的 IP 地址和活动时间，而这两者结合起来可以透露许多关于个人的信息。屏蔽交易保护 blockchain 上发生的事情。它们本身不会隐藏您与服务器之间的连接。

## 视觉化 / 类比

把它想象成一家收藏了所有曾出版报纸的公共图书馆。全节点是将整个档案带回家的读者。轻钱包则是向图书管理员索取每日摘要的读者——一张薄纸，只包含足以发现是否有内容与自己相关的信息。

这份摘要是密封的：图书管理员在无法读取哪些内容对您重要的情况下将其整理好，您再用自己的密钥在家中打开它。这就是紧凑区块，而打开它就是在您的设备上进行试解密。

但图书管理员仍能看到是哪位读者走进来、何时到来，以及带走了多厚的一捆材料。这就是 IP 地址和时间——无论信封密封得多好，从柜台都能看到。Tor 相当于派遣匿名快递员：图书管理员仍交付同一捆材料，但不再知道它会送往谁的家。

## 深入探讨

### 通过 Tor 路由

Tor 会切断您的 IP 地址与钱包流量之间的联系，从而移除上表中最强的标识符。

许多 Zcash 钱包所依赖的 Rust 库支持这一功能。zcash_client_backend 包含一个基于 [Arti](https://tpo.pages.torproject.net/core/arti/) 构建的 Tor 模块；Arti 是 Tor 的 Rust 实现，因此钱包可以通过 Tor 路由同步、交易广播和价格查询，而无需附带单独的 Tor 客户端。

Zaino 开发者也提出了相同论点，并直接引用了威胁模型：需要"使用匿名传输协议（如 Nym 或 Tor）来混淆客户端相对于 Zcash 索引服务器的身份"。

在 **ZODL** 中，Tor 是"高级设置"中的一项设置。该钱包的发行说明建议用户，如果他们"希望减少元数据暴露"，可使用手动连接模式"并在高级设置中启用 Tor"；该应用还会在您恢复钱包前提供开启 Tor 的选项，因为此时新的 IP 本来会与整个钱包历史关联。

有两点注意事项。Tor 会向服务器隐藏您的 IP，但不会改变服务器从您发出的请求中获知的信息。而且，洋葱路由会增加延迟，因此同步需要更长时间。自行运行服务器则以另一种方式避开信任问题，因为运营者就是您自己。

### Zaino，Rust 索引器

[Zaino](/zcash-tech/zaino) 是由 Zingo 团队以 Rust 编写的索引器，旨在作为 zcashd 弃用工作的一部分替代 lightwalletd。它为轻客户端、完整客户端和区块链浏览器提供服务，读取由"Zebra 或 zcashd 全验证器"持有的链数据。

它正处于积极开发阶段，0.8.0 版本于 2026 年 8 月发布。它旨在尽可能保持与 lightwalletd 的向后兼容性，因此钱包无需重写即可指向它。

Zaino 拥有自己的页面及架构图，因此本页仅介绍其作为轻钱包服务器的角色。

### 自行运行

最稳妥的选择是自行运营，这会彻底消除信任问题。两个服务器都是开源的：以 Go 编写的 [lightwalletd](https://github.com/zcash/lightwalletd)，以及以 Rust 编写的 [Zaino](https://github.com/zingolabs/zaino)。两者都从全验证器读取数据，因此您还需要 [Zebra](/zcash-tech/zebra-full-node)。

## 常见错误

**认为服务器能够读取您的交易**。它不能。您的密钥保留在设备上，完全屏蔽交易中的金额和备忘录会保持加密——即使面对已攻破服务器的对手也是如此。

**将"屏蔽"理解为"匿名连接"**。屏蔽交易保护 blockchain 上发生的事情。您的 IP 地址和活动时间属于另一个层面，而这正是服务器能看到的层面。

**假设 Tor 能消除所有痕迹**。Tor 会向服务器隐藏您的 IP，但不会改变服务器从您发出的请求中获知的信息，而且会增加同步延迟。

**信任 wiki 页面上的服务器列表**。运营者时来时去。在将钱包指向任何服务之前，请查看 [hosh.zec.rocks](https://hosh.zec.rocks/zec) 以了解实际正在运行的服务。

## 总结

轻钱包让您无需占用磁盘空间即可使用屏蔽池，这是很好的取舍。只需明确您在交换什么。服务器无法拿走您的资金，也无法读取您的屏蔽金额，但它特别容易看到您的 IP 地址以及您交易的时间。通过 Tor 路由，有意识地选择运营者，或者自行运行服务器。
