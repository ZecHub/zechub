# Zcash 轻钱包节点

## TL;DR

* 大多数人通过轻钱包使用 Zcash，轻钱包不会下载整个区块链。相反，它会与一台已经完成该工作的服务器通信。
* 如今有两款软件为轻钱包提供服务：以 Go 编写的原始服务 **lightwalletd**，以及以 Rust 编写的较新索引器 **Zaino**。
* 你的密钥绝不会离开设备，服务器无法花费你的资金，也无法读取完全屏蔽交易中的金额和备注。
* 服务器能够了解的是你的 IP 地址和活动时间——屏蔽交易保护区块链上发生的内容，而非你与服务器之间的连接。
* Tor 会移除 IP 标识符；它可用于基于 `zcash_client_backend` 构建的钱包，在 ZODL 中则可在高级设置中启用。
* 你可以更改钱包使用的服务器，或自行运行服务器——lightwalletd 和 Zaino 都是开源的。

## 核心说明

大多数人通过轻钱包使用 Zcash，轻钱包不会下载整个区块链。相反，它会与一台已经完成该工作的服务器通信。本页说明这些服务器是什么、它们能和不能了解你的哪些信息、如何通过 Tor 路由连接，以及如何更改钱包使用的服务器。

如今有两款软件为轻钱包提供服务。**lightwalletd** 是以 Go 编写的原始服务。**Zaino** 是以 Rust 编写的较新索引器，作为 zcashd 弃用工作的一部分构建。

### 轻钱包服务器的作用

轻钱包服务器位于你的钱包与 Zcash 区块链之间，为钱包提供高带宽效率的链上视图。它为你完成三项工作。

它提供紧凑区块。它不发送完整区块，而是发送紧凑形式，其中仅包含钱包检测向其屏蔽地址付款、检测其票据被花费以及更新见证所需的信息。

它转发你的交易。当你发送交易时，钱包将完成的交易交给服务器，由服务器向网络广播。

它回答链上查询，例如当前区块高度以及钱包所需的手续费信息。

你的钱包仍会在本地完成私密工作。它持有你的密钥，对区块进行试解密以寻找你的票据，并在设备上构建和签署交易。

### 服务器能和不能看到什么

这一部分很容易被误解。你的密钥绝不会离开设备，但这并不等于服务器无法了解任何与你有关的信息。

这里的参考资料是 [Zcash 钱包应用威胁模型](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)，如果你关心此问题，值得完整阅读。它列出了几类对手。本页相关的是能够监控钱包与互联网之间，以及服务器与互联网之间流量的对手。服务器运营者天然处于这种位置的一部分，因为你的钱包直接连接到他们。

先说受到保护的内容。针对模型中的所有对手，包括已攻破服务器的对手，他们“无法获知用户的任何加密密钥材料（花费密钥、查看密钥、助记词等）”，无法窃取你的资金，也无法让你发送非你本意的资金。完全屏蔽交易中的金额和备注仍保持加密。

接下来是未受保护的内容。威胁模型将以下内容列为面对流量观察型对手时的已知弱点：

| 弱点 | 方式 |
|:--|:--|
| 判断你是谁 | “对手知道用户的 IP 地址，这可能让其关联到用户的真实身份” |
| 大致判断你身处何地 | 在“地理位置数据库中查询”你的 IP 地址，以估计你的位置 |
| 判断你是否以及何时发送或接收了屏蔽交易 | 发送交易“会使用更多带宽，即使连接已加密，这一点仍可见”。模型指出，发送和接收这一行为本身对服务器可见 |
| 统计你长期以来完成了多少交易 | 相同的带宽模式，在更长时间内被观察到 |
| 识别重复出现的付款模式 | 观察活动发生的时间 |
| 判断某个地址是否属于你 | 已知某个地址的对手“可以向该地址发送资金，并观察你的钱包获取它时是否出现带宽峰值” |

该模型还指出，通常情况假定“用户与 lightwalletd 服务器运营者之间存在信任关系”。

因此，诚实的总结是：轻钱包服务器无法花费你的钱，也无法读取你屏蔽交易中的金额或备注。它非常容易了解到的是你的 IP 地址及活动时间，而二者结合起来能够透露许多个人信息。屏蔽交易保护区块链上发生的内容，但它们本身不会隐藏你与服务器之间的连接。

## 直观说明 / 类比

想象一座保存着历来所有报纸的公共图书馆。全节点就像一位把整套档案带回家的读者。轻钱包则像一位向图书管理员索取每日摘要的读者——这是一张薄纸，仅包含足以发现是否有内容与自己有关的信息。

摘要是密封的：图书管理员在无法读取哪些项目对你重要的情况下整理它，而你用自己的密钥在家中打开它。这就是紧凑区块，而打开的过程就是在设备上进行的试解密。

但图书管理员仍能看到是哪位读者走进来、何时到来，以及带走的包裹有多厚。这就是 IP 地址和时间信息——无论信封密封得多好，从柜台都能看见。Tor 相当于派遣匿名快递员：图书管理员仍交出相同的包裹，但不再知道它送往谁家。

## 深入解析

### 通过 Tor 路由

Tor 会切断你的 IP 地址与钱包流量之间的关联，从而消除上表中最强的标识符。

许多 Zcash 钱包所依赖的 Rust 库支持此功能。zcash_client_backend 包含一个基于 [Arti](https://tpo.pages.torproject.net/core/arti/) 的 Tor 模块；Arti 是 Tor 的 Rust 实现，因此钱包可以通过 Tor 路由同步、交易广播和价格查询，无需附带独立的 Tor 客户端。

Zaino 开发者也提出了相同观点，并直接引用威胁模型：有“必要使用匿名传输协议（如 Nym 或 Tor），以混淆客户端在 Zcash 索引服务器前的身份”。

在 **ZODL** 中，Tor 是高级设置中的一个选项。该钱包的发行说明建议，如果用户“希望减少元数据暴露”，可使用手动连接模式“并在高级设置中启用 Tor”；应用也会在你恢复钱包前提供开启 Tor 的选项，此时新的 IP 地址原本可能会与整个钱包历史关联。

有两点需要注意。Tor 会向服务器隐藏你的 IP，但不会改变服务器从你发出的请求中获知的内容。而且洋葱路由会增加延迟，因此同步需要更长时间。自行运行服务器则以另一种方式避免信任问题，因为此时运营者就是你自己。

### Zaino，Rust 索引器

[Zaino](/zcash-tech/zaino) 是由 Zingo 团队以 Rust 编写的索引器，旨在作为 zcashd 弃用工作的一部分取代 lightwalletd。它为轻客户端、全客户端和区块浏览器提供服务，读取“Zebra 或 Zcashd 全验证器”持有的链上数据。

它正在积极开发中，0.8.0 版本于 2026 年 8 月发布。它旨在尽可能保持与 lightwalletd 的向后兼容性，因此钱包无需重写即可指向它。

Zaino 有自己的页面和架构图，因此本页仅介绍其作为轻钱包服务器的角色。

### 自行运行

最强的选择是自行运营，从而彻底消除信任问题。两种服务器都是开源的：以 Go 编写的 [lightwalletd](https://github.com/zcash/lightwalletd) 和以 Rust 编写的 [Zaino](https://github.com/zingolabs/zaino)。二者都从全验证器读取数据，因此你还需要 [Zebra](/zcash-tech/zebra-full-node)。

## 常见误区

**认为服务器可以读取你的交易**。它不能。你的密钥留在设备上，完全屏蔽交易中的金额和备注仍保持加密——即使对手已经攻破服务器也是如此。

**将“屏蔽”理解为“匿名连接”**。屏蔽交易保护区块链上发生的内容。你的 IP 地址和活动时间是另一个层面，而这正是服务器能看到的层面。

**认为 Tor 会消除一切痕迹**。Tor 会向服务器隐藏你的 IP，但不会改变服务器从你发出的请求中获知的内容，并且会增加同步延迟。

**信任 wiki 页面上的服务器列表**。运营者会来去更替。在将钱包指向任何服务前，请查看 [hosh.zec.rocks](https://hosh.zec.rocks/zec)，确认实际运行的服务。

## 总结

轻钱包让你无需占用磁盘空间即可使用屏蔽资金池，这是很好的取舍。只要清楚自己在交换什么即可。服务器无法拿走你的资金或读取你的屏蔽金额，但它很容易看到你的 IP 地址以及交易时间。通过 Tor 路由，有意识地选择运营者，或自行运行服务器。
