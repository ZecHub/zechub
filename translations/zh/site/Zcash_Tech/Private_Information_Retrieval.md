# 私有信息检索 [Private information retrieval]

## TL;DR

- 私有信息检索，或 PIR，让设备能够从服务器的数据库中获取一项内容，而服务器无法得知请求的是哪一项
- Zcash需要它，因为隐私钱包 [private wallet] 无法向服务器询问哪些交易 [transactions] 属于自己，否则会暴露自身
- 如今，钱包下载和扫描的数据远超实际所需，这是同步缓慢的主要原因
- PIR 可让钱包以保护隐私的方式仅获取自己的数据，在保持隐私 [privacy] 完整的同时消除这一瓶颈
- 对于 Zcash 而言，这是一个活跃的研究领域，理论上功能强大，并且正被实用化以服务真实钱包

<br/>

## 适合哪些读者

- 曾想知道隐私钱包如何在不泄露哪些币属于自己的情况下找到它们的任何人

## PIR 为 Zcash 解决的问题

Zcash 隐藏了一笔交易的接收者身份。这种隐私带来了一个棘手的问题：如果网络无法看到哪些交易属于你，你自己的钱包又如何找到它们？

如今的答案很直接。钱包不能向服务器询问哪些交易属于自己，因为这个问题会揭示 Zcash 正试图隐藏的内容。因此，钱包会下载大量数据，并在本地逐项测试哪些内容属于自己。这种方法有效，也能保护隐私，但速度慢且负担重。这种扫描是钱包同步感觉迟缓的主要原因之一。

理想的方式是，钱包能够向服务器准确请求自己的数据并接收它，而服务器始终无法得知请求了什么。这正是私有信息检索所提供的能力。

<br/>

## 什么是 PIR

私有信息检索是一种密码学方法，使客户端能够读取服务器数据库中的一个条目，而不向服务器透露其读取的是哪个条目。

想象一座图书馆：你可以拿到自己想要的那本书，但图书管理员永远不知道交给你的是哪本书。你获得了所需内容，而你的兴趣仍然私密。PIR 就是这一理念的数学版本，适用于任何数据库。

这个概念已在密码学领域研究数十年。它最早于 1995 年由 Chor、Goldreich、Kushilevitz 和 Sudan 提出，他们描述了多服务器方法；随后 Kushilevitz 和 Ostrovsky 于 1997 年提出了首个单服务器版本。这并非 Zcash 发明的技术，而是一个成熟领域，Zcash 现在正将其应用于一个真实且顽固的问题。

<br/>

## PIR 如何运作：初步介绍

构建 PIR 有两种主要方式，而两者的差异很重要。

第一种使用多个服务器。客户端向多个服务器分别发送查询的一部分，并在本地合并它们的回答。任何单个服务器都无法看到足够的信息来得知请求内容。这种方式效率很高，但依赖服务器之间不相互串通，而这在现实世界中很难保证。

第二种使用单个服务器，并以巧妙的密码学代替多方参与。这里客户端依赖一种名为同态加密 [homomorphic encryption] 的特殊工具，而这正是对实际部署最有用的方向，因为它不需要多个彼此不串通的服务器。

<br/>

## 机制：同态加密

同态加密是一类加密 [encryption] 技术，使服务器能够在数据保持加密状态时对其进行计算。服务器无需看到底层数值，也能生成正确的加密答案。

以下是以这种方式构建的单服务器 PIR 的原理。客户端想从列表中获取第 3 项。它构建一个查询，实际上是在第 3 个位置放置加密的“是”，并在其他每个位置放置加密的“否”。对服务器而言，这个查询只是一段毫无意义的噪声，它无法判断哪个位置包含“是”。

随后，服务器利用同态加密的特殊性质，将数据库与这个加密查询结合：把每个存储项乘以对应的加密“是”或“否”，再将结果相加。最终得到的是一个单独的加密包，其中恰好包含客户端想要的项目，而且没有任何信息能揭示它是哪一项。客户端解密该包并读取自己的项目。服务器回答了问题，却从未知道问题本身。

一种更强的版本称为对称 PIR，它增加了第二项保证：客户端只能获知自己请求的项目，而无法获知数据库中任何其他条目。这同时保护了数据库和客户端。

<br/>

## 面向技术读者的深入介绍

现代单服务器方案建立在格密码学之上，最常见的是“带误差学习”假设。客户端的查询是一个密文向量，即目标索引处为 1、其他位置为 0 的加密形式；这种加密具有加法同态性，因此服务器可以在不解密的情况下，对密文进行相加，并将其与明文数据库条目相乘。

服务器将数据库视为一个矩阵，应用加密的选择向量，并返回一个可解密为目标行的单一密文。由于查询与随机噪声不可区分，服务器无法获得有关索引的信息。

历史上的障碍始终是成本。朴素地说，服务器必须针对每次查询访问数据库中的每一个条目，这会带来高昂的计算成本；而密文很大，也会带来高昂的带宽成本。近期研究通过预处理来解决这一问题：SimplePIR 和 FrodoPIR 等方案让服务器预先准备数据库，并向每个客户端提供一个小型提示，将大量工作转移到离线阶段，使实时查询变得快速。一个有益的额外优势是，基于格的构造也被认为能够抵抗量子攻击，这与 Zcash 更广泛地转向后量子隐私的方向一致。

<br/>

## Zcash 中的 PIR

PIR 是使 Zcash 在大规模条件下同时实现隐私和快速性能的工作的一部分。

前文所述的钱包扫描瓶颈正是目标。Valar Group 的工作正在开发私有信息检索技术，让钱包能够从服务器获取自己的数据，而服务器无法得知请求了哪些条目。一个具体应用是以保护隐私的方式检查 nullifier。nullifier 是在一个 note 被花费时发布的唯一标记，用于防止同一笔资金被重复花费。钱包通常需要检查某个 nullifier 是否已经出现，换句话说，某个 note 是否仍未被花费；而如今通过服务器进行这项检查，可能会泄露正在查询哪个 note。私有信息检索让钱包能够提出这个问题，而不暴露它所关心的是哪个 nullifier。这与其他扩容工作并行，包括 Project Tachyon 以及新的节点软件，旨在消除如今限制隐私钱包性能的瓶颈。

必须诚实看待其所处阶段。这是活跃的研究和工程工作，而非已完成并发布的功能。概念已经成熟，方向也已明确，但要让 PIR 对普通设备上的日常钱包足够高效，正是当前正在解决的难题。

<br/>

## 常见误解

- PIR 隐藏你请求的是哪一项，但不一定隐藏你曾联系服务器这一事实；网络层元数据是另一个问题
- PIR 并非 Zcash 独有；它是一种通用密码学工具，Zcash 正将其用于保护钱包隐私
- PIR 带来的更快同步是一个正在推进的目标，而非钱包中已具备的功能
- 下载全部数据并在本地扫描这一当前方法能够保护隐私，但速度较慢；PIR 旨在保持隐私的同时消除这种缓慢
