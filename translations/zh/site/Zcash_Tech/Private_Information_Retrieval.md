# 私密信息检索

## 简介

- 私密信息检索（Private information retrieval，简称 PIR）让设备从服务器数据库中获取一条数据，而服务器无法得知请求的是哪一条
- Zcash 需要这项技术，因为私密钱包无法在不暴露自己的情况下，询问服务器哪些交易属于自己
- 如今，钱包下载并扫描的数据远超所需，这是同步缓慢的主要原因之一
- PIR 可以让钱包私密地只获取自己的数据，消除这一瓶颈，同时保留隐私
- 这是 Zcash 的一个活跃研究领域，理论上功能强大，目前正逐步走向实用，可用于真实钱包
- 现已有可用的现场演示：[ZecBlock Private](https://private.zecblock.com) 是第一个完整基于 PIR 的 Zcash 区块浏览器（支持交易、区块和地址查询）

## 适用对象

- 想知道私密钱包如何在不泄露哪些币属于自己的情况下找到它们的人
- 经常看到 PIR 与 Zcash 扩容工作一同被提及的新人
- 想先了解概念，再了解背后密码学原理的读者
- 对可用的 PIR 区块浏览器感兴趣的人

## PIR 为 Zcash 解决的问题

Zcash 隐藏了交易的收款对象。这种隐私带来一个棘手的问题：如果网络看不到哪些交易属于你，你的钱包要如何找到它们？

如今的答案很直接：钱包无法询问服务器哪些交易属于自己，因为这样的问题会暴露 Zcash 试图隐藏的信息。因此，钱包会下载大量数据，并在本地逐条检查哪些数据属于自己。这种做法可行，也能保护隐私，但速度慢、开销大。这种扫描是钱包同步感觉迟缓的主要原因之一。

理想情况下，钱包可以向服务器请求并接收恰好属于自己的数据，同时服务器始终无法得知请求的内容。私密信息检索正是为此而生。

## 什么是 PIR

私密信息检索是一种密码学方法，让客户端从服务器数据库中读取一条记录，同时不向服务器泄露读取的是哪一条。

想象一座图书馆：你可以拿到自己想要的那本书，而图书管理员始终不知道递给了你哪本书。你拿到了想要的东西，同时保留了自己的兴趣隐私。PIR 就是这个想法在数学上的实现，可应用于任何数据库。

这个概念在密码学领域已经研究了数十年。它于 1995 年由 Chor、Goldreich、Kushilevitz 和 Sudan 首次提出，他们描述了多服务器方案；1997 年，Kushilevitz 和 Ostrovsky 又提出了第一个单服务器版本。PIR 并非 Zcash 发明的，它是一个成熟的领域，而 Zcash 正在将其用于解决一个现实且棘手的问题。

## PIR 的基本原理

构建 PIR 大致有两种方式，它们的区别很重要。

第一种使用多个服务器。客户端向多个服务器分别发送查询的一部分，然后在本地合并它们的答复。任何单个服务器都无法获得足够信息来推断请求内容。这种方式效率高，但依赖服务器之间不串通，而这在现实中很难保证。

第二种使用单个服务器，并以巧妙的密码学取代多个参与方。在这种方案中，客户端依赖一种称为同态加密的特殊工具。这也是最适合实际部署的方向，因为它不需要多个互不串通的服务器。

## 核心机制：同态加密

同态加密是一种加密方式，服务器可以在数据保持加密的情况下对其进行计算。服务器无需查看底层数值，就能生成正确的加密答复。

下面是以这种方式构建单服务器 PIR 的基本思路。客户端想从列表中获取第 3 项。它构造一个查询，实质上是对第 3 个位置加密表示“是”，对其他每个位置加密表示“否”。对服务器来说，这个查询只是一团毫无意义的噪声，它无法判断哪个位置对应“是”。

随后，服务器利用同态加密的特殊性质，将数据库与这个加密查询结合起来：用匹配的加密“是”或“否”乘以每条已存储数据，再把结果相加。最终得到的是一个加密数据包，其中恰好包含客户端想要的那一项，而且没有任何信息泄露它是哪一项。客户端解密该数据包并读取其中的内容。服务器回答了问题，却始终不知道问题是什么。

一种称为对称 PIR 的增强版本还提供第二重保证：客户端只能获知所请求的数据，无法了解数据库中的其他任何记录。这既保护了客户端，也保护了数据库。

## 技术读者深入了解

现代单服务器方案建立在格密码学之上，最常见的是学习带误差问题假设。客户端的查询是一个密文向量：目标索引处加密一个 1，其他位置加密 0。由于加密具有加法同态性，服务器可以对密文求和，也可以用明文数据库记录乘以密文，而无需解密。

服务器将数据库视为矩阵，应用加密的选择向量，并返回一个解密后对应所需行的单一密文。由于该查询与随机噪声无法区分，服务器无法获得有关索引的信息。

长期以来，主要障碍一直是成本。对于每次查询，服务器都必须接触数据库中的每一条记录，这会带来高昂的计算开销；密文也很大，因此带宽开销也很高。近期研究通过预处理来解决这些问题。例如，SimplePIR 和 FrodoPIR 等方案让服务器提前准备数据库，并向每个客户端提供一个简短提示，把大量工作转移到离线阶段，从而加快实时查询速度。一个有用的附带优势是，基于格的构造也被认为能够抵御量子攻击，这与 Zcash 向后量子隐私迈进的大方向一致。

## PIR 在 Zcash 中的应用

PIR 是让 Zcash 在大规模应用中兼具隐私性和速度的一项工作。

前文提到的钱包扫描瓶颈正是目标所在。Valar Group 正在开发私密信息检索技术，让钱包可以从服务器获取自己的数据，同时不让服务器知道请求了哪些记录。其中一个具体应用是私密地检查 nullifier。nullifier 是 note 被花费时发布的唯一标记，可以防止同一笔资金被花费两次。钱包通常需要检查某个 nullifier 是否已经出现，也就是检查某个 note 是否仍未花费。如今通过服务器进行这项检查，可能会泄露正在查询哪个 note。私密信息检索让钱包可以提出这个问题，同时不透露自己关注的是哪个 nullifier。这项工作与其他扩容工作并行开展，包括 Project Tachyon 和新的节点软件，旨在消除当今限制私密钱包性能的瓶颈。

必须如实说明当前进展：这仍是活跃的研究和工程工作，并非已经完成并发布的功能。这个概念已经成熟，发展方向也已明确，但让 PIR 足够高效，以便普通设备上的日常钱包使用，正是目前努力攻克的难点。

## 现场示例：ZecBlock Private

2026 年 11 月，ZecBlock 发布了 **ZecBlock Private**（private.zecblock.com），这是其区块浏览器的一个版本，使用私密信息检索查询交易、区块和地址。

这是第一个基于 PIR 构建的完整 Zcash 区块浏览器（支持交易、区块和地址查询）。此前的 PIR 区块浏览器演示仅支持更有限的查询，例如地址余额。

### 私密查询的工作方式

- 查询内容（交易 ID、区块高度/哈希或地址）会在发送之前完全在浏览器中加密。
- 服务器会处理整个已发布数据集，但无法得知请求的是哪条记录。
- 服务器会返回单个加密响应，只有浏览器可以解密。
- 搜索存在的内容与搜索不存在的内容无法区分（请求的大小和形式相同）。

每次搜索后，网站都会显示所发送内容的简短摘要，便于检查其隐私属性。

### 验证步骤

每次数据发布都会进行签名。浏览器会在显示结果之前验证每个结果的签名，因此恶意服务器或有缺陷的服务器都无法替换为其他数据。

### 数据新鲜度

新区块每隔几秒就会发布一次。私密浏览器上的数据通常比常规 ZecBlock 区块浏览器的数据滞后约 20 秒。

### 带宽成本

PIR 的开销高于普通查询，因为服务器必须处理整个数据集：

- 交易查询：上传约 1.2 MB
- 地址查询：上传约 0.4 MB

这就是服务器对查询内容一无所知所付出的实际成本。

### 客户端实现

浏览器客户端是一个 Rust → WebAssembly 封装层（目前位于 ZecBlock 仓库中的 `prototype/pir-browser` 下）。它基于 Valar Group 的开源 PIR 库构建。这个封装层尚未作为独立 npm 软件包发布，但已有发布计划。

### 与钱包 PIR 的区别

ZecBlock Private 展示了如何对**公开**链上数据使用 PIR（查询已知交易、区块或地址，同时不透露查询的是哪一个）。它**并未**解决更难的钱包问题：私密地发现哪些 note 属于某个 viewing key，或私密地检查哪些 nullifier 对应尚未花费的 note。这些仍是活跃的研究领域。

## 常见误解

- PIR 会隐藏你请求了哪一项，但不一定会隐藏你联系过服务器；网络层元数据是另一个需要考虑的问题
- PIR 并非 Zcash 独有，它是一种通用密码学工具，Zcash 正在将其用于钱包隐私
- 通过 PIR 加快同步仍是正在推进的目标，并非钱包中已有的功能
- 当前做法是下载所有数据并在本地扫描，这种方式保护隐私但速度慢；PIR 旨在保留隐私，同时消除速度瓶颈
