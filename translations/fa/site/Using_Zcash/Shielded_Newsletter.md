# خبرنامه محافظت‌شده

> یک note با فرمت markdown را با استفاده از Zallet به‌صورت یادداشت‌های Zcash برای فهرستی از آدرس‌های محافظت‌شده ارسال کنید. فهرست گیرندگان و note از آدرس‌های شفاف دور می‌مانند.

خبرنامه محافظت‌شده مجموعه‌ای از تراکنش‌های محافظت‌شده است. هر خروجی مبلغ بسیار کمی به Unified Address یک گیرنده پرداخت می‌کند و بخش بعدی note را در فیلد یادداشت حمل می‌کند. Zallet این تراکنش‌ها را می‌سازد و ارسال می‌کند. Zebra و Zaino فقط داده‌های زنجیره را فراهم می‌کنند.

اسکریپت‌ها در [`site/tutorials/shieldedNewsletter`](https://github.com/ZecHub/zechub/tree/main/site/tutorials/shieldedNewsletter) قرار دارند. آن‌ها برای یک نسخه اولیه از Zallet نوشته شده‌اند و اجرای بدون تغییر آن‌ها روی نسخه فعلی ایمن نیست. این صفحه روال به‌روزشده است. بررسی‌شده در برابر Zallet `v0.1.0-beta.3` و کتاب Zallet تا تاریخ 7 اکتبر 2026.

## آنچه نیاز دارید

- Zebra به‌طور کامل همگام‌سازی‌شده، با RPC متصل به localhost.
- Zaino همگام‌سازی‌شده با آن نود Zebra.
- Zallet نسخه `v0.1.0-beta.3` یا جدیدتر، نسخه ساخته‌شده با کیف‌پول، با RPC متصل به localhost. کتاب، `z_sendmany` را پیاده‌سازی‌شده فهرست می‌کند. کارمزد عددی پذیرفته نمی‌شود: اگر `fee` را ارسال کنید، باید `null` باشد، زیرا Zallet همیشه از کارمزد ZIP 317 استفاده می‌کند.
- یک حساب دارای موجودی که Unified Address آن بتواند وجوه محافظت‌شده را خرج کند.
- Unified Address های گیرندگان. یادداشت روی یک آدرس شفاف خطا محسوب می‌شود.

آدرس دارای موجودی یا کوکی را در ویکی یا در اسکریپتی که commit می‌شود قرار ندهید. `txBuilderFromFile.sh` فعلی یک Unified Address را به‌صورت hardcode در خود دارد. آن را به‌صورت محلی جایگزین کنید و commit نکنید.

## پیکربندی Zallet

با Zallet که اجرا می‌کنید یک فایل پیکربندی بسازید، سپس آن را به Zebra و Zaino متصل کنید. نمونه موجود در آموزش قدیمی از `as_of_version = "0.0.0"` و یک مسیر home شخصی استفاده می‌کند. با آن فایل مانند یک نسخه لحظه‌ای رفتار کنید، نه یک الگو.

```bash
zallet init
zallet -c ~/.zallet/zallet.toml start
zallet -c ~/.zallet/zallet.toml rpc help
```

`rpc help` باید شامل `z_sendmany`، `z_getoperationstatus` و `z_getoperationresult` باشد. RPC را فقط به `127.0.0.1` متصل کنید.

## فهرست گیرندگان

در هر خط یک Unified Address، بدون علامت نقل‌قول و بدون خط خالی. اسکریپت `daoAddresses.md` را می‌خواند. readme قدیمی `daoAddress.md` را ذکر می‌کند. آن فایل در مخزن وجود ندارد و نام‌ها با هم مطابقت ندارند.

```text
u1...
u1...
```

## ارسال یک یادداشت

`z_sendmany` ناهمگام است. یک شناسه عملیات برمی‌گرداند. `z_getoperationstatus` را آن‌قدر بررسی کنید تا وضعیت `success` یا خطا شود. یک توقف ثابت 5 ثانیه‌ای، که همان کاری است که اسکریپت انجام می‌دهد، وقتی ساخت تراکنش طولانی‌تر شود نتیجه را از دست می‌دهد. `z_getoperationresult` عملیات را مصرف می‌کند، پس تا زمانی که وضعیت نهایی نشده آن را فراخوانی نکنید.

کارمزد حذف شده است. Zallet کارمزد ZIP 317 را محاسبه می‌کند. عددی ارسال نکنید.

```bash
MEMO_HEX=$(printf '%s' "$NOTE" | xxd -p -c 9999)
zallet -c ~/.zallet/zallet.toml rpc z_sendmany \
  "$FROM_UA" \
  "[{\"address\":\"$TO_UA\",\"amount\":0.0001,\"memo\":\"$MEMO_HEX\"}]"
```

فیلد یادداشت به‌صورت hex خام است و حداکثر 512 بایت. `ascii2hex` فقط ASCII را رمزگذاری می‌کند. Note ای که هر نویسه غیر ASCII داشته باشد با شکست مواجه می‌شود. `xxd` یا `python3 -c 'import sys; sys.stdout.write(sys.stdin.buffer.read().hex())'` از UTF-8 پشتیبانی می‌کند.

سیاست حریم خصوصی به‌طور پیش‌فرض `FullPrivacy` است. این پیش‌فرض درست برای یک گیرنده محافظت‌شده است. `AllowFullyTransparent` را ارسال نکنید.

## نقص‌های اسکریپت

این موارد تا تاریخ 8 اکتبر 2026 در کد وجود دارند. تا زمانی که برطرف نشده‌اند `shieldNewsletter.sh` را اجرا نکنید.

- `[[ bytesInFile -lt 512 ]]` فاقد `$` است. شاخه تک‌یادداشتی هرگز اجرا نمی‌شود.
- حلقه تقسیم‌بندی، hex را ذخیره می‌کند، سپس `hex2ascii` آن را رمزگشایی می‌کند و بعد `txBuilderFromFile.sh` دوباره آن را رمزگذاری می‌کند. آخرین بخش ارسال نمی‌شود مگر اینکه خطی بعدی از 512 فراتر رود. یک خط طولانی تقسیم نمی‌شود. به‌طور کامل ارسال می‌شود و می‌تواند از یادداشت 512 بایتی فراتر رود.
- `txBuilderFromFile.sh`، `./zallet rpc` را بدون مسیر پیکربندی فراخوانی می‌کند و انتظار دارد فایل اجرایی در دایرکتوری جاری باشد. از `zallet -c <config> rpc` استفاده کنید.
- `toCurl.sh` با یک کوکی روی پورت 8232 با Zebra ارتباط برقرار می‌کند و `getinfo` و `sendmany` را فراخوانی می‌کند. Zallet، `sendmany` را ارائه نمی‌دهد. حلقه انتظار برای استخراج نیز از `[[ chainHeight -gt temp ]]` بدون `$` استفاده می‌کند، بنابراین منتظر نمی‌ماند.
- `z_gettotalbalance 0 true` به‌صورت آرگومان‌های موقعیتی اضافی ارسال می‌شود. پیش از استفاده از آن فراخوانی، `rpc help z_gettotalbalance` را روی فایل اجرایی‌ای که اجرا می‌کنید بررسی کنید.
- هر بخش `0.0001` ZEC برای هر گیرنده ارسال می‌کند. کارمزد ZIP 317 به آن اضافه می‌شود. یک note طولانی برای آدرس‌های زیاد، بیش از مبالغ ناچیز هزینه دارد.

## پس از رفع نقص

یک اجراکننده اصلاح‌شده باید:

1. Note را به‌صورت بایت بخواند و آن را بر اساس مرزهای 512 بایتی تقسیم کند، نه بر اساس خطوط.
2. هر بخش را فقط یک بار به hex رمزگذاری کند.
3. `zallet -c <config> rpc z_sendmany` را با UA دارای موجودی، آرایه گیرندگان و بدون آرگومان کارمزد فراخوانی کند.
4. `z_getoperationstatus` را برای آن شناسه عملیات بررسی کند.
5. Txid را فقط پس از `success` ثبت کند.
