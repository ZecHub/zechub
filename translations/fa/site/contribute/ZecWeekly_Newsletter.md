# خبرنامه ZecWeekly

ZecWeekly یک خبرنامه است که هر یکشنبه صبح منتشر می‌شود. این خبرنامه همه اخبار هفته در اکوسیستم Zcash را در بر می‌گیرد. اخبار هر هفته توسط اعضای کامیونیتی گردآوری می‌شود و همه لینک‌های مرتبط به خبرنامه افزوده می‌شوند. لطفاً از [اینجا](https://zechub.substack.com/) در خبرنامه مشترک شوید.

## مشارکت

مشارکت در خبرنامه زمانی بهترین نتیجه را دارد که یک مشارکت‌کننده نسخه هفته درست را آماده کند، رشته فعلی bounty یا هماهنگی را دنبال کند و پس از آماده شدن لینک‌های هفته، pull request را ارسال کند. لطفاً پیش از آنکه ZecHub تاریخ یک نسخه آینده را اعلام یا تأیید کند، آن نسخه را ارسال نکنید. Pull requestهای زودهنگام اغلب به‌روزرسانی‌های پایان هفته را از دست می‌دهند، با گردآورنده تعیین‌شده تداخل پیدا می‌کنند یا از مهلت اشتباه استفاده می‌کنند.

### 1. نسخه فعلی را تأیید کنید

پیش از شروع نوشتن:

- [ZEC Bounties](https://bounties.zechub.wiki/) را برای وظیفه فعلی خبرنامه بررسی کنید.
- منتظر بمانید تا این وظیفه به شما واگذار شود.
- نسخه‌های خبرنامه در رده XS از [سیاست مبالغ bounty](https://bounties.zechub.wiki/docs/bounty-amounts) قرار می‌گیرند. مبلغ واقعی همان رقم ZEC در bounty فعال است، نه هیچ عنوان قدیمی‌تری در راهنماهای مشارکت.

### 2. مخزن را fork کنید

اگر با GitHub تازه آشنا شده‌اید، از این روند کاری استفاده کنید:

1. [مخزن ZecHub](https://github.com/ZecHub/zechub) را باز کنید.
2. روی **Fork** کلیک کنید و یک fork زیر حساب GitHub خود بسازید.
3. در fork خود، یک branch جدید برای این نسخه بسازید. یک نام روشن برای branch مفید است، مانند `digest-may-30-2026`.
4. مطمئن شوید که pull request شما `ZecHub/zechub` را به‌عنوان مخزن پایه و `main` را به‌عنوان branch پایه هدف قرار می‌دهد.

اگر از خط فرمان استفاده می‌کنید، همین روند کاری به این شکل است:

```bash
git clone https://github.com/YOUR-USERNAME/zechub.git
cd zechub
git checkout -b digest-month-day-year
```

`YOUR-USERNAME` را با نام کاربری GitHub خود جایگزین کنید. URL بالا یک نمونه جایگزین است و به همین شکل کار نخواهد کرد.

### 3. فایل خبرنامه را بسازید

از [قالب خبرنامه](https://github.com/ZecHub/zechub/blob/main/newsletter/newslettertemplate.md) به‌عنوان نقطه شروع استفاده کنید. نسخه‌های خبرنامه در پوشه [`newsletter`](https://github.com/ZecHub/zechub/tree/main/newsletter) قرار می‌گیرند.

هنگام ساختن فایل:

- قالب نام فایل را مطابق با آنچه issue خواسته یا نسخه‌های پذیرفته‌شده اخیر به کار برده‌اند، انتخاب کنید.
- ترتیب بخش‌ها را مانند قالب حفظ کنید، مگر اینکه وظیفه قالب دیگری بخواهد.
- فقط لینک‌های مربوط به همان هفته را اضافه کنید.
- برای هر لینک یک توضیح کوتاه و روشن بنویسید تا خوانندگان بفهمند چرا اهمیت دارد.
- در صورت نیاز، منابع غیرانگلیسی را به انگلیسی ترجمه یا خلاصه کنید.
- پیش از باز کردن pull request، همه لینک‌ها را بررسی کنید.

### 4. لینک‌ها را در زمان مناسب جمع‌آوری کنید

ZecWeekly معمولاً فعالیت‌های اکوسیستم Zcash در هفته جاری را پوشش می‌دهد و نزدیک به پایان هفته منتشر می‌شود. مطمئن‌ترین زمان‌بندی به این صورت است:

- پس از انتشار issue یا وظیفه خبرنامه فعلی، جمع‌آوری لینک‌ها را شروع کنید.
- تا زمانی که هفته هنوز ادامه دارد، یک پیش‌نویس نگه دارید.
- Pull request را نزدیک به تاریخ ارسال درخواستی و پس از بررسی به‌روزرسانی‌های پایان هفته ارسال کنید.
- خبرنامه هفته‌های آینده را پیش از آنکه وظیفه آن تاریخ ایجاد شود یا پیش از آنکه ZecHub تأیید کند که شما باید آن را آماده کنید، ارسال نکنید.

اگر یک issue می‌گوید تا تاریخ مشخصی ارسال کنید، از همان تاریخ پیروی کنید. اگر میان این صفحه و یک issue فعلی تناقضی وجود دارد، از issue فعلی پیروی کنید.

### 5. Pull request را باز کنید

وقتی فایل خبرنامه شما آماده شد:

1. تغییرات خود را در fork خود commit کنید.
2. یک pull request به `ZecHub/zechub` روی branch `main` باز کنید.
3. از عنوانی متناسب با نسخه استفاده کنید، مانند `Zcash Ecosystem Digest | May 30th`.
4. Issue را در متن pull request لینک کنید تا بازبین‌ها بتوانند کار را به وظیفه مربوط کنند.

نمونه متن pull request:

```md
Closes #ISSUE_NUMBER

Summary:
- Adds the Zcash Ecosystem Digest for Month Day.
- Uses the newsletter template and the current issue deadline.
- Checks links and descriptions for the requested week.
```

پس از باز شدن pull request، نظرات بازبینی را دنبال کنید. اگر ZecHub درخواست ویرایش کرد، به‌جای باز کردن pull request دوم برای همان نسخه، همان branch را به‌روزرسانی کنید.

### نمونه‌های واقعی

از این pull requestهای ادغام‌شده خبرنامه به‌عنوان نمونه‌هایی از ارسال‌های پذیرفته‌شده استفاده کنید:

- [خلاصه اکوسیستم Zcash | 14 فوریه](https://github.com/ZecHub/zechub/pull/1474)

هنگام مقایسه کار خود با یک نمونه، به محل فایل، قالب عنوان، ترتیب بخش‌ها، توضیحات لینک‌ها و اینکه آیا pull request به وظیفه درست مرتبط است، توجه کنید.

### اشتباهات رایجی که باید از آن‌ها پرهیز کنید

- باز کردن pull request پیش از تأیید تاریخ نسخه یا وظیفه.
- کار روی issueای که از قبل یک pull request لینک‌شده دارد.
- ارسال pull request به fork خودتان به‌جای `ZecHub/zechub`.
- استفاده از نام فایل اشتباه یا قرار دادن فایل بیرون از پوشه `newsletter`.
- کپی کردن یک نسخه قدیمی بدون به‌روزرسانی همه تاریخ‌ها، لینک‌ها و توضیحات.
- افزودن لینک‌هایی از هفته اشتباه.
- باقی گذاشتن لینک‌های خراب، لینک‌های تکراری یا متن‌های جایگزین قالب.
- باز کردن pull request جدید پس از نظرات بازبینی به‌جای به‌روزرسانی branch اصلی.

### چک‌لیست نهایی

پیش از درخواست بازبینی، تأیید کنید که:

- تاریخ issue یا وظیفه با فایل خبرنامه شما مطابقت دارد.
- هیچ pull request باز دیگری از قبل همان issue یا نسخه را پوشش نمی‌دهد.
- فایل در پوشه `newsletter` قرار دارد.
- بخش‌های قالب کامل هستند.
- همه لینک‌ها کار می‌کنند و توضیح مفیدی دارند.
- متن pull request به issue درست لینک شده است.
- در صورت درخواست تغییرات از سوی بازبین‌ها، برای انجام ویرایش‌ها در دسترس هستید.
