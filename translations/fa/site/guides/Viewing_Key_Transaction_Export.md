# خروجی گرفتن از تاریخچهٔ تراکنش‌ها از یک Viewing Key

خروجی بیشتر کیف‌پول‌ها اطلاعات اندکی دارد. برای مثال، خروجی مالیاتی ZODL تاریخ‌ها، مبالغ و کارمزدهای سال تقویمی گذشته را به شما می‌دهد، اما هیچ شناسهٔ تراکنش، یادداشت یا آدرسی در آن نیست. این برای دفترداری، برای بررسی انتقال کیف‌پول، یا برای فهمیدن اینکه چه بر سر یک پرداخت آمده، کافی نیست.

برای دیدن تصویر کامل به عبارت بازیابی خود نیازی ندارید. یک کلید مشاهدهٔ کامل یکپارچه (UFVK، که با `uview1` آغاز می‌شود) می‌تواند همهٔ تراکنش‌های ورودی و خروجی یک حساب را ببیند، و دو ابزار می‌توانند آن را به فایلی تبدیل کنند که نزد خود نگه می‌دارید: سرور GraphQL Zkool و zingo-cli. این راهنما روش‌های مطرح‌شده در [این رشتهٔ انجمن](https://forum.zcashcommunity.com/t/exporting-transaction-history-to-json-csv-from-ufvk-seed/54662) را گردآوری کرده و آن‌ها را برای نسخه‌های فعلی به‌روز می‌کند.

در سپتامبر 2026 با Zkool 6.30.0 و zingo-cli از zingolib 6.0.0 آزمایش شده است.

## پیش از شروع

به دو چیز نیاز دارید:

1. **UFVK** مربوط به حساب. صفحهٔ [کلیدهای مشاهده](/zcash-tech/viewing-keys) توضیح می‌دهد که این کلید چه چیزهایی را آشکار می‌کند و چگونه می‌توانید از آن خروجی بگیرید.
2. **یک ارتفاع تولد**، یعنی بلوکی که اسکن از آن آغاز می‌شود. ارتفاعی را به کار ببرید که پیش از نخستین تراکنش شما باشد. اگر آن را بیش از حد بالا تنظیم کنید، تاریخچهٔ قدیمی‌تر بی‌صدا از دست می‌رود. اگر آن را بیش از حد پایین تنظیم کنید، فقط اسکن طولانی‌تر می‌شود. ارتفاع فعال‌سازی Sapling (419200) همیشه امن است، اما اسکن آن ممکن است ساعت‌ها طول بکشد.

## آن را خصوصی نگه دارید

کلید مشاهده نمی‌تواند وجوه را خرج کند، اما کل تاریخچهٔ شما را به هر کسی که آن را در اختیار داشته باشد نشان می‌دهد.

- آن را در هیچ وب‌سایت یا بلاک اکسپلورری وارد نکنید. آن را در نرم‌افزاری وارد کنید که خودتان اجرا می‌کنید.
- سروری که از آن همگام‌سازی می‌کنید، آدرس IP شما و تراکنش‌هایی را که به‌طور کامل دانلود می‌کنید می‌بیند. هر دو ابزار زیر هر یک از تراکنش‌های شما را با شناسه‌اش دریافت می‌کنند تا یادداشت‌ها و کارمزدها را بخوانند، و [ZIP 307](https://zips.z.cash/zip-0307) اشاره می‌کند که این کار به سرور می‌گوید کدام تراکنش‌ها متعلق به شماست. همگام‌سازی از نود Zebra خودتان با Zaino یا lightwalletd از این مشکل جلوگیری می‌کند. [آموزش Zingolib و Zaino](/guides/zingolib-and-zaino-tutorial) شما را گام‌به‌گام با یک راه‌اندازی آشنا می‌کند.
- zingo-cli 6 پرداخت‌ها را از طریق میکس‌نت Nym ارسال می‌کند، اما همگام‌سازی آن همچنان مستقیماً به سرور متصل می‌شود، بنابراین نکتهٔ بالا دربارهٔ آن نیز صدق می‌کند.
- به این ابزارها کلید مشاهده بدهید، هرگز عبارت بازیابی. سرور GraphQL Zkool به‌طور پیش‌فرض هیچ ورودی (login) ندارد، و API آن عبارت بازیابی هر حسابی را که از روی آن ساخته شده باشد برمی‌گرداند و می‌تواند وجوه را ارسال کند.
- سرور را روی دستگاه خودتان نگه دارید. فرمان Docker زیر فقط روی `127.0.0.1` گوش می‌دهد.
- هر دو ابزار کلید و تاریخچهٔ شما را بدون رمزنگاری ذخیره می‌کنند. وقتی کارتان تمام شد داده‌های کاری را حذف کنید و خروجی را در جایی رمزنگاری‌شده نگه دارید.

## گزینهٔ 1: GraphQL Zkool

`zkool_graphql` موتور کیف‌پول Zkool در قالب یک سرور مستقل است. این برنامه‌ای جدا از اپلیکیشن Zkool است. ساده‌ترین راه اجرای آن، ایمیج رسمی Docker (amd64 و arm64) است. یک فایل اجرایی Linux برای x86-64 نیز در [Zkoolصفحهٔ انتشارها](https://github.com/hhanh00/zkool2/releases) وجود دارد؛ این فایل به glibc نسخهٔ 2.38 یا جدیدتر نیاز دارد، بنابراین روی Ubuntu 24.04 کار می‌کند ولی روی Debian 12 نه.

### 1. سرور را راه‌اندازی کنید

```bash
docker run -d --name zkool-export \
  -p 127.0.0.1:8000:8000 \
  -v zkool-export:/data \
  hhanh00/zkool-graphql:6.30.0 \
  --db-path /data/zkool.db
```

این سرور از `https://zec.rocks` همگام‌سازی می‌کند، مگر اینکه `--lwd-url` را همراه با سرور خودتان اضافه کنید. در نخستین اجرا، پارامترهای Sapling (حدود 50 MB) را دانلود می‌کند. اگر این کار ناموفق باشد، `docker start zkool-export` دوباره تلاش می‌کند.

`http://127.0.0.1:8000/graphiql` را در مرورگر باز کنید. می‌توانید هر یک از گام‌های بعدی را آنجا وارد و اجرا کنید.

### 2. کلید را وارد کنید

```graphql
mutation {
  createAccount(newAccount: {
    name: "export"
    key: "uview1..."
    aindex: 0
    birth: 2500000
    useInternal: true
  })
}
```

این کار شناسهٔ حساب جدید را برمی‌گرداند که روی یک سرور تازه برابر با 1 است.

- همیشه `birth` را تنظیم کنید. بدون آن، Zkool از بلوک فعلی شروع می‌کند و چیزی پیدا نمی‌کند.
- `useInternal: true` باعث می‌شود Zkool آدرس‌های باقی‌ماندهٔ (change) شفاف را نیز بررسی کند. برای کلیدهای ZODL آن را روشن نگه دارید؛ این همان تنظیمی است که صفحهٔ [بازیابی وجوه](/using-zcash/recovering-funds) برای عبارت‌های بازیابی ZODL به کار می‌برد.

### 3. همگام‌سازی

```graphql
mutation { synchronizeAccount(idAccount: 1) }
```

این فرمان تا پایان همگام‌سازی اجرا می‌شود. `fast: true` را اضافه نکنید. این گزینه دانلود تراکنش‌های کامل را نادیده می‌گیرد، در حالی که یادداشت‌ها، کارمزدها و خروجی‌ها از همان‌جا به دست می‌آیند.

عددی که برمی‌گرداند ارتفاعی است که هدف‌گیری کرده بود، نه اثباتی بر اینکه به آن رسیده است. یک خطای شبکه می‌تواند همگام‌سازی را زودتر و بدون گزارش هیچ چیزی پایان دهد، پس بررسی کنید:

```graphql
{ currentHeight accounts { id name height } }
```

اگر `height` حساب از `currentHeight` عقب‌تر است، همگام‌سازی را دوباره اجرا کنید. از همان جایی که متوقف شده بود ادامه می‌دهد.

### 4. خروجی گرفتن

این را با نام `history.graphql` ذخیره کنید:

```graphql
{
  transactionsByAccount(idAccount: 1) {
    txid height time value fee
    notes { pool scope address value memo }
    spends { pool scope address value }
    outputs { pool vout address value memo }
  }
}
```

آرگومان `height` را حذف کنید، مگر اینکه واقعاً به آن نیاز داشته باشید. این آرگومان یک حداقل تعیین می‌کند، بنابراین `height: 3000000` در مثال انجمن همه چیز پیش از آن بلوک را حذف می‌کند.

آن را به‌صورت JSON دریافت کنید:

```bash
jq -n --rawfile q history.graphql '{query: $q}' |
  curl -s http://127.0.0.1:8000/graphql \
    -H 'content-type: application/json' --data-binary @- > history.json
```

هر تراکنش باید کارمزدی بیشتر از 0 نشان دهد، به‌جز پاداش‌های استخراج. اگر تراکنشی `"fee": "0"` و بدون یادداشت نشان داده شود، جزئیات آن دانلود نشده است. Zkool پس از اسکن، تراکنش‌های کامل را یکی‌یکی دریافت می‌کند و یک شکست بی‌صدا بقیه را متوقف می‌کند. برای فهرست کردن موارد آسیب‌دیده:

```bash
jq -r '.data.transactionsByAccount[] | select(.fee == "0") | .txid' history.json
```

اگر موردی نمایش داده شد، چند دقیقه بعد دوباره همگام‌سازی کنید و دوباره خروجی بگیرید.

سپس آن را به CSV تبدیل کنید، یک ردیف برای هر تراکنش:

```bash
jq -r '["txid","height","time_utc","net_zec","fee_zec","memos"],
  (.data.transactionsByAccount[] |
    [.txid, .height, .time, .value, .fee,
     ([.notes[].memo, .outputs[].memo] | map(select(. != null and . != "")) | unique | join(" | "))])
  | @csv' history.json > history.csv
```

### خواندن خروجی

| فیلد | معنا |
|---|---|
| `value` | تغییر خالص حساب بر حسب ZEC، با احتساب کارمزد. برای ارسال‌ها منفی است. |
| `fee` | کارمزد بر حسب ZEC. در پرداخت‌هایی که دریافت کرده‌اید، فرستنده آن را پرداخته و در `value` لحاظ نشده است. |
| `time` | زمان بلوک به وقت UTC، بدون نشانگر منطقهٔ زمانی |
| `notes` | آنچه حساب در این تراکنش دریافت کرده، شامل باقی‌مانده (change). یادداشت‌هایی که برای شما فرستاده شده‌اند اینجا هستند. ورودی‌های شفاف آدرس ندارند. |
| `spends` | note‌های خود حساب که این تراکنش آن‌ها را مصرف کرده است |
| `outputs` | آنچه تراکنش ارسال کرده است: همهٔ خروجی‌های شفاف، به‌علاوهٔ پرداخت‌های محافظت‌شده به آدرس‌های دیگر همراه با یادداشت‌هایشان |
| `pool` | 0 شفاف، 1 Sapling، 2 Orchard، 3 Ironwood |
| `scope` | 0 خارجی (یک پرداخت ورودی)، 1 داخلی (باقی‌مانده) |

اپلیکیشن Zkool نیز در منوی حساب گزینه‌های Export Transactions، Memos و Notes را دارد، اما این‌ها خروجی خام جدول‌ها هستند: مبالغ بر حسب zatoshi، مهرهای زمانی Unix، و یادداشت‌ها در فایلی جداگانه.

## گزینهٔ 2: zingo-cli

zingo-cli کیف‌پول خط فرمان Zingo است. هیچ فایل از پیش ساخته‌شده‌ای برای دانلود وجود ندارد، بنابراین باید آن را با Rust بسازید:

```bash
git clone --branch zingolib_v6.0.0 https://github.com/zingolabs/zingolib.git
cd zingolib
cargo build --release -p zingo-cli
cargo build --release --manifest-path zingo-netutils/Cargo.toml --features nym --bin nym-proxy
cp zingo-netutils/target/release/nym-proxy target/release/
```

حتی فقط برای همگام‌سازی هم به `nym-proxy` نیاز دارید. zingo-cli 6 بدون آن به هیچ سروری متصل نمی‌شود.

نخستین اجرا یک کیف‌پول فقط‌مشاهده می‌سازد، آن را همگام‌سازی می‌کند و تاریخچه را چاپ می‌کند:

```bash
./target/release/zingo-cli --data-dir "$HOME/zingo-export" \
  --viewkey "uview1..." --birthday 2500000 \
  --server https://zec.rocks:443 \
  --waitsync transactions > transactions.txt
```

- `--data-dir` باید یک مسیر مطلق باشد.
- `--viewkey` و `--birthday` فقط هنگام ساخت کیف‌پول اعمال می‌شوند. پس از آن، آن‌ها را حذف کنید.
- zingo-cli به‌طور پیش‌فرض به‌صورت آفلاین شروع می‌شود. `--server` سرور را انتخاب می‌کند و همچنین به‌منزلهٔ رضایت شما برای آنلاین شدن است.
- کلید در تاریخچهٔ shell شما ثبت می‌شود، پس پس از آن، تاریخچه را پاک کنید.

اجراهای بعدی:

```bash
Z="./target/release/zingo-cli --data-dir $HOME/zingo-export"
$Z --server https://zec.rocks:443 --waitsync transactions > transactions.txt
$Z --offline value_transfers > value_transfers.txt
$Z --offline messages > memos.json
```

`--offline` آنچه را که از قبل همگام‌سازی شده است، بدون استفاده از شبکه می‌خواند.

- `transactions` برای هر تراکنش یک ورودی می‌دهد: txid، زمان (UTC)، ارتفاع، نوع (`received`، `sent`، `shield` یا `send-to-self`)، مقدار، کارمزد و note‌های درگیر.
- `value_transfers` برای هر پرداخت یک ورودی می‌دهد، بنابراین ارسال به دو نفر دو ورودی است که هر کدام آدرس گیرنده و یادداشت‌ها را دارد.
- `messages` یادداشت‌ها را به‌صورت JSON فهرست می‌کند.

چند نکته دربارهٔ خروجی که باید بدانید:

- `transactions` و `value_transfers` متن ساده‌ای چاپ می‌کنند که کمی شبیه JSON است اما JSON نیست.
- مبالغ بر حسب zatoshi هستند (100,000,000 برابر با 1 ZEC) و همیشه مثبت‌اند. `kind` جهت را به شما می‌گوید. برای ارسال‌ها، `value` مبلغی است که به دیگران رفته، بدون کارمزد.
- وقتی تراکنشی وجوه شفافی را خرج می‌کند که متعلق به شما نبوده است، کارمزد به‌صورت «not available» نمایش داده می‌شود. فقط یادداشت‌های متنی نمایش داده می‌شوند.
- اگر همگام‌سازی ناموفق باشد، خطا به ترمینال می‌رود نه به فایل، و zingo-cli همچنان به‌طور عادی خارج می‌شود. پیش از اعتماد به `transactions.txt`، ترمینال را بررسی کنید.

[zingoHelper](https://github.com/dismad/zingoHelper) از dismad یک اسکریپت `exportToJSON.sh` دارد که `transactions` را به JSON تبدیل می‌کند. این اسکریپت پیش از zingo-cli 6 نوشته شده، برای testnet تنظیم شده است، برخی ورودی‌های خروجی Sapling و شفاف را به‌عنوان جای‌نگهدار علامت‌گذاری می‌کند و به ابزارهای GNU نیاز دارد، بنابراین روی macOS پیش‌فرض اجرا نمی‌شود. خروجی آن را نقطهٔ شروع در نظر بگیرید و جمع‌ها را بررسی کنید.

## آنچه کلید مشاهده نمی‌تواند به شما بگوید

- **قیمت‌ها.** هیچ‌یک از این دو ابزار قیمت ZEC را در زمان هر تراکنش ثبت نمی‌کند. ارزش‌های فیات را خودتان اضافه کنید.
- **تاریخچهٔ شفاف، اگر کلید آن را شامل نشود.** بخش شفاف یک UFVK طبق [ZIP 316](https://zips.z.cash/zip-0316) اختیاری است. با zingo-cli، `$Z --offline parse_viewkey uview1...` نشان می‌دهد که یک کلید کدام استخرها را پوشش می‌دهد.
- **چه کسی به شما پرداخت کرده است.** پرداخت‌های محافظت‌شده آدرس فرستنده را با خود ندارند. مگر اینکه فرستنده آن را در یادداشت قرار داده باشد، در هیچ جای دیگری وجود ندارد.
- **برخی جزئیات خروجی.** آدرس مقصد، مبلغ و یادداشت ارسال‌های محافظت‌شده با رمزگشایی به‌وسیلهٔ کلید بازیابی می‌شوند. یک کیف‌پول می‌تواند تراکنش را طوری بسازد که این کار ممکن نباشد، هرچند بیشتر کیف‌پول‌ها چنین نمی‌کنند.

## ابزارهای دیگر

| ابزار | آنچه به دست می‌آورید |
|---|---|
| ZODL | CSV مالیاتی با تاریخ‌ها، مبالغ، کارمزدها و یک برچسب. فقط سال تقویمی گذشته، تراکنش‌های محافظت‌سازی را نادیده می‌گیرد، بدون txid، یادداشت یا آدرس. |
| اپلیکیشن Zkool | خروجی‌های خام جدول‌ها از منوی حساب |
| [Zenith](https://code.vergara.tech/Vergara_Tech/zenith) | یک UFVK را با `importvk` وارد می‌کند. `listreceived` از طریق RPC note‌های دریافتی را همراه با txid و یادداشت برمی‌گرداند، اما بدون ارسال‌ها و بدون کارمزدها. |
| [Zallet](https://github.com/zcash/zallet) | `z_listtransactions` جزئیات زیادی دارد اما آزمایشی علامت‌گذاری شده است، و Zallet فقط کلیدهای مشاهدهٔ Sapling را وارد می‌کند، نه UFVK‌ها را |
| [zcash-devtool](https://github.com/zcash/zcash-devtool) | یک UFVK را با `wallet init-fvk` وارد می‌کند، سپس `wallet list-tx`. حالت CSV آن txid یا آدرس ندارد، و پروژه توصیه می‌کند از آن در محیط عملیاتی استفاده نکنید. |
