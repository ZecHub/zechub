# BTCPay Server با پشتیبانی از Zcash: راهنمای کامل نصب و یکپارچه‌سازی

BTCPay Server به کسب‌وکارهای آنلاین امکان می‌دهد پرداخت‌های رمزارزی را مستقیماً و بدون واسطه یا امانت‌دار دریافت کنند. این راهنما شما را گام‌به‌گام در کل فرایند راه‌اندازی BTCPay Server با پشتیبانی بومی از پرداخت‌های محافظت‌شده‌ی Zcash همراهی می‌کند.

> تمرکز این مستندات بر یکپارچه‌سازی Zcash با نمونه‌ی BTCPay Server شما است.  
> این راهنما هم **فول‌نود (Zebra)** و هم **پیکربندی‌های مبتنی بر lightwalletd** را پوشش می‌دهد.

## چرا از BTCPay Server همراه با Zcash استفاده کنیم

تجارت آنلاین روزبه‌روز بیشتر رمزارز را می‌پذیرد. رمزارز سریع و جهانی است و بدون بانک کار می‌کند. این هم به سود فروشندگان است و هم به سود مشتریان. اما نکته‌ی مهمی وجود دارد که بسیاری از آن غافل می‌شوند.

مشتری هنگام ثبت سفارش معمولاً اطلاعات شخصی خود را ارائه می‌دهد: نام، آدرس ارسال و شماره‌ی تلفن. اگر پرداخت از طریق یک بلاک‌چین عمومی انجام شود - مانند Bitcoin، Ethereum یا استیبل‌کوین‌ها روی Ethereum یا Tron - تراکنش برای همیشه قابل مشاهده و تحلیل خواهد بود.

هر کسی، حتی بدون اینکه بداند چه چیزی سفارش داده شده است، می‌تواند:

- ببیند چه زمانی و چه مبلغی پرداخت شده است  
- ردیابی کند که وجوه از کجا آمده و به کجا رفته است  
- در صورت وجود هرگونه نقطه‌ی ارتباط (برای مثال یک ایمیل افشاشده یا نام گیرنده‌ی مرسوله)، یک آدرس رمزارزی را به یک شخص واقعی پیوند دهد

این یعنی یک خرید ساده ممکن است کل سابقه‌ی مالی یک مشتری را آشکار کند.

این موضوع در جهت عکس نیز صادق است. اگر آدرس یک فروشنده حتی یک بار on-chain ظاهر شده باشد، او در معرض دید قرار می‌گیرد. رقبا و ناظران شخص ثالث می‌توانند حجم پرداخت‌ها، فعالیت تأمین‌کنندگان و ساختار جریان‌های تجاری را ردیابی کنند.

### ترکیب BTCPay Server و Zcash می‌تواند این مشکل را حل کند.


BTCPay Server یک سیستم رایگان و غیرمتمرکز برای دریافت پرداخت‌های رمزارزی است.  
این سیستم واسطه‌ی پرداخت نیست و هیچ وجهی را نگهداری نمی‌کند. همه‌ی پرداخت‌ها مستقیماً به کیف‌پول فروشنده واریز می‌شوند.  
این کیف‌پول می‌تواند یک کیف‌پول شخصی یا یک پیکربندی چندامضایی در یک سازمان باشد.

سرور وظایف هماهنگی را بر عهده دارد:

- برای هر سفارش یک آدرس منحصربه‌فرد ایجاد می‌کند  
- زمان دریافت پرداخت را پیگیری کرده و آن را به سفارش پیوند می‌دهد  
- رسید و اعلان صادر می‌کند  
- یک رابط پرداخت برای مشتری فراهم می‌کند  

همه‌چیز تحت کنترل صاحب فروشگاه اجرا می‌شود، بدون اتکا به سرویس‌های شخص ثالث.

Zcash رمزارزی است که بر پایه‌ی اثبات‌های دانش صفر ساخته شده است. این رمزارز از یک مدل تراکنش کاملاً خصوصی پشتیبانی می‌کند.  
هنگام استفاده از آدرس‌های محافظت‌شده (که از این پس به‌سادگی «آدرس‌ها» نامیده می‌شوند)، فرستنده، گیرنده و مبلغ تراکنش روی بلاک‌چین آشکار نمی‌شوند.

برای فروشگاه‌های آنلاین، این یعنی:

- خریدار می‌تواند بدون آشکار کردن سابقه‌ی مالی خود پرداخت را انجام دهد  
- فروشنده بدون افشای آدرس، حجم فروش یا ساختار تراکنش‌های خود پرداخت را دریافت می‌کند  
- هیچ ناظر خارجی نمی‌تواند پرداخت را به سفارش یا به اطلاعات مشتری پیوند دهد

### مثال عملی

کاربری سفارشی ثبت می‌کند و Bitcoin یا USDT را به‌عنوان روش پرداخت انتخاب می‌کند.  
وب‌سایت یک آدرس پرداخت ایجاد کرده و مبلغ را نمایش می‌دهد.  
پس از انجام پرداخت، این آدرس روی بلاک‌چین ثبت شده و عمومی می‌شود.  
مهاجم تنها کافی است یک سفارش را به این آدرس پیوند دهد تا به کل تاریخچه‌ی تراکنش‌های آن دید بلندمدت پیدا کند.

حال همین وضعیت را با Zcash تصور کنید.  
BTCPay Server یک آدرس محافظت‌شده ایجاد می‌کند. خریدار پرداخت را ارسال می‌کند.  
از دید بلاک‌چین، هیچ اتفاقی نمی‌افتد. هیچ داده‌ی عمومی‌ای برای تحلیل وجود ندارد.  
سرور تأییدیه را دریافت می‌کند، آن را به سفارش پیوند می‌دهد و فرایند را تکمیل می‌کند.

برای هر فرد بیرونی، به نظر می‌رسد هیچ اتفاقی رخ نداده است.  
همه‌ی منطق میان فروشگاه و مشتری باقی می‌ماند - همان‌طور که باید باشد.

این راهکار هیچ خللی در خودکارسازی یا سهولت استفاده ایجاد نمی‌کند.  
همه‌چیز درست مانند سایر رمزارزها کار می‌کند، فقط بدون خطر نشت داده‌ها.



## BTCPay Server چگونه کار می‌کند

BTCPay Server به‌عنوان یک پل پردازش پرداخت میان پلتفرم تجارت الکترونیک شما و بلاک‌چین عمل می‌کند. روند کار به این صورت است:

1. **مشتری سفارشی ثبت می‌کند** در وب‌سایت شما (برای مثال WooCommerce، Magento یا هر پلتفرمی که با BTCPay یکپارچه شده است).

2. **فروشگاه یک فاکتور پرداخت درخواست می‌کند** از BTCPay Server. سرور یک فاکتور منحصربه‌فرد ایجاد می‌کند که شامل موارد زیر است:
   - مبلغ سفارش
   - یک تایمر شمارش معکوس
   - یک آدرس یکپارچه‌ی Zcash (UA) - برای مثال `u1...` - که به‌طور پیش‌فرض شامل یک گیرنده‌ی Orchard (محافظت‌شده) است.

3. **مشتری صفحه‌ی پرداخت را می‌بیند** و ZEC را به آدرس ارائه‌شده ارسال می‌کند.

4. **BTCPay Server بلاک‌چین را پایش می‌کند** و پرداخت را با موارد زیر تطبیق می‌دهد:
   - مبلغ مورد انتظار
   - آدرس دریافت‌کننده
   - مُهر زمانی فاکتور

5. **پس از شناسایی و تأیید تراکنش**، BTCPay به فروشگاه اطلاع می‌دهد.

6. **مشتری تأییدیه‌ی پرداخت را دریافت می‌کند.** در صورت تمایل، سرور می‌تواند رسید را از طریق ایمیل ارسال کند.

کل این فرایند **به‌صورت خودکار** و بدون هیچ واسطه یا امانت‌داری انجام می‌شود.  
BTCPay Server **هیچ وجهی را نگهداری نمی‌کند** - این سرور صرفاً سیستم سفارش را به‌صورت امن و خصوصی به بلاک‌چین متصل می‌کند.
## وجوه کجا نگهداری می‌شوند؟ کلیدهای خصوصی در اختیار چه کسی است؟

BTCPay Server یک کیف‌پول **نیست** و **به کلیدهای خصوصی نیازی ندارد**.  
همه‌ی وجوه **مستقیماً** به کیف‌پول فروشنده واریز می‌شوند. امنیت با استفاده از **معماری مبتنی بر کلید مشاهده** تضمین می‌شود.

### نحوه‌ی کار

- **کیف‌پول از قبل ایجاد می‌شود.**  
  فروشنده از یک کیف‌پول Zcash استفاده می‌کند که از کلیدهای مشاهده پشتیبانی می‌کند - مانند [Zkool](https://github.com/hhanh00/zkool2/) یا [Zingo! Wallet](https://zingolabs.org/).  
  فهرست کامل در [ZecHub.wiki](https://zechub.wiki/wallets) در دسترس است.

- **BTCPay Server از طریق کلید مشاهده متصل می‌شود.**  
  کلید مشاهده یک **کلید فقط‌خواندنی** است: می‌تواند پرداخت‌های ورودی را شناسایی کرده و آدرس‌های دریافت جدید ایجاد کند،  
  اما نمی‌تواند وجوه را خرج کند. سرور هیچ عبارت بازیابی یا کلید خصوصی‌ای ذخیره نمی‌کند.

- **دسترسی به داده‌های بلاک‌چین از طریق یک سرور `lightwalletd` انجام می‌شود.**  
  شما می‌توانید از یک نود عمومی مانند `https://zec.rocks` استفاده کنید، یا برای استقلال کامل، پشته‌ی `Zebra + lightwalletd` خود را اجرا کنید.

- **هر سفارش یک آدرس منحصربه‌فرد دریافت می‌کند.**  
  کلیدهای مشاهده به سرور امکان می‌دهند برای هر فاکتور آدرس‌های محافظت‌شده‌ی جدید Zcash استخراج کند،  
  که این امر پیگیری امن پرداخت‌ها را ممکن کرده و از استفاده‌ی مجدد از آدرس جلوگیری می‌کند.

- **کنترل کامل وجوه در اختیار شما باقی می‌ماند.**  
  حتی اگر سرور به خطر بیفتد، هیچ‌کس نمی‌تواند پول شما را بدزدد - تنها فراداده‌های پرداخت ممکن است افشا شوند.

این طراحی **زیرساخت** را از **کنترل دارایی‌ها** جدا می‌کند.  
شما می‌توانید BTCPay Server را بدون به خطر انداختن هیچ وجهی به‌روزرسانی، منتقل یا دوباره نصب کنید.

## چگونه BTCPay Server را برای پذیرش Zcash راه‌اندازی کنیم

در بخش‌های قبلی توضیح دادیم که BTCPay Server چگونه با Zcash کار می‌کند و چرا برای پرداخت‌های حافظ حریم خصوصی اهمیت دارد. اکنون زمان کار عملی است.

پیکربندی دقیق شما به چند عامل بستگی دارد:

- آیا از قبل یک نمونه‌ی BTCPay Server دارید؟
- آیا می‌خواهید از یک lightwalletd عمومی استفاده کنید یا فول‌نود خود را اجرا کنید؟
- آیا سرور روی یک VPS اجرا خواهد شد یا در خانه؟

این فصل همه‌ی سناریوهای پیکربندی فعلی را پوشش می‌دهد - از پیکربندی‌های حداقلی تا استقرارهای کاملاً مستقل.

موارد زیر را گام‌به‌گام بررسی خواهیم کرد:

- نحوه‌ی استقرار همه‌چیز از صفر روی یک VPS، از جمله فول‌نود (Zebra)
- نحوه‌ی اجرای BTCPay Server در خانه در حالی که IP شما با استفاده از **Cloudflare Tunnel** پنهان می‌ماند
- نحوه‌ی فعال‌سازی و پیکربندی پشتیبانی از Zcash در رابط وب BTCPay Server
- نحوه‌ی یکپارچه‌سازی BTCPay با وب‌سایت یا فروشگاه آنلاین شما


## استقرار BTCPay Server با پشتیبانی از Zcash

بیایید به سراغ راه‌اندازی واقعی برویم. در این بخش، BTCPay Server را با پشتیبانی از Zcash نصب می‌کنیم - یا روی یک VPS تازه، یا با افزودن پشتیبانی از ZEC به یک نمونه‌ی موجود.

اگر از قبل BTCPay Server را در حال اجرا دارید (برای مثال برای BTC یا Lightning)، نیازی به نصب مجدد همه‌چیز نیست - فقط کافی است افزونه‌ی ZEC را فعال کنید.

پیکربندی‌های مختلفی را بررسی خواهیم کرد، از پیکربندی‌های حداقلی با استفاده از یک نود عمومی `lightwalletd` تا نصب‌های کاملاً مستقل با فول‌نود شخصی شما.  
بهترین گزینه به محل سرور شما و میزان استقلالی که از زیرساخت‌های خارجی می‌خواهید بستگی دارد.

> مستندات رسمی افزونه:  
> [https://github.com/btcpay-zcash/btcpayserver-zcash-plugin](https://github.com/btcpay-zcash/btcpayserver-zcash-plugin)
>
> **هشدار - یک کیف‌پول برای هر نمونه:**  
> افزونه‌ی Zcash از **یک کیف‌پول مشترک** برای **همه‌ی فروشگاه‌ها** در نمونه‌ی BTCPay استفاده می‌کند.  
> اگر چند فروشگاه مستقل را روی یک نمونه میزبانی می‌کنید، همه‌ی آن‌ها از یک کیف‌پول Zcash مشترک استفاده خواهند کرد.  
> اگر به جداسازی کامل کیف‌پول‌ها نیاز دارید، از نمونه‌های جداگانه استفاده کنید.

### پیکربندی پیشنهادی VPS

پیش از نصب، مطمئن شوید که موارد زیر را در اختیار دارید:

- یک VPS با **Ubuntu 22.04+**
- یک نام دامنه که (از طریق DNS) به آدرس IP سرور شما اشاره کند
- `git`، `docker` و `docker-compose` نصب‌شده
- دسترسی SSH به سرور

## آماده‌سازی سرور (بخش پنهان)

<details>
  <summary>برای باز کردن کلیک کنید</summary>

برای استقرار BTCPay Server با پشتیبانی از Zcash، به موارد زیر نیاز خواهید داشت:

### 1. VPS با Ubuntu 22.04 یا جدیدتر

توصیه می‌کنیم از نصب حداقلی **Ubuntu Server 22.04 LTS** استفاده کنید.  
هر ارائه‌دهنده‌ی VPS که آدرس IP اختصاصی ارائه دهد مناسب است.  

**حداقل نیازمندی‌ها**:  
- 2 هسته‌ی CPU  
- 4 GB RAM  
- 40 GB فضای دیسک  

اگر از lightwalletd برای Zcash استفاده می‌کنید، این پیکربندی کافی است.  
اگر قصد دارید یک **نود کامل Zcash** اجرا کنید، به **دست‌کم 300 GB** فضای خالی دیسک نیاز خواهید داشت.

---

### 2. نام دامنه‌ای که به سرور شما اشاره کند

در داشبورد ارائه‌دهنده‌ی DNS خود، یک رکورد `A` برای یک زیردامنه  
(برای مثال `btcpay.example.com`) ایجاد کنید که به آدرس IP سرور VPS شما اشاره کند.  

این دامنه برای دسترسی به BTCPay Server از طریق مرورگر  
و برای ایجاد خودکار یک **گواهی SSL رایگان** از طریق Let's Encrypt استفاده خواهد شد.

---

### 3. دسترسی SSH به سرور

برای نصب BTCPay Server، باید از طریق SSH به VPS خود متصل شوید.  
در ترمینال خود این دستور را اجرا کنید:

`ssh root@YOUR_SERVER_IP`

اگر از macOS، Linux یا WSL روی Windows استفاده می‌کنید، SSH از قبل در ترمینال در دسترس است.
روی Windows معمولی، از یک کلاینت SSH مانند **PuTTY** استفاده کنید.

---

### 4. نصب Git، Docker و Docker Compose

پس از اتصال از طریق SSH، بسته‌های سیستم خود را به‌روزرسانی کرده و اجزای مورد نیاز را نصب کنید:

```
sudo apt update && sudo apt upgrade -y
sudo apt install git curl docker.io docker-compose-plugin -y
sudo systemctl enable docker
```

> در Ubuntu 22.04 و نسخه‌های جدیدتر، `docker-compose` از APT منسوخ شده است.
> بسته‌ی توصیه‌شده `docker-compose-plugin` است که دستور `docker compose` را فراهم می‌کند (به فاصله به‌جای خط تیره توجه کنید).

محیط سرور شما اکنون برای نصب BTCPay Server آماده است.

</details>

## راه‌اندازی فول‌نود Zcash اختصاصی شما

اگر ترجیح می‌دهید به نودهای عمومی `lightwalletd` متکی **نباشید**، می‌توانید فول‌نود Zcash خودتان را همراه با lightwalletd روی همان سرور مستقر کنید.  
این کار به شما **استقلال کامل** می‌دهد؛ بدون هیچ وابستگی خارجی و بدون نیاز به اعتماد.

---

### گام 1: از کافی بودن فضای دیسک اطمینان حاصل کنید

یک فول‌نود Zcash (Zebra + lightwalletd) در حال حاضر به **بیش از 300 GB** فضای دیسک نیاز دارد و این مقدار همچنان در حال افزایش است.

جزئیات:

- پایگاه داده بلاک‌چین Zebra: حدود 260-270 GB
- نمایه‌سازی lightwalletd: حدود 15-20 GB

#### فضای ذخیره‌سازی پیشنهادی:

- **بیش از 400 GB** اگر سرور **فقط** برای پرداخت‌های Zcash استفاده می‌شود
- **بیش از 800 GB** اگر سرور BTCPay Server، PostgreSQL، Nginx و موارد دیگر را نیز اجرا می‌کند

> بهتر است از یک دیسک SSD/NVMe با **ظرفیت 1 TB** استفاده کنید، به‌ویژه اگر قصد ندارید داده‌ها را به‌طور منظم هرس کنید.

---

### گام 2: متغیرهای محیطی را تنظیم کنید

برای فعال‌سازی پیکربندی فول‌نود، موارد زیر را به تنظیمات محیطی خود اضافه کنید:

```
export BTCPAYGEN_EXCLUDE_FRAGMENTS="zcash"
export BTCPAYGEN_ADDITIONAL_FRAGMENTS="zcash-fullnode"
```

این کار فرگمنت `zcash-fullnode` را اضافه می‌کند که هر دو `zebrad` و `lightwalletd` را درون BTCPay Server اجرا می‌کند.

---

### گام 3: نصب‌کننده را دوباره اجرا کنید

`. ./btcpay-setup.sh -i`

این اسکریپت:

* ایمیج‌های Docker را برای Zebra و lightwalletd دانلود می‌کند
* سرویس‌ها را درون استک BTCPay راه‌اندازی می‌کند
* پلاگین Zcash را به نمونه **محلی** `lightwalletd` متصل می‌کند

> **همگام‌سازی کامل بلاک‌چین ممکن است چند روز طول بکشد**، به‌ویژه روی سرورهای VPS با منابع محدود.
> تا زمانی که همگام‌سازی کامل نشود، پرداخت‌های محافظت‌شده در دسترس نخواهند بود.


## اتصال به یک نود خارجی lightwalletd

در بیشتر موارد، استقلال کامل ضروری نیست و ممکن است فروشندگان نخواهند برای اجرای یک فول‌نود Zcash وقت و فضای دیسک صرف کنند.  
به‌طور پیش‌فرض، BTCPay Server برای پردازش پرداخت‌های محافظت‌شده به یک نود عمومی `lightwalletd` متصل می‌شود، بدون اینکه کل بلاک‌چین را دانلود کند.

اندپوینت پیش‌فرض:

`https://zec.rocks:443`

با این حال، شما می‌توانید BTCPay Server را طوری پیکربندی کنید که به **هر نود خارجی `lightwalletd`** متصل شود، مانند:

`https://lightwalletd.example:443`

این بخش نشان می‌دهد چگونه این کار را با استفاده از یک **فرگمنت سفارشی Docker** انجام دهید.

> یک نمونه پیکربندی کامل با همه متغیرهای محیطی در [مخزن پلاگین](https://github.com/btcpay-zcash/btcpayserver-zcash-plugin/blob/master/docs/zcash-lightwalletd.custom.yml) موجود است.  
> گام‌های زیر یک راه‌اندازی حداقلی و کارآمد را نشان می‌دهند.

---

### گام 1: یک فرگمنت سفارشی Docker ایجاد کنید

در پوشه پروژه BTCPayServer خود، یک فایل فرگمنت سفارشی ایجاد کنید:

```
cd ~/BTCPayServer/btcpayserver-docker
mkdir -p docker-compose-generator/docker-fragments
nano docker-compose-generator/docker-fragments/zcash-lightwalletd.custom.yml
```

محتوای زیر را اضافه کنید:

```
exclusive:
- zcash
```

دستور `exclusive` تضمین می‌کند که در هر زمان فقط یک فرگمنت با برچسب یکسان (در این مورد `zcash`) فعال باشد.
این کار از تداخل پیکربندی‌ها جلوگیری می‌کند؛ برای مثال، شما نمی‌توانید فرگمنت `zcash-fullnode` و این فرگمنت سفارشی `lightwalletd` خارجی را هم‌زمان اجرا کنید.
با علامت‌گذاری آن به‌عنوان `exclusive: zcash`، BTCPay Server به‌طور خودکار کانتینرهای پیش‌فرض `zcash-fullnode` و `lightwalletd` داخلی را غیرفعال می‌کند و به شما امکان می‌دهد به‌جای آن‌ها به نود خارجی خودتان متصل شوید.

---

### گام 2: متغیرهای محیطی را تنظیم کنید

در ترمینال:

```
export BTCPAYGEN_EXCLUDE_FRAGMENTS="$BTCPAYGEN_EXCLUDE_FRAGMENTS;zcash"
export BTCPAYGEN_ADDITIONAL_FRAGMENTS="$BTCPAYGEN_ADDITIONAL_FRAGMENTS;zcash-lightwalletd.custom"
```

---

### گام 3: آدرس نود خارجی را تعریف کنید

فایل `.env` خود را باز کنید:

`nano .env`

خط زیر را اضافه کنید و URL را با اندپوینت انتخابی خود جایگزین کنید:

`ZCASH_LIGHTWALLETD=https://lightwalletd.example:443`

شما می‌توانید از این موارد استفاده کنید:

* یک **نود عمومی**، مانند `https://zec.rocks:443`
* نود خودمیزبان خودتان که جدا از BTCPay Server مستقر شده است

> اگر `lightwalletd` خارجی در دسترس نباشد یا بیش از حد بارگذاری شود، پرداخت‌های محافظت‌شده با شکست مواجه می‌شوند.
> برای سرویس‌های حیاتی، یک **اندپوینت پایدار و آزموده‌شده** (مانند `zec.rocks` پیش‌فرض) انتخاب کنید.

> می‌خواهید `lightwalletd` را خودتان میزبانی کنید؟
> می‌توانید از `docker-compose.lwd.yml` موجود در [Zebra مخزن](https://github.com/ZcashFoundation/zebra/blob/main/docker/docker-compose.lwd.yml) استفاده کنید.
> **هشدار:** این راه‌اندازی به‌طور رسمی مستند نشده است و به تنظیم دستی TLS، port forwarding و پیکربندی فایروال نیاز دارد؛ فقط برای کاربران پیشرفته توصیه می‌شود.

---

### گام 4: نصب‌کننده را دوباره اجرا کنید

`. ./btcpay-setup.sh -i`

BTCPay Server پیکربندی سفارشی شما را اعمال می‌کند و به نود `lightwalletd` مشخص‌شده متصل می‌شود.

از این پس، پلاگین Zcash برای پردازش تراکنش‌های محافظت‌شده از آن اندپوینت خارجی استفاده خواهد کرد.


## میزبانی BTCPay Server در خانه با Cloudflare Tunnel

می‌خواهید پرداخت‌های Zcash را بپذیرید و هم‌زمان BTCPay Server را روی یک دستگاه خانگی میزبانی کنید، مانند Raspberry Pi 5 یا هر سرور محلی دیگری **بدون IP ثابت**؟  
شما می‌توانید نمونه خود را با استفاده از **Cloudflare Tunnel** به‌طور امن در اینترنت در دسترس قرار دهید.

این روش نیاز به port forwarding را از بین می‌برد و IP واقعی شما را از دید عموم پنهان می‌کند، در حالی که سرور شما همچنان از طریق HTTPS در دسترس است.

همچنین به شما کمک می‌کند **از هزینه اجاره VPS اجتناب کنید**؛ این موضوع زمانی ایده‌آل است که پرداخت‌های رمزارزی یک قابلیت اختیاری باشند و نه هسته اصلی کسب‌وکار شما.

---

### گام 1: Cloudflare Tunnel را نصب کنید

1. در [cloudflare.com](https://www.cloudflare.com) یک حساب کاربری ایجاد کنید و دامنه خود را اضافه کنید.
2. روی **سرور خانگی** خود، Cloudflare Tunnel را با استفاده از مخزن بسته رسمی Cloudflare نصب کنید:

```bash
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update
sudo apt install cloudflared
```

اگر `apt install cloudflared` با شکست مواجه شد، به‌جای آن `.deb` متناظر را نصب کنید:

```bash
# Raspberry Pi / ARM64
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64.deb
sudo dpkg -i cloudflared.deb
```

```bash
# x86_64
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb
```

3. با Cloudflare احراز هویت کنید:

`cloudflared tunnel login`

این دستور یک پنجره مرورگر باز می‌کند. وارد شوید و دسترسی به دامنه خود را مجاز کنید.
Cloudflare به‌طور خودکار یک فایل `credentials` حاوی یک توکن روی سرور شما ایجاد می‌کند.

4. یک تونل جدید ایجاد کنید (می‌توانید نام آن را `btcpay` یا هر نام دیگری بگذارید):

`cloudflared tunnel create btcpay`

این کار یک فایل `btcpay.json` حاوی شناسه تونل و اطلاعات اعتبارنامه ایجاد می‌کند که در گام بعدی به آن نیاز خواهید داشت.

---

### گام 2: فایل پیکربندی تونل را ایجاد کنید

پوشه پیکربندی را (در صورت عدم وجود) ایجاد کنید و فایل پیکربندی را باز کنید:

```
sudo mkdir -p /etc/cloudflared
sudo nano /etc/cloudflared/config.yml
```

پیکربندی زیر را در آن قرار دهید:

```
tunnel: btcpay    # your tunnel name
credentials-file: /root/.cloudflared/btcpay.json

ingress:
  - hostname: btcpay.example.com      # your domain
    service: http://127.0.0.1:80
  - service: http_status:404
```

#### توضیحات:

* `tunnel` - نام تونلی که پیش‌تر ایجاد کردید
* `credentials-file` - مسیر فایل توکن ایجادشده در طول `cloudflared tunnel login`
* `hostname` - دامنه شما که در Cloudflare ثبت شده است (برای مثال `btcpay.example.com`)
* `service` - آدرس محلی BTCPay Server شما (معمولاً `http://127.0.0.1:80` برای Nginx)

> Cloudflare ترافیک را به‌طور امن به سرور محلی شما پراکسی می‌کند، بدون اینکه IP خانگی شما افشا شود.


### گام 3: یک رکورد DNS برای تونل خود اضافه کنید

پس از ایجاد تونل، Cloudflare معمولاً **به‌طور خودکار یک رکورد CNAME DNS** برای دامنه شما اضافه می‌کند. این رکورد باید به این شکل باشد:

`btcpay.example.com -> <UUID>.cfargotunnel.com`

اگر به‌طور خودکار ظاهر نشد، آن را دستی اضافه کنید:

1. به [داشبورد Cloudflare](https://dash.cloudflare.com/) خود بروید
2. به بخش **DNS** بروید
3. یک رکورد CNAME جدید اضافه کنید:
   - **Name**: `btcpay`
   - **Target**: `<UUID>.cfargotunnel.com`  
     مقدار دقیق را می‌توانید در فایل `btcpay.json` خود یا با اجرای دستور زیر پیدا کنید:
     
     `cloudflared tunnel list`
     
   - **Proxy status**: فعال (ابر نارنجی)

> این رکورد تضمین می‌کند که همه درخواست‌ها به `btcpay.example.com` از طریق Cloudflare Tunnel هدایت شوند و IP واقعی شما از دید عموم پنهان بماند.

---

### گام 4: تونل را هنگام راه‌اندازی سیستم فعال کنید

برای اینکه تونل هنگام بوت شدن به‌طور خودکار اجرا شود، آن را به‌عنوان یک سرویس سیستمی نصب کنید:

`sudo cloudflared service install`

سپس سرویس را فعال و اجرا کنید:

```
sudo systemctl enable cloudflared
sudo systemctl start cloudflared
```

وضعیت را بررسی کنید:

`sudo systemctl status cloudflared`

باید پیامی مانند `Active: active (running)` و تأییدیه‌ای مبنی بر آنلاین بودن `btcpay.example.com` ببینید.

> از این پس، تونل در هر بار راه‌اندازی مجدد به‌طور خودکار اجرا می‌شود و BTCPay Server شما به‌صورت عمومی در دسترس خواهد بود؛ بدون port forwarding و بدون افشای IP واقعی شما.

---

### گام 5: راه‌اندازی BTCPay Server را نهایی کنید

اگر قصد دارید BTCPay Server را برای اولین بار نصب کنید، پیش از اجرای اسکریپت راه‌اندازی، دامنه خود را تنظیم کنید:

`export BTCPAY_HOST="btcpay.example.com"`

این کار تضمین می‌کند که هنگام ایجاد **پیکربندی Nginx** و **گواهی‌های SSL** از دامنه صحیح استفاده شود.

اگر BTCPay Server از قبل نصب شده است و فقط تونل را اضافه می‌کنید:

```
cd ~/BTCPayServer/btcpayserver-docker
. ./btcpay-setup.sh -i
```

فرایند راه‌اندازی پیکربندی‌ها را دوباره ایجاد می‌کند و دامنه جدید را اعمال می‌کند.
اکنون باید بتوانید از این آدرس به سرور خود دسترسی داشته باشید:

`https://btcpay.example.com`

> چه از یک `lightwalletd` عمومی استفاده کنید و چه از فول‌نود خودتان، این موضوع تأثیری بر تونل ندارد.
> تنها چیزی که اهمیت دارد این است که BTCPay Server به‌صورت محلی روی `127.0.0.1:80` در حال گوش دادن باشد.


## پیکربندی پلاگین Zcash در رابط وب BTCPay Server

> **نکته مهم برای راه‌اندازی‌های چندفروشگاهی:**  
> کیف‌پول Zcash که در اینجا پیکربندی می‌شود برای کل نمونه **سراسری** است. همه فروشگاه‌ها از این کیف‌پول استفاده خواهند کرد، مگر اینکه نمونه‌های جداگانه BTCPay اجرا کنید.

پس از استقرار موفق نمونه BTCPay Server خود، باید برخی پیکربندی‌های پایه را از طریق رابط وب مدیریت انجام دهید.  
مستندات رسمی دستورالعمل‌های کامل را به زبان انگلیسی ارائه می‌دهد؛ در اینجا گام‌های ضروری را مرور می‌کنیم و به‌طور ویژه بر پیکربندی پلاگین Zcash تمرکز می‌کنیم.

---

### گام 1: وارد رابط وب شوید

به نمونه خود در این آدرس بروید:

`[https://btcpay.example.com](https://btcpay.example.com)`

- نام کاربری و رمز عبور مدیر خود را وارد کنید.
- اگر این اولین ورود شماست، از شما خواسته می‌شود یک حساب کاربری ایجاد کنید.
- اولین حسابی که ثبت می‌کنید به‌طور خودکار دسترسی مدیر دریافت می‌کند.

---

### گام 2: پلاگین Zcash را نصب کنید

1. در منوی اصلی، به این بخش بروید:

`Plugins -> Browse Plugins`

2. پلاگین **Zcash (ZEC)** را پیدا کنید. در صورت نیاز از نوار جستجو استفاده کنید.
3. روی **Install** کلیک کنید و تأیید کنید.

> این فرایند را برای هر آلت‌کوین دیگری که هنگام پیکربندی سرور فعال کرده‌اید تکرار کنید.

پس از نصب، روی **Restart Server** کلیک کنید تا رابط کاربری با پلاگین‌های فعال دوباره بارگذاری شود.


### گام 3: کیف‌پول خود را از طریق Viewing Key متصل کنید

پس از نصب پلاگین، یک بخش جدید **Zcash** در منوی تنظیمات ظاهر می‌شود.

1. به این بخش بروید:

`Zcash -> Settings`

2. **Full Viewing Key یکپارچه (UFVK)** خود را وارد کنید؛ BTCPay برای هر صورتحساب یک آدرس یکپارچه استخراج می‌کند و پرداخت‌های محافظت‌شده ورودی را شناسایی می‌کند.

> **توجه:** کلیدهای مشاهده قدیمی Sapling پشتیبانی می‌شوند، اما برای استفاده از Orchard/آدرس‌های یکپارچه باید یک **UFVK** ارائه دهید.


   قالب نمونه:

`uview184syv9wftwngkay8d...`

3. مقداری را در فیلد Block height وارد کنید

* **راه‌اندازی اولیه با یک کیف‌پول جدید (عبارت بازیابی جدید):** ارتفاع بلوک فعلی Zcash را وارد کنید (می‌توانید آن را در 3xpl.com/zcash بررسی کنید)؛ این کار اسکن اولیه را سریع‌تر می‌کند.
* **مهاجرت روی همان سرور از یک راه‌اندازی قدیمی فقط Sapling به آدرس‌های یکپارچه / Orchard:** این فیلد را خالی بگذارید.
* **انتقال فروشگاه شما به یک سرور جدید با همان کیف‌پول/UFVK:** در صورت تمایل، ارتفاع تولد را وارد کنید؛ یعنی ارتفاع تقریبی اولین سفارش پرداخت‌شده فروشگاه شما (تاریخ سفارش را در 3xpl تطبیق دهید تا محدوده اسکن کوچک‌تر شود). اگر مطمئن نیستید، آن را خالی بگذارید.

> هنوز همه کیف‌پول‌ها از خروجی گرفتن **Full Viewing Key یکپارچه (UFVK)** پشتیبانی نمی‌کنند.  
> گزینه‌های پیشنهادی:  
> – [**Zkool**](https://github.com/hhanh00/zkool2/)  
> – [**کیف‌پول Zingo! (نسخه رایانه)**](https://zingolabs.org/)  
> در هر دو برنامه، گزینه خروجی UFVK را در بخش پشتیبان‌گیری/خروجی جستجو کنید.

این کلیدها از **چرخش خودکار آدرس** پشتیبانی می‌کنند، به این معنا که:
- هر مشتری یک آدرس پرداخت **منحصربه‌فرد** دریافت می‌کند
- شما یک موجودی **واحد و یکپارچه** می‌بینید

فهرست گسترده‌تری از سازگاری را می‌توانید در [ZecHub -> کیف‌پول‌ها](https://zechub.wiki/wallets) پیدا کنید.

پس از پر کردن همه فیلدها، روی **Save** کلیک کنید.

---

### جریان پرداخت ZEC خود را آزمایش کنید

تبریک می‌گوییم؛ کیف‌پول Zcash شما اکنون به BTCPay Server متصل است.

بیایید یک آزمایش انجام دهیم:

1. به این بخش بروید:

`Invoices -> Create New`

2. یک صورتحساب آزمایشی برای مبلغی کم به ZEC ایجاد کنید.
3. وجه را از **یک کیف‌پول دیگر** (نه کیف‌پولی که به BTCPay متصل است) ارسال کنید.
4. پس از شناسایی تراکنش، صفحه صورتحساب یک جشن تصویری نمایش می‌دهد.
5. تأیید کنید که وضعیت صورتحساب به **Paid** تغییر می‌کند.

اگر همه چیز درست کار کند، شما آماده‌اید تا پرداخت‌های ZEC را با استفاده از API یا پلاگین‌های CMS در وب‌سایت خود ادغام کنید.



## ادغام BTCPay Server با وب‌سایت شما

پس از اتصال کیف‌پول Zcash شما به BTCPay Server، می‌توانید سیستم پرداخت را در وب‌سایت خود ادغام کنید.  
چند روش برای این کار وجود دارد؛ از دسترسی مستقیم به API تا پلاگین‌های آماده برای پلتفرم‌های محبوب CMS.

---

### گزینه‌های ادغام

- **ادغام از طریق API**  
  ایده‌آل برای وب‌سایت‌های سفارشی یا سیستم‌های بدون CMS.  
  کنترل کامل بر ایجاد صورتحساب، پیگیری پرداخت و اعلان‌ها را به شما می‌دهد؛ همه در چارچوب رابط و منطق خودتان.  
  به دانش پایه برنامه‌نویسی نیاز دارد، بنابراین بهتر است این کار را توسعه‌دهنده شما انجام دهد.

- **پلاگین‌های CMS**  
  برای پلتفرم‌هایی مانند **WooCommerce**، **PrestaShop** و موارد دیگر در دسترس هستند.  
  این پلاگین‌ها به شما امکان می‌دهند تنها در چند دقیقه پرداخت دریافت کنید؛ بدون نیاز به کدنویسی.

- **دکمه پرداخت یا Iframe**  
  ساده‌ترین روش.  
  مناسب برای صفحات فرود، وب‌سایت‌های شخصی یا هر سایتی که فقط می‌خواهید یک لینک کمک مالی یا ویجت پرداخت در آن قرار دهید.

---

### ادغام از طریق API

اگر از یک پلتفرم سفارشی استفاده می‌کنید (یا اصلاً CMS ندارید)، API بهترین گزینه است.  
این روش انعطاف‌پذیری کامل به شما می‌دهد: می‌توانید صورتحساب ایجاد کنید، وضعیت آن‌ها را پیگیری کنید، اعلان دریافت کنید و تجربه کاربری را به‌طور کامل کنترل کنید.

> توجه: حتی برخی پلاگین‌های CMS نیز در پشت صحنه از API استفاده می‌کنند، بنابراین ایجاد یک کلید API اغلب **اولین گام ضروری** است، صرف‌نظر از روش ادغام شما.

گام بعدی: برای فروشگاه خود یک کلید API ایجاد کنید و برای ساخت ادغام خود از [Greenfield API](https://docs.btcpayserver.org/API/Greenfield/v1/) استفاده کنید.


### ایجاد کلید API

برای ادغام BTCPay Server با وب‌سایت یا برنامه خود، باید یک کلید API ایجاد کنید.

1. وارد BTCPay Server شوید و **منوی کاربر** (گوشه بالا سمت راست) را باز کنید
2. به **API Keys** بروید
3. روی **Create a new API key** کلیک کنید
4. یک نام برای کلید خود وارد کنید
5. در بخش **Permissions**، موارد زیر را فعال کنید:
   - `Can create invoice`
   - `Can view invoice`
   - *(اختیاری)* `Can modify store settings` - فقط اگر به مدیریت در سطح فروشگاه نیاز دارید

6. روی **Generate** کلیک کنید. کلید API شخصی شما نمایش داده می‌شود؛ آن را کپی کرده و در جای امنی نگه دارید.

> این کلید به صورتحساب‌های فروشگاه شما دسترسی می‌دهد.  
> آن را به‌صورت عمومی به اشتراک **نگذارید** و در کد سمت کلاینت افشا نکنید.

---

### مثال: ایجاد صورتحساب از طریق API

**اندپوینت:**

```
POST /api/v1/stores/{storeId}/invoices
Authorization: token {apiKey}
Content-Type: application/json
```

**بدنه درخواست:**

```
{
  "amount": 5,
  "currency": "ZEC",
  "checkout": {
    "speedPolicy": "HighSpeed",
    "paymentMethods": ["Zcash"]
  }
}
```

**پاسخ:**

یک شیء JSON دریافت خواهید کرد که شامل موارد زیر است:

* `invoiceId`
* یک URL پرداخت که می‌توانید آن را در وب‌سایت خود قرار دهید یا برای مشتری ارسال کنید

مستندات کامل را ببینید:
[Greenfield API – ایجاد صورتحساب](https://docs.btcpayserver.org/API/Greenfield/v1/#operation/CreateInvoice)

---

### راه‌اندازی Webhook (اختیاری)

برای دریافت اعلان‌های بلادرنگ هنگام تغییر وضعیت صورتحساب‌ها (برای مثال، هنگام دریافت یک پرداخت):

1. به تنظیمات فروشگاه خود -> **Webhooks** بروید
2. URL اندپوینت بک‌اند خود را که درخواست‌های `POST` از BTCPay Server را پردازش می‌کند اضافه کنید
3. BTCPay هنگام پرداخت یا منقضی شدن یک صورتحساب، به‌طور خودکار اعلان ارسال می‌کند

محتوای Webhook و منطق تلاش مجدد در [مستندات رسمی Webhook](https://docs.btcpayserver.org/FAQ/General/#how-to-create-a-webhook-) شرح داده شده‌اند.

> نمونه‌های ادغام برای زبان‌های برنامه‌نویسی مختلف در مستندات BTCPay و مخازن GitHub در دسترس هستند.



### ادغام با CMS

BTCPay Server از پلاگین‌هایی برای سیستم‌های مدیریت محتوای (CMS) محبوب پشتیبانی می‌کند.  
پخته‌ترین و پرکاربردترین ادغام با **WordPress + WooCommerce** است که دریافت پرداخت‌های ZEC را **بدون نوشتن کد** آسان می‌کند.

---

#### WooCommerce (WordPress)

BTCPay Server به‌طور رسمی از یک پلاگین برای WooCommerce پشتیبانی می‌کند.

گام‌های ادغام:

1. پلاگین **BTCPay for WooCommerce** را از فهرست پلاگین‌های WordPress یا از GitHub نصب کنید.
2. در پنل مدیریت WordPress خود، به این بخش بروید:

`WooCommerce -> Settings -> Payments`

3. **BTCPay** را در فهرست پیدا کنید و روی **Set up** کلیک کنید
4. URL BTCPay Server خود را وارد کنید و دستورالعمل‌های مجوزدهی را دنبال کنید  
   (ایجاد خودکار کلید API توصیه می‌شود)
5. روش پرداخت را فعال کنید و تنظیمات خود را ذخیره کنید

> دستورالعمل‌های دقیق، آموزش‌های ویدیویی و راهنماهای رفع اشکال در مستندات پلاگین در دسترس هستند.

گزینه‌های دیگر ادغام با CMS را نیز در همان بخش از مستندات BTCPay پیدا خواهید کرد.

---

### دکمه پرداخت یا Iframe (بدون نیاز به CMS یا API)

اگر از CMS استفاده نمی‌کنید و نمی‌خواهید با API کار کنید، ساده‌ترین راه برای دریافت پرداخت‌های ZEC این است که **یک لینک یا ویجت پرداخت** را مستقیماً در وب‌سایت خود قرار دهید.

این روش برای موارد زیر ایده‌آل است:

- صفحات فرود
- سایت‌های نمونه‌کار
- وبلاگ‌ها یا صفحات ایستا
- پروژه‌های بدون سرور بک‌اند

---

#### گزینه 1: دکمه پرداخت (لینک)

1. در BTCPay Server، یک صورتحساب را به‌صورت دستی در بخش **Invoices** ایجاد کنید
2. لینک پرداخت را کپی کنید، برای مثال:

`[https://btcpay.example.com/i/abc123](https://btcpay.example.com/i/abc123)`

3. لینک را به HTML خود اضافه کنید:

```
<a href="https://btcpay.example.com/i/abc123" target="_blank">
  Pay with ZEC
</a>
```

---

#### گزینه 2: صورتحساب جاسازی‌شده (Iframe)

برای نمایش صورتحساب مستقیماً در سایت خود، از یک iframe استفاده کنید:

`<iframe src="https://btcpay.example.com/i/abc123" width="600" height="350" frameborder="0"></iframe>`

> شما می‌توانید ظاهر دکمه یا کانتینر iframe را متناسب با طراحی سایت خود تنظیم کنید؛ BTCPay Server امکان شخصی‌سازی انعطاف‌پذیر ظاهر صفحه صورتحساب را فراهم می‌کند.

## نتیجه‌گیری

این راهنما طولانی بود، اما تنها جنبه‌های پایه‌ای یکپارچه‌سازی پرداخت‌های Zcash با BTCPay Server را پوشش می‌دهد.

رابط BTCPay Server قابلیت‌های بسیار بیشتری از آنچه در اینجا نشان دادیم ارائه می‌دهد. خوشبختانه، رابط کاربری به چندین زبان (از جمله روسی) در دسترس است و همین امر کاوش و آزمایش بیشتر را برای شما آسان می‌کند.

BTCPay ابزاری بسیار انعطاف‌پذیر است. شما می‌توانید:

* چندین فروشگاه مستقل را روی یک نمونهٔ واحد میزبانی کنید
* نقش‌ها و مجوزهای سفارشی برای اعضای تیم تعریف کنید، از دسترسی فقط مشاهدهٔ سفارش‌ها تا مدیریت کامل
* از دامنه‌ها و برندینگ خودتان استفاده کنید
* وب‌هوک‌ها، کیف‌پول‌های جایگزین و حتی دسترسی Tor را راه‌اندازی کنید
* تنظیمات پیشرفته‌ای مانند قوانین مالیاتی، کدهای تخفیف، سفارشی‌سازی صفحهٔ پرداخت، محدودیت‌های روش پرداخت و موارد دیگر را پیکربندی کنید

BTCPay به‌عنوان جایگزینی متن‌باز برای ارائه‌دهندگان متمرکز خدمات پرداخت ساخته شده است. اگر به دنبال پذیرش پرداخت‌های خصوصی ZEC بدون هیچ واسطه‌ای هستید، این پلتفرم قطعاً ارزش توجه شما را دارد.

برای شما در کاوش اکوسیستم BTCPay و تبدیل پرداخت‌هایتان به پرداخت‌هایی که واقعاً متعلق به خودتان است، آرزوی موفقیت داریم.
