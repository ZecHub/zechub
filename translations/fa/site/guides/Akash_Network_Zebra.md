# نحوه اجرای Zebra روی Akash Network

راهنمای گام‌به‌گام برای استقرار یک فول‌نود Zebra Zcash روی Akash.

### آنچه مستقر می‌کنید

یک فول‌نود Zebra که:

-> کل بلاک‌چین Zcash را همگام‌سازی می‌کند (بیش از 100GB برای mainnet و حدود 40GB برای testnet)

-> بسته به قیمت توکن AKT، تقریباً ماهانه 15$ هزینه دارد

-> همگام‌سازی کامل آن چند ساعت تا چند روز طول می‌کشد

-> از 4 vCPU، 16GB RAM و 350GB فضای ذخیره‌سازی (mainnet) یا 2 vCPU، 8GB RAM و 50GB (testnet) استفاده می‌کند

قالب awesome-akash اکنون نسخه **Zebra 7.0.0** را تثبیت می‌کند (هرگز `:latest`). این قالب Prometheus (`9999`) و health (`8080`) را به‌صورت داخلی فعال می‌کند، JSON-RPC را به‌صورت داخلی برای یک **lightwalletd** هم‌مکان روی gRPC **9067** فعال می‌کند، و پرچم‌های ویژگی `ENABLE_METRICS` / `ENABLE_HEALTH` / `ENABLE_RPC` / `ENABLE_LIGHTWALLETD` را نیز فعال می‌کند.

برای یک نود Mainnet هرس‌شده و سریع‌تر، به [نحوه اجرای Zakura روی Akash](/guides/akash-network-zakura) مراجعه کنید. برای یک داشبورد Regtest یک‌بارمصرف، به [چنین گفت Zakura روی Akash](/guides/thus-spoke-zakura-akash) مراجعه کنید.


### Akash پورت‌ها را چگونه منتشر می‌کند

اعداد موجود در SDL (`port` / `as`) **پورت‌های کانتینر** هستند. Zebra همچنان روی **8233**، lightwalletd روی **9067** و health روی **8080** گوش می‌دهد. این اعداد برای خود پروسه و برای سرویس‌های دیگر در همان استقرار (`zebra:8232`) هستند.

این‌ها پورت‌های IP عمومی ارائه‌دهنده **نیستند**.

**پیش‌فرض (این قالب):** بدون IP اختصاصی. برای هر expose از نوع TCP با `global: true`، ارائه‌دهنده یک **پورت بالای تصادفی** را روی یک میزبان مشترک به پورت کانتینر شما نگاشت می‌کند. پس از برقراری lease، بخش **Leases → URIs** در Console/Air نقاط پایانی واقعی را فهرست می‌کند، برای مثال:

```
zebra-8233: provider.example:31482
lightwalletd-9067: provider.example:32011
```

همتاها و کیف‌پول‌ها از **همین** مقادیر host:port استفاده می‌کنند. URI مربوط به expose موردنظر خود را کپی کنید (P2P در مقابل lightwalletd). اگر `ZEBRA_NETWORK__EXTERNAL_ADDR` را تنظیم می‌کنید، آن را روی URI نگاشت‌شده P2P (`provider.example:31482`) قرار دهید، نه `…:8233`.

**HTTP** (`as: 80` همراه با `http_options`، که در داشبورد Thus Spoke استفاده می‌شود): بسیاری از ارائه‌دهندگان به‌جای یک پورت TCP تصادفی، یک **نام میزبان ingress** (اغلب روی 80/443) منتشر می‌کنند. URI آن سرویس را در مرورگر باز کنید.

**داخلی** (`global: false` یا `to: service: lightwalletd`): فقط DNS خوشه (`zebra:8232`). بدون URI عمومی.

**IPهای اختصاصی** (`endpoints` / `kind: ip` در SDL) یک **امکان اضافی ویژه** هستند. آن‌ها می‌توانند یک IP عمومی و گاهی پورت `as` روی آن IP را تثبیت کنند. این قالب‌ها چنین چیزی را درخواست **نمی‌کنند**. اگر یک `host:8233` پایدار می‌خواهید، بعداً خودتان آن را اضافه کنید؛ انتظار هزینه بیشتر و ارائه‌دهندگان پیشنهاددهنده کمتری را داشته باشید.

### از کدام سایت استفاده کنید (پرداخت‌ها)

SDL یکسان است. تفاوت دو رابط وب Akash در **نحوه پرداخت** شماست.

| سایت | پرداخت‌ها | کیف‌پول |
| --- | --- | --- |
| [console.akash.network](https://console.akash.network) | پرداخت وب سنتی (کارت / روش‌های فیات ارائه‌شده توسط Console) | حساب Console |
| [air.akash.network](https://air.akash.network) | پرداخت‌های بومی روی زنجیره Akash (AKT / ACT) | **Keplr** |

وقتی می‌خواهید با Keplr به‌صورت on-chain پرداخت کنید، از **Air** استفاده کنید. وقتی یک روند پرداخت وب متعارف می‌خواهید، از **Console** استفاده کنید. در Console انتظار تسویه بومی Keplr را نداشته باشید.

### پیش‌نیازها

**اگر در Console پرداخت می‌کنید (پرداخت وب)**

1. یک حساب Console در [console.akash.network](https://console.akash.network)
2. یک روش پرداخت که رابط کاربری Console بپذیرد
3. چند دقیقه وقت در رابط کاربری

**اگر در Air پرداخت می‌کنید (بومی Akash / Keplr)**

1. افزونه مرورگر **Keplr** (Chrome/Brave/Firefox)
2. **AKT / ACT** در Keplr برای سپرده و lease (از یک صرافی یا IBC)
3. [air.akash.network](https://air.akash.network) را باز کنید

#### گام 1: اتصال

**Console (پرداخت‌های وب)**

-> به [https://console.akash.network](https://console.akash.network) بروید

-> وارد شوید / روند ایجاد حساب Console را کامل کنید

-> از روند پرداختی که رابط کاربری ارائه می‌دهد استفاده کنید (نه Keplr به‌صورت on-chain)

**Air (پرداخت‌های بومی Akash)**

-> به [https://air.akash.network](https://air.akash.network) بروید

-> روی **«Connect Wallet»** کلیک کنید

-> **Keplr** را انتخاب کرده و اتصال را تأیید کنید

-> اطمینان حاصل کنید که موجودی AKT/ACT شما برای سپرده به‌علاوه lease کافی است

#### گام 2: ایجاد استقرار

-> روی **«Deploy»** کلیک کنید

-> گزینه **«Build your template»** را انتخاب کنید (یا مستقیماً به بارگذاری SDL بروید)


##### گزینه A: بارگذاری فایل SDL (توصیه‌شده)

**پرداخت‌های وب (Console)**

[![استقرار روی Akash Console](/content-images/deploy-with-akash-btn-74abb88d44.svg)](https://console.akash.network/new-deployment?step=edit-deployment&templateId=akash-network-awesome-akash-zcash-zebra)

**پرداخت‌های بومی Akash با Keplr (Air)**

[این قالب را در Air باز کنید](https://air.akash.network/new-deployment?step=edit-deployment&templateId=akash-network-awesome-akash-zcash-zebra)

##### گزینه B: استفاده از ویرایشگر SDL

اگر می‌خواهید [SDL](https://github.com/akash-network/awesome-akash/blob/master/zcash-zebra/deploy.yaml) را به‌صورت دستی جای‌گذاری کنید:

-> محتوای *zebra-akash.yml* را کپی کنید

-> آن را در ویرایشگر SDL جای‌گذاری کنید

-> در صورت نیاز تغییر دهید (به بخش پیکربندی در ادامه مراجعه کنید)

-> روی **«Create Deployment»** کلیک کنید


#### گام 3: بررسی و تأیید سپرده

رابط کاربری موارد زیر را به شما نشان می‌دهد:

-> **سپرده استقرار**: حدود 5 AKT (هنگام بستن استقرار آن را پس می‌گیرید)

-> **هزینه تخمینی**: بر اساس قیمت‌گذاری SDL شما

در **Air**، روی **«Approve»** کلیک کرده و در **Keplr** امضا کنید. در **Console**، روند پرداخت وبی را که رابط کاربری ارائه می‌دهد کامل کنید.

#### گام 4: انتخاب ارائه‌دهنده

پس از حدود 30 ثانیه، پیشنهادهای ارائه‌دهندگان را خواهید دید. هر پیشنهاد نشان می‌دهد:

-> **قیمت به‌ازای هر بلوک** (به AKT یا USDC)

-> **هزینه تخمینی ماهانه**

-> **جزئیات ارائه‌دهنده** (زمان فعال بودن، منطقه و غیره)


**فقط ارزان‌ترین را انتخاب نکنید.** موارد زیر را بررسی کنید:

-> درصد زمان فعال بودن (هدف: بیش از 95%)

-> منطقه (نزدیک‌تر به شما = تأخیر کمتر، اما برای نودهای بلاک‌چین اهمیت چندانی ندارد)

-> وضعیت ممیزی (تیک سبز = قابل‌اعتمادتر)


روی **«Accept Bid»** ارائه‌دهنده انتخابی خود کلیک کنید. در Air، در Keplr امضا کنید. در Console، با روند پرداخت وب تأیید کنید.

#### گام 5: انتظار برای استقرار

Console:

-> Lease را با ارائه‌دهنده انتخابی شما ایجاد می‌کند

-> Manifest را ارسال می‌کند (به ارائه‌دهنده می‌گوید چه چیزی را اجرا کند)

-> کانتینر شما را راه‌اندازی می‌کند

این کار 1 تا 2 دقیقه طول می‌کشد. به‌روزرسانی‌های وضعیت را در رابط کاربری خواهید دید.

#### گام 6: اطمینان از اجرای آن

پس از استقرار، موارد زیر را خواهید دید:

-> زبانه **Services**: سرویس *zebra* شما را همراه با وضعیت آن نشان می‌دهد

-> زبانه **Logs**: لاگ‌های زنده کانتینر

-> زبانه **Leases**: جزئیات استقرار شما (DSEQ، ارائه‌دهنده، هزینه)


##### بررسی لاگ‌ها

روی **Logs** کلیک کنید؛ باید راه‌اندازی Zebra را ببینید:

```bash
Loading config from environment variables
Mainnet network selected
Listening for peer connections on [::]:8233
Starting initial sync...
```

همگام‌سازی بسته به شبکه **چند ساعت تا چند روز** طول می‌کشد. به این موارد توجه کنید:

-> افزایش ارتفاع بلوک‌ها

-> اتصالات همتا (باید 10 تا 30 همتا باشد)

-> عدم وجود خطاهای تکراری


#### گام 7: دریافت آدرس نود

روی زبانه **Leases** و سپس **URIs** کلیک کنید.

چیزی شبیه به این خواهید دید:

```
zebra-8233: provider-hostname.com:31482
lightwalletd-9067: provider-hostname.com:32011
```

هر خط یک expose از نوع `global: true` است. نام شامل پورت `as` در SDL (8233، 9067) است. عدد پس از نام میزبان، **پورت نگاشت‌شده ارائه‌دهنده** است که هنگام ایجاد lease تخصیص داده می‌شود. سایر نودهای Zcash به `provider-hostname.com:31482` متصل می‌شوند. کیف‌پول‌های فشرده از URI مربوط به lightwalletd استفاده می‌کنند (TLS خاموش است، مگر اینکه خودتان TLS را خاتمه دهید).

کانتینر همچنان روی 8233 / 9067 گوش می‌دهد. آدرس عمومی همیشه همان URI است، مگر اینکه بعداً یک IP اختصاصی اضافه کنید (در این قالب وجود ندارد).

### گزینه‌های پیکربندی

#### تغییر به Testnet

SDL به‌طور پیش‌فرض روی Mainnet است. برای استفاده از Testnet:

-> **پیکربندی Mainnet را کامنت کنید** در بخش *env*:

   ```yaml
   # - "ZEBRA_NETWORK__NETWORK=Mainnet"
   # - "ZEBRA_NETWORK__LISTEN_ADDR=[::]:8233"
   ```

-> **پیکربندی Testnet را از حالت کامنت خارج کنید**:

   ```yaml
   - "ZEBRA_NETWORK__NETWORK=Testnet"
   - "ZEBRA_NETWORK__LISTEN_ADDR=[::]:18233"
   ```

-> **پورت expose‌شده را به‌روزرسانی کنید** در بخش *expose*:

   ```yaml
   # Comment out Mainnet port:
   # - port: 8233
   #   as: 8233
   #   to:
   #     - global: true
   #   proto: tcp

   # Uncomment Testnet port:
   - port: 18233
     as: 18233
     to:
       - global: true
     proto: tcp
   ```

-> **اختیاری: منابع را کاهش دهید** برای Testnet در *profiles.compute.zebra.resources*:

   ```yaml
   cpu:
     units: 2  # Down from 4
   memory:
     size: 8Gi  # Down from 16Gi
   storage:
     - size: 50Gi  # Down from 150Gi
   ```

-> **اختیاری: قیمت‌گذاری را کاهش دهید** در *profiles.placement.akash.pricing*:

   ```yaml
   amount: 5000  # Down from 10000
   ```

#### فعال‌سازی دسترسی RPC

RPC به دلایل امنیتی به‌طور پیش‌فرض غیرفعال است. برای فعال‌سازی آن:

**برای Mainnet:**

-> در بخش *env* از حالت کامنت خارج کنید:

   ```yaml
   - "ZEBRA_RPC__LISTEN_ADDR=0.0.0.0:8232"
   - "ZEBRA_RPC__COOKIE_DIR=/home/zebra/.cache/zebra"
   ```

-> پورت RPC مربوط به Mainnet را در *expose* از حالت کامنت خارج کنید:

   ```yaml
   - port: 8232
     as: 8232
     to:
       - global: false  # Keep internal for security
     proto: tcp
   ```

**برای Testnet:**

-> در بخش *env* از حالت کامنت خارج کنید:

   ```yaml
   - "ZEBRA_RPC__LISTEN_ADDR=0.0.0.0:18232"
   - "ZEBRA_RPC__COOKIE_DIR=/home/zebra/.cache/zebra"
   ```

-> پورت RPC مربوط به Testnet را در *expose* از حالت کامنت خارج کنید:

   ```yaml
   - port: 18232
     as: 18232
     to:
       - global: false
     proto: tcp
   ```

**هشدار**: اگر برای RPC مقدار *global: true* را تنظیم کنید، آن را در معرض اینترنت قرار می‌دهید. Zebra به‌طور پیش‌فرض از احراز هویت مبتنی بر cookie استفاده می‌کند، اما با این حال، مگر اینکه دقیقاً بدانید چه می‌کنید، این کار را انجام ندهید.

اگر RPC را با `global: true` expose کنید، آدرس عمومی همچنان یک **URI مربوط به lease** (`host:&lt;random-high-port&gt;`) است، نه `host:8232`. با `global: false` (این قالب)، RPC روی شبکه استقرار باقی می‌ماند (`zebra:8232` برای lightwalletd). Leaseهای دارای IP اختصاصی یک گزینه پولی جداگانه هستند و در SDL وجود ندارند.

#### فعال‌سازی متریک‌ها (Prometheus)

برای جمع‌آوری متریک‌ها جهت پایش:

-> در *env* از حالت کامنت خارج کنید:

   ```yaml
   - "ZEBRA_METRICS__ENDPOINT_ADDR=0.0.0.0:9999"
   ```

-> پورت متریک‌ها را در *expose* از حالت کامنت خارج کنید:

   ```yaml
   - port: 9999
     as: 9999
     to:
       - global: false
     proto: tcp
   ```

#### تنظیم منابع/قیمت‌گذاری

اگر پیشنهادی دریافت نمی‌کنید یا می‌خواهید هزینه را بهینه کنید:

**برای ارائه‌دهندگان با مشخصات پایین‌تر**، در بخش *profiles.compute.zebra.resources* کاهش دهید:

-> CPU: *units: 2* (حداقل برای سرعت همگام‌سازی معقول)

-> حافظه: *size: 12Gi* (حداقل برای پایداری)

-> فضای ذخیره‌سازی: *size: 120Gi* (حداقل برای mainnet)

**برای جذب پیشنهادهای بیشتر**، در *profiles.placement.akash.pricing* افزایش دهید:

-> Mainnet: مقدار *amount: 1000000* uakt/block را امتحان کنید

-> Testnet: مقدار *amount: 1000000* uakt/block را امتحان کنید

### به‌روزرسانی استقرار

آیا پس از استقرار نیاز به تغییر پیکربندی دارید؟

-> در Console به **My Deployments** بروید

-> استقرار Zebra خود را پیدا کنید

-> روی **«Update Deployment»** کلیک کنید

-> SDL را ویرایش کنید

-> روی **«Update»** کلیک کنید (Air: در Keplr امضا کنید؛ Console: روند پرداخت وب را تأیید کنید)

**توجه**: به‌روزرسانی، کانتینر شما را راه‌اندازی مجدد می‌کند. نود از وضعیت ذخیره‌شده خود (فضای ذخیره‌سازی پایدار) ادامه می‌دهد، اما انتظار 1 تا 2 دقیقه قطعی را داشته باشید.

### پایش

#### از طریق Console

-> **زبانه Logs**: لاگ‌های زنده کانتینر

-> **زبانه Shell**: دسترسی به یک shell داخل کانتینر (برای اشکال‌زدایی مفید است)

-> **زبانه Events**: رویدادهای Kubernetes (عمدتاً بی‌فایده، مگر اینکه چیزی خراب شده باشد)


#### از طریق RPC (در صورت فعال بودن)

اگر RPC را فعال کرده‌اید، می‌توانید نود خود را مانند یک فول‌نود معمولی zebrad پرس‌وجو کنید (چون واقعاً همین است!)

### بستن استقرار

وقتی کارتان تمام شد یا می‌خواهید پرداخت را متوقف کنید:

-> به **My Deployments** بروید

-> استقرار Zebra خود را پیدا کنید

-> روی **«Close Deployment»** کلیک کنید

-> تأیید کنید (Air: در Keplr امضا کنید؛ Console: در رابط کاربری Console تأیید کنید)

سپرده 5 AKT شما بازپرداخت می‌شود. **فضای ذخیره‌سازی پایدار** باید توسط ارائه‌دهنده حفظ شود، اما به آن تکیه نکنید؛ با آن مانند هر ارائه‌دهنده ابری دیگری رفتار کنید.

### عیب‌یابی

#### خطای «Insufficient funds»

در Air، کیف‌پول Keplr را با AKT/ACT تأمین کنید. در Console، روش پرداخت Console را شارژ کنید.

#### هیچ پیشنهادی نمایش داده نمی‌شود

یکی از این موارد:

-> قیمت‌گذاری شما بیش از حد پایین است (*amount* را در SDL افزایش دهید)

-> نیازمندی‌های منابع شما برای ارائه‌دهندگان موجود بیش از حد بالاست (CPU/حافظه/فضای ذخیره‌سازی را کاهش دهید)

-> بیشتر صبر کنید (گاهی ظاهر شدن پیشنهادها 60 تا 90 ثانیه طول می‌کشد)


#### استقرار در وضعیت «pending» گیر کرده است

ممکن است ارائه‌دهنده با مشکل مواجه باشد. استقرار را ببندید و ارائه‌دهنده دیگری را امتحان کنید.

#### لاگ‌های Zebra پیام «No peers connected» را نشان می‌دهند

این در چند دقیقه اول طبیعی است. Zebra همتاها را به‌طور خودکار پیدا می‌کند. اگر پس از بیش از 10 دقیقه ادامه داشت، ممکن است مشکل شبکه داشته باشید (در Akash بعید است).

#### خطاهای «Out of memory» در لاگ‌ها

در RAM صرفه‌جویی کرده‌اید. استقرار را ببندید و با حداقل 12Gi حافظه (16Gi توصیه می‌شود) دوباره مستقر کنید.

#### همگام‌سازی بی‌پایان طول می‌کشد

منظورتان از «بی‌پایان» چیست:

-> **چند ساعت**: طبیعی است

-> **چند روز**: برای mainnet از صفر نیز طبیعی است

-> **چند هفته**: مشکلی وجود دارد، لاگ‌ها را برای یافتن خطا بررسی کنید


### مدیریت هزینه

هزینه‌های خود را در Console یا Air پایش کنید:

-> **My Deployments** -> استقرار شما -> تخمین «Cost per month» را نشان می‌دهد

-> Air: موجودی AKT/ACT شما در Keplr با گذشت زمان کاهش می‌یابد. Console: موجودی پرداخت Console شما کاهش می‌یابد.


وقتی موجودی شما کم شود، Akash استقرار شما را به‌طور خودکار می‌بندد. **کیف‌پول خود را به‌طور دوره‌ای شارژ کنید** یا هشدار تنظیم کنید.

#### کاهش هزینه‌ها

-> **از Testnet استفاده کنید** برای آزمایش‌های غیرتولیدی (50% ارزان‌تر)

-> **CPU/حافظه را کاهش دهید** اگر به همگام‌سازی سریع نیاز ندارید

-> **ارائه‌دهندگان ارزان‌تر را انتخاب کنید** (همیشه عاقلانه نیست؛ زمان فعال بودن مهم است)


### Mainnet در مقابل Testnet

```markdown
----------------------------------------------------------------------------------
|            | Mainnet (default)               | Testnet                         |
---------------------------------------------------------------------------------|
| Purpose   | Production Zcash blockchain      | Testing and development         |
| Network   | ZEBRA_NETWORK__NETWORK=Mainnet   | ZEBRA_NETWORK__NETWORK=Testnet  |
| P2P Port  | 8233                             | 18233                           |
| RPC Port  | 8232                             | 18232                           |
| Sync time | Days                             | Hours                           |
| Storage   | 350GB+                           | 50GB                            |
| Resources | 4 CPU / 16GB RAM                 | 2 CPU / 8GB RAM                 |
| Cost      | ~$15/month                       | ~$5/month                       |
----------------------------------------------------------------------------------
```

اگر فقط روند استقرار را آزمایش می‌کنید، با Testnet شروع کنید. برای پیکربندی به بخش «تغییر به Testnet» در بالا مراجعه کنید.
