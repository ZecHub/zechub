# Zcash 지갑 동기화

## 요약

* 거래정보 보호 거래(Zcash)는 세부 정보를 숨기므로, 서버는 비트코인이나 이더리움 같은 투명 코인의 경우처럼 지갑 잔액을 단순히 조회할 수 없습니다.
* 라이트 지갑은 전문 서버(lightwalletd)에서 작은 “컴팩트 블록”을 내려받고, 개인 키로 관련 데이터를 직접 복호화합니다.
* 이러한 블록을 복호화하고 처리하는 데 시간이 걸리므로, 지갑은 더 빨리 자금을 사용할 수 있도록 동기화 속도를 높이는 방법을 사용합니다.
* 주요 방식으로는 Warp Sync(YWallet), 동기화 전 사용(Zcash Mobile Wallet SDK V2), Blaze Sync(Zecwallet), 그리고 제안된 DAGSync가 있습니다.
* 이러한 방식은 일반적으로 더 빠른 동기화를 위해 메모리나 처리 능력을 더 사용합니다.

## 핵심 설명

### Zcash 동기화 작동 방식

Zcash는 영지식 증명을 사용해 권한이 없는 당사자로부터 거래 세부 정보를 보호합니다. 이러한 프라이버시 보호 특성 때문에 라이트 지갑은 전체 블록체인을 로컬에 저장하지 않고 필요한 정보를 서버에 의존하므로 동기화가 더 어렵습니다. 비트코인이나 이더리움의 경우 서버는 블록체인을 색인화하고 계정 데이터를 빠르게 반환할 수 있습니다. 하지만 Zcash에서는 서버가 거래 세부 정보를 볼 수 없습니다. 그렇다면 라이트 지갑은 블록체인 전체를 직접 내려받아 복호화하지 않고 어떻게 잔액과 거래 내역을 동기화할 수 있을까요?

Zcash는 여러 방식을 결합해 이 문제를 해결합니다. 여기에는 풀 노드에서 데이터를 필터링하고 거래 식별에 필요한 데이터만 남기는 전문 서버인 lightwalletd가 있습니다. 이 데이터는 컴팩트 블록이라고 하며, 원래 블록보다 훨씬 작습니다. 라이트 지갑은 먼저 lightwalletd 서버에서 이러한 컴팩트 블록을 내려받은 다음 개인 키로 복호화합니다.

이러한 컴팩트 블록을 복호화하고 처리하는 데도 상당한 시간이 걸릴 수 있으며, 특히 블록마다 거래가 많을 때 그렇습니다. 그래서 지갑은 동기화 속도를 높여 가능한 한 빨리 자금을 사용할 수 있도록 다양한 방법을 사용합니다.

## 시각 자료 / 비유

블록체인을 잠긴 상자가 가득한 거대한 우편물 분류실이라고 생각해 보세요. 투명 코인의 경우 분류실 직원은 상자에 붙은 표식을 읽고 어느 상자가 여러분의 것인지 즉시 알려줄 수 있습니다. Zcash에서는 표식이 숨겨져 있으므로 지갑이 열 수 있는 상자를 찾기 위해 열쇠를 들고 조용히 하나씩 확인해야 합니다. 아래의 동기화 방식은 상자를 더 빠르게 확인하기 위한 서로 다른 전략입니다.

## 자세히 알아보기

### Warp Sync

Warp sync는 각 컴팩트 블록을 복호화하고 처리하는 중간 단계를 건너뛰고 최종 결과로 바로 넘어가는 YWallet 기능입니다.

이를 위해 각 단계를 거치지 않고 수학과 암호 기술을 사용해 최종 결과를 계산합니다.

Warp sync는 초당 수천 개의 블록을 처리할 수 있어 일반적인 동기화 방식보다 훨씬 빠릅니다. 따라서 YWallet 사용자는 계정에 수십만 건의 거래와 받은 노트가 있어도 빠르고 원활하게 이용할 수 있습니다.

YWallet는 단계를 건너뛰는 기법뿐만 아니라 여러 블록을 동시에 처리해 사용 가능한 하드웨어에 작업을 분산함으로써 처리 속도를 더욱 높일 수 있습니다.

[Warp Sync](https://ywallet.app/warp/)에서 더 알아보기

> 여기서는 Warp sync를 동기화 기법으로 설명합니다. Ywallet 자체는 더 이상 유지 관리되지 않으며 Ironwood용으로 업데이트되지 않으므로, 현재 설치할 수 있는 지갑이 아닙니다.

### 동기화 전 사용

동기화 전 사용은 Zcash Mobile Wallet SDK V2의 새로운 기능으로, 지갑의 전체 동기화가 끝날 때까지 기다리지 않고 지갑을 열자마자 자금을 사용할 수 있게 해줍니다. 이 기능은 지갑에서 사용할 수 있는 잔액을 더 빠르게 확인하고 사용자 경험을 개선합니다.

Spend-before-sync는 lightwalletd 서버의 블록을 비선형 순서로 처리하는 소형 블록(compact-blocks) 동기화 알고리즘을 사용합니다. 즉, 지갑은 한 블록이 완전히 처리될 때까지 기다린 다음 다음 블록으로 넘어가는 대신, 메모리와 처리 능력을 조금 더 사용해 블록체인의 여러 구간을 검색할 수 있습니다. 일반적으로 여러 범위를 검색하면서 오래된 블록을 다운로드하고 처리하는 동안 새로운 거래를 찾습니다. 최근의 미사용 노트가 발견되면 즉시 사용할 수 있게 됩니다.

### Blaze Sync

Zecwallet 팀이 개발한 Blaze sync는 가장 높은 최신 블록부터 시작해 과거 방향으로 블록체인을 검색하는 라이트 지갑용 동기화 알고리즘입니다.

이 방식은 지갑이 받은 노트보다 사용된 노트를 먼저 찾을 수 있게 하며, 이전에 미사용 상태였던 노트도 전체 동기화가 끝날 때까지 기다리지 않고 사용할 수 있도록 합니다.

또한 동기화 구성 요소를 서로 분리하는 Out-of-Order Sync를 사용합니다. 즉, 블록 내려받기, 시험 복호화 수행, witness 업데이트를 서로 분리해 병렬로 처리합니다. 이 방식은 메모리와 CPU 리소스를 더 사용하지만 동기화 속도를 5배 높입니다.

### DAGSync

DAGSync는 동기화 속도를 높여 Zcash 거래정보 보호 지갑의 사용자 경험을 개선하기 위해 제안된 동기화 알고리즘입니다.

이 알고리즘은 Zcash 지갑의 노트, witness, nullifier 사이의 의존 관계를 나타내기 위해 [방향성 비순환 그래프(DAG)](https://words.str4d.xyz/dagsync-graph-aware-zcash-wallets/)를 사용합니다.

DAG는 노드와 간선으로 구성된 데이터 구조이며, 각 간선에는 두 노드 사이의 관계를 나타내는 방향이 있습니다. DAG에는 순환이 없습니다. 즉, 어떤 노드에서 시작해 간선을 따라가더라도 다시 같은 노드로 돌아올 수 없습니다.

## 실질적인 영향

흥미롭게도 이러한 모든 메커니즘은 Zcash Security가 게시물 [확장 가능한 프라이빗 메시징](https://zecsec.com/posts/scalable-private-money-needs-scalable-private-messaging/)에서 제기한 질문과 프라이빗 결제 시스템과의 관계를 다루기 위한 것입니다. 일부 방식은 한 걸음 더 나아가 주소에만 해당하는 데이터를 제외한 모든 메모 데이터를 서버에서 내려받습니다. 리소스를 조금 더 사용하는 대신 프라이버시를 높이는 방식입니다.

또한 Zcash Foundation는 라이트 지갑의 성능을 개선할 다른 대안도 검토해 왔습니다. 그 사례가 [정보 비공개 메시지 검색(OMR)](https://zfnd.org/oblivious-message-retrieval/)입니다. 재단은 이 기법이 “Zcash 지갑 사용자에게 영향을 미친 최근 성능 문제에 대한 잠재적인 해결책인지 판단하기 위해” 연구해 왔습니다.

## 흔히 하는 실수

**lightwalletd 서버가 잔액을 알고 있다고 가정하는 것.** 서버는 컴팩트 블록만 전달하며, 지갑이 자체 키를 사용해 로컬에서 이를 복호화하고 해석합니다.

**동기화를 너무 일찍 중단하는 것.** 일부 방식은 전체 동기화가 끝나기 전에 최근에 사용할 수 있는 자금을 제공하지만, 오래된 거래 내역과 노트는 여전히 처리 중일 수 있습니다.

**Zcash 동기화를 투명 체인 동기화와 직접 비교하는 것.** 속도가 느린 것은 프라이버시를 지키기 위해 감수해야 하는 비용일 수 있으며 결함이 아닙니다. 지갑은 공개 코인 서버가 계정을 공개적으로 읽어 처리하는 작업을 대신 수행합니다.
