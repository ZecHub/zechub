# Zcash 라이트 지갑 노드

## 요약

* 대부분의 사용자는 라이트 지갑을 통해 Zcash을 사용합니다. 라이트 지갑은 전체 블록체인을 다운로드하는 대신, 이미 해당 작업을 마친 서버와 통신합니다.
* 현재 라이트 지갑을 지원하는 소프트웨어는 2가지입니다. Go로 작성된 최초의 서비스인 **lightwalletd**와 Rust로 작성된 새로운 인덱서인 **Zaino**입니다.
* 키는 기기 밖으로 나가지 않으며, 서버는 자금을 사용할 수도 없고 완전히 거래정보 보호된 거래 안의 금액과 메모를 읽을 수도 없습니다.
* 서버가 파악하기 쉬운 정보는 IP 주소와 활동 시점입니다. 거래정보 보호 거래는 블록체인에서 일어나는 일을 보호하지만, 서버와의 연결까지 보호하지는 않습니다.
* Tor은 IP 식별자를 제거합니다. `zcash_client_backend` 기반 지갑에서 사용할 수 있으며, ZODL에서는 고급 설정의 옵션으로 제공됩니다.
* 지갑에서 사용하는 서버를 변경하거나 직접 운영할 수 있습니다. lightwalletd와 Zaino 모두 오픈 소스입니다.

## 핵심 설명

대부분의 사용자는 라이트 지갑을 통해 Zcash을 사용합니다. 라이트 지갑은 전체 블록체인을 다운로드하는 대신, 이미 해당 작업을 마친 서버와 통신합니다. 이 페이지에서는 이러한 서버가 무엇인지, 사용자에 관해 무엇을 볼 수 있고 볼 수 없는지, Tor을 통해 연결을 라우팅하는 방법, 그리고 지갑에서 사용하는 서버를 변경하는 방법을 설명합니다.

현재 라이트 지갑을 지원하는 소프트웨어는 2가지입니다. **lightwalletd**는 Go로 작성된 최초의 서비스입니다. **Zaino**는 zcashd 폐기 작업의 일환으로 만들어진, Rust로 작성된 새로운 인덱서입니다.

### 라이트 지갑 서버의 역할

라이트 지갑 서버는 지갑과 Zcash 블록체인 사이에서 작동하며, 대역폭을 효율적으로 사용하는 체인 정보를 제공합니다. 서버는 다음 3가지 작업을 수행합니다.

간결한 블록을 제공합니다. 전체 블록 대신 지갑이 거래정보 보호 주소로 결제된 내역을 감지하고, 노트가 사용된 내역을 감지하며, 증인을 갱신하는 데 필요한 정보만 담은 간결한 형식으로 전송합니다.

거래를 중계합니다. 사용자가 거래를 전송하면 지갑은 완성된 거래를 서버에 전달하고, 서버가 이를 네트워크에 브로드캐스트합니다.

현재 높이와 지갑에 필요한 수수료 정보 등 체인에 대한 질문에 답합니다.

개인 정보와 관련된 작업은 여전히 지갑에서 직접 수행합니다. 지갑은 키를 보관하고, 블록을 시험 복호화하여 노트를 찾으며, 기기에서 거래를 생성하고 서명합니다.

### 서버가 볼 수 있는 정보와 볼 수 없는 정보

여기서 잘못 이해하기 쉽습니다. 키가 기기 밖으로 나가지 않는다고 해서 서버가 사용자에 관해 아무것도 알 수 없는 것은 아닙니다.

여기서 참고한 자료는 [Zcash 지갑 앱의 위협 모델](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)입니다. 이 주제가 중요하다면 전체 내용을 읽어보시는 것이 좋습니다. 이 문서는 여러 유형의 공격자를 설명합니다. 이 페이지에서 중요한 유형은 지갑과 인터넷 간의 트래픽, 그리고 서버와 인터넷 간의 트래픽을 감시할 수 있는 공격자입니다. 서버 운영자는 지갑이 직접 연결되므로 본질적으로 이러한 상황의 일부에 놓여 있습니다.

먼저 보호되는 정보를 살펴보겠습니다. 서버를 장악한 공격자를 포함해 위협 모델에 등장하는 모든 공격자가 “사용자의 암호화 키 자료(spending keys, viewing keys, seed phrase 등)를 알아낼 수 없고”, 자금을 훔치거나 의도하지 않은 자금 전송을 유도할 수도 없습니다. 완전히 거래정보 보호된 거래 안의 금액과 메모는 암호화된 상태로 유지됩니다.

다음으로 보호되지 않는 정보가 있습니다. 위협 모델은 트래픽을 관찰하는 공격자에 대한 알려진 취약점으로 다음을 제시합니다.

| 취약점 | 방법 |
|:--|:--|
| 사용자가 누구인지 파악 | “공격자는 사용자의 IP 주소를 알고 있으며, 이를 통해 사용자의 실제 신원을 알아낼 수 있습니다” |
| 사용자의 대략적인 위치 파악 | IP 주소를 “지리 위치 데이터베이스에서 조회하여 위치를 추정” |
| 거래정보 보호 거래를 전송하거나 받은 사실과 시점 파악 | 전송 시 “대역폭 사용량이 늘어나 연결이 암호화되어 있어도 이를 볼 수 있습니다”. 문서에서는 전송과 수신 행위 자체는 서버에도 보인다고 설명합니다 |
| 시간에 따른 거래 횟수 파악 | 더 긴 기간에 걸쳐 관찰한 동일한 대역폭 패턴 |
| 반복되는 결제 패턴 파악 | 활동이 일어나는 시점을 관찰 |
| 특정 주소가 사용자의 주소인지 추론 | 이미 주소를 알고 있는 공격자는 “해당 주소로 자금을 보내고, 지갑이 주소 정보를 가져올 때 대역폭 급증이 있는지 관찰”할 수 있습니다 |

또한 문서에서는 일반적인 상황을 “사용자와 lightwalletd 서버 운영자 사이의 신뢰 관계”를 전제로 한다고 설명합니다.

따라서 솔직하게 요약하면 이렇습니다. 라이트 지갑 서버는 사용자의 돈을 쓸 수 없으며, 거래정보 보호 거래의 금액이나 메모를 읽을 수도 없습니다. 하지만 IP 주소와 활동 시점을 파악하기는 쉽고, 이 두 정보를 결합하면 사용자의 상당한 정보를 알 수 있습니다. 거래정보 보호 거래는 블록체인에서 일어나는 일을 보호합니다. 하지만 그것만으로 서버와의 연결이 감춰지는 것은 아닙니다.

## 시각 자료 / 비유

세상에 인쇄된 모든 신문을 보관하는 공공 도서관을 떠올려 보세요. 풀 노드는 자료실 전체를 집으로 가져가는 독자입니다. 라이트 지갑은 사서에게 매일 요약본을 요청하는 독자와 같습니다. 요약본은 자신과 관련된 내용이 있는지 알아보기에 충분한 정보만 담은 얇은 종이입니다.

요약본은 봉인되어 있습니다. 사서는 어떤 항목이 사용자에게 중요한지 알 수 없는 상태로 요약본을 만들고, 사용자는 집에서 자신의 키로 이를 엽니다. 이것이 간결한 블록이며, 기기에서 이를 여는 과정이 시험 복호화입니다.

하지만 사서는 어떤 독자가 몇 시에 들어왔는지, 얼마나 두꺼운 묶음을 들고 나갔는지 여전히 볼 수 있습니다. 이것이 IP 주소와 활동 시점입니다. 봉투를 아무리 잘 봉인해도 안내 데스크에서는 이 정보가 보입니다. Tor은 익명 배달원을 보내는 것과 같습니다. 사서는 여전히 같은 묶음을 건네지만, 더 이상 어느 집으로 가는지는 알 수 없습니다.

## 자세히 알아보기

### Tor을 통한 라우팅

Tor은 IP 주소와 지갑 트래픽의 연결을 끊어 위 표에서 가장 강력한 식별 정보를 제거합니다.

많은 Zcash 지갑의 기반이 되는 Rust 라이브러리에서 이를 지원합니다. zcash_client_backend에는 Tor 모듈이 포함되어 있습니다. [Arti](https://tpo.pages.torproject.net/core/arti/)를 기반으로 하는 이 모듈은 Tor의 Rust 구현이므로, 별도의 Tor 클라이언트를 함께 제공하지 않아도 지갑이 동기화, 거래 브로드캐스트, 가격 조회를 Tor을 통해 라우팅할 수 있습니다.

**Zaino** 개발자들도 위협 모델을 직접 인용하며 같은 주장을 합니다. “Zcash 인덱싱 서버에서 클라이언트의 신원을 감추려면 Nym 또는 Tor 같은 익명 전송 프로토콜을 사용해야 합니다.”

**ZODL**에서는 Tor이 고급 설정의 옵션입니다. 지갑의 릴리스 노트에서는 “메타데이터 노출을 줄이고 싶다면” 수동 연결 모드를 선택한 뒤 “고급 설정에서 Tor을 활성화”하라고 안내합니다. 또한 지갑 복원 전에 Tor을 켤 수 있도록 제안합니다. 지갑을 복원하는 시점에는 새 IP 주소가 지갑의 전체 기록과 연결될 수 있기 때문입니다.

주의할 점은 2가지입니다. Tor은 서버에서 IP 주소를 숨기지만, 요청을 통해 서버가 파악하는 정보는 바꾸지 않습니다. 또한 어니언 라우팅은 지연 시간을 늘리므로 동기화에 더 오래 걸립니다. 직접 서버를 운영하면 운영자가 본인이 되므로 다른 방식으로 신뢰 문제를 피할 수 있습니다.

### Zaino, Rust 인덱서

[Zaino](/zcash-tech/zaino)는 Zingo 팀이 Rust로 작성한 인덱서입니다. zcashd 폐기 작업의 일환으로 lightwalletd를 대체하기 위해 만들어졌습니다. 이 인덱서는 라이트 클라이언트, 풀 클라이언트, 블록 탐색기에 서비스를 제공하며, “Zebra 또는 zcashd 풀 검증 노드”가 보유한 체인 데이터를 읽습니다.

현재 활발히 개발되고 있으며, 2026년 9월에 버전 0.10.1이 출시되었습니다. 가능한 경우 lightwalletd와의 하위 호환성을 유지하는 것을 목표로 하므로, 지갑을 다시 작성하지 않고도 이 인덱서를 가리키도록 설정할 수 있습니다.

Zaino에는 아키텍처 다이어그램이 포함된 별도 페이지가 있으므로, 이 페이지에서는 라이트 지갑 서버로서의 역할만 다룹니다.

### 직접 운영하기

가장 확실한 방법은 직접 운영자가 되는 것입니다. 그러면 신뢰 문제가 완전히 사라집니다. 두 서버 모두 오픈 소스입니다. [lightwalletd](https://github.com/zcash/lightwalletd)는 Go로 작성되었으며, [Zaino](https://github.com/zingolabs/zaino)는 Rust로 작성되었습니다. 두 서버 모두 풀 검증 노드에서 데이터를 읽으므로, [Zebra](/zcash-tech/zebra-full-node)도 필요합니다. 해당 zec.rocks 서버는 오픈 소스 Helm 차트와 Docker Compose 키트인 [Zcash Stack](/guides/zcash-stack)을 사용해 배포합니다. 이 키트는 Zebra와 lightwalletd를 함께 실행합니다.

## 실제 적용

### 서버 목록

[hosh.zec.rocks](https://hosh.zec.rocks/zec) 대시보드에서는 공개 서버와 상태를 추적하며, 실제로 운영 중인 서버를 확인할 수 있습니다. [status.zec.rocks](https://status.zec.rocks/)에서는 서비스 상태를 확인할 수 있습니다.

작성 당시 대시보드에 등록된 서버는 다음과 같습니다.

| 서버 | 참고 사항 |
|:--|:--|
| zec.rocks:443 | 지역별 엔드포인트인 na.zec.rocks, eu.zec.rocks, ap.zec.rocks, sa.zec.rocks도 함께 등록되어 있습니다 |
| zec-node.cakewallet.com:443 | Cake Wallet 도메인에 있습니다 |
| zec.0xrpc.io:443 | 여러 체인의 공개 엔드포인트를 무료로 제공하는 0xRPC가 운영하며, 용량 유지를 위한 기부를 요청합니다 |
| zaino.unsafe.zec.rocks:443 | Zaino 인스턴스입니다. 호스트 이름을 확인하고 실험용으로 취급하세요 |
| testnet.zec.rocks:443 | 테스트넷입니다. Zaino 테스트넷 인스턴스는 zaino.testnet.unsafe.zec.rocks에 등록되어 있습니다 |

이 목록을 그대로 믿기보다는 대시보드를 확인하세요. 운영자는 바뀔 수 있으며, 이런 페이지의 정보는 오래될 수 있습니다.

### 지갑에서 서버 변경하기

신뢰하는 운영자를 선택하거나, 여러 운영자에게 활동을 분산하거나, 직접 운영하는 서버를 지정하려는 경우 유용합니다.

아래 메뉴 경로는 이 페이지를 업데이트한 시점에는 맞았지만, 지갑 인터페이스는 바뀔 수 있으므로 정확한 경로가 아닌 참고 정보로 봐주세요. 고급 설정이나 서버 옵션을 찾아보세요.

#### ZODL

이전 이름은 Zashi입니다. 오른쪽 위의 톱니바퀴를 누른 다음 고급 설정을 선택하세요. Tor도 같은 화면에 있습니다. 서버가 오래되어 동기화에 실패한 경우에는 ZODL에서 서버 전환 바로 가기도 제공합니다.

#### Zkool

Ywallet의 후속 제품으로, 같은 개발자가 만들었습니다(Ywallet 자체는 더 이상 유지 관리되지 않으며 Ironwood 이후 네트워크를 따라갈 수 없습니다). 계정 화면 상단의 톱니바퀴 아이콘(설정 열기)을 누른 다음 Light Node Server 필드로 이동합니다. 옆의 목록 버튼을 누르면 알려진 서버 중에서 선택할 수 있으며, 그 아래의 Direct / Tor / Nym / Proxy 전환 버튼으로 지갑의 연결 방식을 설정합니다.

## 흔히 하는 실수

**서버가 거래 내용을 읽을 수 있다고 생각하기**. 서버는 거래 내용을 읽을 수 없습니다. 키는 기기에 남아 있으며, 완전히 거래정보 보호된 거래 안의 금액과 메모는 서버가 장악된 경우에도 암호화된 상태로 유지됩니다.

**“거래정보 보호”를 “익명 연결”로 이해하기**. 거래정보 보호 거래는 블록체인에서 일어나는 일을 보호합니다. IP 주소와 활동 시점은 별개의 계층이며, 서버가 보는 것은 바로 이 계층의 정보입니다.

**Tor이 모든 흔적을 없앤다고 생각하기**. Tor은 서버에서 IP 주소를 숨기지만, 요청을 통해 서버가 파악하는 정보는 바꾸지 않으며 동기화 지연 시간을 늘립니다.

**위키 페이지의 서버 목록을 그대로 믿기**. 운영자는 바뀔 수 있습니다. 지갑을 서버에 연결하기 전에 실제로 운영 중인 서버가 무엇인지 [hosh.zec.rocks](https://hosh.zec.rocks/zec)에서 확인하세요.

## 요약

라이트 지갑을 사용하면 디스크 공간을 많이 차지하지 않고 거래정보 보호 구역을 이용할 수 있어 좋은 선택입니다. 다만 무엇을 맞바꾸는지 분명히 알아야 합니다. 서버는 자금을 가져가거나 거래정보 보호 금액을 읽을 수 없지만, IP 주소와 거래 시점을 파악하기는 쉽습니다. Tor을 통해 라우팅하거나, 운영자를 신중하게 선택하거나, 직접 서버를 운영하세요.
