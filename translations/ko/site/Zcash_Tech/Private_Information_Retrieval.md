# 비공개 정보 검색

## 요약

- 비공개 정보 검색(Private Information Retrieval, PIR)을 사용하면 서버가 어떤 항목을 요청했는지 알지 못한 채 기기에서 서버 데이터베이스의 항목 하나를 가져올 수 있습니다
- Zcash에는 이 기능이 필요합니다. 비공개 지갑이 서버에 자신의 거래가 무엇인지 물으면 정체가 드러날 수 있기 때문입니다
- 현재 지갑은 필요한 것보다 훨씬 많은 데이터를 다운로드하고 검색합니다. 이 때문에 동기화가 느려집니다
- PIR을 사용하면 지갑이 자신의 데이터만 비공개로 가져올 수 있어, 프라이버시를 지키면서 병목을 해소할 수 있습니다
- Zcash에서 활발히 연구 중인 분야로, 이론적으로는 강력하며 실제 지갑에서 쓸 수 있도록 실용화가 진행되고 있습니다
- 이미 이용할 수 있는 실시간 시연이 있습니다. [ZecBlock Private](https://private.zecblock.com)는 거래, 블록, 주소를 모두 다루는 최초의 완전한 PIR 기반 Zcash 블록 탐색기입니다

## 대상 독자

- 비공개 지갑이 어떤 코인인지 노출하지 않고 자신의 코인을 어떻게 찾는지 궁금했던 사람
- Zcash 확장성 작업과 함께 PIR이라는 말을 자주 접하는 초보자
- 암호학적 원리보다 개념을 먼저 알고 싶은 독자
- 실제로 작동하는 PIR 기반 블록 탐색기가 궁금한 사람

## PIR이 Zcash에서 해결하는 문제

Zcash는 거래의 수신자가 누구인지 숨깁니다. 이 프라이버시 때문에 난감한 질문이 생깁니다. 네트워크가 어떤 거래가 내 것인지 알 수 없다면, 내 지갑은 그 거래를 어떻게 찾을까요?

현재 답은 단호합니다. 지갑은 서버에 어떤 거래가 내 것인지 물을 수 없습니다. 그런 질문을 하면 Zcash가 숨기려는 정보가 그대로 드러나기 때문입니다. 그래서 지갑은 대신 많은 데이터를 다운로드한 뒤 각 항목을 로컬에서 검사해 자기 것인지 확인합니다. 이 방법은 작동하고 프라이버시도 지켜 주지만, 느리고 부담이 큽니다. 이런 검색 작업은 지갑 동기화가 더디게 느껴지는 주요 원인 중 하나입니다.

이상적인 방법은 지갑이 서버에 자신의 데이터만 정확히 요청해 받아 오면서, 서버는 무엇을 요청받았는지 전혀 알지 못하게 하는 것입니다. 이것이 바로 비공개 정보 검색이 제공하는 기능입니다.

## PIR이란?

비공개 정보 검색은 클라이언트가 서버 데이터베이스의 항목 하나를 읽을 때, 어떤 항목을 읽었는지 서버에 알리지 않도록 하는 암호학적 방법입니다.

원하는 책을 정확히 받아 가면서도 사서가 어떤 책을 건넸는지 알지 못하는 도서관을 떠올려 보세요. 원하는 항목을 받으면서 관심사는 비공개로 유지됩니다. PIR은 이 아이디어를 모든 데이터베이스에 적용한 수학적 방식입니다.

이 개념은 수십 년 동안 암호학 분야에서 연구되어 왔습니다. 1995년 Chor, Goldreich, Kushilevitz, Sudan이 여러 서버를 사용하는 방식을 설명하며 처음 제안했고, 1997년 Kushilevitz와 Ostrovsky가 최초의 단일 서버 버전을 발표했습니다. Zcash가 발명한 것이 아니라, 확립된 분야이며 Zcash가 이제 실제로 해결하기 어려운 문제에 적용하고 있습니다.

## PIR의 기본 작동 방식

PIR을 구현하는 방법은 크게 두 가지이며, 둘의 차이는 중요합니다.

첫 번째는 여러 서버를 사용합니다. 클라이언트가 여러 서버에 질의의 일부씩 보내고, 답변을 로컬에서 조합합니다. 어느 서버도 요청 내용을 알아낼 만큼 충분한 정보를 보지 못합니다. 효율적이지만, 서버끼리 공모하지 않는다는 전제가 필요하며 현실에서는 이를 보장하기 어렵습니다.

두 번째는 여러 참여자 대신 단일 서버와 영리한 암호학을 사용합니다. 이 방식에서 클라이언트는 동형 암호라는 특수한 도구를 이용합니다. 여러 서버가 서로 공모하지 않는다는 전제가 필요 없으므로 실제 배포에 가장 유용한 방향입니다.

## 작동 원리: 동형 암호

동형 암호는 데이터가 암호화된 상태로 서버가 연산할 수 있게 하는 암호화 방식입니다. 서버는 원래 값을 보지 않고도 올바른 암호화된 답변을 만듭니다.

이 방식을 이용한 단일 서버 PIR의 원리는 다음과 같습니다. 클라이언트는 목록에서 세 번째 항목을 원합니다. 그래서 세 번째 위치에는 암호화된 ‘예’를, 다른 모든 위치에는 암호화된 ‘아니요’를 담은 질의를 만듭니다. 서버가 보기에는 이 질의는 의미 없는 잡음일 뿐이며, 어느 위치가 ‘예’인지 알 수 없습니다.

그런 다음 서버는 동형 암호의 특수한 성질을 이용해 데이터베이스와 암호화된 질의를 결합합니다. 저장된 각 항목에 해당하는 암호화된 ‘예’ 또는 ‘아니요’를 곱하고 결과를 모두 더합니다. 그 결과 클라이언트가 원한 항목만 담은 하나의 암호화 패키지가 만들어지며, 어느 항목인지 드러나지 않습니다. 클라이언트는 패키지를 복호화해 항목을 읽습니다. 서버는 질문의 내용도 모른 채 답변한 셈입니다.

대칭 PIR이라고 하는 더 강력한 방식은 두 번째 보장도 제공합니다. 클라이언트는 요청한 항목만 알 수 있고 데이터베이스의 다른 항목에 대해서는 아무것도 알 수 없습니다. 이렇게 하면 클라이언트뿐 아니라 데이터베이스도 보호할 수 있습니다.

## 기술 독자를 위한 자세한 설명

현대의 단일 서버 방식은 격자 암호학을 기반으로 하며, 가장 흔히 학습 오류 가정을 사용합니다. 클라이언트의 질의는 암호문 벡터로, 대상 인덱스에는 1을, 나머지에는 0을 암호화해 담습니다. 이 암호화는 덧셈 동형이므로 서버는 복호화하지 않고 암호문을 더하고 평문 데이터베이스 항목을 곱할 수 있습니다.

서버는 데이터베이스를 행렬로 취급하고 암호화된 선택 벡터를 적용한 뒤, 복호화하면 원하는 행이 나오는 암호문 하나를 반환합니다. 질의는 무작위 잡음과 구별할 수 없으므로 서버는 인덱스에 관한 정보를 얻지 못합니다.

역사적으로 가장 큰 장애물은 비용이었습니다. 단순한 방식에서는 서버가 각 질의마다 데이터베이스의 모든 항목에 접근해야 하므로 연산 비용이 많이 들고, 암호문도 커서 대역폭 비용도 큽니다. 최근 연구는 사전 처리로 이 문제를 해결하고 있습니다. SimplePIR, FrodoPIR 같은 방식은 서버가 데이터베이스를 미리 준비하고 각 클라이언트에 작은 힌트를 제공할 수 있게 합니다. 작업의 상당 부분을 오프라인 단계로 옮겨 실시간 질의를 빠르게 처리하는 방식입니다. 유용한 부수 효과로, 격자 기반 구성은 양자 공격에도 안전한 것으로 여겨집니다. 이는 포스트 양자 프라이버시를 향한 Zcash의 더 광범위한 움직임과도 맞닿아 있습니다.

## Zcash에서의 PIR

PIR은 Zcash를 대규모 환경에서도 비공개이면서 빠르게 만들려는 노력의 일부입니다.

앞서 설명한 지갑 검색 병목을 해결하는 것이 목표입니다. Valar Group에서는 지갑이 서버에 어떤 항목을 요청했는지 알리지 않고 자신의 데이터를 가져올 수 있도록 비공개 정보 검색 기술을 개발하고 있습니다. 구체적인 적용 사례 중 하나는 널리파이어를 비공개로 확인하는 것입니다. 널리파이어는 노트가 사용될 때 공개되는 고유한 표식으로, 같은 자금이 두 번 사용되는 것을 막습니다. 지갑은 특정 널리파이어가 나타났는지, 즉 노트가 아직 사용되지 않았는지 확인해야 하는 경우가 많습니다. 현재 서버를 통해 확인하면 어떤 노트에 관해 묻는지 드러날 수 있습니다. 비공개 정보 검색을 이용하면 지갑은 어떤 널리파이어에 관심이 있는지 밝히지 않고 질문할 수 있습니다. 이 작업은 프라이빗 지갑의 성능을 제한하는 요소를 없애려는 Project Tachyon와 새로운 노드 소프트웨어를 비롯한 다른 확장성 작업과 함께 진행되고 있습니다.

현재 단계에 대해서는 솔직해야 합니다. 완성되어 배포된 기능이 아니라, 활발한 연구와 엔지니어링이 진행 중입니다. 개념은 확립되어 있고 방향도 정해졌지만, 일반 기기에서 일상적으로 쓰는 지갑에 충분히 효율적인 PIR을 구현하는 것이 지금 해결 중인 어려운 과제입니다.

## 실시간 사례: ZecBlock Private

2026년 11월 ZecBlock는 거래, 블록, 주소 조회에 비공개 정보 검색을 사용하는 탐색기 버전인 **ZecBlock Private**(private.zecblock.com)를 출시했습니다.

이는 PIR 기반으로 구축된 최초의 완전한 Zcash 블록 탐색기입니다. 거래, 블록, 주소를 모두 다룹니다. 이전 PIR 탐색기 시연은 주소 잔액과 같은 제한된 질의만 지원했습니다.

### 비공개 조회 방식

- 브라우저는 질의(거래 ID, 블록 높이/해시 또는 주소)를 전송하기 전에 완전히 암호화합니다.
- 서버는 어떤 레코드가 요청되었는지 알지 못한 채 공개된 데이터 전체를 처리합니다.
- 서버는 브라우저만 복호화할 수 있는 암호화된 응답 하나를 반환합니다.
- 존재하는 항목을 검색하는 것과 존재하지 않는 항목을 검색하는 것은 구별할 수 없습니다. 요청의 크기와 형태가 같기 때문입니다.

검색이 끝날 때마다 사이트는 정확히 무엇을 전송했는지 간단히 보여 주므로 프라이버시가 어떻게 보장되는지 쉽게 확인할 수 있습니다.

### 검증 단계

각 데이터 공개본에는 서명이 붙습니다. 브라우저는 결과를 표시하기 전에 모든 결과의 서명을 검증하므로, 악의적이거나 버그가 있는 서버가 다른 데이터로 바꿔치기할 수 없습니다.

### 데이터 최신성

새 블록은 몇 초마다 공개됩니다. 비공개 탐색기의 데이터는 일반적으로 정규 ZecBlock 탐색기보다 약 20초 이내로 늦습니다.

### 대역폭 비용

PIR은 서버가 데이터 전체에 접근해야 하므로 일반 조회보다 비용이 많이 듭니다.

- 거래 조회: 업로드 약 1.2MB
- 주소 조회: 업로드 약 0.4MB

이는 서버가 질의 내용을 전혀 알지 못하게 하는 데 드는 실질적인 비용입니다.

### 클라이언트 구현

브라우저 클라이언트는 Rust → WebAssembly 래퍼입니다(현재 `prototype/pir-browser` 아래 ZecBlock 저장소에 있습니다). Valar Group의 오픈 소스 PIR 라이브러리를 기반으로 만들었습니다. 이 래퍼는 아직 독립형 npm 패키지로 공개되지 않았지만, 공개가 계획되어 있습니다.

### 지갑 PIR과의 차이

ZecBlock Private는 **공개된** 체인 데이터에 PIR을 적용하는 사례를 보여 줍니다. 어떤 거래, 블록, 주소인지 밝히지 않고 이미 알고 있는 거래, 블록, 주소를 조회합니다. 하지만 열람 키에 속하는 노트를 비공개로 찾아내거나, 사용되지 않은 노트의 널리파이어를 비공개로 확인하는 더 어려운 지갑 문제를 해결하지는 않습니다. 이 문제들은 여전히 활발한 연구 분야입니다.

## 흔한 오해

- PIR은 요청한 항목을 숨겨 주지만, 서버에 접속했다는 사실 자체까지 반드시 숨기는 것은 아닙니다. 네트워크 수준의 메타데이터는 별개의 문제입니다
- PIR은 Zcash에만 쓰이는 기술이 아닙니다. 일반적인 암호학 도구이며, Zcash는 이를 지갑 프라이버시에 적용하고 있습니다
- PIR을 통한 동기화 속도 향상은 진행 중인 목표이며, 지갑에 이미 구현된 기능은 아닙니다
- 현재 방식은 모든 데이터를 다운로드해 로컬에서 검색하는 것으로, 프라이버시는 지키지만 느립니다. PIR은 프라이버시를 유지하면서 속도 저하를 없애려 합니다
