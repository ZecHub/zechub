# NU7

> NU7은 2026년 11월 6일(UTC 02:34, 미국 시간대 기준 11월 5일 저녁) 3,543,405번 블록에서 Zcash Mainnet에 활성화되었으며, 그 이후 계속 가동 중입니다.

이 문서에서 알아볼 내용: NU7에서 바뀐 점(더 빠른 블록, 쉴드 풀 작업 한도, 수수료 재순환, 버전 4 트랜잭션 종료), 그대로 유지된 점, 그리고 노드 운영자, 지갑, 거래소, 채굴자가 해야 했던 일입니다.

NU7은 Zcash [네트워크 업그레이드](../start-here/network-upgrades)이며, [ZIP 259](https://zips.z.cash/zip-0259)에 따라 배포되었습니다. 블록 간격을 75초에서 25초로 줄이고, 한 블록에 포함되는 쉴드 풀 작업 수를 제한했으며, 향후 채굴자에게 재발행할 수 있도록 트랜잭션 수수료의 60%를 유통량에서 제거하기 시작했습니다. 또한 버전 4 트랜잭션을 무효화해 기존 Sprout 풀을 폐쇄했습니다. 새로운 트랜잭션 형식은 도입하지 않았습니다. 합의 브랜치 ID는 `0x77190ad9`입니다.

중요한 이유. NU7 이전에는 첫 확인까지 평균 75초를 기다려야 했습니다. 상점 계산대에서 결제하거나 거래소에 입금하거나 크로스체인 스왑을 할 때는 느린 속도입니다. NU7은 ZEC을 더 발행하지 않고 확인 시간을 약 25초로 줄였습니다. 블록당 보상이 3분의 1로 줄어 하루 발행량은 그대로 유지되었습니다. 또한 블록 보상이 줄어든 뒤 네트워크 보안 비용을 마련하기 위한 메커니즘을 추가한 첫 업그레이드입니다.

Zcash이 처음이신가요? 먼저 [ZEC이란 무엇인가Zcash](../start-here/what-is-zec-and-zcash)와 [쉴드 풀](../using-zcash/shielded-pools)을 읽고 돌아오세요.

## TL;DR

쉽게 말해, 이제 블록은 25초마다 생성되고 하루 신규 ZEC 발행량은 그대로이며, 각 수수료의 일부는 나중에 채굴자에게 지급하도록 보관되고, 기존 Sprout 풀은 폐쇄되었습니다.

- **25초 블록**([ZIP 218](https://zips.z.cash/zip-0218)): 첫 확인까지 약 25초가 걸립니다. 이전에는 75초였습니다. 블록 보조금은 1.5625에서 0.52083333 ZEC으로 줄어 하루 약 1,800 ZEC이 계속 발행됩니다.
- **쉴드 풀 작업 한도**(ZIP 218): 모든 풀을 합쳐 블록당 쉴드 풀 작업은 최대 330개이며, 풀별 한도도 적용됩니다. 이를 통해 최악의 경우에도 블록 검증 및 지갑 동기화 비용을 이전보다 낮게 유지합니다.
- **네트워크 지속 가능성 메커니즘**([ZIP 235](https://zips.z.cash/zip-0235) + [ZIP 237](https://zips.z.cash/zip-0237)): 각 블록의 트랜잭션 수수료 중 60%를 유통량에서 제외하고, 8,939,664번 블록(2031년 2월경으로 예상)부터 채굴자에게 재발행합니다. 2,100만 개 공급량 한도는 바뀌지 않았습니다.
- **버전 4 트랜잭션 무효화**([ZIP 2003](https://zips.z.cash/zip-2003)): 지갑은 v5 또는 v6 트랜잭션을 만들어야 합니다. Sprout은 v4로만 전송할 수 있으므로, 아직 Sprout에 남은 자금은 이제 동결되었습니다.
- **소프트웨어**: [Zebra 7.0.0](https://github.com/ZcashFoundation/zebra/releases/tag/v7.0.0) 이상은 NU7을 따릅니다. NU7을 지원하는 `zcashd` 릴리스는 없습니다.

## 시각적 비유

블록체인을 기차 노선이라고 생각해 보세요. NU7 이전에는 75초마다 기차가 출발했고 2 MB에 들어가는 만큼 승객을 태울 수 있었습니다. NU7에서는 25초마다 기차가 출발하고, 기관사에게 기존 운임의 3분의 1을 지급해 하루 총액은 그대로 유지합니다. 또한 가장 무거운 승객(쉴드 풀 작업)이 한 기차에 탈 수 있는 수를 제한해 어느 기차든 검사에 지나치게 오래 걸리지 않도록 합니다.

## NU7에서 바뀐 점

### 25초 블록 목표 간격(ZIP 218)

- 난이도 조정의 목표가 75초마다 한 블록에서 **25초마다 한 블록**으로 바뀌어 블록 생성 빈도가 세 배가 되었습니다.
- 블록 보조금은 3분의 1로 줄었습니다. 현재 반감기 기간에는 블록당 **0.52083333 ZEC**입니다(이전에는 1.5625 ZEC). 하루 발행량은 약 1,800 ZEC으로 유지됩니다(하루 1,152개 블록에서 3,456개 블록으로 증가).
- 반감기는 계속 4년마다 일어납니다. 블록이 빨라져 다음 반감기는 **6,132,390번 블록**으로 앞당겨졌으며, 25초 간격이 유지되면 2028년 11월 말경으로 예상됩니다(ZIP 259).
- 난이도 평균 산정 구간이 17개에서 **102개 블록**으로 늘어 조정 시 비슷한 시간 범위를 계속 살펴봅니다.
- 기본 트랜잭션 만료 기간이 40개에서 **120개 블록**으로 늘어 약 50분으로 유지됩니다.

### 쉴드 풀 작업 한도(ZIP 218)

이제 각 블록에는 공통 한도와 풀별 한도가 적용됩니다.

| 한도 | 블록당 |
|---|---|
| 모든 풀의 쉴드 풀 작업 합계 | 330 |
| Orchard 작업 | 330 |
| Ironwood 작업 | 330 |
| Sapling 입력 + 출력 | 300 |
| Sprout JoinSplits | 허용되지 않음 |

NU7 이전에는 2 MB 블록 하나에 Orchard 작업 약 617개, Ironwood 작업 약 617개, 또는 Sapling 출력 약 2,107개를 담을 수 있었고 풀별 한도는 없었습니다. ZIP 218은 새 한도를 정해 블록 수가 세 배가 되더라도 노드와 지갑 동기화의 최악 조건이 이전보다 나아지도록 합니다(예를 들어 라이트 클라이언트의 쉴드 풀 동기화 최대 대역폭은 하루 약 271 MB에서 169 MB로 줄어듭니다). 한편 Orchard 프로토콜 처리량은 두 배 이상 증가합니다(2개 작업 트랜잭션 기준 초당 약 2.9건에서 6.6건).

### 네트워크 지속 가능성 메커니즘(ZIP 235 + ZIP 237)

- **수수료 제거(ZIP 235):** 각 블록의 트랜잭션 수수료 중 60%를 유통량에서 제외하고, 나머지 40%는 이전처럼 채굴자에게 지급합니다. 소각과 달리 제외된 ZEC은 나중에 다시 발행할 수 있도록 추적됩니다.
- **재발행(ZIP 237):** 제외된 ZEC은 NSM Value Balance라는 공개 합의 상태에 보관됩니다. 과거에 채굴자가 청구하지 않고 남긴 368.58 ZEC을 NU7에서 초기값으로 설정했습니다. **8,939,664번 블록**(2031년 2월경으로 예상)부터 각 블록은 기존 반감기 일정에 더해 잔액의 일정 부분을 발행합니다.
- 공급량 한도는 늘어나지 않습니다. 잔액이 0이 되면 발행량은 기존 반감기 일정과 정확히 같아집니다.
- NU7은 사용자 자발적 제거인 [ZIP 233](https://zips.z.cash/zip-0233)이나 반감기를 부드러운 곡선으로 대체하는 [ZIP 234](https://zips.z.cash/zip-0234)를 배포하지 **않았습니다**. 코인 보유자 투표에서 반감기를 유지하는 설계를 ZIP 237에서 선택했습니다.
- 수수료 제거와 재발행에 관한 자세한 내용은 [Network Sustainability Mechanism](./Network_Sustainability_Mechanism.md).

### 버전 4 트랜잭션 금지(ZIP 2003)

- NU7부터 모든 버전 4 트랜잭션이 무효입니다. Sprout 전송뿐 아니라 투명 주소만 사용하는 트랜잭션과 v4 형식으로 만들어진 Sapling 트랜잭션도 포함됩니다. 버전 5(NU5)와 버전 6([Ironwood](../zcash-tech/ironwood)) 트랜잭션은 바뀌지 않았습니다.
- Sprout 전송은 v4 형식으로만 존재하므로 [Sprout](../zcash-tech/sprout) 풀의 자금은 더 이상 사용할 수 없습니다. [자금 복구](../using-zcash/recovering-funds)를 참조하세요.

### 그 밖의 변경 사항

- 25초 블록에 맞게 개발 기금 규칙을 개정했습니다([ZIP 207](https://zips.z.cash/zip-0207) 개정 2, [ZIP 214](https://zips.z.cash/zip-0214) 개정 3). 기금 스트림 주소 목록도 업데이트했습니다([ZIP 2008](https://zips.z.cash/zip-2008)).
- NU7 노드는 Mainnet에서 네트워크 프로토콜 버전 **170190**을 알리고 활성화 이후 구버전 피어와 연결을 끊습니다.

## NU7에서 바뀌지 않은 점

- **새 트랜잭션 형식은 없습니다.** NU7은 Ironwood이 v6 트랜잭션을 도입한 직후 지갑과 파서가 다시 이전하도록 하는 일을 의도적으로 피했습니다.
- **공급량 한도나 4년 반감기 주기는 바뀌지 않았습니다.**
- **코인베이스 성숙도는 바뀌지 않았습니다.** 채굴한 코인은 여전히 사용하기 전에 100개 블록을 기다려야 합니다(이제 약 2시간이 아니라 약 42분).
- **새 쉴드 풀이 없습니다.** Ironwood(NU6.3)이 최신 풀로 남아 있으며, Orchard는 Ironwood 이후 계속 그래 왔듯 전송 전용으로 유지됩니다.

## 그룹별 조치 사항

- **노드 운영자:** [Zebra 7.0.0](https://github.com/ZcashFoundation/zebra/releases/tag/v7.0.0) 이상을 실행해야 합니다. Zebra 7은 처음 시작할 때 데이터베이스를 v28 형식에서 v29 형식으로 이전합니다. Zebra 6.x는 v29를 읽을 수 없으므로 업그레이드 전에 `state/v28`을 백업하세요. `zcashd`에는 NU7 릴리스가 없습니다(최신 릴리스는 2026년 6월의 6.20.0입니다). Zebra 책의 [zcashd API 이전 가이드](https://zebra.zfnd.org/user/zcashd-api-migration-guide.html)는 각 `zcashd` RPC를 Zebra, [Zallet](../zcash-tech/zallet) 또는 대체 항목에 대응시킵니다. [전체 노드](../zcash-tech/full-nodes) 및 [보안 강화 Zebra 가이드](../guides/hardened-zebrad)를 참조하세요.
- **지갑:** v4 트랜잭션 생성을 중단하고, 120블록 기본 만료 기간을 사용하며, 3블록 앵커 깊이(이제 약 1.25분)를 유지하고, 블록별 작업 한도를 준수해야 합니다. 단독으로 한도를 초과하는 트랜잭션은 채굴될 수 없습니다.
- **거래소 및 결제 서비스:** 이제 확인에 25초가 걸리므로 같은 확인 횟수로 보장되는 시간은 3분의 1이 됩니다. 습관적으로 이전 횟수를 유지하지 말고, 원하는 시간과 보안 수준에 맞춰 입금 확인 횟수를 다시 검토하세요.
- **채굴자 및 풀:** 채굴 소프트웨어와 템플릿은 새 보조금, 수수료 분배, 작업 한도를 적용해야 합니다. 이전 규칙으로 만든 블록은 거부됩니다.

## 흔한 오해

- **“예전 노드가 아직 실행 중이니 괜찮다.”** NU7에 한해 ZIP 259는 업그레이드 전 소프트웨어가 활성화 전에 자동 종료되는 일반 규칙을 면제했습니다. 6.x Zebra 또는 `zcashd` 노드는 구 규칙으로 온라인 상태를 유지하면서 실제 체인에서 조용히 이탈할 수 있습니다. 노드가 3,543,405보다 높은 블록 높이를 보고하고 블록 탐색기와 일치하는지 확인하세요.
- **“블록이 빨라지면 ZEC이 더 많이 발행된다.”** 그렇지 않습니다. 블록당 보조금이 3분의 1로 줄어 하루 발행량은 바뀌지 않습니다.
- **“수수료의 60%는 영원히 소각된다.”** 그렇지 않습니다. NSM이 유통량에서 제외한 뒤 채굴자에게 재발행합니다. 공급량 한도는 바뀌지 않았습니다.
- **“v4 변경의 영향을 받는 건 Sprout 사용자뿐이다.”** 투명 주소만 사용하는 트랜잭션과 Sapling 트랜잭션을 포함해 v4 트랜잭션을 계속 만드는 모든 지갑이나 스크립트가 작동을 멈췄습니다. 대기 중이던 v4 트랜잭션은 활성화 시 무효가 되었으며, 다시 서명하는 것만으로 유효하게 만들 수 없습니다.
- **“블록 수 기준 설정은 그대로 적용된다.”** 확인 횟수, 만료 기간, 잠금 시간, 타임아웃처럼 블록 수로 측정하는 값은 실제 시간 기준으로 세 배 빠르게 지나갑니다.

| 용어 | 쉬운 설명 |
|---|---|
| Block target spacing | 난이도 조정이 목표로 삼는 블록 간 평균 시간: NU7 이후 25초 |
| Block subsidy | 각 블록에서 새로 생성되는 ZEC으로, 채굴자와 개발 기금 스트림이 나눠 가짐 |
| Shielded action | 트랜잭션 내 쉴드 풀 작업 한 단위(Orchard 또는 Ironwood 작업, 또는 Sapling 입력이나 출력) |
| Network Sustainability Mechanism (NSM) | 수수료 일부를 유통량에서 제외하고 향후 채굴자에게 재발행하는 규칙 |
| NSM Value Balance | 유통량에서 제외되어 재발행을 기다리는 ZEC의 공개 누계 |
| Version 4 transaction | Sapling의 트랜잭션 형식으로, NU7에서 무효화됨. v5와 v6는 계속 유효함 |
| Consensus branch ID | 합의 규칙 집합을 식별하는 번호. 서명에 이 번호가 포함되므로 구 규칙에 따라 서명한 트랜잭션은 새 규칙에서 무효임 |

## FAQ

**NU7은 언제 활성화되었나요?** 2026년 11월 6일 02:34 UTC에 Mainnet의 3,543,405번 블록에서 활성화되었습니다. Testnet은 그보다 앞선 2026년 10월 4일 4,465,026번 블록에서 활성화되었습니다.

**블록 보상은 바뀌었나요?** 블록당 보상은 1.5625 ZEC에서 0.52083333 ZEC으로 줄었습니다. 하루 기준으로는 바뀌지 않았으며 어느 쪽이든 약 1,800 ZEC입니다.

**내 Sprout ZEC은 사라졌나요?** 더 이상 옮길 수 없습니다. Sprout을 전송하려면 v4 트랜잭션이 필요한데 이제 무효이기 때문입니다. 실제로 어떤 의미인지 [자금 복구](../using-zcash/recovering-funds)를 참조하세요.

**새 지갑이 필요한가요?** NU7을 지원하는 지갑 버전이 필요합니다. ZecHub의 [지갑](../using-zcash/wallets) 페이지에서 어떤 지갑이 NU7과 호환되는지 확인할 수 있습니다.

**수수료 재발행은 언제 시작되나요?** Mainnet의 8,939,664번 블록에서 시작되며, 블록 평균 간격이 25초로 유지되면 2031년 2월경으로 예상됩니다.

**NU7은 왜 새 트랜잭션 형식을 건너뛰었나요?** Ironwood의 v6 형식 직후 지갑과 파서가 다시 이전해야 하는 상황을 피하고, 수수료 분배가 블록별로 계산되어 새 트랜잭션 필드가 필요하지 않았기 때문입니다.

## 이해도 확인

1. NU7 이후에도 하루 ZEC 발행량이 그대로인 이유는 무엇인가요?
2. 유통량에서 제외된 수수료 60%는 어떻게 되나요?
3. NU7 이후 Sprout 자금을 사용할 수 없는 이유는 무엇인가요?
4. 이번 업그레이드에서 한 번도 업그레이드하지 않은 노드가 특히 위험한 이유는 무엇인가요?

정답: (1) 블록당 보조금이 3분의 1로 줄어든 반면 블록 생성 빈도는 세 배가 되었기 때문입니다. (2) NSM Value Balance에 들어가 8,939,664번 블록부터 채굴자에게 재발행됩니다. (3) Sprout 전송은 v4 형식으로만 존재하며, NU7에서 해당 형식을 무효화했기 때문입니다. (4) ZIP 259는 자동 종료를 면제했으므로 구버전 노드가 잘못된 체인에서 계속 실행될 수 있습니다.
