# NU7

> NU7은 2026년 11월 6일(02:34 UTC, 미국 시간대 기준 11월 5일 저녁) 블록 3,543,405에서 Zcash 메인넷에 활성화되었으며, 그 이후 계속 적용되고 있습니다.

이 문서에서는 NU7에서 달라진 점(더 빠른 블록, 거래정보 보호 작업 수 제한, 수수료 재분배, 버전 4 거래의 종료)과 그대로 유지된 점, 그리고 노드 운영자, 지갑, 거래소, 채굴자가 해야 했던 일을 알아봅니다.

NU7은 Zcash에서 [네트워크 업그레이드](../start-here/network-upgrades)로 배포한 [ZIP 259](https://zips.z.cash/zip-0259)입니다. 블록 간격을 75초에서 25초로 줄이고, 블록 하나에 포함할 수 있는 거래정보 보호 작업 수를 제한했습니다. 또한 거래 수수료의 60%를 유통량에서 제외해 향후 채굴자에게 다시 발행하기 시작했으며, 버전 4 거래를 무효화해 기존 Sprout 풀을 폐지했습니다. 새로운 거래 형식은 도입하지 않았습니다. 합의 브랜치 ID는 `0x77190ad9`입니다.

중요한 이유. NU7 이전에는 첫 확인을 받기까지 평균 75초를 기다려야 했습니다. 상점 계산대 결제, 거래소 입금, 크로스체인 스왑을 처리하기에는 느린 속도였습니다. NU7에서는 ZEC을 더 많이 발행하지 않으면서 대기 시간을 약 25초로 줄였습니다. 블록당 보상이 3분의 1로 줄어 하루 발행량은 그대로 유지되었습니다. 블록 보상이 줄어든 뒤 네트워크 보안을 위한 재원 마련을 목표로 한 메커니즘을 추가한 첫 업그레이드이기도 합니다.

Zcash이 처음이신가요? 먼저 [ZEC이란 무엇이며 Zcash](../start-here/what-is-zec-and-zcash)와 [거래정보 보호 구역](../using-zcash/shielded-pools) 페이지를 읽은 다음 이 문서로 돌아오세요.

## 요약

쉽게 말해, 이제 블록은 25초마다 생성되고 하루 신규 ZEC 발행량은 그대로 유지됩니다. 수수료의 일부는 향후 채굴자를 위해 적립되며, 기존 Sprout 풀은 폐쇄되었습니다.

- **25초 블록**([ZIP 218](https://zips.z.cash/zip-0218)): 첫 확인까지 걸리는 시간이 75초에서 약 25초로 줄었습니다. 블록 보조금은 1.5625에서 0.52083333 ZEC으로 감소했으므로, 하루 약 1,800 ZEC이 계속 발행됩니다.
- **거래정보 보호 작업 수 제한**(ZIP 218): 모든 풀을 합해 블록당 거래정보 보호 작업을 최대 330개로 제한하고, 풀별 상한도 설정했습니다. 이를 통해 최악의 경우에도 블록 검증 및 지갑 동기화 비용이 이전보다 낮게 유지됩니다.
- **네트워크 지속 가능성 메커니즘**([ZIP 235](https://zips.z.cash/zip-0235) + [ZIP 237](https://zips.z.cash/zip-0237)): 블록 거래 수수료의 60%가 유통량에서 제외되었다가 나중에 채굴자에게 다시 발행됩니다. 이 절차는 블록 8,939,664부터 시작될 예정이며, 예상 시점은 2031년 2월경입니다. 총발행량 상한인 2,100만 개는 바뀌지 않았습니다.
- **버전 4 거래 무효화**([ZIP 2003](https://zips.z.cash/zip-2003)): 지갑은 v5 또는 v6 거래를 만들어야 합니다. Sprout은 v4로만 사용할 수 있으므로, Sprout에 남아 있는 자금은 이제 동결되었습니다.
- **소프트웨어**: [Zebra 7.0.0](https://github.com/ZcashFoundation/zebra/releases/tag/v7.0.0) 이상 버전은 NU7을 따릅니다. NU7을 지원하는 `zcashd` 릴리스는 없습니다.

## 비유로 이해하기

블록체인을 기차 노선이라고 생각해 보세요. NU7 이전에는 75초마다 기차가 출발했고, 2MB 공간에 들어가는 만큼 승객을 태울 수 있었습니다. NU7에서는 25초마다 기차가 출발합니다. 운전기사에게는 이전 운임의 3분의 1을 지급해 하루 총액은 그대로 유지하고, 한 기차에서 검사하는 데 시간이 가장 오래 걸리는 승객(거래정보 보호 작업)의 수를 제한해 어느 기차도 검사에 지나치게 오래 걸리지 않도록 합니다.

![NU7 in four panels: blocks are three times faster and new ZEC per day stays the same; 60% of fees go into a public reserve for rewards from 2031; the legacy Sprout pool from 2016 can no longer be spent; 98.9% of voting ZEC chose to keep halvings](https://raw.githubusercontent.com/ZecHub/zechub/main/site/Zcash_Tech/assets/nu7-four-changes.png)

## NU7에서 달라진 점

### 25초 블록 목표 간격 (ZIP 218)

- 난이도 조정 목표가 75초마다 블록 하나에서 **25초마다 블록 하나**로 바뀌어 블록이 3배 더 자주 생성됩니다.
- 블록 보조금이 3분의 1로 줄었습니다. 현재 반감기 기간에는 블록당 **0.52083333 ZEC**입니다(이전에는 1.5625 ZEC). 하루 발행량은 약 1,800 ZEC으로 그대로 유지됩니다(하루 블록 수는 1,152개에서 3,456개로 증가).
- 반감기는 여전히 4년마다 발생합니다. 블록 생성 속도가 빨라지면서 다음 반감기 블록은 **6,132,390**으로 변경되었으며, 25초 간격을 기준으로 2028년 11월 말경으로 예상됩니다(ZIP 259).
- 난이도 평균 산정 구간이 17개 블록에서 **102개 블록**으로 늘어나 조정 시 여전히 비슷한 시간 범위를 살펴봅니다.
- 기본 거래 만료 시간이 40개 블록에서 **120개 블록**으로 늘어나 약 50분으로 유지됩니다.

### 거래정보 보호 작업 수 제한 (ZIP 218)

이제 각 블록에는 풀 간에 공유되는 예산과 풀별 상한이 적용됩니다.

| 제한 | 블록당 |
|---|---|
| 모든 풀의 거래정보 보호 작업 합계 | 330 |
| Orchard 작업 | 330 |
| Ironwood 작업 | 330 |
| Sapling 입력 + 출력 | 300 |
| Sprout JoinSplits | 허용 안 됨 |

NU7 이전에는 2MB 블록 하나에 Orchard 작업 약 617개, Ironwood 작업 약 617개, 또는 Sapling 출력 약 2,107개를 넣을 수 있었으며 풀별 제한은 없었습니다. ZIP 218에서는 새로운 상한을 설정해 블록이 3배 더 자주 생성되더라도 노드와 지갑 동기화에 필요한 최악의 비용이 이전보다 낮도록 했습니다(예: 라이트 클라이언트의 최대 거래정보 보호 동기화 대역폭은 하루 약 271MB에서 169MB로 감소). 동시에 Orchard 프로토콜 처리량은 2배 넘게 증가합니다(작업 2개를 포함하는 거래의 경우 초당 약 2.9건에서 6.6건으로 증가).

### 네트워크 지속 가능성 메커니즘 (ZIP 235 + ZIP 237)

- **수수료 제외(ZIP 235):** 블록마다 거래 수수료의 60%를 유통량에서 제외하고, 나머지 40%는 이전과 같이 채굴자에게 지급합니다. 소각과 달리 제외된 ZEC은 나중에 다시 발행할 수 있도록 추적됩니다.
- **재발행(ZIP 237):** 제외된 ZEC은 NSM 가치 잔액이라는 공개 합의 상태에 보관됩니다. 이 잔액은 NU7에서 과거에 채굴자가 청구하지 않고 남겨 둔 가치로 초기화되었습니다. 블록 **8,939,664**부터(2031년 2월경으로 예상) 각 블록에서 해당 잔액의 고정된 비율을 일반 반감기 일정에 더해 발행합니다.
- 총발행량 상한은 늘어나지 않습니다. 잔액이 0이 되면 발행량은 기존 반감기 일정과 정확히 같아집니다.
- NU7에서는 [ZIP 233](https://zips.z.cash/zip-0233)(사용자가 자발적으로 유통량에서 제외하는 방식)이나 [ZIP 234](https://zips.z.cash/zip-0234)(반감기를 완만한 곡선으로 대체하는 방식)을 배포하지 않았습니다. 코인 보유자 투표에서는 반감기를 유지하는 설계가 ZIP 237에서 선택되었습니다.
- 수치(초기 잔액 368.58 ZEC, 블록당 재발행 비율, 블록 8,939,664부터 시작하는 이유)는 [네트워크 지속 가능성 메커니즘](./Network_Sustainability_Mechanism.md) 페이지에서 확인할 수 있습니다.

### 버전 4 거래 사용 금지 (ZIP 2003)

- NU7부터 모든 버전 4 거래는 무효입니다. Sprout 전송뿐 아니라 v4 형식으로 만들어진 투명 전용 거래와 Sapling 거래도 무효입니다. 버전 5(NU5) 및 버전 6([Ironwood](../zcash-tech/ironwood)) 거래는 변경되지 않았습니다.
- Sprout 전송은 v4 형식으로만 존재하므로 [Sprout](../zcash-tech/sprout) 풀에서는 더 이상 자금을 사용할 수 없습니다. [자금 복구](../using-zcash/recovering-funds)를 참조하세요.

### 기타 변경 사항

- 25초 블록에 맞게 개발 기금 규칙을 개정해 자금 지원 흐름이 작동하도록 했습니다([ZIP 207](https://zips.z.cash/zip-0207) 개정 2, [ZIP 214](https://zips.z.cash/zip-0214) 개정 3). 자금 지원 흐름 주소 목록도 업데이트했습니다([ZIP 2008](https://zips.z.cash/zip-2008)).
- NU7 노드는 메인넷에서 네트워크 프로토콜 버전 **170190**을 알리고, 활성화 후에는 이전 버전 피어와 연결을 끊습니다.

## NU7에서 바뀌지 않은 점

- **새로운 거래 형식은 도입하지 않았습니다.** NU7은 Ironwood에서 v6 거래가 도입된 직후 지갑과 파서가 다시 마이그레이션해야 하는 상황을 의도적으로 피했습니다.
- **총발행량 상한과 4년 반감기 주기는 변경되지 않았습니다.**
- **코인베이스 성숙도는 변경되지 않았습니다.** 채굴한 코인은 계속 100개 블록이 지나야 사용할 수 있습니다(이제 약 2시간이 아니라 약 42분).
- **새로운 거래정보 보호 구역은 추가되지 않았습니다.** Ironwood(NU6.3)이 여전히 최신 풀입니다. Orchard은 Ironwood 이후 계속 사용 전용으로 유지됩니다.

## 각 그룹이 해야 했던 일

- **노드 운영자:** [Zebra 7.0.0](https://github.com/ZcashFoundation/zebra/releases/tag/v7.0.0) 이상을 실행해야 합니다. Zebra 7은 처음 실행할 때 데이터베이스를 v28 형식에서 v29 형식으로 변경합니다. Zebra 6.x는 v29를 읽을 수 없으므로 업그레이드 전에 `state/v28`을 백업하세요. `zcashd`에는 NU7 릴리스가 없습니다(최신 릴리스는 2026년 6월의 6.20.0입니다). Zebra 책의 [zcashd API 마이그레이션 안내서](https://zebra.zfnd.org/user/zcashd-api-migration-guide.html)에서는 각 `zcashd` RPC를 Zebra, [Zallet](../zcash-tech/zallet) 또는 대체 기능에 대응시켜 설명합니다. [풀 노드](../zcash-tech/full-nodes) 및 [강화된 Zebra 안내서](../guides/hardened-zebrad)를 참조하세요.
- **지갑:** v4 거래 생성을 중단하고, 기본 만료 시간 120개 블록을 사용하며, 앵커 깊이 3개 블록(이제 약 1.25분)을 유지하고, 블록당 작업 수 제한을 준수해야 합니다. 제한을 단독으로 초과하는 거래는 채굴될 수 없습니다.
- **거래소 및 결제 서비스:** 이제 확인 한 번에 25초가 걸리므로 같은 확인 횟수로 보장되는 시간은 이전의 3분의 1입니다. 기존 숫자를 관성적으로 유지하기보다 원하는 시간과 보안 수준에 맞춰 입금 확인 횟수를 다시 검토하세요.
- **채굴자 및 풀:** 채굴 소프트웨어와 템플릿에서 새로운 보조금, 수수료 배분, 작업 수 제한을 사용해야 합니다. 이전 규칙으로 만든 블록은 거부됩니다.

## 흔히 하는 실수

- **“이전 노드가 아직 실행 중이니 괜찮습니다.”** NU7에 한해 ZIP 259에서는 업그레이드 전 소프트웨어가 활성화 전에 자동으로 종료되는 일반 규칙을 면제했습니다. 6.x Zebra 또는 `zcashd` 노드는 이전 규칙을 적용한 채 온라인 상태를 유지하다가 실제 체인에서 조용히 이탈할 수 있습니다. 노드가 3,543,405보다 높은 높이를 표시하고 블록 탐색기의 정보와 일치하는지 확인하세요.
- **“블록이 빨라지면 ZEC이 더 많이 발행됩니다.”** 그렇지 않습니다. 블록당 보조금이 3분의 1로 줄었으므로 하루 발행량은 그대로입니다.
- **“수수료의 60%는 영원히 소각됩니다.”** 그렇지 않습니다. NSM이 해당 수수료를 유통량에서 제외했다가 나중에 채굴자에게 재발행합니다. 총발행량 상한은 그대로입니다.
- **“v4 변경은 Sprout 사용자에게만 영향을 미칩니다.”** 투명 전용 거래와 Sapling 거래를 포함해 v4 거래를 계속 생성하는 모든 지갑이나 스크립트가 작동을 멈췄습니다. 활성화 시 대기 중이던 v4 거래도 무효가 되었으며, 다시 서명하는 것만으로 유효하게 만들 수는 없습니다.
- **“블록 수 기준 설정은 그대로 적용됩니다.”** 확인 횟수, 만료, 잠금 시간, 시간 초과 등 블록 수로 측정되는 모든 것은 실제 시간 기준으로 이제 3배 빠르게 지나갑니다.

## 용어집

| 용어 | 쉬운 설명 |
|---|---|
| Block target spacing | 난이도 조정이 목표로 삼는 블록 간 평균 시간입니다. NU7 이후에는 25초입니다. |
| Block subsidy | 각 블록에서 새로 생성되는 ZEC으로, 채굴자와 개발 기금 지원 흐름에 배분됩니다. |
| Shielded action | 거래에서 수행되는 거래정보 보호 작업 1단위입니다(Orchard 작업, Ironwood 작업, 또는 Sapling 입력이나 출력). |
| Network Sustainability Mechanism (NSM) | 수수료 일부를 유통량에서 제외하고 향후 채굴자에게 다시 발행하는 규칙입니다. |
| NSM Value Balance | 유통량에서 제외되어 재발행을 기다리는 ZEC의 공개 누적 잔액입니다. |
| Version 4 transaction | Sapling의 거래 형식으로, NU7에 의해 무효화되었습니다. v5와 v6는 여전히 유효합니다. |
| Consensus branch ID | 합의 규칙 집합을 식별하는 숫자입니다. 서명은 이 값에 연결되므로 이전 규칙에 맞춰 서명한 거래는 새로운 규칙에서는 무효입니다. |

## 자주 묻는 질문

**NU7은 언제 활성화되었나요?** 메인넷 블록 3,543,405에서 2026년 11월 6일 02:34 UTC에 활성화되었습니다. 테스트넷에서는 더 일찍, 2026년 10월 4일 블록 4,465,026에서 활성화되었습니다.

**블록 보상은 바뀌었나요?** 블록당 보상은 바뀌었습니다. 1.5625 ZEC 대신 0.52083333 ZEC입니다. 하루 보상은 바뀌지 않았습니다. 어느 쪽이든 약 1,800 ZEC입니다.

**제 Sprout ZEC은 사라졌나요?** 더 이상 옮길 수 없습니다. Sprout을 사용하려면 v4 거래가 필요한데, v4 거래는 이제 무효이기 때문입니다. 실제로 어떤 의미인지 알아보려면 [자금 복구](../using-zcash/recovering-funds)를 참조하세요.

**새 지갑이 필요한가요?** NU7을 지원하는 지갑 버전이 필요합니다. ZecHub의 [지갑](../using-zcash/wallets) 페이지에서 어떤 지갑이 NU7과 호환되는지 확인할 수 있습니다.

**수수료 재발행은 언제 시작되나요?** 메인넷 블록 8,939,664부터 시작되며, 블록 평균 간격이 25초로 유지된다면 2031년 2월경으로 예상됩니다.

**NU7은 왜 새로운 거래 형식을 도입하지 않았나요?** Ironwood의 v6 형식이 도입된 직후 지갑과 파서가 다시 마이그레이션해야 하는 상황을 피하기 위해서입니다. 또한 수수료 배분은 블록 단위로 계산되므로 거래에 새로운 필드가 필요하지 않았습니다.

## 이해도 확인

1. NU7 이후에도 하루 ZEC 발행량이 그대로 유지되는 이유는 무엇인가요?
2. 유통량에서 제외된 수수료 60%는 어떻게 되나요?
3. NU7 이후에는 왜 Sprout 자금을 사용할 수 없나요?
4. 한 번도 업그레이드하지 않은 노드가 이번 업그레이드에서 특히 위험한 이유는 무엇인가요?

답변: (1) 블록당 보조금은 3분의 1로 줄었지만 블록 생성 빈도는 3배가 되었기 때문입니다. (2) NSM 가치 잔액에 들어가 블록 8,939,664부터 채굴자에게 재발행됩니다. (3) Sprout 사용은 v4 형식으로만 가능하며, NU7에서 해당 형식이 무효화되었기 때문입니다. (4) ZIP 259에서는 자동 종료가 면제되었으므로, 이전 노드가 잘못된 체인에서 계속 실행될 수 있습니다.
