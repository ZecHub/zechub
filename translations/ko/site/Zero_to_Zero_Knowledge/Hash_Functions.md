## 1부: 해시 함수

오늘은 블록체인에서 사용하는 암호학의 핵심 요소인 **해시 함수**를 살펴봅니다. 시리즈 후반부에서는 해시 함수의 속성을 활용하는 몇 가지 주제를 다룰 예정입니다.

### 해시 함수란 무엇인가요?

해시 함수는 길이에 제한이 없는 입력을 받아 고정된 길이의 출력을 생성합니다.

- **해시할 메시지** = 입력
- **사용되는 알고리즘** = 해시 함수
- **생성된 출력** = 해시 값

### 암호학적 해시 함수의 속성

암호학적 해시 함수에는 다음 **3가지 속성**이 있어야 합니다.

1. **일방향성** - 해시 함수를 역으로 계산하는 것이 현실적으로 불가능해야 합니다.
2. **충돌 저항성** - 서로 다른 두 입력이 같은 출력으로 해시되어서는 안 됩니다.
3. **결정성** - 어떤 입력이든 해시 함수는 항상 같은 결과를 내야 합니다.

---

### 일반적인 해시 함수

해시 함수에는 여러 종류가 있습니다. 몇 가지 예를 들어 보겠습니다.

- 보안 해시 알고리즘 (**SHA-3**)
- 메시지 다이제스트 알고리즘 5 (**MD5**)
- **BLAKE2b** - Zcash 키 파생에 사용됩니다.

**BLAKE2 소개:** https://www.blake2.net

### 해시 함수의 실제 활용 사례

#### 1. 무결성 해싱(데이터 무결성 검사)
데이터 무결성 검사는 “무결성 해싱”의 한 사례입니다. 데이터 파일의 체크섬을 생성하고 데이터가 올바르다는 확신을 사용자에게 제공하는 데 사용됩니다.

![Integrity Hashing example](/content-images/Fn_Or0MWIAI6sgx-9aab89b808.webp)

#### 2. Merkle 트리(해시 트리)
**해시 트리** 또는 **Merkle 트리**는 데이터 블록의 암호학적 해시가 표시된 가지와 잎 노드로 이루어집니다.

![Merkle Tree diagram](/content-images/Fn_O7ndWIAY5PA-8e30e442ed.webp)

Merkle 트리는 **암호학적 커밋먼트 방식**의 한 예입니다. 트리의 루트는 커밋먼트로 간주되며, 잎 노드는 원래 커밋먼트에 속한다는 것이 증명됩니다.

P2P 네트워크에서 저장되거나 전송되는 데이터를 검증하여, 피어로부터 받은 데이터가 변조되지 않았음을 확인합니다.

#### 3. Zcash의 노트 커밋먼트 트리
Zcash **Sapling** 및 **Orchard** 거래정보 보호 구역에서는 **노트 커밋먼트 트리**를 사용해 합의를 기준으로 거래의 유효성을 검증하는 동시에 송신자, 수신자 및 사용된 금액을 완전히 숨깁니다.

#### 4. 서명 해시(Bitcoin 방식 블록)
**SHA256**은 Bitcoin 체인의 각 블록을 변경 불가능하게 만드는 데 사용되는 “서명 해시”의 한 예입니다. 채굴자는 새 블록을 만들 때 이전 블록의 해시, 현재 블록의 모든 거래 해시(hashMerkleRoot), 타임스탬프, 임의의 값 또는 네트워크 난이도를 사용합니다.

![SHA256 block diagram](/content-images/Fn_PaVZXoAApHPf-936e479067.webp)

#### 5. Equihash(Zcash 채굴)
**Equihash**은 Zcash 채굴에 사용되는 해싱 알고리즘입니다. Komodo 및 Horizen과 같은 네트워크에서도 사용됩니다.

**Equihash: 일반화된 생일 문제에 기반한 비대칭 작업 증명**(Biryukov and Khovratovich): https://eprint.iacr.org/2015/946
