# ZecHub 해커톤 빌더 가이드

## 요약

- 코드를 작성하기 전에 왜 만드는지 파악하세요. 복잡성보다 유용성이 중요합니다.
- 단순하게 유지하세요. 잘 만든 작은 아이디어가 끝내지 못한 큰 아이디어보다 낫습니다.
- Zcash 인프라 스택을 일찍 익히세요. 가장 어려운 과정입니다.
- 앱에서 자금을 이동한다면 메인넷에서 작동해야 합니다. 테스트넷에서 개발한 뒤 메인넷에서 입증하세요.
- 문서와 명확한 데모가 제품 자체보다 중요할 수 있습니다.
- 수상은 출발점입니다. 평판을 쌓고 커뮤니티에서 새로운 기회를 열어 줍니다.

<br/>

## 대상

- ZecHub 또는 Zcash 해커톤에 처음 참가하는 빌더
- 다른 생태계에서 왔으며 Zcash이 처음인 개발자
- 해커톤 프로젝트를 오래 지속될 무언가로 발전시키고 싶은 사람

<br/>

## 먼저 이유를 생각하세요

편집기를 열기 전에 어떤 문제를 해결하려는지, 그리고 사람들이 왜 관심을 가져야 하는지 파악하세요. 간단한 방법으로 확인할 수 있습니다. 만들고 있는 것이 없다면 누군가 아쉬워할까요? 자신이 직접 사용할 만한 것을 만드세요. 프라이버시는 Zcash이 존재하는 이유입니다. 따라서 프로젝트 대상이 되는 사람들에게 프라이버시가 왜 중요한지 이해하고, 이를 프로젝트 전반에 반영하세요.

<br/>

## 먼저 스택을 익히세요

다른 체인에서 온 빌더들이 가장 흔히 놀라는 점은 코딩이 아니라 Zcash 인프라를 익히는 데 필요한 시간입니다. 앱을 설계하기 전에 각 요소가 어떻게 맞물리는지 이해할 시간을 확보하세요. 흔히 Z의 세 요소라고 불리는 핵심 스택인 zebrad, 라이트 서버, 지갑부터 시작하세요. 그런 다음 개발 도구를 익히세요.

1. [zechub.wiki/developers](https://zechub.wiki/developers)의 위키 개발자 페이지를 읽으세요. 권장하는 첫 방문 자료입니다.
2. zingolib과 zingo-cli을 살펴보세요. 이들의 호출 기능은 여러 트랙에서 프로젝트에 필요한 대부분의 작업을 지원합니다.
3. 더 낮은 수준의 구성 요소는 librustzcash와 ZODL의 참조 지갑을 살펴보세요.
4. FROST 프로젝트라면 Zcash Foundation의 frostd와 crates.io의 frost-core를 사용하고, 정의를 작성할 때 AI의 도움을 받으세요. 다만 FROST을 안전하게 사용하는 데에는 여전히 상당한 노력과 시간이 필요합니다.

<br/>

## 메인넷이 의미하는 바를 이해하세요

여러 트랙에서는 앱이 Zcash 메인넷과 상호작용해야 합니다. 실제로는 프로젝트 자체 또는 이를 사용하는 사람(예: AI 에이전트)이 메인넷에서 실제 자금을 보내거나 받거나, 이를 가능하게 하는 도구를 만들고 개선해야 한다는 뜻입니다. 앱에서 거래가 이루어진다면 제출물에서 해당 거래를 메인넷으로 시연해야 합니다.

개발하는 동안에는 테스트넷을 사용하세요. 메인넷 활동에는 실제 ZEC가 들고 시간이 지날수록 비용이 더 커질 수 있으므로, 테스트넷에서 반복 개발하는 것을 권장합니다. 최종 증명을 위해 메인넷으로 전환하세요. 흐름을 설계할 때 한 가지 유의하세요. 자금이 거래정보 보호 주소로 들어오면 지갑이 이를 스캔해 찾아야 사용할 수 있으며, 스캔에는 약간의 시간이 걸립니다. 들어온 자금을 즉시 사용할 수 있다고 가정하지 말고, 앱에 짧은 대기 시간을 반영하세요.

<br/>

## 단순하게 유지하세요

단순하고 완성도 높게 실행한 아이디어가 복잡한 아이디어를 여러 차례 앞선 적이 있습니다. 심사위원들은 같은 행사에서 기술적으로 더 야심 찬 프로젝트보다 기본적인 아이디어가 좋은 평가를 받는 것을 지켜봤습니다. 실제 문제를 해결하고 이해하기 쉬웠기 때문입니다. 완성할 수 있다고 생각하는 것보다 적은 범위를 맡으세요. 세부 사항을 간과하거나, 범위를 너무 크게 잡거나, 조사를 생략하는 실수는 수상 기회를 놓치게 합니다. 핵심 개념부터 첫 명령어까지, 프로젝트를 이해하고 실행하기 쉽게 만드세요.

<br/>

## 첫 30초에 좋은 인상을 남기세요

검토자는 빠르게 강한 인상을 형성하므로, 솔루션의 참신성뿐 아니라 발표 방식, 주제, 시각적 요소도 큰 비중을 차지합니다. 문서와 명확한 데모는 나중에 덧붙일 요소가 아닙니다. 만든 것을 아무도 이해하지 못하면 성공할 수 없으므로, 아이디어를 전달하는 일이 때로는 아이디어 자체보다 중요합니다. 심사는 대체로 기술적 깊이, 사용자 경험, 독창성, 실용성을 종합적으로 평가하며, 탄탄한 문서는 이 모든 요소를 높여 줍니다.

<br/>

## 더 어렵고 경쟁이 덜한 트랙을 살펴보세요

경쟁이 덜한 분야를 원한다면 어려운 트랙에 참가해 보세요. 시도하는 사람이 적어 출품작도 적은 경우가 많습니다. 회계 트랙은 온체인 거래 작업을 피하고 싶은 초보자에게 좋은 선택입니다. FROST은 강력하지만 충분히 활용되지 않고 있으며, 프로젝트의 탄탄한 기반이 될 수 있습니다. 커뮤니티가 만들 것을 정해 주지는 않습니다. 따라서 처음부터 시작하기보다는 생태계에 이미 있는 유용한 도구를 활용해 만드는 것이 현명합니다.

<br/>

## 해커톤 이후

수상은 끝이 아닙니다. 수상하면 포트폴리오와 평판을 쌓고 커뮤니티에서 기회를 넓힐 수 있으며, 제안서를 통해 자금 지원으로 이어질 수도 있습니다.

1. 유망한 프로젝트를 로드맵, 마일스톤, 예산 근거를 갖춘 제안서로 발전시켜 ZecHub DAO 또는 Zcash Community Grants에 제출하세요.
2. 포럼, Discord, X에서 커뮤니티 활동을 이어가세요.
3. Arborist R and D 회의에 참여하고, 아이디어를 게시하고, 의견을 구하세요.
4. 수상하지 못하더라도 계속 개발하고 다음 해커톤을 살펴보세요.
