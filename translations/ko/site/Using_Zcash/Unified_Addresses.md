# 통합 주소

> Zcash의 모든 기능을 하나의 주소로 이용하세요. 이 주소를 공유하면 보내는 사람의 지갑이 가장 높은 수준으로 거래정보를 보호하는 결제 방식을 찾아냅니다.

## 요약

* 통합 주소(unified address, UA)는 여러 수신 주소인 Ironwood, Sapling, 투명 주소를 하나로 묶은 단일 Zcash 주소입니다.
* 메인넷 통합 주소는 `u1`로 시작합니다. ZIP 316에서 이를 정의했으며, 2022년 5월 31일 NU5 업그레이드와 함께 도입되었습니다.
* 보내는 사람의 지갑은 양쪽 지갑이 모두 지원하는 풀 중 거래정보를 가장 잘 보호하는 풀을 선택합니다. 직접 풀을 선택할 필요가 없습니다.
* 2026년 7월 Ironwood 풀이 가동된 뒤에도 통합 주소는 계속 사용할 수 있었습니다. 새 주소를 공유할 필요가 없었습니다.
* 지갑에서 보내는 사람마다 새 통합 주소를 만들 수 있으며, 모든 주소로 같은 계정에 결제금을 받을 수 있습니다.

## 핵심 설명

통합 주소(unified address, UA)는 여러 수신 주소를 하나로 묶은 단일 Zcash 주소입니다. 수신 주소는 특정 가치 풀이 자금을 받을 수 있도록 하는 주소의 일부입니다. 여기에는 Ironwood, Sapling, 투명 주소가 있습니다. 메인넷 통합 주소는 `u1`로 시작하며, [ZIP 316](https://zips.z.cash/zip-0316)에서 정의되어 2022년 5월 31일 NU5 네트워크 업그레이드와 함께 도입되었습니다.

통합 주소가 생기기 전에는 ZEC을 받으려면 주소 유형을 고려해야 했습니다. `zs` 주소는 Sapling 자금을 받았고, `t` 주소는 투명 자금을 받았습니다. 주소 유형이 다른 경우에는 보내는 과정에 추가 단계가 필요했습니다. 통합 주소는 이런 번거로움을 없앱니다. 주소 하나만 공유하면 나머지는 지갑이 알아서 처리합니다.

### 작동 방식

누군가 통합 주소로 자금을 보내면, 보내는 사람의 지갑은 통합 주소에 포함된 수신 주소를 확인하고 양쪽 지갑이 지원하는 풀 중 거래정보를 가장 잘 보호하는 풀을 선택합니다.

1. 두 지갑이 모두 현재 거래정보 보호 구역을 지원하면 결제금은 거래정보 보호 방식으로 도착합니다. 온체인에 공개되는 정보는 없습니다.
2. 보내는 사람이 이전 풀에서만 보낼 수 있다면, 지갑은 양쪽이 모두 지원하는 가장 적합한 수신 주소를 사용합니다. 예를 들면 Sapling가 있습니다.
3. 보내는 사람이 투명 자금만 보낼 수 있다면 결제금은 통합 주소의 투명 수신 주소에 도착하고, 이후 지갑에서 거래정보를 보호할 수 있습니다.

직접 관리할 필요는 없습니다. 주소는 그대로 유지되고, 주소 안에서 경로 선택이 이루어집니다.

### 지금 중요한 이유

Zcash은 계속 업그레이드되고 있습니다. 2026년 7월 28일 NU6.3과 함께 Ironwood 풀이 활성화되었을 때도 통합 주소 보유자에게는 새 주소가 필요하지 않았습니다. 지갑이 기존 주소에 포함된 Ironwood 수신 주소를 선택하기 시작했을 뿐입니다. 이전의 독립형 주소를 사용하던 사람들은 주소를 이전해야 했지만, 통합 주소 보유자는 아무것도 할 필요가 없었습니다.

이것이 설계 목표입니다. 앞으로 네트워크 업그레이드로 새로운 풀이 추가되어도 통합 주소에 자동으로 포함되므로, 누구든 주소를 다시 공유하거나 직접 자금을 옮길 필요가 없습니다. 현재 사용 가능한 풀 목록은 [Zcash 가치 풀](/using-zcash/shielded-pools)에서 확인하세요.

### 보내는 사람마다 새 주소 사용

지갑은 하나의 계정에 대해 다양한 통합 주소를 여러 개 생성할 수 있습니다. 각 주소로 받은 자금은 같은 계정에 들어가지만, 온체인에서는 서로 연결할 수 없습니다. 결제하는 사람이나 서비스마다 다른 통합 주소를 알려주면, 어느 누구도 여러 주소를 비교해 해당 주소들이 같은 지갑으로 결제되는지 알아낼 수 없습니다.

## 시각 자료 / 비유

우편 투입구가 3개 있는 현관문을 떠올려 보세요. 가장 새로운 투입구에 넣은 편지는 잠긴 금고(Ironwood)로 들어갑니다. 두 번째 투입구에 넣은 편지는 잠긴 서랍(Sapling)으로 들어갑니다. 세 번째 투입구에 넣은 편지는 창문 너머로 누구나 볼 수 있는 열린 쟁반(투명 주소)에 놓입니다.

우편 배달원은 보내는 사람의 지갑입니다. 자신이 이용할 수 있는 투입구 중 거래정보를 가장 잘 보호하는 것을 사용합니다. 문에 붙은 주소 하나만 알려주면 되고, 집에 새 금고가 생겨도 문에 붙은 주소는 그대로 유지됩니다.

## 자세히 알아보기

### 관련 도구

- **Viewing key.** 모든 계정에는 통합 viewing key가 있어, 지출 권한을 공유하지 않고도 통합 주소로 받은 자금(또는 계정에서 보낸 모든 자금)을 공유할 수 있습니다. 접두사는 `uview`와 `uivk`입니다. [viewing key](/zcash-tech/viewing-keys)를 참조하세요.
- **TEX 주소.** 현재 Binance를 비롯한 일부 거래소는 투명한 출처에서 입금된 자금만 받습니다. TEX 주소([ZIP 320](https://zips.z.cash/zip-0320))는 바로 이런 경우에 통합 주소와 함께 사용하는 투명 전용 주소입니다. [거래소 입금용 투명 주소](/using-zcash/transparent-exchange-addresses)를 참조하세요.
- **결제 요청.** 통합 주소는 금액과 메모가 미리 입력된 결제 요청 URI에 포함할 수 있습니다. [결제 요청 URI](/using-zcash/payment-request-uris)를 참조하세요.

### 주요 정보

| | |
|---|---|
| 접두사 | `u1`(메인넷) |
| 인코딩 | bech32m |
| 정의 문서 | [ZIP 316](https://zips.z.cash/zip-0316) |
| 도입 시기 | NU5, 2022년 5월 31일 |
| 포함 항목 | Ironwood, Sapling, 투명 수신 주소 |
| Spending key | 계정마다 하나씩 있으며, 해당 계정의 모든 통합 주소에서 공유 |

통합 주소를 지원하는 지갑은 [지갑](/wallets) 페이지에서 확인하세요.

## 자주 하는 실수

- **이전 `zs` 또는 `t` 주소를 공유하는 경우.** 독립형 주소는 하나의 풀에만 연결되며 새 풀을 자동으로 지원하지 않습니다. 통합 주소를 공유하세요.
- **모든 사람에게 같은 통합 주소를 알려주는 경우.** 결제한 두 사람이 메모를 비교해 같은 주소를 확인할 수 있습니다. 지갑에서 보내는 사람마다 새 통합 주소를 만들어 알려주세요.
- **통합 주소로 결제하면 언제나 거래정보가 보호될 거라고 생각하는 경우.** 투명 자금만 보낼 수 있는 사람은 투명 수신 주소로 결제하며, 해당 결제 정보는 공개됩니다. 이후 지갑에서 거래정보를 보호하세요.
