# Zcash TEX 주소란 무엇인가요?

## 요약

* TEX 주소는 다른 형식으로 표기된 투명 Zcash 주소입니다. `tex1`로 시작하며 [ZIP 320](https://zips.z.cash/zip-0320)에 정의되어 있습니다.
* 지갑에 한 가지를 알려 줍니다. 이 주소로 투명 자금만 보내라는 것입니다.
* 잔액이 거래정보 보호 상태라면 호환되는 지갑이 두 단계를 대신 처리합니다. 금액을 임시 투명 주소로 옮긴 다음 TEX 주소로 보냅니다.
* 2023년, Binance은 Zcash 커뮤니티에 거래정보 보호 입금을 거부하고 돌려보낼 방법을 요청했습니다. TEX 주소가 그 해답이며, Binance은 ZecHub [수탁형 거래소](/using-zcash/custodial-exchanges) 목록에서 TEX 입금을 받는 거래소입니다.
* 보내는 쪽의 지원도 확대되었습니다. Coinbase에서는 사용자가 ZEC를 TEX 주소로 보낼 수 있으며, 지갑 툴킷에도 ZIP 320 지원이 추가되고 있습니다.
* TEX 주소로 보내는 결제는 다른 투명 결제와 마찬가지로 블록체인에 공개됩니다. 거래정보 보호 잔액의 나머지는 비공개로 유지됩니다.

## 핵심 설명

Zcash TEX 주소는 특수한 수신 주소입니다. TEX는 “Transparent Exchange”의 약자입니다. 단일 p2pkh 투명 주소를 Bech32m으로 다시 인코딩한 것입니다. TEX 주소는 `tex1`로 시작하며 통합 주소와는 별개의 주소 유형입니다.

TEX 주소는 호환되는 지갑에 투명 전용(T -> T) 거래를 수행하라고 알립니다.

처리 방식은 다음과 같습니다. 호환되는 지갑이 TEX 주소를 감지하면 이를 디코딩하여 주소에 포함된 투명 수신자를 확인합니다. 그런 다음 지갑은 거래에 필요한 자금을 거래정보 보호 구역에서 별도의 사용자 소유 임시 투명 주소로 보냅니다(Z -> T). 이어서 해당 자금을 디코딩한 TEX 주소의 투명 수신자에게 보냅니다(T -> T).

TEX 주소에 대한 기술 제안은 Zcash [ZIP 320](https://zips.z.cash/zip-0320)에 설명되어 있습니다. 이 제안은 투명 주소에서 자금을 받기 위한 전용 주소 유형을 정의합니다.

![TEX](/content-images/ZashiTex-b1cbec5f07.webp)

### TEX 주소는 얼마나 널리 사용되나요?

도입은 아직 일부에 그치지만, 이제 단일 거래소에만 국한되지는 않습니다. 구분해야 할 역할은 2가지입니다.

* **TEX 입금 주소 발급.** Binance은 [수탁형 거래소](/using-zcash/custodial-exchanges) 목록에서 입금용 TEX 주소를 발급하는 거래소입니다. 따라서 자금은 투명한 출처에서 들어옵니다([ZIP 320, 배경](https://zips.z.cash/zip-0320#background)). ZIP 320은 결제가 어느 주소에서 왔는지 알아야 하는 경우가 아니라면 다른 거래소가 TEX 주소를 발급할 것으로 예상하지 않습니다.
* **TEX 주소로 보내기.** 이 부분은 지원이 확대되었습니다. 2024년 10월, Coinbase은 Coinbase.com 사용자가 Zcash를 TEX 주소로 보낼 수 있다고 발표했습니다([Coinbase 자산 관련 발표](https://x.com/CoinbaseAssets/status/1844428577921507416)). 지갑 툴킷에도 ZIP 320 지원이 추가되고 있습니다. KeepKey은 펌웨어 7.15에서 TEX 거래 서명 기능을 추가했고([keepkey/hdwallet #75](https://github.com/keepkey/hdwallet/pull/75)), 유효한 `tex1` 수신자를 거부하던 XChainJS `zcash-js` 라이브러리도 수정되었습니다(자세한 내용은 아래 참조).

따라서 TEX 주소가 보편적으로 지원되는 것은 아니지만, 이제 Binance만 TEX 주소를 사용하는 곳이라고 생각해서는 안 됩니다.

### TEX 주소는 언제 필요한가요?

#### 투명 주소로 직접 보내는 기능을 지원하지 않는 지갑을 사용해 투명 주소로 자금을 보낼 때 TEX 주소가 필요합니다.

일부 지갑은 투명 주소로 직접 보내는 것을 허용하지 않으며, 수신자가 이에 대응하는 TEX 주소를 제공하지 않을 수도 있습니다. 따라서 경우에 따라 투명 주소를 TEX 주소로 변환해야 할 수 있습니다. [zip-320](https://zips.z.cash/zip-0320#reference-implementation)에 설명된 참조 구현을 실행하면 직접 변환할 수 있습니다.

#### 자금이 투명한 출처에서 와야 한다고 요구하는 중앙화 거래소로 자금을 보낼 때 TEX 주소가 필요합니다.

[Binance](https://www.binance.com/)가 TEX 주소가 만들어진 이유입니다. 2023년 11월, 해당 거래소는 거래정보 보호 주소에서 들어오는 입금을 거부하고 입금자에게 돌려보낼 방법이 없다면 Zcash 커뮤니티에서 ZEC의 상장 폐지를 검토할 수 있다고 알렸습니다([ZIP 320, 배경](https://zips.z.cash/zip-0320#background)). ZIP 320은 결제가 어느 주소에서 왔는지 알아야 하는 경우가 아니라면 다른 거래소가 TEX 주소를 발급할 것으로 예상하지 않습니다. Binance은 [수탁형 거래소](/using-zcash/custodial-exchanges) 목록에서 TEX 주소로 입금을 받는 거래소입니다.
TEX 주소는 호환되는 지갑에 해당 주소로 보내는 모든 자금이 투명해야 하며, 거래정보 보호 상태의 값은 하나도 해당 주소로 보내면 안 된다고 알립니다.
Binance 같은 거래소가 전송된 자금을 거부하면 해당 자금이 온 주소로 돌려보낼 수단을 갖추고 있습니다. 또한 Binance 같은 기관이 정부나 기타 당국이 부과한 법률과 규정을 준수하는 데도 도움이 됩니다.

### TEX 주소를 지원하는 지갑은 무엇인가요?

최신 목록은 [지갑](/using-zcash/wallets) 페이지에서 확인할 수 있습니다. TEX 주소 필터를 사용하세요.

## 시각 자료 / 비유

거래정보 보호 잔액을 집에 있는 잠긴 금고 속 돈이라고 생각해 보세요. 밖에 있는 사람은 안에 얼마가 있는지 볼 수 없습니다.

Binance 같은 거래소의 계산대에는 “내용물이 보이는 봉투로만 결제할 수 있습니다”라는 안내문이 있습니다. 그래야 직원이 돈이 어디에서 왔는지 확인하고 필요하면 돌려줄 수 있습니다. TEX 주소가 바로 그 안내문입니다.

지갑은 안내문을 보면 금액을 금고에서 꺼내 반송 주소가 적힌 투명한 봉투, 즉 임시 투명 주소에 담아 계산대로 가져갑니다. 금고는 계속 잠겨 있으므로 그 안의 다른 내용물은 누구도 알 수 없습니다.

## 자세히 알아보기

### TEX 주소의 구성

`t1`로 시작하는 일반 투명 주소에는 Base58Check로 표기된 20바이트 키 해시가 들어 있습니다. TEX 주소에는 동일한 20바이트가 `tex`(테스트넷에서는 `textest`) 접두사를 사용하는 Bech32m 형식으로 다시 인코딩되어 들어 있습니다. 한 형식을 다른 형식으로 변환하는 데는 몇 줄의 코드면 충분하며, ZIP 320의 참조 구현에서 그 방법을 확인할 수 있습니다.

이 단순한 설계는 Binance의 요구 사항이었습니다. 거래소의 프런트엔드 코드에서 Base58Check와 Bech32m 라이브러리만으로 변환을 수행할 수 있어야 했습니다. ZIP 320의 초기 초안은 이 기능을 통합 주소에 포함했지만, 이러한 이유로 해당 방식은 폐기되었습니다.

TEX 주소는 통합 주소 형식에서 Bech32m 인코딩을 가져왔지만 구조는 거의 공유하지 않습니다. Bech32m과 Zcash 주소의 검증 방식이 낯설다면 [통합 주소](/using-zcash/unified-addresses) 페이지에서 [ZIP 316](https://zips.z.cash/zip-0316)에 따른 기본 내용을 확인할 수 있습니다. TEX 주소는 다음 4가지 점에서 통합 주소와 구체적으로 다릅니다.

| | 통합 주소 (ZIP 316) | TEX 주소 (ZIP 320) |
|---|---|---|
| 포함된 내용 | 여러 수신자를 하나로 묶음 | 단일 P2PKH 투명 수신자 |
| 사람이 읽을 수 있는 접두사(HRP) | `u` (메인넷) | `tex` (테스트넷에서는 `textest`) |
| F4Jumble 난독화 | 예 | 아니요 |
| 수신자별 타입 코드 | 예 | 아니요 |

요약하면 TEX 주소는 가장 단순한 Bech32m 래퍼입니다. 투명 키 해시 하나와 `tex` 접두사만 있으며 그 외에는 아무것도 없습니다.

### 지갑과 통합 구현의 처리 규칙

구현 과정에서 잘못 처리된 사례가 있어 명확히 설명할 필요가 있습니다. TEX 주소를 감지한 지갑이나 통합 구현은 **거래정보 보호 구역에서 TEX 목적지로 직접 지출해서는 안 됩니다.** ZIP 320은 TEX 결제의 모든 입력이 투명해야 한다고 요구하므로 결제는 다음 2단계로 구성됩니다.

1. **거래정보 보호 해제.** 금액을 거래정보 보호 구역에서 지갑이 소유한 새 사용자 소유 임시 투명 주소로 옮깁니다(Z -> T).
2. **투명 주소에서 투명 주소로 전송.** 해당 임시 출력값을 지출해 TEX 주소 안의 디코딩된 P2PKH 수신자로 보냅니다(T -> T).

다음 규칙을 따르면 안전하게 처리할 수 있으며, 모두 ZIP 320에 명시되어 있습니다.

* 임시 주소는 seed phrase에서 파생해야 합니다. 그러면 거래소가 자금을 돌려보내더라도 지갑에서 이를 찾아 지출할 수 있습니다.
* 서로 다른 결제의 연결을 막으려면 매번 새로운 임시 주소를 사용해야 합니다.
* 두 번째 거래에는 투명 입력만 사용해야 거래소에서 투명 주소 간의 깔끔한 입금으로 확인할 수 있습니다.

변환과 2단계 흐름은 [ZIP 320 참조 구현](https://zips.z.cash/zip-0320#reference-implementation)에 나와 있습니다. 이를 잘못 처리하는 것은 최근에도 발생한 실제 문제입니다. 2026년 10월, XChainJS `zcash-js` 라이브러리는 “Invalid 'to' address” 오류와 함께 유효한 `tex1` 수신자를 거부했습니다. 검증기가 Base58Check `t1` 형식만 허용했기 때문이며, 이로 인해 `tex1` 주소를 게시하는 서비스로의 ZEC 입금이 실패했습니다([이슈 #1782](https://github.com/xchainjs/xchainjs-lib/issues/1782)). 검증기가 ZIP 320 인코딩도 허용하도록 수정해 이 문제가 해결되었습니다([PR #1783](https://github.com/xchainjs/xchainjs-lib/pull/1783)).

### TEX 결제로 드러나는 정보

TEX 결제는 투명 결제이므로 공개됩니다. 다만 관찰자가 무엇을 볼 수 있고 볼 수 없는지 정확히 설명할 필요가 있습니다.

온체인에서 **공개되는 정보**:

* 임시 투명 주소. 거래정보 보호 해제 단계의 출력이자 최종 전송의 입력으로 표시되기 때문입니다.
* 두 거래의 금액: Z -> T 단계에서 거래정보 보호 구역을 떠난 금액과 T -> T 단계에서 전달된 금액입니다.
* 거래소의 투명 수신자. TEX 주소에 인코딩된 P2PKH 주소입니다.

**숨겨지는 정보**:

* 거래정보 보호 잔액의 나머지와 결제에 사용된 구체적인 거래정보 보호 노트입니다. 거래정보 보호 해제 단계에서는 풀에서 임시 주소로 어떤 값이 나왔다는 사실만 드러날 뿐, 풀 안의 어디에서 나온 값인지는 드러나지 않습니다.

따라서 관찰자는 임시 주소와 거래소 결제를 연결할 수 있습니다. 동일한 자금이 투명 주소에서 투명 주소로 이동하기 때문입니다. 또한 해당 주소에 거래정보 보호 출금으로 자금이 보충되었다는 사실도 볼 수 있습니다. 그러나 이 주소를 다른 거래정보 보호 자금이나 활동과 연결할 수는 없습니다. 온체인에는 결제를 “TEX” 전송이라고 표시하는 정보가 없습니다. ZIP 320에 설명되어 있듯이, TEX 주소로 보내는 결제는 해당 `t1` 주소로 보내는 결제와 구분할 수 없습니다. 합의 규칙은 그대로이고 전체 규칙은 지갑에만 적용되기 때문입니다.

![On-chain footprint of a TEX send: funds leave the shielded pool to an ephemeral transparent address, then go transparent-to-transparent to the exchange; the ephemeral address, both amounts and the exchange address are visible, while the rest of the shielded balance stays hidden](/content-images/tex-onchain-footprint.webp)

### 블록체인에 표시되는 내용

TEX 규칙은 지갑에 적용됩니다. 노드는 이 규칙을 확인하지 않으므로 합의 규칙은 그대로 유지됩니다. 온체인에서 TEX 주소로 보내는 결제는 해당 `t1` 주소로 보내는 결제와 동일하게 보입니다. 다른 투명 거래와 마찬가지로 금액, 임시 주소, 거래소 주소가 공개됩니다.
