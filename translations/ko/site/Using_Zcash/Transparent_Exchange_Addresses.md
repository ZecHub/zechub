# Zcash TEX 주소란 무엇인가요?

## 요약

* TEX 주소는 다른 형식으로 작성된 투명 Zcash 주소입니다. `tex1`로 시작하며 [ZIP 320](https://zips.z.cash/zip-0320)에 정의되어 있습니다.
* 지갑에 한 가지를 알려 줍니다. 이 주소에는 투명 자금으로만 지급하라는 것입니다.
* 잔액이 보호되어 있다면, 호환되는 지갑이 두 단계를 대신 수행합니다. 금액을 임시 투명 주소로 옮긴 다음 TEX 주소로 보냅니다.
* 2023년, Binance는 Zcash 커뮤니티에 보호된 예치를 거부하고 되돌려 보낼 방법을 요청했습니다. TEX 주소가 그 해답이며, Binance은 ZecHub [수탁형 거래소](/using-zcash/custodial-exchanges) 목록에서 TEX 예치를 받는 거래소입니다.
* TEX 주소로의 결제는 모든 투명 결제처럼 블록체인에서 공개됩니다. 나머지 보호된 잔액은 비공개로 유지됩니다.

## 핵심 설명

Zcash TEX 주소는 특수한 유형의 수신 주소입니다. TEX는 "Transparent Exchange"를 뜻합니다. 단일 p2pkh 투명 주소를 Bech32m으로 다시 인코딩한 것입니다. TEX 주소는 `tex1`로 시작하며 Unified Address와는 별개의 유형입니다.

TEX 주소는 호환되는 지갑에 투명 전용(T -> T) 트랜잭션을 생성하도록 지시합니다. 

작동 방식은 다음과 같습니다. 호환되는 지갑이 TEX 주소를 감지하면 이를 디코딩하여 포함된 투명 수신자를 가져옵니다. 그런 다음 지갑은 트랜잭션에 필요한 자금을 보호된 풀에서 별도의 사용자가 제어하는 임시 투명 주소로 보냅니다(Z -> T). 이후 해당 자금을 TEX 주소에서 디코딩한 투명 수신자에게 보냅니다(T -> T).  

TEX 주소의 기술 제안은 Zcash [ZIP 320](https://zips.z.cash/zip-0320)에 설명되어 있으며, 투명 주소에서 오는 자금만 수신하기 위한 주소 유형을 정의합니다.

![TEX](/content-images/ZashiTex-b1cbec5f07.webp)

TEX 주소는 아직 널리 채택되지 않았습니다. Zcash 사용자는 결국 이를 사용해야 할 수도 있습니다.

### TEX 주소는 언제 필요한가요?

#### 투명 주소로 직접 전송을 지원하지 않는 지갑을 사용하여 투명 주소에 자금을 보낼 때 TEX 주소가 필요합니다.

일부 지갑은 투명 주소로 직접 보내는 것을 허용하지 않으며, 수신자가 TEX에 해당하는 주소를 제공하지 않을 수도 있습니다. 따라서 때때로 투명 주소를 TEX 주소로 변환해야 할 수 있습니다. 이는 [zip-320](https://zips.z.cash/zip-0320#reference-implementation)에 설명된 참조 구현을 실행하여 수동으로 수행할 수 있습니다.

#### 자금이 투명 출처에서 와야 한다고 요구하는 중앙화 거래소로 자금을 보낼 때 TEX 주소가 필요합니다.

[Binance](https://www.binance.com/)가 TEX 주소가 존재하는 이유입니다. 2023년 11월, Zcash 커뮤니티에 보호된 주소의 예치를 거부하고 예치자에게 되돌려 보낼 방법이 없으면 ZEC가 상장 폐지될 수 있다고 알렸습니다([ZIP 320, 배경](https://zips.z.cash/zip-0320#background)). ZIP 320은 다른 거래소가 결제가 어느 주소에서 왔는지 알아야 하는 경우가 아니라면 TEX 주소를 발급할 것으로 예상하지 않습니다. Binance은 당사의 [수탁형 거래소](/using-zcash/custodial-exchanges) 목록에서 TEX 주소 예치를 받는 거래소입니다.
TEX 주소는 호환되는 지갑에 해당 주소로 보내는 모든 자금이 투명해야 하며, 보호된 가치는 해당 주소로 전송하지 말아야 함을 알립니다.
Binance와 같은 거래소가 전송된 가치를 거부하면, 그 가치를 원래 출처 주소로 되돌려 보낼 수단을 갖추고 있습니다. 또한 Binance와 같은 기관이 정부나 기타 당국이 부과한 법률 및 규정을 준수하는 데 도움이 됩니다.

### 어떤 지갑이 TEX 주소를 지원하나요?

가장 최신 목록은 당사의 [지갑](/using-zcash/wallets) 페이지에서 볼 수 있습니다. TEX Address 필터를 사용하세요.

## 시각화 / 비유

보호된 잔액을 집에 있는 잠긴 금고 안의 돈이라고 생각해 보세요. 외부에서는 안에 얼마나 들어 있는지 아무도 볼 수 없습니다.

Binance와 같은 거래소의 창구에는 표지판이 있습니다. 계산원이 돈의 출처를 확인하고 필요하면 돌려줄 수 있도록 투명 봉투에 든 결제만 받는다는 표지판입니다. TEX 주소가 바로 그 표지판입니다.

지갑이 표지판을 보면 금고에서 금액을 꺼내 반송 주소가 적힌 투명 봉투에 넣고(임시 투명 주소), 그 봉투를 창구로 가져갑니다. 금고는 계속 잠겨 있고, 그 밖에 무엇이 들어 있는지는 아무도 알 수 없습니다.

## 심층 분석

### TEX 주소의 구성 방식

`t1`로 시작하는 일반적인 투명 주소에는 Base58Check로 작성된 20바이트 키 해시가 들어 있습니다. TEX 주소는 동일한 20바이트를 접두사 `tex`(testnet에서는 `textest`)를 사용해 Bech32m으로 다시 인코딩합니다. 하나를 다른 하나로 변환하는 데는 몇 줄의 코드만 필요하며, ZIP 320은 참조 구현에서 이를 보여 줍니다.

단순한 설계는 Binance의 요구사항이었습니다. 변환은 거래소 프런트엔드 코드에서 Base58Check와 Bech32m 라이브러리만으로 실행되어야 했습니다. ZIP 320의 이전 초안은 이 개념을 Unified Address에 포함했지만, 이 이유로 해당 버전은 폐기되었습니다.

### 보호된 잔액으로 TEX 주소에 결제하기

ZIP 320은 호환되는 지갑이 여기서 두 개의 트랜잭션을 생성하도록 요구합니다. 첫 번째는 보호된 잔액에서 새 임시 투명 주소로 자금을 옮깁니다. 두 번째는 해당 주소에서 TEX 주소로 자금을 보냅니다.

거래소가 예치를 거부하면 자금을 임시 주소로 반환합니다. 지갑은 이를 찾아 사용할 수 있어야 하므로, ZIP 320은 지갑이 시드 문구에서 임시 주소를 파생하도록 요청합니다. 또한 별도의 결제가 서로 연결되지 않도록 지갑이 매번 새로운 임시 주소를 사용하도록 요청합니다.

### 블록체인에 표시되는 내용

TEX 규칙은 지갑에 존재합니다. 노드는 이를 검사하지 않으므로 합의 규칙은 동일하게 유지됩니다. 온체인에서 TEX 주소로의 결제는 대응하는 `t1` 주소로의 결제와 동일하게 보입니다. 모든 투명 트랜잭션과 마찬가지로 금액, 임시 주소, 거래소 주소는 공개됩니다.
